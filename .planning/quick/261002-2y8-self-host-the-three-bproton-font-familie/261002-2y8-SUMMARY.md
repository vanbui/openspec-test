## Coverage decision

**Option C (locked):** latin is preloaded; each family's latin-ext companion face is downloaded only when a page renders one of its characters.

**Why (RESEARCH.md section 4):** C is the only option that meets three constraints together. Names with latin-ext characters (Ł, ő, ș, ā) render in family, as they did in the Google era. The preload stays limited to latin, which every page needs. The total shipped stays modest. Option A (latin only) would render latin-ext letters in the fallback face mid-word. Option B (one call per family) would preload all 12 files on every page.

`next/font/local` sets `preload` and descriptors per call, so each subset needs its own call. The companion's `unicode-range` excludes U+0020, so it is never the first available font and needs no fallback metrics.

### Auto-fixed Issues

**1. [Rule 1 - Bug] The README file-name pattern in the unit test missed the licence files**
- **Found during:** Task 1 (green run)
- **Issue:** the plan's pattern for README file names, `` `[a-z0-9-]+\.(woff2|txt)` ``, cannot match the upper-case `*-OFL.txt` names it requires. Case 3 reported the three licence files as unlisted.
- **Fix:** I widened the pattern to `[A-Za-z0-9-]+` with a comment. The check is unchanged otherwise, and it still requires every committed file to be listed and hashed.
- **Files modified:** apps/csrm/src/lib/security/self-hosted-fonts.test.ts
- **Commit:** 4913c90

**2. [Rule 1 - Plan expectation] The Requestor button renders at weight 400, not 500**
- **Found during:** Task 2 (the first Playwright run)
- **Issue:** the plan expected `button[name="role"][value="Requestor"]` to render `PlusJakartaSans-Medium`. A diagnostic showed its computed `font-weight` is `400`. The unlayered `button, select, input, textarea { font: inherit; }` in globals.css beats the layered `.text-button` utility (weight 500, per direction section 3.10). Nothing on /sign-in uses Jakarta 500 (`jakarta 500 unloaded`). This is a pre-existing cascade defect that the loader cannot affect. The research spike proved Medium with a probe, not the button.
- **Fix:** the product was not changed. Fixing the cascade would change button size and weight app-wide, which goes against D-1, so I logged it in `deferred-items.md`. The proof now requires the button to render in the Jakarta face of its computed weight, which holds before and after a cascade fix. It also adds a `font-weight: 500` sans probe that must render `PlusJakartaSans-Medium`. Every shipped weight (sans 400/500/600, mono 400/500, display 400) is still proved by postScriptName.
- **Files modified:** apps/csrm/e2e/design-system-conformance.spec.ts
- **Commit:** b85a778

**3. [Rule 2 - Added check] The browser proof also requires that no request leaves the web origin**
- The plan's step 7 checked the host pattern and the font request origins. The must-have truth says "no request from /sign-in leaves the web origin", so the test asserts that directly too (data: URLs excepted).
