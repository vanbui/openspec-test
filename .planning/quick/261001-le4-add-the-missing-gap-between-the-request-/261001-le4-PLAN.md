<objective>
Give the Security Analyst's request detail view (`/app/review/requests/{documentId}`) the same 24px vertical gap after the "Request relationships" card that the Requestor's request detail view (`/app/requests/{documentId}`) already has.

Root cause, confirmed by reading the working tree at `5d6d66b` (no uncommitted source changes):

- Requestor view, `apps/csrm/app/(app)/app/requests/[documentId]/page.tsx` lines 59-84: the stepper, the hub, the "Request context" section and the actions section are all children of one `<div className="grid gap-6">`. The grid's gap puts 24px between every pair of blocks.
- Analyst view, `apps/csrm/src/features/assessments/assessment-detail.tsx` lines 76-86: the same blocks are loose siblings in a fragment, each spaced by its own one-sided margin. The hub sits in `<div className="mt-6">` (line 77, top margin only), and the "Request context" section sits in a separate `<div className="grid gap-6">` (line 79, no margin). Nothing separates the two:
  - Request not `submitted`, or assessment available (the reported page): the "Request relationships" card's bottom edge touches the "Request context" card's top edge. Gap 0px.
  - Request `submitted` with no available assessment: line 78 renders the "Return to draft" button in `<div className="mb-4">`. The button touches the "Request relationships" card above it (0px) and has 16px below it.
- The page's `main` element (class `page`, `apps/csrm/app/globals.css` line 645) is a plain block container, so the existing `mt-6` margins collapse with the page header's 24px bottom margin. That is why the other intervals already measure 24px and only the interval after the hub is wrong.

The fix makes the Analyst view use the Requestor view's pattern: `PageHeader` stays outside, and every block below it becomes a direct child of one `grid gap-6` div. The one-sided margins (`mt-6` on the stepper, hub and questionnaire generation wrappers, `mb-4` on the reversal wrapper, the `mt-6` class passed to `AssessmentDraftJob`) go away, because the grid gap now owns the rhythm. This sets the interval after the hub to 24px in both states and leaves every other interval at the 24px it already measures.

Requirement IDs, local to this quick task:
- RGAP-01: With no "Return to draft" control, 24px separates the "Request relationships" card from the "Request context" card.
- RGAP-02: With the "Return to draft" control, 24px separates it from the card above and from the card below, and the button keeps its intrinsic width.
- RGAP-03: Every other interval stays at 24px with no doubling; mobile and desktop both hold; the Requestor view and the shared components are untouched.

Purpose: The two request detail views share one vertical rhythm, owned by one container, so a block added later cannot land flush against its neighbour.
Output: A restructured populated return in `assessment-detail.tsx` (same blocks, same order, one grid container) and two regression tests in `assessment-review-workflow.test.tsx`.
</objective>
