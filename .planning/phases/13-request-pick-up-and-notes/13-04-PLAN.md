## Phase Goal

**As a** Security Analyst, **I want to** pick up a request and exchange notes with the Requestor on it, **so that** ownership is clear and new information has a home at any point.

This plan's slice: the analyst's web layer can find who may hold a request, change the assignee with the server's reasons in plain words, and read who holds every request, with every person shown by name only.

## Recorded planning decisions

- **Eligible read.** `listAssignableAnalysts({ strapi, requestDocumentId, caller, q })` in `request-assignment.ts`: 404 for a missing request; 403 `OWN_REQUEST` when the caller is the requestor; 409 `REQUEST_NOT_SUBMITTED` for a draft; otherwise one bounded Document Service read of `api::idambox-user.idambox-user` filtered to `accountStatus: "active"`, a role named `HUMAN_SECURITY_ANALYST_ROLE_NAME` and, with `q`, `displayName` `$containsi` the trimmed term, with roles populated to `functionApis`, sorted `displayName:asc` then `id:asc`, limit 200; then `isEligibleAssignee` per row; the first 50 projected with `projectPerson`. The current assignee stays in the set (it is eligible); the web picker leaves them out (`pickerOptions`).
- **Route.** In `routes/request-assignment.ts`: `GET /v1/assessment_requests/:requestId/assignable_analysts`, handler `api::csrm-assessment-request.request-assignment.listAssignableAnalysts`, operation `CSRM_ASSESSMENT_REQUEST_OPERATIONS.listAssignableAnalysts` (its human-only literal already exists, 13-03). The controller accepts only the query key `q` (string, 1 to 100 characters after trimming); any other key → 400.
- **Spec.** Path `/v1/assessment_requests/{requestId}/assignable_analysts` `get`, operationId `assessment-workflow/get-assignable-analysts`, tag `assessment-workflow`, query `q` (`minLength: 1, maxLength: 100`); 200 `AssignableAnalystListResponse` = `{ data: ActiveUserSummary[] (maxItems 50) }`, closed; 400, 403, 404, 409 `AssessmentWorkflowErrorResponse`.
- **Catalogue.** `function.risk_assessment_requests.assignment_api.api.02` (`List Assignable Security Analysts`, `GET:/api/v1/assessment_requests/{requestId}/assignable_analysts`, sourceEntities `CsrmAssessmentRequest`, `IdamBoxUser`).
- **Request read projection.** `request-people.ts` gains `ALLOWED_REQUEST_READ_POPULATE = ["informationSystems", "informationAssets", "questionnaire", "assessment"]`, `filterRequestReadPopulate(populate: unknown): unknown` (accepts the string, comma list, array and object forms; drops `*` and every other key), `REQUEST_PEOPLE_POPULATE` (`requestor`, `revertedBy`, `assignedAnalyst`, `assignedBy` each with `fields: PERSON_FIELDS`), and `projectRequestorAssignment(assignee)` → `{ assignee: { displayName } | null }`. `findOne` filters `ctx.query.populate` before `super.findOne`, reads the request once more with `REQUEST_PEOPLE_POPULATE` plus `assignmentLog`, `assignedAt` and `requestStatus`, and adds `revertedBy` (projected, or null) and `assignment`: the analyst view (`projectAnalystAssignment` from 13-03, with `resolvePeople` over the history's ids) when `csrmAuthorization.assessmentRequestActor === "analyst"` and `csrmAuthorization.humanAnalyst === true`; otherwise the Requestor view. A requesting analyst reading their own request through the analyst grant gets the analyst view with `ownRequest: true` and `actions: []`.
- **Spec for the read.** The request read's `populate` enum becomes exactly the four allowed names; the findOne response's data schema (the one declaring `requestor`, `relationships` and `lifecycle`) gains `revertedBy: AssessmentRequestRevertActor | null` (replacing any populated-user shape) and `assignment` `oneOf [AssessmentRequestAssignment, AssessmentRequestRequestorAssignment]`, where `AssessmentRequestRequestorAssignment` = `{ assignee: { displayName: string } | null }` closed.
- **Revert response.** `revertRequestToDraft` populates `revertedBy` with `fields: PERSON_FIELDS` and the controller replaces it with `projectPerson(...)` before sanitising, so the revert response carries `documentId` and `displayName` only.
- **Web actions.** `assignment-actions.ts` (`'use server'`): `changeAssigneeAction(input: unknown)` (strict `{ requestId, requestNumber, analyst: string | null, expectedAnalyst: string | null, reason?: string }`) returns `{ ok: true; data: RequestAssignment } | { ok: false; kind: 'blocked' | 'retryable'; reason?: ConflictReason; message: string; currentHolder?: string | null }`; on `ASSIGNMENT_CHANGED` it calls `getRequest(requestId)` once and returns the holder's display name (or null) in `currentHolder` and in the message; on success it revalidates `/app/review/requests`, `/app/review/requests/{id}`, `/app/review/assigned`, `/app` and `/app/requests/{id}`. `listAssignableAnalystsAction(input: unknown)` (strict `{ requestId, q? }`) returns `{ ok: true; data: Person[] } | { ok: false; kind; reason?; message }` with no revalidation.
- **Family K.** `refusal-copy.ts` gains family `requestAssignment` (K) and `assignmentRefusal(reason, { holderName, targetName }, status?)` returning UI-SPEC §7.4's sentences and kinds verbatim: the two `ASSIGNMENT_CHANGED` forms, `ASSIGNEE_NOT_ELIGIBLE`, `OWN_REQUEST`, `REQUEST_NOT_SUBMITTED`, `ASSIGNMENT_REQUIRED`, a 403 without a known reason, the 409 fallback, and the retryable network sentence; 404 maps to Phase 10's locked request refusal.
- **Domain.** `assignment-domain.ts` gains `pickerOptions(people, currentAssigneeId)` (drops the current assignee, keeps server order) and `assignmentTitle(action, requestNumber)`; zod-free.
