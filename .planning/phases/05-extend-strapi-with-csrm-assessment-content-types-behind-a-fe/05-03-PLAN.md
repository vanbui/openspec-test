# Plan 05-03: CSRM Verification Documentation And Types

<objective>
Prove the Phase 5 CSRM model and feature-flag contract with static verification, documentation, and type/build checks.
</objective>

<requirements>
- CSRM-01: Administrator can enable CSRM backend collections through the `csrmAppIsEnabled` environment flag.
- CSRM-02: Backend can manage CSRM Assessment Request records.
- CSRM-03: Backend can manage CSRM Assessment Questionnaire records associated with assessment requests.
- CSRM-04: Backend can manage CSRM Assessment records associated with assessment requests and release state.
</requirements>

<threat_model>
## Threat Model

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-07 | Static checks pass while locked CSRM fields, enums, relations, or guards were dropped. | high | Add `verify:csrm-model` assertions for all seven schemas, key enum values, relation targets, route policy usage, docs, and package script. |
| T-05-08 | Documentation implies Phase 5 includes frontend workflows, OIDC login, or fine-grained CSRM authorization. | medium | Docs explicitly state Phase 5 is backend content model only and Phase 6 owns UI/login/workflow transitions. |
| T-05-09 | Generated Strapi types drift from schema files and break future builds. | medium | Regenerate or verify `apps/backend/types/generated/contentTypes.d.ts` after adding schemas. |
</threat_model>
