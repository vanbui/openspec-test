## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: Bob switches on the security pack in the Files section, reads exactly what the AI will see, generates, and finds the pack, and only the pack, in "What the AI used"; Jane never sees a switch, and Bob cannot steer the AI on a request he raised.

- **Actions** (`attachments-actions.ts`): `setAttachmentAiInputAction({ requestId, attachmentId, included })` returns the projection or family P (`attachmentAiRefusal`, with the list's classification and ceiling); `getAttachmentAiTextAction({ requestId, attachmentId })` returns `{ text, facts }` or a refusal with its status (the sheet maps 409 to its own line).
- **Control** (`file-ai-control.tsx`, `'use client'`): rendered by `FilesList` in the `AI inputs` column (analysts only), the card's `AI inputs: {facts}` line and the phone sheet; with `ai.canChange` and `aiPolicy.canChange`, the `Switch` labelled `Changes the AI inputs` (`aria-describedby` the file's name), the X-22 facts line, and `Preview text` (ghost small, `ScanText`, `Preview text of {name}`, `aria-haspopup="dialog"`) when included; on: the pending opacity and `Reading the file’s text…` with the inline spinner until the server answers, then the facts and the toast `{name} included in the AI inputs.` with `Undo` (`{name} no longer included.`); off: immediate, the toast `{name} no longer included in the AI inputs.` with `Undo` (waits, `{name} included again.`), rolling back with a danger toast titled `Inclusion not changed`; `unavailableReason` lines (`Images can’t be included, because the AI reads text only.`, `It can be included once it passes the malware check.`); blocked and unavailable files show nothing; closed windows show the facts line read-only.
- **Section lines** (`files-section.tsx`): for analysts, one line under the description from `aiPolicy`: `OWN_REQUEST` (`Lock`), `AI_CLASSIFICATION_ABOVE_CEILING` and `AI_POLICY_NOT_CONFIGURED` (`ShieldBan`), or the allowed line `Include only files whose content is within this request’s {level} classification.`; the Requestor keeps §3.1's sentence only.
- **Sheet** (`file-text-sheet.tsx`, `'use client'`, loaded with `next/dynamic` from the control): X-13 side sheet from 768px at the form dialog width and full screen at 375px; title `Text the AI will read`; description `{name} · {facts line}. CSRM sends this text to the AI as information to analyse, never as instructions.`; the text in a `--color-bg-inset` well, `--text-body`, `whitespace-pre-wrap`, `[overflow-wrap:anywhere]`, rendered as a text node; the end line when truncated; `Close text preview`, `Escape` closes, focus returns to `Preview text`; loading shows nothing for 300ms, then the title, description and eight text-line skeletons; error `We couldn’t load the file’s text` with `Try again`; 409 `This file’s text is no longer included, so there’s nothing to preview.`; 403 family P.
- **Run sheet** (`ai-run-sheet.tsx`): after the `Notes` group, `Files`: `{n} {file|files} included`, then per included file in upload order a record link `{name}` → `/app/review/requests/{requestId}#file-{fileId}` (the sheet closes, then the route navigates) and the value `{Requestor|Security Analyst} file · {s} characters sent`, plus ` · first {s} of {m}` when truncated and ` · Removed since` when removed; none: `None included`; never the text.
- **Failure list** (`context-too-large-files.tsx`, server-safe, no directive): `ContextTooLargeFiles({ requestId, files })` renders `The files included in the AI inputs hold more text than CSRM can send at once, so nothing was sent. Exclude a file, then try again.` and an `ul` of record links to `#file-{id}`; both job cards render it when the failure code is `CONTEXT_TOO_LARGE` and `failure.attachments` is non-empty, else Phase 12's copy unchanged.
