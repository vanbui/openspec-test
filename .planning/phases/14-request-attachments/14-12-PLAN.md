## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: Jane opens her draft, chooses her vendor's security pack and sees it added and listed with her name and the time; a wrong, oversized or infected file is refused in place with what to do next, and nothing she chose is lost if she navigates away.

<objective>
Build the web's attachment feature for adding files on a draft: the zod-free domain module, the X-23 size formatter, the upload and list Server Actions, the X-19 field, the X-20 queue, the tab's in-memory file store in the `(app)` layout, and the first `Files` section on the Requestor's request page (D-26 to D-28; UI-SPEC §1, §3.1, §3.2, §3.6, §3.7); create the attachments Playwright spec with the intake and refusal journeys at both widths, and pin the Playwright Strapi's attachment settings.

Purpose: COLLAB-02 criteria 1 and 2 in the UI; ROADMAP success criterion 3.
Output: seven web modules, one page change, one new journey spec.

Edits Strapi source? No. Changes the specification? No. Runs Playwright? Yes (the new spec).
Scope note: 18 files: seven new web modules with their seven unit test files; the `(app)` shell that mounts the file store; the Requestor's request page that mounts the Files section; the new Playwright spec and the configuration that pins Strapi's attachment settings. They change together because the tracer proves one file added on a draft in a real browser, which needs the action, the field, the queue, the store, the section and the page at once, and each module ships with its own test (accepted, as 14-06).
</objective>

## Recorded planning decisions

- **Domain** (`attachments-domain.ts`, zod-free, no directive): types mirroring the schema (`RequestAttachment`, `AttachmentState`, `AttachmentAddFacts`, `AttachmentType`); `ATTACHMENT_ACCEPT = ".pdf,.docx,.xlsx,.pptx,.csv,.txt,.png,.jpg,.jpeg"`; `ALLOWED_TYPES_SENTENCE = "PDF, Word (.docx), Excel (.xlsx), PowerPoint (.pptx), CSV, text (.txt), PNG or JPEG"`; `MAX_FILE_BYTES = 26_214_400`; `precheckChosenFiles(files, { remaining, existingKeys })` (extension, empty, size, remaining count, duplicate by name, size and `lastModified`) returning rows with a family N reason or `null`; the queue model `QueueRow = { key, file, stage: "chosen" | "waiting" | "adding" | "added" | "pending" | "refused" | "failed", message?, offerNewNote? }` and `queueReducer`; copy builders `fileFieldHint(remaining)`, `queueCountLine(rows)`, `filesCountLabel(n)`, `fileTypeLabel(type)` (`PDF`, `DOCX`, …), `fileTypeIconName(type)` (X-21), `filesEmptyState(window, viewer)` and `filesLockedLine(refusal, viewer)` (§1.2, §3.6, §3.7 verbatim).
- **Sizes** (`lib/files/format-file-size.ts`): `formatFileSize(bytes)`: under 1,024 `{n} bytes`; under 1,048,576 whole KB rounded up (`640 KB`); otherwise MB to one decimal (`2.4 MB`); `tabular-nums` is the renderer's (X-23).
- **Actions** (`attachments-actions.ts`, `'use server'`): `listRequestAttachmentsAction({ requestId })`; `uploadAttachmentAction(formData)` reading `requestId`, `file` and optional `noteId`, refusing locally (without calling Strapi) a missing or non-`File` part, then calling `uploadRequestAttachment` and returning `{ ok: true, data }` or `{ ok: false, kind, message, reason, offerNewNote }` through `attachmentAddRefusal` with `sizeLabel: formatFileSize(file.size)` and the transport's `detection`. Upload actions never call `revalidatePath`, `refresh` or `redirect` (14-RESEARCH Pitfall 18); the draft page refreshes the list with `router.refresh()` after its queue settles.
- **Field** (`file-field.tsx`, `'use client'`): X-19 exactly (label prop `Add files` or `Add files with a note`; hidden `input type="file" multiple accept={ATTACHMENT_ACCEPT}` labelled by the field label; `Choose files` outline small, full width below 768px; `Drag files here, or` from 768px; the hint with `aria-describedby`); while mounted, `usePageFileDropGuard` adds `window` `dragover` and `drop` listeners that call `preventDefault()` and set `dropEffect = "none"` for file drags outside the region, removed on unmount (UI-D30).
- **Queue** (`upload-queue.tsx`, `'use client'`, loaded with `next/dynamic` by the section): the X-20 rows and actions from UI-SPEC §1.4 verbatim, including each control's accessible name (`Retry {name}`, `Remove from list: {name}`, `Choose another file to replace {name}`); the count line with `role="status"`; sends `waiting` rows in order, one `uploadAttachmentAction` at a time; `aria-busy` on a row while adding; focus rules of §1.4; `useLeaveGuard(inFlight, …)` while any row is waiting or adding, and `{ beforeUnloadOnly: true }` while the store keeps any file.
- **Store** (`file-store.tsx`, `'use client'`): `AttachmentFileStoreProvider` holds `Map<string, QueueRow[]>` in React state keyed `{ownerKey}:{requestId}:{scope}` (`scope` is `draft` or `note:{noteId}`), with `useAttachmentQueue(ownerKey, requestId, scope)`, `useFilesInFlight(ownerKey, requestId)` (waiting plus adding, for UI-D5's submit dialog) and `useKeptFiles(...)`; `File` objects live only in memory; nothing is written to `localStorage`, `sessionStorage` or IndexedDB. `components/shell/app-shell.tsx` wraps `{children}` with it in the authorised branch only.
- **Section** (`files-section.tsx`): `FilesSection({ requestId, viewer, summary, attachments, draftOwnerKey })` renders a `DetailSection` titled `Files` (h2, `id="files"`, `tabIndex={-1}`) with §3.1's description for the viewer, the count line, the main list (newest first; a `DataTable` from 768px with `Name` (type icon, name, type label), `Size`, `Added by`, `Added` (`LocalInstant`), `Note` (`Note · {instant}` or `Before submission`); cards below 768px), the §3.7 empty states, and, for the draft's requestor, the field and the queue (files added at once). Each row or card has `id="file-{documentId}"` and `tabIndex={-1}`. Download, remove and restore, the states' badges, the analyst page and the phone actions sheet arrive in 14-13.
- **Page**: `app/(app)/app/requests/[documentId]/page.tsx` loads `listRequestAttachments` when the request read carries `attachments` and renders `FilesSection` directly before the Notes section; nothing renders without `attachments`.
- **Playwright**: `e2e/request-attachments.spec.ts` (each test with its own records; files read from `../backend/tests/fixtures/attachments/` or built in memory; never a malware test string other than `CSRM-TEST-MALWARE-SIGNATURE-7c1e4a`); `playwright.config.ts`'s Strapi `webServer.env` gains `CSRM_ATTACHMENT_STORAGE: 'local'`, `CSRM_ATTACHMENT_LOCAL_DIR: join(e2eRuntimeRoot, 'attachments')`, `CSRM_ATTACHMENT_SCANNER: 'development'`, and the mobile project's `testMatch` gains `'**/request-attachments.spec.ts'`.
