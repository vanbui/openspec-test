## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: every reason a file is refused has one name everywhere and one sentence on the screen. A file carrying malware is refused with a 422 whose reason and detection survive from Strapi through the contract and the web transport to the words the person reads.

<objective>
Add Phase 14's closed refusal reasons in one contract change to Strapi's list, both error response schemas (with `detection` for the 422) and the web's list (D-04 item 10, D-11); make the web transport keep the reason and detection on a 422 (Orchestrator Confirmations); and add refusal families N, O and P to `refusal-copy.ts` with the 14-UI-SPEC §8 sentences verbatim.

Purpose: COLLAB-02 criterion 2 ("refused with its reason") at the contract and copy layers, once, so the operation plans 14-06 to 14-11 never touch the vocabulary again (the 12-11 pattern).
Output: one vocabulary change, one transport change, three copy families.

Edits Strapi source? Yes (the reason list only). Changes the specification? Yes (error schemas only: no operation, grant or success schema). Runs Playwright? No. Regenerates `served-operations.json`? No.
</objective>
