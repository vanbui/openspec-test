## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: the real Risks route, measured. A Security Analyst opens Risks from the assessment and moves through 150 risks without lag; decision 7's spike records pass or fail before the rest of the table is built on the grid.

<objective>
Put the grid of 18-03 on the real Risks route (D-06) with the X-58 local navigation and the server's mode (18-04), and run decision 7's measured spike (D-04): axe and a scripted APG walk in both modes, the route budget in `performance.spec.ts`, and the lag thresholds the orchestrator confirmed (D-27) at 150 and 1,000 risks. Output: the Risks route, the local navigation, the lag harness and its fixture builder, the phase spec's first test, the recorded spike result.

</objective>

- **Route.** `[documentId]/(record)/risks/page.tsx` (server): `readAnalystAssessmentRecord = cache(getAnalystAssessment)` in `features/risk-table/assessment-record.ts` (`server-only`), used by `generateMetadata` (`recordRouteMetadata(…, '{assessment number} risks | IdamBox CSRM')`) and the page; a 404 calls `notFound()`, a 403 renders the permission state, other errors the error state with `We couldn’t load the risks` and `Try again`. It renders `PageHeader` (title `Risk assessment review`, as the Overview's h1), `RecordLocalNav`, then `RiskTable` with `riskTableColumns({ actor: "analyst", released })`, the detail's risks and `mode` from `riskTableMode`. `loading.tsx` renders the grid skeleton after 300ms with the default view's columns and density. - **Local navigation (X-58).** `RecordLocalNav({ label, items: { href; label; current }[] })`: a `nav` landmark named `{assessment number}`, links `Overview` and `Risks ({n})` (`{n}` the active risks), `aria-current="page"` on the current one, the 2px ink indicator of the direction's tab row, sliding between items and static under `prefers-reduced-motion`; below 768px the links fill the width in equal parts at the touch-target height.
- **Fixture builder (`e2e/helpers/risk-table-fixtures.ts`).** `createRiskTableAssessment(request, { risks, title })` drives, through `strapiRequest` as Jane then Bob, the published operations today's flow uses (request create and submit, 13's self-assignment, the deterministic questionnaire generation and Jane's answers, the deterministic assessment draft), then adds risks with UAT-C-like content (statement, on-scale likelihood and consequence, owner Jane) until the assessment holds `risks`; it returns `{ documentId, assessmentNumber, riskNumbers }`. This plan adds risks through `POST /api/v1/risk_assessments/{assessmentId}/risks` one at a time, because the bulk operation arrives in 18-07; plan 18-11 switches it to one `risk_changes` call (D-29).
- **Lag harness (`e2e/risk-table-performance.spec.ts`, desktop project only, `test.use({ trace: 'off' })`).** Before the page loads, an init script registers `PerformanceObserver` for `event` (`durationThreshold: 16`, `buffered: true`) and `long-animation-frame` (`buffered: true`) into `window.__riskTableMetrics`. Per sample: read `performance.eventCounts.get('keydown')` before and after; warm up with Enter then Escape; then ArrowDown ×20, ArrowRight ×8, PageDown ×3, Ctrl+End, Ctrl+Home, ten edits (Enter, type, Enter), Shift+ArrowDown ×9 then a value committed with Ctrl+Enter, Ctrl+Z, Ctrl+Y, awaiting each key's visible effect; then `page.mouse.wheel(0, 400)` until the last row is visible, one animation frame per step. Group entries by `interactionId` (max duration each). Three fresh pages per fixture; assert the median of per-sample p75 and of per-sample maxima, and the frame limits; write raw entries and summaries to `apps/csrm/.tmp/performance/risk-table-<fixture>.json` (ignored). `percentile(values, p)` joins `performance-metrics.ts` beside `median`.
- **Budget.** `KeyRoute` gains `'/app/review/assessments/{documentId}/risks'`, resolved from the seeded `ASM-E2E-NAV-OWNER-001` analyst link with `/risks` appended, title `ASM-E2E-NAV-OWNER-001 risks | IdamBox CSRM`, heading `Risk assessment review`, populated by `page.getByRole('grid')`. No override unless the checkpoint records an exception with the file's 1.5 × median rule and a one-line reason (then also in `docs/performance/phase-08-baseline.md`).
- **Phase spec (`e2e/risk-table.spec.ts`).** One `describe` per area; this plan adds `spike: axe and the APG walk` (desktop) on a 12-risk fixture: axe (`@axe-core/playwright`, tags `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag22aa`) with zero serious or critical violations in editable mode and, in read-only mode, on the seeded released assessment `ASM-E2E-P7-RELEASED-001` (a read-only check, so a shared seed is acceptable; D-29 binds the 150-risk fixture); the walk Tab (enters once), arrows, Home and End, Ctrl+Home and Ctrl+End, Page Up and Page Down, Enter or F2 then Escape, Shift+ArrowDown, Ctrl+A, Tab (leaves), asserting `document.activeElement` and exactly one `[role=grid] [tabindex="0"]` after each; and Maya's not-found on the route. The mobile project's `testMatch` lists `risk-table.spec.ts`; desktop-only tests skip on mobile by project name.
