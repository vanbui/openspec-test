## Phase Goal

**As a** Requestor, a risk owner or a Security Analyst, **I want to** be told in the app when work waits for me and to open it in one step, **so that** nothing waits unseen between the people in the flow.

This plan's slice: an assignment and a note tell the person they concern. Phase 13's assignment and notes operations write their notifications in their own transactions and clear them when the work moves on.

Prove each through its HTTP operation, the exclusions (D-06), atomicity both ways (D-05) and the reads.

Purpose: success criteria 1 and 2 (assignment and notes) in the API; plans 19.1-07 to 19.1-10 show them.
Output: two hot services changed and the event integration test file.

## Recorded planning decisions

- **Assignment hook.** Inside `changeRequestAssignee`'s `withRequestLock` work, after the compare-and-set update and the log append and only when the assignee changed: when the previous assignee is set and differs from the new one, call `readNotificationsOnReversal(trx, { reversal: "change-assignee", subjectDocumentId: requestDocumentId, formerAssigneeId, now })`; when the new assignee is set, call `notify(strapi, { kind: "request-assigned", actorDocumentId, requestDocumentId, assigneeDocumentId, at })`. A no-op change (same target) does neither. The actor rule inside `notify` makes picking up oneself silent.
- **Note hooks.** Inside `addRequestNote`'s lock, after the note is created with its sequence: `notify(strapi, { kind: "note-added", actorDocumentId: author, requestDocumentId, note: { documentId, sequence, authorPart }, at: postedAt })`. Inside `markRequestNotesRead`'s lock, after the read state advances to N (and also when it was already at or past N, so a notification written for an earlier note is still cleared): `readNoteNotificationsThrough(trx, { readerId, requestDocumentId, throughSequence: N, now })`.
- **Tests.** `notification-events.integration.test.ts` drives the operations over HTTP with the harness identities (`analyst` as Bob, `second-analyst`, `owner` as Jane, `other` as Maya, `service-agent`, `inactive`) and reads results through `GET /api/v1/notifications` as each person; failure injection uses `withDocumentWriteFailure(NOTIFICATION_UID, "create", 1, …)` and the existing assignment and note write failures.
