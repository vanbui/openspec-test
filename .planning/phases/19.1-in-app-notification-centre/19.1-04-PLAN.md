## Phase Goal

**As a** Requestor, a risk owner or a Security Analyst, **I want to** be told in the app when work waits for me and to open it in one step, **so that** nothing waits unseen between the people in the flow.

This plan's slice: each person reaches their own notifications through Strapi, and only theirs. The three operations, their grants and refusals, the published contract, and the web's typed service with closed parsers.

Prove every grant and refusal in the API and the matrix, closed payloads, hidden-means-missing (D-15) and that no GET writes (D-23).

Purpose: the header, panel and page (19.1-07 to 19.1-10) call only this service; Strapi enforces every rule they display.
Output: three Strapi modules, the policy change, the contract chain, matrix rows and the web service.

## Recorded planning decisions

- **Operations.** `operations.ts`: `CSRM_NOTIFICATION_OPERATIONS = { list: "GET:/api/v1/notifications", summary: "GET:/api/v1/notifications/summary", mark: "POST:/api/v1/notifications/read" } as const`.
- **Routes.** `routes/notifications.ts` exports one `Core.RouterConfig` (`type: "content-api"`) with three routes in the shape of `routes/my-request-status-summary.ts`: paths `/v1/notifications`, `/v1/notifications/summary`, `/v1/notifications/read`; handlers `api::csrm-notification.notifications.list`, `.summary`, `.mark`; `auth: { strategies: ["content-api-token"] }`; policies `global::csrm-app-enabled` then `global::csrm-authorization` with `{ operation, requireNotificationScope: true }`.
- **Policy.** `AuthorizationConfig` gains `requireNotificationScope?: boolean`. The three operations are spread into Phase 19's `SERVICE_IDENTITY_REFUSED_OPERATIONS` (so its guard refuses any caller whose explicit roles include `SECURITY_ANALYST_AGENT_ROLE_NAME`, before any scope). When `requireNotificationScope` is set and the grant check passed, the policy sets `csrmAuthorization.notificationRecipientId = grants.requestorId` and `csrmAuthorization.notificationAnalystKinds` = every kind whose `analystReadOperation` is non-null and `hasHumanAnalystOperation(grants.explicitRoles, analystReadOperation)` holds, then allows. The decision never reads the auth mode.
- **Controller.** `controllers/notifications.ts` default-exports `{ list, summary, mark }`, with `safeError` for actor-neutral 400, 403 and 404 (messages `CSRM notification query is invalid.`, `CSRM notification request is invalid.`, `CSRM notification access is denied.`, `CSRM notification was not found.`), and the scope read only from `ctx.state.csrmAuthorization` (missing scope → 403). `list`: only the keys `view`, `page`, `pageSize` (unknown key → 400; `view` in `all` or `unread`; `page` a whole number from 1 to 10,000; `pageSize` in 10, 25, 50); `asOf = new Date()`; `listNotificationsPage` on `strapi.db.connection`; resolve the page's distinct actor ids with 13-03's `resolvePeople`; `projectNotification` per row (a null projection is skipped); answer `{ data, meta: { pagination: { page, pageSize, pageCount, total }, unread, asOf } }`. `summary`: no query key; `countNotifications`; `{ data: { unread, asOf } }`. `mark`: the body is `{ data }` with exactly one of the three forms of the record, keys closed per form; ids 1 to 50 unique strings of 1 to 255 characters; `asOf` and `markedAt` parsed as instants and refused when later than the server's time; run in `strapi.db.transaction(async ({ trx }) => …)`; `NotificationNotVisibleError` → 404; answer `{ data: { changed, markedAt, unread, asOf } }` with `markedAt` the read time `Mark all as read` wrote (ISO) and null otherwise, `unread` from `countNotifications` inside the transaction with a fresh `asOf`.
- **Specification.** Tag `notifications`; the three paths with operationIds `notifications/list-notifications`, `notifications/get-notification-summary`, `notifications/mark-notifications`; query parameters `view` (enum), `page`, `pageSize` (enum 10, 25, 50); components `NotificationKind` (enum of the five kinds), `Notification` (closed: `documentId`, `kind`, `notifiedAt`, `readAt` nullable, `sentence`, `recordNumber`, `recordTitle`, `destination`), `NotificationListMeta`, `NotificationListResponse`, `NotificationSummary`, `NotificationSummaryResponse`, `NotificationMarkRequest` (`oneOf` of the three closed forms under `data`), `NotificationMarkResult`, `NotificationMarkResponse`; responses `NotificationBadRequest`, `NotificationForbidden`, `NotificationNotFound` in the shape of `CurrentUserAccessBadRequest` and `CurrentUserAccessForbidden`. All objects `additionalProperties: false`.
- **Catalogue.** As 19.1-01 names it, in the docs copy, then copied byte for byte over the bootstrap copy; design note `Notifications (Phase 19.1)` amending design note 6.
- **Matrix.** A `notifications` family: list and summary rows expect owner 200, other 200, analyst 200, serviceAgent 403, noIdentity 403, noToken the token family's status; the mark row uses a fixture notification of the owner, expecting owner 200, other 404, analyst 404, serviceAgent 403, noIdentity 403, with `persistence` snapshotting the owner's `read_at`; every allowed actor cited to a test in `notifications.integration.test.ts`; the refusal-set mirror gains the three literals.
- **Web.** `notifications-domain.ts` (zod-free): `NOTIFICATION_KINDS`, `NOTIFICATION_VIEWS = ['all','unread']`, `NOTIFICATION_PAGE_SIZES = [10,25,50]`, types `NotificationKind`, `NotificationView`, `NotificationItem`, `NotificationListPage { items; pagination; unread; asOf }`, `NotificationSummary { unread; asOf }`, `NotificationMarkInput` (the three forms), `NotificationMarkResult`, and `isInAppNotificationDestination(value)` accepting only `/app/requests/{id}`, `/app/questionnaires/{id}`, `/app/assessments/{id}`, `/app/review/requests/{id}`, `/app/review/questionnaires/{id}` with ids of 1 to 255 characters from `[A-Za-z0-9]`, and `#note-{id}` only after the two request paths. `notifications-schema.ts` (zod, `.strict()` objects): `notificationSchema` (destination refined with `isInAppNotificationDestination`), `notificationListResponseSchema`, `notificationSummaryResponseSchema`, `notificationMarkResponseSchema`. `notifications-service.ts` starts with `import 'server-only'`, exports `listNotifications(query)`, `getNotificationSummary()` and `markNotifications(input)` returning `TransportResult<…>`, and `responseParserModule` with labels `notifications.listNotifications`, `notifications.getNotificationSummary`, `notifications.markNotifications`, in the shape of `features/access/access-service.ts`.
