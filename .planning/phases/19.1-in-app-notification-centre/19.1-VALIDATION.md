**Known infrastructure facts.**
1. **Shared `dist`.** The orchestrator's dev Strapi (1337) and Next (3000) run during planning. Everything that compiles Strapi shares `apps/backend/dist`: the Strapi suite, a single Strapi file, `served-operations:write` and Playwright. All of these wait until the servers are stopped. A task executed while they run records those proofs as pending for the plan's end.
2. **SQLite pool of one.** Inside a transaction, a raw `strapi.db.connection` query without `.transacting(trx)` waits about 60 s and then fails (19.1-RESEARCH Pitfall 1). A Strapi test that hangs for about a minute is this defect, never flakiness.
3. **PostgreSQL is not exercised.** Every suite runs on SQLite (R-08-37). The repository's new constructs (`UPDATE … WHERE id IN (subquery) RETURNING`, `SUM(CASE …)`, `Date` bindings, the request row lock before the assignee read) are recorded in R-08-37 by a plan task, not proven here.
4. **Dates.** Raw SQL binds `Date` objects. SQLite stores Strapi datetimes as epoch milliseconds, so an ISO-string comparison silently gives wrong rows (19.1-RESEARCH Pitfall 3).
5. **Generated files.** `apps/backend/types/generated/*.d.ts` may change after a Strapi boot and are never staged. `apps/csrm/next-env.d.ts` is untracked and ignored.
6. **Windows vitest** can fail with `EPERM: rename`. Rerun that file alone before treating it as a real failure.
7. **Fixtures.** No development seed holds notifications (D-10). Journeys create their own records. Proofs use Jane, Bob, Phase 13's second analyst and Maya (D-38); Strapi tests use the harness identities `owner`, `other`, `analyst`, `serviceAgent`, Phase 10's `second-analyst`, `noIdentity` and `noToken`.
8. **The base changes first.** Phases 10 to 16 and 19 execute before 19.1 and change the files this phase edits (the header, the layout, the guard, the assignment and notes services, the workflow transactions, the policy and the released-assessment predicate). Re-run the plan check before executing.

## Sampling Rate

- **After every task commit:**
  - run the touched web test files by path;
  - run `typecheck` when types change, and `api:check` after any specification change;
  - run the touched Strapi files by path, with the dev servers stopped.
- **After every plan wave:**
  - run the full web suite, `typecheck` and `api:check`;
  - run the full Strapi suite after every plan that edits Strapi (proposed 19.1-03 to 19.1-07);
  - run each UI plan's targeted Playwright specs once at its end (proposed 19.1-08 to 19.1-10).
- **Before `/gsd-verify-work`:** the full suite must be green. That is the phase gate above (proposed plan 19.1-11), recorded with counts, duration, the flaky count and the clean `git status --short`.
- **Max feedback latency:** 90 seconds at task level. The production-build E2E runs only at plan level.
