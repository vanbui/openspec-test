## Phase Goal

**As a** Requestor, a risk owner or a Security Analyst, **I want to** be told in the app when work waits for me and to open it in one step, **so that** nothing waits unseen between the people in the flow.

This plan's slice: every notification the person has, on one page with All and Unread views and their marks; then the proof of the whole phase: the centre's journeys and negative cases at both widths and the full gate.

## Recorded planning decisions

- **Route.** `app/(app)/app/notifications/page.tsx` follows the alerts page: `metadata = { title: routeTitle(pageHeadings.notifications) }`; the capability check before any read (`can('notification:read', granted)`, else `<PermissionDeniedState area="notifications" />`); `notificationListUrlQuerySchema.parse(params)` (in `notifications-schema.ts`: `view` `unread` or absent for All, `page` a whole number, `size` in 10, 25, 50 default 25; any invalid value falls back to its default); `listNotifications({ view, page, pageSize: size })`; a 403 renders the permission state; an error renders the list's error state; a page beyond `pageCount` re-reads the last page; `resolveE2eUiState(params)` for the design-contract fixtures only after an authorised read. `loading.tsx` and `error.tsx` copy the alerts route's files with the UI-SPEC's copy. `pageHeadings.notifications = 'Notifications'`; no navigation item is added.
- **Page list.** `NotificationPageList({ items, pagination, unread, asOf, view })` (`'use client'`) renders `PageHeader` (heading, the description `Updates on the requests, questionnaires and risk assessments you work on. Open one to go to its record.`, and `Mark all as read` as an outline pill while anything is unread, full width below 768px), the `SegmentedControl` labelled `Show` (All, Unread; choosing one resets to page 1), the list (from 768px one card holding a `ul` named `All notifications` or `Unread notifications` of `NotificationItem` with `showMark`; below 768px one card per notification with the mark as a full-width ghost pill at the touch-target height above a hairline), and the shared pagination with its total and `Rows per page`. Marks use `useMarkNotification` and Mark all uses `useMarkAllWithUndo`, so the header count moves with them; marked items stay in place, shown read, until the view reloads; after Mark all, focus moves to the page `h1`.
- **Item mark.** `NotificationItem` with `showMark` adds the ghost small pill `Mark as read` or `Mark as unread` after the link, `aria-describedby` the sentence, with a polite status line.
- **Spec journeys** (each `@journey`, own records named per project): `NOTIFY01_SC2_RELEASES_SUBMISSION_AND_NOTES` (Bob releases Jane's questionnaire, Jane's panel reads `A Security Analyst released a questionnaire for you to answer: {questionnaireNumber} · {title}`, she opens it in one step and submits, which clears it; the assigned Second Security Analyst reads `Jane Doe submitted answers to a questionnaire: …`; Jane's note reaches the assignee and the assignee's reply reaches Jane, each `… added a note to a request: {requestNumber} · {title}` opening at `#note-{id}`; Bob's v1 release reads `A Security Analyst released a risk assessment: {assessmentNumber} · {request title}` for Jane, opening `/app/assessments/{id}`); `NOTIFY01_SC3_PAGE_MARKS_AND_UNREAD_VIEW` (the page's Mark as read and Mark as unread, the Unread view's total equal to the header count, the panel's `{n} unread` link opening the Unread view, Mark all as read with Undo on the page, a marked item staying in place until reload); `NOTIFY01_SC4_LOST_ACCESS_AND_UNRELATED_REQUESTOR` (Bob returns the released questionnaire to analyst review: Jane's notification leaves her panel, page and count; releasing again shows exactly one new; Maya, signed in throughout, sees no capsule, no sentence, number or title of Jane's in her panel or page). API refusals (Maya's 404, the service identity's 403) are proven in Strapi (19.1-04), not here.
- **Shared sweeps.** `accessibility.spec.ts` adds `/app/notifications` (heading `Notifications`, title `Notifications | IdamBox CSRM`) for the Requestor and the Security Analyst, and the Unread view; `design-contract.spec.ts` adds the surface `{ name: 'notifications', route: '/app/notifications', actor: 'Requestor' }` to the empty, error and permission state matrix; `performance.spec.ts` adds `/app/notifications` as a key route under the default budget.
- **Coverage.** `COVERAGE.md` holds one line: `No external API integration: Phase 19.1 adds in-app notifications served by the project's own Strapi API and read by its own web client; no third-party API, SDK or external service is called.`
