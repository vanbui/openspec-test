# Phase 06.3 Plan 02: Collection query and contract foundation Summary

Assessment and analyst-request collection reads now use bounded server-side queries with matching count and page filters, while the OpenAPI boundary exposes the resulting list parameters and pagination envelope.

## Accomplishments

- Added strict assessment `q`, `status`, `sort`, `page`, and `pageSize` parsing, capped page sizes and text, deterministic sorting, explicit population, and one shared filter tree for count and data queries.
- Converted analyst assessment and owner released-assessment lists from fixed unpaginated arrays to `{ data, meta.pagination }` responses.
- Made the analyst request-review response retain its authoritative total and pagination metadata after its bounded projection.
- Added query-builder regression coverage for malformed input, scope composition, count/data equivalence, and pagination boundaries.
- Published list query and pagination metadata in the authoritative specification and regenerated the typed declaration solely through the prescribed command.

## Deferred Work

- Questionnaire state is derived from answer JSON rather than stored as a queryable collection field. The strict questionnaire `status` parameter is validated but not yet included in the Strapi count/data filter tree, so status-filtered questionnaire totals cannot be claimed truthful. This requires a queryable server projection or an approved schema/contract-gap decision before the plan can be considered complete.
- The specification declares the assessment-request review query’s existing nested filter shape; a focused route/catalogue test for all five list operations remains to be added.

## Deviations from Plan

### [Rule 4 - Contract/data-model decision] Questionnaire derived-state filtering

- **Found during:** Task 1
- **Issue:** `not-started`, `draft`, and `submitted` are computed from related question answer JSON and are not a field Strapi can count/filter exactly.
- **Impact:** Implementing a truthful, bounded status-filtered collection needs a queryable server projection or a content-type change, which is outside the plan’s no-schema-change constraint.
- **Resolution:** Deferred without inventing a partial-page client filter or silently changing a content type.
