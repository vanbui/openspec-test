edit an assessment I had already finished reviewing, **so that** no assessment can reach a Requestor
carrying content that no review ever covered.

one place the codebase already funnels every accepted analyst edit through, and updates the tests
and analyst surface that encode the superseded Phase 4 precedent.

notice that names the withdrawn review in text.

## The locked decision and the precedent it supersedes

D-13 is locked: editing a reviewed, unreleased assessment performs a **real** transition of
`assessmentStatus` back to `draft`. It uses only the existing `draft` value of the frozen
`assessmentStatus` enumeration, so the approved contract-gap record for this phase explicitly
records that no schema change is needed for it.

This knowingly supersedes the Phase 4 decision recorded in STATE.md: *"Stamp reviewedBy and
draft-to-review transitions only on the first accepted edit; later edits preserve the original
reviewer and states."* The **reviewer** half of that precedent is retained — `reviewedBy` is still
stamped once and never cleared. The **state** half is superseded for exactly one case: an accepted
edit to an assessment that was already `in-review` *and* release-ready. A future reader must not
read this as a regression: the reason is that release readiness measures field completeness only, so
without a stored transition a reviewed-then-edited assessment could be released with no second
review, which is precisely the gate D-04 exists to impose.

The superseded review fact is not deleted. After the regression the assessment persists
`assessmentStatus` `draft` together with a non-null `reviewedBy` — a combination unreachable for an
assessment that was never reviewed — which is the durable evidence that a completed review was
withdrawn by a later edit. D-16 confirms this transition is audited by the edit record itself and
does **not** prompt for a free-text reason.
