# Phase 06.8 Plan 01: Questionnaire Release Gate Summary

A generated questionnaire is now analyst-only until an Analyst releases it. The release
fact lives in `releasedAt` and `releasedBy`, and the authorization policy reads those
attributes directly, so a Requestor who guesses the questionnaire route before release is
denied by the server rather than merely finding no link. `governanceLog` carries the
append-only, schema-versioned event history that the later revision-timeline plan renders,
and it is deliberately excluded from every authorization decision.

The full Phase 06.8 operation surface — the five governance operations, the request-detail
`lifecycle` field, the `filters[queue]` parameter, and the assessment relation's control
tally — was published once here, across `docs/references/specification.json`, both copies
of the capability catalogue, and the generated client.

## Deviations

The plan's development-database gate was not runnable as written: it called
`process.chdir('apps/strapi')` at runtime while `require('better-sqlite3')` resolves
against the script's own location, so it failed with `MODULE_NOT_FOUND` from the
repository root. The command is now `pnpm --prefix apps/strapi exec node -e "…"`, which
resolves the dependency inside the workspace that owns it. The substantive check was
unaffected once run correctly — the three database objects genuinely exist after a Strapi
boot.

The published contract added a control-implementation tally to the available assessment
relation, and the web-side parser is `.strict()`, so the existing contract parity test
failed until the field was declared. It is optional on both the domain type and the Zod
schema, so a response written before the request hub populates it still parses.
