## Phase Goal

**As a** risk manager or leader, **I want** trends, ageing, cycle times and a heat map, **so that** I can see whether risk and the assessment process are improving.

This plan's slice: the stage history exists and the first two acts feed it. Submitting a request records its entry to intake, a return to draft records its return, and a request with history can no longer be deleted.

<objective>

Wire the first two acts: the request `PUT` submission, now wrapped in `withRequestLock` (Orchestrator Confirmation; 21-RESEARCH Pitfall 1), and the return to draft. Refuse deleting a request with history (409 `REQUEST_HAS_STAGE_HISTORY`) and publish Phase 21's four closed reasons in one contract change (D-03 item 7). History starts at deployment (D-08).

Purpose: D-05's recorded history needs a table, one writer and the acts' own transactions; the delete refusal keeps the rows append-only and following the request's retention.
Output: one new content type, the recorder and its facts loader, two acts wired, the delete refusal, four reasons, a boot and act proof and a recorder unit test.

## Recorded planning decisions

- **Type folder.** `csrm-stage-transition` copies `csrm-risk-history-event`'s minimal folder (16-03): `factories.createCoreService`, `factories.createCoreController`, `factories.createCoreRouter(uid, { only: [] })`. Schema exactly as 21-01's "CsrmStageTransition": `"kind": "collectionType"`, `"collectionName": "csrm_stage_transitions"`, info names, `"draftAndPublish": false`; `request`, `enteredBy`, `round` as unidirectional `manyToOne` relations (no `inversedBy`, copying `riskOwner`'s form); `stage` `{ "type": "string", "required": true, "maxLength": 32 }`; `enteredAt` `{ "type": "datetime", "required": true }`; `cause` `{ "type": "string", "required": true, "maxLength": 64 }`; `sequence` `{ "type": "integer", "required": true, "min": 1 }`.
- **Facts (`stage-facts.ts`).** `loadStageFacts(strapi, requestDocumentId): Promise<StageFacts>`, called inside the caller's transaction (the Document Service joins it through AsyncLocalStorage): the request (`requestStatus`, `revertedAt`) with its questionnaire (`releasedAt`; `questionnaireState(questionnaire) === "submitted"` for `answersSubmitted`) and its assessment; `released` is `RELEASED_REQUEST_STATUSES.includes(requestStatus)` or `isReleased(assessment)`; `gateSetAt` is the assessment's `sharedWithParticipantsAt`; `openRoundKind` is the kind of the assessment's round whose `closedAt` is null (`loadOpenResponseRound`, `loadOpenAcceptanceRound`).
- **Recorder (`stage-recorder.ts`).** `createStageRecorder({ inTransaction, lockRequest, loadFacts, readLatest, append })` returns `withStageRecording(input, work)`; `withStageRecording(strapi, input, work)` builds it from Strapi: `inTransaction` is `strapi.db.inTransaction()`; `lockRequest` is `strapi.db.queryBuilder(REQUEST_UID).select(["id"]).where({ documentId }).forUpdate().transacting(trx)` with the current transaction (19.1's shape, never `withRequestLock`, whose tail is never nested); `readLatest` reads the request's row with the highest `sequence` through `strapi.db.query(UID).findOne({ where: { request: { documentId } }, orderBy: { sequence: "desc" } })`; `append` is `strapi.documents(UID).create`. Input `{ requestDocumentId, cause: StageCause, actorDocumentId: string | null, at: Date, roundDocumentId?: string | null }`. Steps: refuse with `StageRecordingError("CSRM stage recording requires the act's transaction.")` when not in a transaction or when `cause` is not in `STAGE_CAUSES` or `at` is not a valid `Date`; lock; `before = deriveRequestStage(await loadFacts())`; `result = await work()`; `after = deriveRequestStage(await loadFacts())`; `latest = await readLatest()`; append `{ request, stage: after, enteredAt: at.toISOString(), enteredBy: actorDocumentId, cause, round: roundDocumentId ?? null, sequence: (latest?.sequence ?? 0) + 1 }` when `after !== null` and `after !== (latest?.stage ?? before)`; return `result`. Sequential awaits only.
- **Act 1 (submit).** `update(ctx)` in the request controller: the clock is read once (`const submittedAt = new Date()`); everything after the actor check runs in `withRequestLock(strapi, documentId, () => withStageRecording(strapi, { requestDocumentId: documentId, cause: "request-submitted", actorDocumentId: ctx.state.idamboxUser?.documentId ?? null, at: submittedAt }, async () => { re-read persisted; prepareRequestorUpdate(persisted, input, submittedAt) or prepareAnalystUpdate; documents.update }))`. The response, the refusals and their order are unchanged.
- **Act 2 (return to draft).** Inside `revertRequestToDraft`'s `withRequestLock` work, the reads and the update run in `withStageRecording(strapi, { cause: "request-returned-to-draft", actorDocumentId, at: now }, …)`, where `now = input.now ?? new Date()` is the same `Date` written as `revertedAt`.
- **Delete.** In the controller's `delete(ctx)` override, before `super.delete(ctx)` and after the existing refusals: `strapi.db.query(UID).count({ where: { request: { documentId: ctx.params.id } } })` above zero → `denyConflict(ctx, "CSRM assessment request has stage history.", "REQUEST_HAS_STAGE_HISTORY")` through the controller's existing reason-carrying 409 helper.
- **Reasons.** Append `REQUEST_HAS_STAGE_HISTORY`, `REPORT_RECORDS_QUERY_INVALID`, `LIST_FILTER_INVALID` and `INSIGHT_SCOPE_MISSING` to `CONFLICT_REASONS` in both lists and to the `reason` enum of every specification error schema that 16-03 and 20 extended; each list's comment names Phase 21. The core delete's 409 response in the specification lists `REQUEST_HAS_STAGE_HISTORY`.
- **Harness.** `CsrmFixtureUid` gains `"api::csrm-stage-transition.csrm-stage-transition"`; a helper `stageRows(harness, requestDocumentId)` returns the request's rows ordered by `sequence` through the Query Engine (`{ stage, cause, enteredAt, sequence, enteredBy: documentId | null, round: documentId | null }`).
