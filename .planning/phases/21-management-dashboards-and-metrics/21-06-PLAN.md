## Recorded planning decisions

- **`stage-history-read.ts`.** `latestStageRows(connection)` per 21-RESEARCH R7 (columns `request_id`, `stage`, `entered_at`); `joinLatestStage(query, requestIdColumn, alias = "ls")` left-joins it; `whereCurrentStage(query, stage, alias)`; `whereAgeBand(query, band, today, alias)` binding `utcDateToInstant(cutoff)` `Date`s from `ageBandCutoffs(today)` (`not-recorded` is `alias.request_id IS NULL`); `readStageEpisodes(connection, { periodStart, asOf, cap, requestFilter })`: the self-join `st2.sequence = st1.sequence + 1` on the same request link, `st2.entered_at >= periodStart AND < asOf`, request status in reviewable or released, ordered `st2.entered_at DESC, st2.id DESC`, `LIMIT cap + 1`, returning request id, document id, number and title, the assessment's document id and number when one exists, both rows' stage, entry instants and round; `firstIntakeSubquery(connection)` (`MIN(entered_at)` of `intake` rows grouped by request); `stageHistoryRecordedFrom(connection)` (the earliest `entered_at`, or null); `projectInStage(row, today)` → `{ stage, enteredAt, workingDays, calendarDays } | null` through 21-02's `workingDaysBetween` and `calendarDaysSince`.
- **`cycle-times-repository.ts` (`createCycleTimesRepository(strapi)`).** `cycleTimes({ today, period, filters, viewerDocumentId })` → `{ recordedFrom, predatingOpen, timeToRelease: { medianDays, p90Days, sampleSize, truncated, submissionFallbackCount }, stages: { stage, medianDays, p90Days, sampleSize, truncated, slowest: Episode[] (SLOWEST_ITEMS_LIMIT) }[] (every stage but released, in REQUEST_STAGES order), rounds: { measure, medianDays | medianCount, p90, sampleSize }[], acceptanceRoundOutcomes: { any, recalled, returned }, queueAgeing: { team, yours } }`; `stageRecords({ stage, … })` and `roundMeasureRecords({ measure, roundOutcome, … })` → `{ figure, rows }` from the same reads. `timeToReleaseSample(connection, { periodStart, periodEnd, filters })` is today's throughput query (f) left-joined to `firstIntakeSubquery`, keeping a release when it has an intake row or a `submittedDate`, `from = first intake ?? submitted_date`, `to = approval_date`.
- **Round measures (D-10).** `response-rounds`: per assessment with a response round closed in the period, its count of response rounds; `days-to-response`: per response submitted in the period, `submittedAt − round.openedAt`; `acceptance-rounds`: per release in the period, its count of acceptance rounds, and with `roundOutcome` the acceptance rounds opened in the period with that outcome (`any` all); `contest-points`: per acceptance round closed in the period, its points; `days-to-first-answer`: per point first answered in the period, first answer − raised; `days-to-decision`: per completing decision recorded in the period, `recordedAt − round.openedAt`. Counts use the median and nearest rank without the day rounding; each read is a bounded Query Engine read under `THROUGHPUT_SAMPLE_CAP`.
- **Queue ageing.** Over the review queue's open bucket (the queue's own base predicate from `collection-scope.ts`), grouped by `ls.stage` and band through `whereAgeBand`, with `assigned_analyst` equal to the viewer for `yours`; `rows` for each open stage present, columns the five bands, `total`; a totals check equals the open bucket's count.
- **`risk-trend-repository.ts`.** `riskTrend({ today, period, filters })` → `{ available: true; months: { monthStart, partial, counts: RatingCounts }[] } | { available: false }`: Read 1 (knex, typed columns, `TREND_RISK_CAP` count first), Read 2 (`strapi.db.query("api::csrm-risk-history-event.csrm-risk-history-event").findMany` in `TREND_ID_CHUNK` chunks, kinds `residual-reviewed`, `risk-closed`, `risk-reopened`, `occurredAt < asOf`, `TREND_HISTORY_ROW_CAP`), `foldTrend`, then the partial month's counts from the register's live total for `state=open&stage=released&residualRating={rating}` plus the filters. `trendPointRecords({ point, rating, … })` → `{ figure, rows: { riskDocumentId, riskNumber, riskStatement, assessmentDocumentId, assessmentNumber, ratingThen, ratingNow, released, withdrawn, closed }[] }` sorted by risk number.
- **`ai-assistance-repository.ts`.** `aiAssistance({ today, period })` → `{ failedLastSevenDays: { count, windowStart, newest: AiRunRow[] (5) }, months, byOperationAndProvider, outcomes, editShare }`; `aiRunRecords({ outcome, operation, provider, window, period, today, page, pageSize })` → `{ figure, rows: AiRunRow[] }`; `failedRunCount({ today })`. `AiRunRow` = `{ runDocumentId, operation, providerName, startedAt, completedAt, attempt, status, recovery, failureCode, failureMessage, target: { kind: "request" | "questionnaire" | "assessment" | "risk", documentId, number, title }, startedBy: { documentId, displayName } | null }`. Status lists paginate in SQL (`started_at DESC, id DESC`); proposal-outcome lists paginate in code over the capped Query Engine read. The `select` is an explicit column allow-list.
- **Test helper (`tests/helpers/insight-fixtures.ts`).** Writes stage rows, rounds, releases, history rows and runs at given instants directly through the Query Engine (tests only; the static guard scans `src`), plus `injectedToday(date)`.
