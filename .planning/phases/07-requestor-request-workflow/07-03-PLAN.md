<interfaces>
Executor-facing action/UI contracts:
- `RequestActionState` distinguishes idle, field-validation failure, safe service failure, and success; it carries submitted values/field errors/focus target but no raw HTTP or actor data.
- `saveDraftAction`, `submitRequestAction`, and `withdrawRequestAction` resolve the actor in the Server Action, parse only approved FormData keys, call the focused service, and revalidate/redirect only after server acknowledgement.
- Draft validation requires nonblank title. Submit validation additionally requires description, `BAU|Project|Other`, businessPurpose, `Low|Moderate|High|Critical`, explicit true/false thirdPartyInvolvement, and thirdPartyDetails only when true.
- `RequestDetails` accepts the sanitized request DTO and actor-permitted action flags returned from the service; it does not infer ownership or lifecycle permission from URL/form state.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser FormData → Next Server Action | All fields, route IDs, confirmation events, and navigation state are untrusted. |
| Next Server Action → server-only actor/service | The actor must come from the trusted runtime resolver, not FormData or client state. |
| Backend response → rendered detail/form | Data and errors are rendered only after ownership and runtime validation. |
| Development/test actor seam → production build | Fixture identity code must be absent, not merely hidden. |

## STRIDE Threat Register — ASVS L1, block threshold high

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-09 | Tampering / Elevation of privilege | Server Actions | high | mitigate | Shared allowlist validation, server-bound record IDs, trusted actor resolution, and exclusion of owner/status/system fields prevent forged mutation/transition. |
| T-07-10 | Spoofing / Information disclosure | Production actor seam | high | mitigate | Compile-time replacement of the development request actor plus full build tests prevents fixture identity/capability import in production. |
| T-07-11 | Information disclosure | Request Details/error UI | high | mitigate | Capability preflight before load, authoritative backend denial, metadata-free AccessDeniedState, safe error mapping, and DOM-absence tests. |
| T-07-12 | Cross-site request forgery | Mutations | high | mitigate | Use POST-backed Next Server Actions with framework origin checks, server cookies, no GET mutation, and authenticated server-to-server calls; tests ensure direct browser inputs cannot supply credentials. |
| T-07-13 | Information disclosure / Injection | Rendered request content | medium | mitigate | Render text through React, never raw HTML, wrap long content, preserve fixed safe errors, and prohibit raw transport/body logging. |
| T-07-SC | Tampering | UI package surface | high | mitigate | Build from audited dependencies and native/approved equivalents with package/lockfile no-change; stop before any unavoidable package mutation for legitimacy research and blocking provenance approval. |
</threat_model>
