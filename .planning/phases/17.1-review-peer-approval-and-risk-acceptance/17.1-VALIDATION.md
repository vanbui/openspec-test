**Known infrastructure facts.**
1. **Shared `dist`.** Everything that compiles Strapi shares `apps/backend/dist` and `.tmp/tests-dist`: the Strapi suite, a single Strapi file, `served-operations:write` and Playwright. All wait until the orchestrator's dev servers are stopped. Wave 1 runs 17.1-01 (documents only) beside 17.1-02 (the only Strapi compile in the wave); from wave 2 the plans run one at a time.
2. **No live AI.** Every suite pins `CSRM_AI_PROVIDER=deterministic` and Phase 12's empty `CSRM_AI_DATA_CLASSIFICATION_CEILING`. No AI path decides, releases or closes; tests prove the service identity is refused every act of this phase.
3. **Keycloak stays off.** The executive approver persona's fixture subject and realm user change together (17.1-17); `keycloak-identity.unit.test.js` ("the fixture ids match the local realm import") proves it; nobody starts Keycloak.
4. **Fixtures (the 06.9 lesson).** The journey and the second spec create their own records; no development seed is relied on. Strapi tests reach a closed request through the harness's `releaseThroughAcceptance` (17.1-10); reviews before 17.1-05 through `setReviewFactsFixture` (17.1-03).
5. **Windows vitest** can fail with `EPERM: rename`. Rerun that file alone before treating it as a real failure.
6. **The base changes first.** Phases 10 to 16, 19, 19.1 and 17 rewrite this phase's hot files. Re-run the plan check before executing.
7. **Hangs mean deadlock.** A Strapi integration test that runs to the 600,000 ms timeout in a review, round, decision or release path is nested serialisation (research anti-pattern), not slowness.
8. **Interim E2E state.** From 17.1-04 (no save-driven review) and 17.1-10 (release and close) the specs that release through v1 (`assessment-release-workflow`, `risk-curation`, `notification-centre`, `response-stage`, `ai-context-provenance`) cannot pass until 17.1-18 Task 2 moves them; no plan between runs them. Plans 17.1-14 to 17.1-17 run only `performance.spec.ts`, `requestor-request-workflow.spec.ts`, `navigation-and-home.spec.ts` and `production-hardening.spec.ts`, which do not release.

## Sampling Rate

- **After every task commit:**
  - run the touched web test files by path;
  - run `typecheck` when types change, and `api:check` after any spec change;
  - run the touched Strapi files by path, dev servers stopped.
- **After every plan wave:**
  - run the full web suite, `typecheck`, `lint` and `api:check`;
  - run the full Strapi suite after every plan that edits Strapi: 17.1-02 to 17.1-12 and 17.1-17 (the last task of 17.1-04 to 17.1-08, 17.1-10 to 17.1-12 runs it as its plan-level sample);
  - run each UI plan's targeted Playwright specs once at its end (17.1-14, 17.1-15, 17.1-16, 17.1-17).
- **Before `/gsd-verify-work`:** the full suite must be green. That is the phase gate above (17.1-18 Task 4), recorded with counts against the baseline (web 2,048, Strapi 578, Playwright 84 at `678b117`, plus every phase executed since), duration, the flaky count and the clean `git status`.
- **Max feedback latency:** 90 seconds at task level for the per-file runs; the full Strapi suite and Playwright run only as a plan's last sample.
