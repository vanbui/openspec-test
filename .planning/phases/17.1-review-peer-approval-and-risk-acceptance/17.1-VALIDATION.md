# Phase 17.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

**Source and scope.** Seeded on 2026-10-01 from `17.1-RESEARCH.md`, "Validation Architecture", before any plan exists. It maps every requirement, finding, success criterion and decision to an automated proof:
- the four requirements: ASSESS-14, ASSESS-20, ASSESS-24 and ASSESS-25;
- the finding UAT-040, and the asks PD-2 and PD-4;
- the seven ROADMAP success criteria (SC1 to SC7);
- the locked decisions D-01 to D-71 in `17.1-CONTEXT.md` and every negative case in its `<authorisation>` section.

**How the maps are filled.**
- **Per-task map:** the rows below are seeded from the research's proposed plans (`17.1-01` to `17.1-20`, "Plan Grouping and Wave Order"). The planner replaces them with one row per task, taken from each task's `<automated>` verify block, and the plan check verifies them (Dimension 8).
- **Plan numbering:** if the planner merges or splits plans, it records the mapping from the research's numbering here.
- **Markers:** "❌ W0" marks a test file that the owning plan's first RED task creates (the project convention). "Phase N" marks a file an earlier phase's plans create.
- **Status:** every status starts as ⬜ pending.
- **Written ahead:** Phases 10 to 16, 19, 19.1 and 17 execute first. Rows that name their files (`risk-scale.unit.test.ts` from 12-02, the authorization matrix's seventh caller and `risk-owner-journey.spec.ts` from Phase 17, Phase 19's export tests, Phase 19.1's notification tests) depend on those plans creating them.

**Known infrastructure facts.**
1. **Shared `dist`.** Everything that compiles Strapi shares `apps/backend/dist` and `.tmp/tests-dist`: the Strapi suite, a single Strapi file, `served-operations:write` and Playwright. All wait until the orchestrator's dev servers are stopped; after wave 1 the plans run one at a time. A task executed while they run records those proofs as pending for the plan's end.
2. **No live AI.** Every suite pins `CSRM_AI_PROVIDER=deterministic` and Phase 12's empty `CSRM_AI_DATA_CLASSIFICATION_CEILING`. No AI path decides, releases or closes; a test proves the service identity is refused every act of this phase.
3. **Keycloak stays off.** The executive approver persona's fixture subject and realm user change together; `keycloak-identity.unit.test.js` ("the fixture ids match the local realm import") proves it; nobody starts Keycloak.
4. **Fixtures (the 06.9 lesson).** The journey and the second spec create their own records; no development seed is relied on.
5. **Windows vitest** can fail with `EPERM: rename`. Rerun that file alone before treating it as a real failure.
6. **The base changes first.** Phases 10 to 16, 19, 19.1 and 17 rewrite this phase's hot files. Re-run the plan check before executing.
7. **Hangs mean deadlock.** A Strapi integration test that runs to the 600,000 ms timeout in a review, round, decision or release path is nested serialisation (research anti-pattern), not slowness.

## Sampling Rate

- **After every task commit:**
  - run the touched web test files by path;
  - run `typecheck` when types change, and `api:check` after any spec change;
  - run the touched Strapi files by path, dev servers stopped.
- **After every plan wave:**
  - run the full web suite, `typecheck`, `lint` and `api:check`;
  - run the full Strapi suite after every plan that edits Strapi: 17.1-04 to 17.1-13;
  - run each UI plan's targeted Playwright specs once at its end (17.1-15, 17.1-16).
- **Before `/gsd-verify-work`:** the full suite must be green. That is the phase gate above (plan 17.1-20), recorded with counts against the baseline (web 2,048, Strapi 578, Playwright 84 at `678b117`, plus every phase executed since), duration, the flaky count and the clean `git status`.
- **Max feedback latency:** 90 seconds at task level. The production-build E2E runs only at plan level.
