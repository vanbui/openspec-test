## Top 3 Priority Fixes

1. **Questionnaire→request backlink uses `text-foreground`, not the accent link token, on both `questionnaire-detail.tsx:59` and `questionnaire-review.tsx:86`** — every other record link this phase touches (`request-form.tsx` questionnaire/assessment links, `assessment-detail.tsx` questionnaire link, `assessment-editor.tsx` readiness links, `assessment-list.tsx`/`released-assessment.tsx` identifiers) uses `text-text-link`. This one pair of components does not, so the same kind of link renders in two different colours depending which screen you're on — precisely the defect D-05/this phase exists to remove. Fix: change `text-foreground` to `text-text-link` in both files' `QuestionnaireRequestRelationship` link.

2. **Absent-questionnaire copy is not the same message on the analyst view vs. the Requestor view.** `request-form.tsx`'s `RequestRelationships` (Requestor-facing) renders the contract's exact copy — heading `No questionnaire is linked`, body `A questionnaire will appear here when one is created for this request.` `assessment-detail.tsx:79` (analyst-facing review of the same request/questionnaire relation) instead renders `No linked questionnaire` / `Draft assistance is unavailable until a questionnaire is linked and submitted.` Two different strings for the same absence, on two surfaces of the same request. Fix: reuse one shared copy source (or the same component) for both.

3. **Assessment list and released-assessment cards style their identifier links with ad hoc `text-xs`/`text-sm` classes instead of the app's own `--text-table-size` (13px) token that `data-table.tsx` already applies to every other table in the product.** `assessment-list.tsx`'s hand-rolled `<table>` uses `text-sm` body / `text-xs` for the identifier link (12px, not the contract's declared 13px table role), so this phase's new tables read at a different size than the rest of the application's tables. Fix: apply `text-[length:var(--text-table-size)]` (or migrate to `DataTable`) consistently.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

- **Absent-questionnaire text mismatch** (see Fix #2 above). `apps/web/src/features/requests/request-form.tsx:326` uses the contract copy exactly. `apps/web/src/features/assessments/assessment-detail.tsx:79-80` uses different copy for the same semantic state on the analyst-facing review route. The contract's Copywriting table gives one absent-questionnaire string; the codebase now has two.
- **Contextual-Risk tile caption does not match the contract.** Spec (Copywriting Contract, "Assessment tile caption") requires the micro-label `CONTEXTUAL RISKS`. `apps/web/src/features/requests/request-form.tsx:308` renders `Contextual Risks by residual rating` — different casing, different wording, and an appended qualifier not in the contract. (VERIFICATION.md flags the underlying problem this was trying to solve — that the rating wasn't named as residual to sighted users — but the fix was made by silently rewriting the locked caption rather than by updating the contract or finding a compliant alternative.)
- **Contextual-Risk `aria-label` diverges from the contract's example.** Spec example: `Critical contextual risks: 0`. Actual: `` `${rating} residual contextual risks: ${count}` `` → e.g. "Critical residual contextual risks: 0". Same root cause as above — the word "residual" was inserted without updating the governing document.
- Positive: `Return to draft` / `Return request to draft` / `Return questionnaire to draft` / `Reason` / dialog titles all match the contract exactly across all four surfaces (`assessment-detail.tsx`, `questionnaire-detail.tsx`, `questionnaire-review.tsx`, `request-form.tsx`).
- Positive: readiness summary strings (`All release requirements are met`, `{n} of {total} release requirements met`) and `Met`/`Outstanding` state words match the contract exactly in `assessment-editor.tsx`.

### Pillar 2: Visuals (3/4)

- The one-link-per-record rule (D-01) is genuinely enforced: `assessment-list.tsx` and `released-assessment.tsx` no longer render a trailing `Open` control, and only the identifier is a link/tab-stop in both the card and table variants.
- The questionnaire→request backlink (`questionnaire-detail.tsx:59`, `questionnaire-review.tsx:86`) keeps an always-visible underline, so it is not hover-only, but pairing that underline with `text-foreground` means it visually reads closer to emphasised body text than to the app's link convention used one screen away (the request's own questionnaire/assessment links). A user moving from a request to its linked questionnaire and back experiences two different "this is a link" visual languages.
- The release-readiness rows correctly keep icon + explicit state word + link together at every viewport (`assessment-editor.tsx:181-193`), matching the contract's non-colour-only requirement.

### Pillar 3: Color (2/4)

- Accent (`text-text-link`) usage count across this phase's touched files: `request-form.tsx` (2 uses: questionnaire link, assessment tile link), `assessment-detail.tsx` (1 use: questionnaire link), `assessment-list.tsx` (2 uses: card + table identifier), `released-assessment.tsx` (1 use), `assessment-editor.tsx` (1 use, requirement links). Total 7 consistent uses.
- Exactly one component pair breaks that consistency: `questionnaire-detail.tsx` and `questionnaire-review.tsx` both use `text-foreground` for their sole record link (`QuestionnaireRequestRelationship`), never `text-text-link`. This is a direct violation of the Color table's own rule: "Accent reserved for: textual record links..." — this is a textual record link, and it is not accented.
- No hardcoded hex/rgb colors found in the touched feature files (`grep -rn "#[0-9a-fA-F]\{3,8\}"` over the phase's files returns nothing outside `globals.css`, which is the token source of truth).

### Pillar 4: Typography (2/4)

- The contract declares a Table/caption role of 13px/400 (500 for identifier links) for exactly this kind of content (assessment identifiers, requirement rows). The application already has a first-class implementation of this role — `apps/web/src/components/csrm/data-table.tsx` applies `text-[length:var(--text-table-size)]` (13px) to every table it renders, and `text-[length:var(--text-micro-size)]` (11px) to header captions.
- `assessment-list.tsx`'s hand-written `<table>` (lines building `AssessmentList`) does not use `DataTable` and does not use either token: identifier links are `text-xs` (12px, Tailwind default) and body cells are the ambient `text-sm` (14px). `released-assessment.tsx`'s identifier link is likewise `text-xs`.
- Net effect: two different "table text size" values now exist in the product simultaneously — 13px via the token on `DataTable`-backed tables, and 12px/14px via Tailwind defaults on this phase's new assessment tables — despite the contract explicitly specifying the 13px role for this exact content type.
- No more than four size roles and no weight above 600 was found in the touched files, so this is a token-fidelity problem, not a scale-sprawl problem.

### Pillar 5: Spacing (4/4)

- All four `Return to draft` sites place the trigger as the first eligible action with a consistent ~16px gap before following content (`mb-4` in both questionnaire surfaces, `mb-4`/`mb-1`+`gap-3` combinations in the two request surfaces, matching the contract's documented composition).
- The 44px minimum hit target (`min-h-11`) is applied consistently to every record link introduced by this phase: assessment identifiers, the questionnaire backlink, the assessment tile link, and the request's questionnaire link.
- The confirmation dialog is fixed at `w-[min(480px,calc(100vw-32px))]` with header/footer/reason group all inheriting full width — matches the contract and closes the D-05 gap it called out.
- No arbitrary/off-scale spacing values found in the reviewed files beyond the documented 44px exception.

### Pillar 6: Experience Design (3/4)

- Absent, unauthorised, and zero states are modelled as distinct, server-driven states rather than inferred client-side (`RequestAssessmentRelation`/`RequestQuestionnaireRelation` discriminated unions, `residualRiskCounts` always rendering all four ratings including zero). This is a real, substantive implementation of D-02/D-03, not a superficial pass.
- Loading states use layout-matched skeletons (`ReleasedAssessmentListSkeleton`, `AssessmentEditorSkeleton`, `SkeletonCollection`) rather than spinners, matching the contract.
- Deduction: the same semantic state (absent questionnaire) is presented with materially different explanatory text depending on actor route (see Pillar 1), which is an experience-consistency defect specific to this phase's stated goal, not just a copy nit — a Requestor and an analyst looking at the same underlying fact get different guidance about what it means and what happens next.
- The verification record (`06.4-VERIFICATION.md`) documents that a running-browser check caught defects invisible to typecheck/unit suites (inert global link styling, a mis-anchored hit-area overlay, a horizontal-scroll regression from a long reason string) and that these were fixed before sign-off — this is good practice and reduces confidence that further hidden runtime-only defects remain, but does not offset the two source-level consistency defects above, which are visible in code and were not caught because they are cross-file comparisons rather than single-surface behaviour.
