# Phase 06.4 Verification

All eleven plans complete. Every success criterion is met and was confirmed in a
running browser at 375px and 1440px, not only by test assertion.

## Success criteria

**1. A request links to its questionnaire and shows an assessment tile with
contextual Risk counts; neither appears when the record is absent or
unauthorised.** Verified in the browser on the released request: the tile shows
`ASM-2026-33SAEN` with Low 0, Moderate 1, High 0, Critical 0, matching the API
exactly, and an absent questionnaire reads "No questionnaire is linked" rather
than as blank space. An assessment the actor may not open renders nothing at
all, and no unlinked assessment identifier appears on any request the Requestor
owns — asserted as an invariant across all of them.

**2. A questionnaire links back to its request.** Verified on both the Requestor
and analyst surfaces, including the awaiting-submission state. The analyst-scoped
link is correctly absent for a Requestor, who may not follow it.

**3. Release readiness names the record and field behind every outstanding
requirement and shows the complete set.** The projection carries every
requirement with an explicit met or outstanding state, each Risk named by its own
number, and each risk-scoped requirement anchored to that Risk's own section.
Array indices never reach the interface.

**4. Every list opens a record from its identifier or title, with no redundant
open control and an affordance evident without hover.** The two files that
carried a row-level open control no longer do, and the assessment review list
shows six identifier links and zero open buttons.

**5. The reversal reason field fills the dialog and Return to draft is one
control everywhere.** Dialog 480px, reason field 431px — the full content width
inside its padding — and all four trigger sites use the shared button at its
standard treatment.

## Defects found by verification that no other gate caught

Three of these passed both typechecks, both unit suites and diff review, and
were only visible in a running browser:

- Five `"use server"` modules exported a parser-declaration object. Next.js
  throws at runtime on every route importing one; nine of seventeen browser
  journeys failed across administration, assessments, questionnaires, requests
  and the register. Present since the phase 06.3 gap-closure work.
- The anchor reset sat outside every layer, and unlayered CSS beats every
  `@layer`, so link colour and underline utilities were inert product-wide. The
  identifier links this phase introduced looked correct in source and rendered
  as plain text.
- The contextual-Risk tile's hit-area overlay anchored to the link rather than
  the card, leaving a narrow halo clickable instead of the tile surface.
- A 500-character reversal reason — within the field's own limit — widened the
  document to 4126px against a 1440px viewport, scrolling every page showing a
  reverted record sideways. `break-words` was not enough: only
  `overflow-wrap: anywhere` reduces the intrinsic minimum a grid track is
  measured from.
- The tile named its counts as residual only in the assistive label, leaving a
  sighted reader to guess which of the two ratings the product shows side by
  side elsewhere.

## Contract debt closed

Two server projections were serving shapes the contract never declared: the
request relationships block and release readiness as a requirement set. Both are
published now and the declarations regenerated.

The parity guard could not have caught either: it compares a contract against
the client parsers that read it, and nothing parsed those responses yet. **A
server projection with no client is invisible to it** — worth closing before it
recurs.

## Recommendation

Add a test asserting every `"use server"` module exports only functions. A few
lines, and it would have caught the most damaging defect in this phase the moment
it was introduced.
