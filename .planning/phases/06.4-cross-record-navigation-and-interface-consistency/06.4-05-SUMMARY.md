# Phase 06.4 Plan 05: Questionnaire request backlinks Summary

Questionnaire detail surfaces now offer one capability-gated, actor-appropriate assessment-request link while preserving the difference between an ordinary missing relation and a protected relation.

## Accomplishments

- The Requestor page produces `/app/requests/${encodeURIComponent(request.documentId)}` only for the already-safe available relationship and `assessment-request:read` capability.
- The analyst page produces `/app/review/requests/${encodeURIComponent(request.documentId)}` only for the already-safe available relationship and `assessment:review` capability.
- Both detail surfaces place the persistent-underlined, 44px request link below the header metadata and before workflow/audit content. The submitted and awaiting-submission analyst views both retain the same treatment.
- An absent relation renders exactly `No assessment request is linked to this questionnaire.`; unavailable and non-linkable relations render no relationship identity or explanation.
- The existing questionnaire header response parser remains registered in `contractResponseParsers` and is exercised by the response-parity test. No generated declaration was edited.

## Decisions Made

- A safe server projection alone does not offer a link. The page also checks the capability appropriate to its actor route, while Strapi remains the record-level authority.
- The unavailable and absent variants are strict and identity-free. A payload that tries to carry a document ID or number in either state now fails parsing rather than being silently narrowed.
