# Phase 06.4 Plan 01: Release readiness projection Summary

`projectReleaseReadiness` converts the validator's paths-only result into the
complete, named requirement set D-04 requires.

## Accomplishments

- Every requirement, assessment-level and per-Risk, carries an explicit `met` or
  `outstanding` state and its existing domain label, so the set no longer appears
  only when something is wrong and shrink as it is fixed.
- Risk-scoped requirements carry the Risk's own number and a stable per-Risk
  destination, replacing the array index the validator uses internally and the
  single shared `#identified-risks` anchor the client previously produced.
- Conditional treatment requirements are included only for a Risk whose
  treatment action is `Treat`, matching the validator's own rule.
- `ready` is computed from the complete set rather than tracked separately.

## Notes

The plan's own unit test asserted the risk-scoped requirements in Risk-number
order while its fixtures were declared in the opposite order. The projection
preserves the assessment's Risk order deliberately, so the expectation was
corrected rather than the implementation: a checklist that re-sorts into an order
the page never shows would be harder to follow, not easier.

Nothing consumes the projection yet. The contract that publishes it and the
editor that renders it are later plans in this phase.
