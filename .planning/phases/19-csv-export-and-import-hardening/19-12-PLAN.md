## Phase Goal

**As a** Security Analyst or risk manager, **I want to** export any list I can see and to import spreadsheets without fighting the format, **so that** CSRM fits the Excel work around it.

This plan's slice: the released Risk Assessment as a file and as paper. Jane exports her own released assessment and prints it as a clean A4 report; nobody else can reach either.

<objective>
Factor the released page's loader into one shared module and add the two report routes on it (D-23); render the report document and its print rules as X-31 (D-24); put `Print report` and `Export` in both released views' headers, the analyst's only once released (D-15, D-20, D-21; UI-D2); prove the report in Vitest and criteria 2 and 6 in Playwright at both widths, with the Secondary Requestor's not-found pages as the UI negative case (D-16, D-38, D-39).

Purpose: decision 12's print-ready report and the Requestor's own released export, through the reads the one record-read check gates, so Phase 17's participants follow with no change here (G-12).
Output: two report routes, the report document and print CSS, header actions on both released views, and their proofs.

Edits Strapi source? No. Changes the specification? No. Runs Playwright? Yes.

Scope note: 16 files at four tasks; six are the two routes' page, loading and error files.
</objective>

## Recorded planning decisions

- **Loader and model (`released-assessment-report.ts`, `import 'server-only'` for the loaders).** `loadRequestorReleasedAssessment(documentId)` performs exactly the reads the released page performs today (detail, risks, control implementations) and returns `null` when Strapi answers 404; the released page and the Requestor report route both call it. `loadAnalystReleasedAssessment(documentId)` performs the analyst detail read and returns `null` when it is missing or its `released` is false. `toAssessmentReportModel(input)` (pure, exported for tests) maps either into one `AssessmentReportModel` holding only fields the released projection discloses: identifiers, request number and title, release date and released by, overall rating, rationale, summary, recommendations, overall control effectiveness, next review date, risks (number, statement, inherent and residual ratings, treatment action label, the §15.2 fields) with their control implementations, and the AI disclosure flag.
- **Routes.** Each `report/page.tsx` is a Server Component: load, `notFound()` on null, read the viewer's zone, render `PageHeader` with `data-print="hidden"` (eyebrow the assessment number, title `Print report`, description `This is the released assessment as an A4 report. Print it, or save it as a PDF from your browser’s print dialog.`, actions `ReportToolbar` and `Back to the risk assessment`, an outline link with `ArrowLeft` to the released view), then `AssessmentReport`. `loading.tsx` renders the toolbar shape and `AssessmentReportSkeleton`; `error.tsx` renders `We couldn’t load this report` with `Try again` (Phase 11 §2.4 anatomy). Route titles `Print report {number} | IdamBox CSRM`.
- **Report (`assessment-report.tsx`, Server Component).** The §4.3 parts in order with the token, heading-level and spacing values the UI-SPEC names; `Risks overview` is a captioned `table` with `thead`; each Risk in detail is a section with `data-report-risk`; `Notes` holds Phase 12 §10.1's notice when the model says AI assisted, then `This report shows the risk assessment as released. Generated {date and time} ({IANA zone}).` (UTC named when the zone is unknown); absent values read `Not recorded`; with no risks, `No risks were recorded in this assessment.`
- **Toolbar (`report-toolbar.tsx`, the one client component).** `Print or save as PDF` (primary, `Printer`) calls `window.print()`.
- **Print rules (`globals.css`, X-31).** Inside `@media print` and an `@page` rule: `@page { size: A4 portrait; margin: 16mm; }` with a `@bottom-right` margin box `Page {n} of {m}` through `counter(page)` and `counter(pages)` in the caption size and secondary text colour (tokens); `[data-report-document]` loses its card edge, padding and shadow; `thead { display: table-header-group; }`; `[data-report-risk] { break-inside: avoid; }`; the `Risks in detail` section `break-before: page`; nothing clamped (the Print refinements rule). On screen the document is the card X-31 describes.
- **Header actions.** `released-assessment.tsx`'s header gains, after its existing actions, `Print report` (outline link, `Printer`, to `/app/assessments/{id}/report`) then `ExportButton` (heading the assessment number, view `released-assessment`, `action={exportReleasedAssessmentAction}` bound to the id, `fixedTables` from `tables.released-assessment`, scope sentence `{number} as released: its summary, {r} {risk|risks} and {c} mitigation {control|controls}.` from the released read's counts). The analyst review page adds the same pair with `/app/review/assessments/{id}/report` only when the detail's `released` is true.
- **Playwright journeys (in `exports-and-imports.spec.ts`).** `released assessment export @journey`: Jane opens her seeded released assessment, sees `Print report` then `Export {number}`, exports XLSX (name `^[a-z0-9-]+-risk-assessment-\d{4}-\d{2}-\d{2}\.xlsx$`, `PK`), then CSV with `Table` `Mitigation controls` (BOM). `released assessment refused to another Requestor @journey`: the Secondary Requestor opens Jane's assessment URL and its report URL and sees the in-shell not-found with no `Print report` and no button whose name starts with `Export`. `print report @journey`: Jane opens `Print report`; under `page.emulateMedia({ media: "print" })` the sidebar, header and toolbar are hidden and the document visible; reset with `{ media: null }`; on the desktop project only, `page.pdf({ format: "A4", preferCSSPageSize: true })` yields a PDF whose bytes hold at least one `/Type /Page`; at 375 the report has no horizontal scroll; an axe scan of the report route reports no serious or critical violation, through the helper the accessibility spec uses.
