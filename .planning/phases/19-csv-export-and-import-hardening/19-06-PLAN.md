## Phase Goal

**As a** Security Analyst or risk manager, **I want to** export any list I can see and to import spreadsheets without fighting the format, **so that** CSRM fits the Excel work around it.

This plan's slice: the first export a person can use. From the Risk register's header, Bob opens the export dialog, chooses a format and columns, and saves the file the server built, with the server's name and count; the dialog, its column choice and the action pattern are the ones every other list reuses.

## Recorded planning decisions

- **Validator (`file-response.ts`, extended).** `FileSignature` gains `"utf8-bom"` (EF BB BF); `EXPORT_RESPONSE_CONTENT_TYPES = { csv: "text/csv; charset=utf-8", xlsx: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet" }`; `EXPORT_RESPONSE_MAX_BYTES = 67_108_864` (64 MiB, research open question 4); `exportFileRule(format)` accepts exactly that format's content type (the CSV rule accepts `text/csv` with or without the charset parameter), a name matching `^[a-z0-9][a-z0-9-]{0,150}\.(csv|xlsx)$` with the format's extension, at most 64 MiB, and the signature `utf8-bom` for CSV or `zip` for XLSX. `attachmentFileRule` is unchanged.
- **Service (`risk-service.ts`).** `exportRiskRegister(input: { query: RiskRegisterExportQuery; format: "csv" | "xlsx"; columns?: readonly string[]; timeZone?: string })` calls `client.GET("/v1/risks/export", { params: { query: { ...query, format, columns: columns?.join(","), timeZone } }, parseAs: "arrayBuffer" })`, returns `{ error: TransportError }` on a 4xx or 5xx (keeping `reason`, `rowCount`, `rowCap`), reads `content-type`, `content-disposition` and `x-csrm-row-count` (an integer from 0 to 10,000, else a `file-check` failure), and returns `{ data: { fileName, contentType, bytes: Uint8Array, rowCount } }` or `{ error: { kind: "file-check", failure } }`. The module registers the operation with the parity guard's `file-response` mode, its media types equal to `EXPORT_RESPONSE_CONTENT_TYPES`.
- **Action (`features/exports/export-actions.ts`, `'use server'`).** `exportRiskRegisterAction(input: unknown): Promise<ExportActionResult>` parses `{ query, format, columns?, table? }` with zod: `query` through the register's shared `riskRegisterQuerySchema` with `page` and `pageSize` omitted, `format` `csv` | `xlsx`, `columns` a unique subset of the `risk-register` vocabulary keys (1 to 40); reads `readViewerTimeZone()` (passes it only when present); calls the service; maps a failure through `exportRefusal` (19-02). `type ExportActionResult = { ok: true; fileName; contentType; bytes: Uint8Array; rowCount } | { ok: false; refusal: ExportRefusalCopy }`. An invalid input returns the 400 refusal copy. No `cookies().set`, no `revalidatePath`.
- **Scope helpers (`features/exports/export-scope.ts`, no directive, no zod).** `EXPORT_ROW_LIMIT = 10_000` (a web test asserts it equals Strapi's `EXPORT_ROW_CAP` by reading `apps/backend/src/csrm/exports/run-export.ts`); `exportScopeSentence({ total, records, searchActive, filtersActive, multiplePages })` returns the four §2.2 sentences with `en-AU` counts; `exportFilterLines({ search, chips })` returns `Search: “{term}”` and `Filters: {label}: {value} · …`; `exportDialogState({ total, checkedColumns })` returns `ready`, `empty-filtered`, `empty`, `over-limit` or `no-columns`.
- **Components (`components/csrm/export/`, client).** `ExportButton({ heading, view, action, total, searchActive, search, chips, multiplePages, visibleColumns?, fixedTables? })`: an outline pill with a 16px `Download` icon, accessible name `Export {heading}`, never disabled; it loads `ExportDialog` with `next/dynamic` on first activation and shows the inline 16px spinner only if the code has not loaded within 300ms. `ExportDialog`: Dialog at the form size from 768px, a full-screen Sheet with a title row and `Close` below (as X-13's phone form); one `form`; groups in the §2.1 order; `Format` as the shared `SegmentedControl` with the §2.3 hints; `Table` radio group only for fixed tables and only while CSV is checked; `ColumnChoice` for single-table views, or the `Every column of each table is included, as on the page.` line for fixed tables; the §2.5 state line or alert above the actions; `Export file` (primary, `Download`) and `Cancel`; pending `Exporting…` with the inline spinner and read-only controls; closing while pending discards the result; success saves with `saveFile`, closes, returns focus to `Export` and toasts `Exported {file name}` with `{n} {row|rows}.`; a refusal shows an alert (warning or danger tone, `Try again` when `retry`) and moves focus to its title. The last format is stored under `csrm.export.format` in `localStorage`, read and written inside try/catch, falling back to XLSX. `ColumnChoice({ columns, checked, onChange, visibleKeys, hint? })`: a fieldset with legend `Columns`, the `{k} of {n} columns` count, `Select all` (hidden when all are checked) and `Reset to visible` (shown only when the choice differs), checkboxes one column below 640px and two from 640px, and the `Choose at least one column.` field error. Business logic stays in `export-scope.ts`, not JSX. Client modules import no zod.
- **Register page.** `app/(app)/app/risks/page.tsx` passes to `PageHeader`'s actions an `ExportButton` with heading `Risk register`, view `risk-register`, `action={exportRiskRegisterAction}`, the list's `meta.pagination.total`, the active search and chip labels the page already renders, and `multiplePages` from the pagination; it renders nothing for the export where the page renders its gate.
