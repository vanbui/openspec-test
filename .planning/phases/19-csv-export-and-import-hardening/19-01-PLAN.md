Paths, view keys, catalogue URLs and underlying reads:

  - Risk assessments: `/api/v1/risk_assessments/export`, view `risk-assessments`, read `GET:/api/v1/risk_assessments`.
  - My requests, My questionnaires, My risk assessments: `/api/v1/my_requests/export`, `/api/v1/my_questionnaires/export`, `/api/v1/my_risk_assessments/export`, views `my-requests`, `my-questionnaires`, `my-risk-assessments`, reads `GET:/api/v1/my_requests`, `GET:/api/v1/my_questionnaires`, `GET:/api/v1/my_risk_assessments`.
  - Reference data: `/api/v1/risk_types/export`, `/api/v1/controls/export`, `/api/v1/information_systems/export`, `/api/v1/information_assets/export`, views `risk-types`, `controls`, `information-systems`, `information-assets`, reads `CSRM_ADMINISTRATION_OPERATIONS.listRiskTypes`, `.listControls`, `.listInformationSystems`, `.listInformationAssets`.
- **Fixed-table exports (D-03, D-21, D-22; UI-D5: no `columns` parameter).**
  - Reports: `POST /api/v1/reports/{reportKey}/export` (reserved, unchanged URL), view `report:{reportKey}`, read `GET:/api/v1/reports/{reportKey}`. Closed JSON body `{ format, table?, timeZone?, query? }`: `table` is one of that report's table keys, required when `format` is `csv` and refused (400) when `xlsx`; `query` is an object of the report's own query parameters as strings (at most 16 keys, each value at most 200 characters), parsed by the report's own parser.
  - The released assessment (D-03 group 2): `GET /api/v1/risk_assessments/{assessmentId}/export?format&table&timeZone`, view `released-assessment`, read `GET:/api/v1/risk_assessments/{assessmentId}`; `table` is `risks` or `mitigation-controls`, required for CSV and refused for XLSX.
- **Import support (D-03 group 3).** Per collection path segment `risk_types`, `controls`, `information_systems`, `information_assets`: `GET /api/v1/{segment}/import/template?format=csv|xlsx`; `POST /api/v1/{segment}/import/error_report` (multipart: `file`, and exactly one of `previewDigest` or `resultToken`). The existing preview (`POST …/import/preview`) and commit (`POST …/import`) accept `.xlsx`; the preview adds `warnings` (ignored headers as typed), `notes` (closed codes `issues-column`, `read-only-columns`, `example-row`) and the sixth row state `similar` with `matchedName`; the commit takes `decisions` (a JSON object string of row number to `update` or `skip`, at most 5,000 entries) and returns `resultToken`.
- **Responses.** A 200 file response carries `text/csv; charset=utf-8` or `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `Content-Disposition: attachment` with an ASCII `filename` and an RFC 5987 `filename*` (through 14-07's `contentDispositionFor`), `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, and on exports `X-CSRM-Row-Count` (the server's integer row count: data rows across the table sheets, the Summary sheet not counted). Errors are JSON with a closed `details.reason` in the existing `AssessmentWorkflowErrorResponse` envelope. File names follow 19-UI-SPEC §3.2.

- **Policy (D-13).** `csrm-authorization.ts` gains `AuthorizationConfig.underlyingRead?: string` (the list read, held through the same grant path that admitted the operation: the human Security Analyst role for an analyst operation, the explicit or birthright roles otherwise) and the exported `SERVICE_IDENTITY_REFUSED_OPERATIONS: ReadonlySet<string>`, named generically because Phases 19.1 and 17 add members: a caller whose roles include `Security Analyst Agent` is refused 403 on every member, whatever it holds, its Requestor birthright included. Phase 19's members are the 14 export operations. - **The one released-assessment record-read check (D-14; orchestrator constraint).** Module `apps/backend/src/api/csrm-assessment/services/released-assessment-read.ts`: `type AssessmentViewer = { kind: "requestor"; documentId: string } | { kind: "analyst" }`; `RELEASED_ASSESSMENT_FILTERS` (today: `assessmentStatus` `approved`, the release facts, the owning request `approved`); `readableAssessmentFilters(viewer)` (today: the requestor is the viewer; the analyst reads all); `isReadableReleasedAssessment(document, viewer)`; `findReadableReleasedAssessment({ documents, viewer, documentId, populate })`. The released detail, risks and control-implementation reads, the released-assessment export and (through those reads) the A4 report route all call it; nothing else decides who may read a released assessment. Phase 17 widens "readable" to every current participant and Phase 17.1 widens "released" to an owning request in `approved` or `closed`, each in this one module.
- **Closed reasons (D-03 group 4; added to `CONFLICT_REASONS`, its web mirror and both spec enums).** `EXPORT_ROW_LIMIT` (422, details `rowCount` and `rowCap`), `ASSESSMENT_NOT_RELEASED` (409; 19-UI-SPEC recommended `EXPORT_NOT_RELEASED`, named so Phase 17 D-29 reuses this one code for a participant's export before release), and the import refusals `IMPORT_FILE_TYPE` (415), `IMPORT_FILE_TOO_LARGE` (413), `IMPORT_TOO_MANY_ROWS`, `IMPORT_ENCODING_WINDOWS_1252`, `IMPORT_ENCODING_UTF16`, `IMPORT_ENCODING_UNKNOWN`, `IMPORT_DELIMITER`, `IMPORT_LEGACY_XLS`, `IMPORT_MACRO_WORKBOOK`, `IMPORT_ENCRYPTED_WORKBOOK`, `IMPORT_WORKBOOK_TOO_LARGE`, `IMPORT_NO_HEADER`, `IMPORT_NO_ROWS`, `IMPORT_DUPLICATE_HEADER`, `IMPORT_MISSING_COLUMN` (each 422 unless stated, with the closed details object `found`: `headers` and `labels` (each at most 20 strings of at most 200 characters, controls removed), `delimiter` (`semicolon` | `tab`), `rows`, `bytes`), and `IMPORT_DECISION_MISSING` and `IMPORT_REVIEW_EXPIRED` (409). An invalid filter, sort, column, format, table or zone is a 400 with no reason code (D-16).
- **Events (D-18; extends 14-03's `security-event-log.ts`, no persisted entity).** `export.completed` (outcome `exported`) and `export.refused` (outcome `refused`; reason `EXPORT_ROW_LIMIT`, `invalid-query` or `ASSESSMENT_NOT_RELEASED`), with `actor { documentId, displayName }`, `view`, `format`, `columns` (keys), `table`, `filters`, `search`, `sort` (the closed parsed values, never the raw query), `timeZone` (the zone or `UTC-fallback`), `rowCount` (null when refused before counting) and `subject` (`{ kind: "risk-assessment", documentId }` for the released export); `import.committed` (outcome `committed`) with `actor`, `collection`, `fileName` (at most 255 characters, controls removed; D-18 names it), `sha256`, `format` and `counts` (`created`, `updated`, `unchanged`, `rejected`, `ambiguous`, `skipped`). Never a cell value. Policy denials stay in Strapi's request log. Phase 17 adds `people.searched` through the same module (G-17).
- **Bounds and constants.** `EXPORT_ROW_CAP = 10_000` (one definition, `csrm/exports/run-export.ts`; ids fetched with `limit: cap + 1`, 19-RESEARCH Pitfall 8). Imports keep 5 MiB, 5,000 rows and 64 KiB per record; an XLSX upload is refused before any inflate when its archive declares more than 512 entries or more than 52,428,800 bytes (50 MiB) uncompressed, through 14-02's `readZipDirectory` with these bounds, and every inflate uses `maxOutputLength`. The neutraliser mark is a leading single quote (D-11, Orchestrator Confirmations). The clear token is `#CLEAR`. The template example row's natural key is `Example (CSRM skips this row)` (`EXAMPLE` for a Control number). The result record mirrors the preview record (actor- and collection-bound, 5-minute TTL, 256 global and 16 per actor and collection).
