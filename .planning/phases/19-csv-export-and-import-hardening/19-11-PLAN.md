## Phase Goal

**As a** Security Analyst or risk manager, **I want to** export any list I can see and to import spreadsheets without fighting the format, **so that** CSRM fits the Excel work around it.

This plan's slice: every remaining list exports from its page. Bob exports his queue, the questionnaire and assessment lists, his alerts and each report; everyone exports their own requests, questionnaires and assessments, with the same dialog and the server's files.

## Recorded planning decisions

- **Services (each `import 'server-only'`, each registered in the parity guard's file-response inventory).** `assessment-service.ts`: `exportReviewRequests`, `exportRiskAssessments`, `exportMyRiskAssessments`, `exportReleasedAssessment(assessmentId, { format, table?, timeZone? })`; `request-service.ts`: `exportMyRequests`; `questionnaire-service.ts`: `exportQuestionnaires`, `exportMyQuestionnaires`; `alert-service.ts`: `exportAlerts`; `report-service.ts`: `exportReport(reportKey, { format, table?, timeZone?, query })` (POST with the closed body). Each follows `exportRiskRegister`'s shape (19-06): `parseAs: "arrayBuffer"`, the `x-csrm-row-count` parse, `validateFileResponse` with `exportFileRule(format)`.
- **Actions (`export-actions.ts`).** One per view, each parsing its input with the list's own shared web schema with `page` and `pageSize` omitted (`parseAssessmentRequestReviewQuery`'s schema for Requests and Assigned to me, `requestListQuerySchema` for My requests, the questionnaire list schema for both questionnaire lists, `parseAssessmentCollectionQuery`'s schema for both assessment lists, `alertListQuerySchema` for Alerts, the report's period schema for reports), `format`, and `columns` from that view's vocabulary (none for `exportReportAction` and `exportReleasedAssessmentAction`, which take `table` from the vocabulary's tables and refuse `columns`). `exportReleasedAssessmentAction({ assessmentId, format, table? })` validates the id as the assessment pages do.
- **Pages.** Each Server Component page passes `ExportButton` the heading (§1: `Requests`, `Assigned to me`, `Questionnaires`, `Risk assessments`, `Alerts`, the report title, `My requests`, `My questionnaires`, `My risk assessments`), its view key, its action, `meta.pagination.total` (a report passes its table count and no total check), the active search and chip labels it already renders, and `multiplePages`. `Assigned to me` uses the `requests` view and passes its visible columns without `assignee`. A report passes `fixedTables` from the vocabulary's `reports.<key>.tables`. The button renders only where the page renders the list (never in a gate, error or not-found state).
- **Playwright journeys (added to `exports-and-imports.spec.ts`).** `list exports @journey`: Bob opens Risk exposure, activates `Export Risk exposure`, checks `CSV (.csv)`, chooses the second table in `Table`, exports, and the saved file is named `risk-exposure-{table slug}-{date}.csv` and starts with EF BB BF; Jane opens My requests, exports XLSX, and the saved file is named `my-requests-{date}.xlsx` and starts with `PK`. `analyst exports refused to a Requestor @journey`: Jane opens `/app/alerts` and `/app/review/requests` and sees each gate with no button whose name starts with `Export`.
