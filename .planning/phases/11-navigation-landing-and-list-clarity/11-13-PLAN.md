## Phase Goal

**As a** Requestor or Security Analyst, **I want to** have a sectioned sidebar and a Home that leads with my next action, **so that** I always know where my work is and what to do next.

This plan's slice: the sidebar tells each actor how much work waits on them, item by item, without slowing any page.

<objective>
Add the count badges of D-10 to the sidebar and drawer: server-scoped, bounded reads through existing service functions (D-11), started in the layout without awaiting them and streamed to the navigation, fail-soft, with accessible names that carry the meaning (UI-SPEC §1.3, X-6). Update the exact-name link locators the counts change (UI-SPEC §14.1 E12, E13) and prove each badge equals its list.

Purpose: UX-07 criterion 2 ("review items show counts") and UAT-002's "no sense of how much work waits".
Output: the counts module and its tests, the one-row queue count function, the layout and shell wiring, the badge rendering and CSS, the locator changes and the browser proofs.

Edits Strapi? No. Changes the specification? No. Runs Playwright? Yes (the navigation specs, then the full suite: every journey's sidebar links change their names). Alone in wave 13 (D-05).
</objective>

## Recorded planning decisions

- **Module (Planner's Discretion).** `components/shell/navigation-counts.ts` starts with `import 'server-only'`; `NavigationCounts = Partial<Record<NavigationCountKey, number>>`; the function chooses its reads with `can(…, granted)` (`assessment:review` adds the queue and alert reads) and returns `Promise<NavigationCounts>` that never rejects. A value of 0 is kept as 0; the badge hides it.
- **Meaning strings (UI-SPEC §1.3)** live in `navigation.ts` (zod-free) as `navigationCountMeaning(key, n)`: `need your action`/`needs your action`, `to answer`, `need attention`/`needs attention`, `overdue`.
- **Rendering.** `ItemCount({ counts, countKey })` reads `use(counts)[countKey]` and renders, inside the link after the label, `<span className="sr-only">, </span><span className="nav-count">{n}</span><span className="sr-only"> {meaning}</span>` when `n > 0`; wrapped in `<Suspense fallback={null}>`. The collapsed own-section button renders the sum of its items' counts the same way. `.nav-count` in `globals.css` is the sidebar neutral tag (X-6): pill, `--color-border-on-dark-strong` border, `--text-micro`, `tabular-nums`, `margin-inline-start: auto`, colour inherited from the item.
- **Shell.** `AppShellProps.counts: Promise<NavigationCounts>`; `AppShell` passes it to `CapabilityNavigation` and `MobileNavigation`. The layout's permission branch passes `Promise.resolve({})`.
- **Locators.** Exact-name sidebar locators whose item gains a count become anchored patterns (`/^Requests\b/`, `/^Alerts\b/`, `/^My requests\b/`); `openFromNavigation(page, name: string | RegExp, exact?)` accepts a pattern.
- **Assumption A2.** The E2E proves whether a revalidating Server Action refreshes the counts. If the badge stays stale until a router refresh or reload, the executor records A2 as false in the summary and asserts after `page.reload()`, which D-11 guarantees.
