## Phase Goal

**As a** Requestor or Security Analyst, **I want to** have a sectioned sidebar and a Home that leads with my next action, **so that** I always know where my work is and what to do next.

This plan's slice: on a phone a request page says which step it is on and what happens next on its first screen, with the full lifecycle one tap away.

<objective>
Build the compact lifecycle stepper below 768px (D-26, X-9) on both request pages, with one next action displayed per width (UI-D23) and Phase 10's generation-job override feeding it on the analyst hub (D-28). Then carry the orchestrator's zod boundary item: extend the guard to every route and move incidental zod imports out of client modules (UI-SPEC Notes carried).

Edits Strapi? No. Changes the specification? No. Runs Playwright? Yes. Alone in wave 9 (D-05).
</objective>

## Recorded planning decisions

- **One presentation helper.** `nextActionPresentation(nextAction: RequestLifecycleNextAction | null, override?: string): { summary: string; href?: string } | null` in `request-domain.ts` (zod-free): the override, when present, as plain text; otherwise the summary with an href only when `holder === actor` and `href` is present. The hub and the stepper both call it.
- **Client component.** `RequestLifecycleStepper` becomes `'use client'` (disclosure state); its props are `{ lifecycle, nextActionOverride? }`. `n` is the current step's 1-based index; `m` is `lifecycle.steps.length` (8).
- **Responsive markup.** One `ol` only: its classes keep today's grid from `md` and, below `md`, `hidden` unless expanded (then one column). The compact block (`Step n of m`, next action, button) carries `md:hidden`. Both next-action lines stay in the DOM; only one is displayed at any width.
- **Spacing and type (§6.3, UI-D24).** 8px between heading, step line and next action; 16px before the disclosure; heading `text-heading-sm`; step labels caption at 500; the step cards keep their shipped corners and fills (Notes carried).
- **Zod boundary.** `routesWithoutClientValidation` gains every route directory under `app/(app)` except those whose pages validate in the browser by design (the request form and edit routes, the administration forms, the CSV import); a comment lists the exclusions and why. Each chain the widened guard reports is fixed by moving the value (a vocabulary or constant) into a zod-free `*-domain.ts` module and importing it from there; schemas keep re-exporting it. Expected: `alert-list.tsx` (a new `alert-domain.ts`), `questionnaire-list.tsx`, `questionnaire-review-list.tsx`, `questionnaire-governance.tsx` (`questionnaire-domain.ts`) and the request hub's `assessmentStatuses` chain.
