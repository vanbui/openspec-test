# Phase 11 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

**Source and scope.** Seeded on 2026-09-28 from `11-RESEARCH.md` § "Validation Architecture". Revised on 2026-10-01 after plan check iteration 1 to match the 21 plans (11-01 to 11-21). It maps every requirement, finding and decision group to an automated proof:
- the five requirements: UX-07, UX-08, UX-09, UX-10 and DASH-03;
- the nine findings: UAT-001, UAT-002, UAT-003, UAT-004, UAT-035, UAT-038, UAT-048, UAT-060 and UAT-065;
- the locked decisions D-01 to D-58 in `11-CONTEXT.md`.

**How the maps are filled.**
- **Per-task map:** one row per task (`11-NN-TT`), 58 rows: 57 automated chains and the 11-21 walk checkpoint. Each command and failure signal is taken from the task's `<automated>` and `<fails_when>`, without the Node preamble. The plan check verifies them (Dimension 8).
- **Markers:** "❌ W0" marks a test file that the task creates (RED first), as in Phase 10.
- **Status:** every status starts as ⬜ pending.
- **Phase 10 first:** Phase 10 executes and passes its gate before any Phase 11 plan (D-04). Several proofs below rely on Phase 10's artifacts: `LocalInstant`, the navigation guard (`navigation-guard.test.tsx`), the interface copy guard (`interface-copy-guard.test.ts`) and `analyst-route-gate.test.tsx`.
- **Waves:** one plan per wave, 1 to 21, in plan order. Shared files (D-05), the specification changes and Playwright's single worker serialise them.

**Known infrastructure facts.**
1. **Shared `dist`:** the orchestrator's dev Strapi (1337) and Next (3000) run during planning and between plans. Anything that compiles Strapi shares `apps/backend/dist`: a Strapi file, the Strapi suite and `served-operations:write`. So does a Playwright run. These wait until the servers are stopped, and the executor never starts or stops them. A task executed while they run records those proofs as pending for the plan's end.
2. **No hosted AI:** automated suites pin the deterministic provider. No Phase 11 proof triggers generation, except the existing journeys that already generate with the deterministic provider.
3. **Jobs are process-local** (R-08-36). The analyst Home's "Generation in progress" figure is proven through the existing queue bucket tests. No E2E relies on a job outliving a restart.
4. **Windows vitest:** vitest can fail with `EPERM: rename`. Rerun that file alone before treating it as a real failure.
5. **Fixtures:** the E2E proofs reuse seeded fixtures that no other spec consumes: Jane's navigation-lifecycle requests and her seeded questionnaire, and the Phase 7 analyst-insights Risks. 11-16 adds one accepted, released Risk to `seed-analyst-insights.ts` (D-45). Journeys that change state create their own records through the UI, which is the 06.9 lesson. From 11-06 they use `createSubmittedRequest` from `e2e/helpers/requests.ts`.
6. **Sign-in proves the shell:** from plan 11-02, every sign-in asserts the level-one "Home" heading and the role in the banner. `e2e-sign-in-assertions.test.ts` enforces this.

## Sampling Rate

- **After every task commit:** run the task's `<automated>` chain. Each chain starts with the touched web test files by path and `typecheck` (and `api:check` after any spec change), so a fault there surfaces within 90 seconds. Strapi files, the Strapi suite and Playwright come after them in the same chain and run only with the dev servers stopped; otherwise they are recorded as pending for the plan's end.
- **After every plan:**
  - Run the full web suite, `typecheck` and `api:check`.
  - Run the full Strapi suite (`pnpm --dir apps/backend test`) after every plan that edits Strapi. These are 11-06, 11-07, 11-08, 11-10, 11-14, 11-15, 11-16 and 11-17, each in its last task (11-08 in its Task 2).
  - 11-12 compiles Strapi only to regenerate `served-operations.json` (Task 2, conditional). The next Strapi suite run, in 11-14 Task 3, and the 11-21 gate prove that file.
  - Each plan runs its targeted Playwright specs once, in the tasks the map names.
  - Nine tasks end with one full Playwright run, because every journey passes through what they change: 11-02 Task 2 (Home and the redirect), 11-03 Task 2 (recovery copy), 11-04 Task 3 (headings and labels), 11-05 Task 3 (the sidebar), 11-09 Task 3 (the zod boundary), 11-12 Task 3 (the Requestor Home), 11-13 Task 3 (the sidebar counts), 11-20 Task 3 (quick find), and 11-21 Task 1 (the gate).
- **Before `/gsd-verify-work`:** the full suite must be green. That is plan 11-21's phase gate, recorded in `11-21-SUMMARY.md` with counts, duration, flaky count, the static checks and the clean tree.
- **Max feedback latency:** 90 seconds for the unit part of each chain. Production-build E2E and Strapi suites run only where the map names them.
