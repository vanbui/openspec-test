## Phase Goal

**As a** Requestor or Security Analyst, **I want to** have a sectioned sidebar and a Home that leads with my next action, **so that** I always know where my work is and what to do next.

This plan's slice: quick find tells people what it is doing and what it searched, works as a full-screen sheet on a phone, never loses focus or input, and provably shows nobody else's records.

## Recorded planning decisions

- **Timing.** The skeleton appears 300ms after a first search starts (a timer cleared when results arrive); pending opacity uses the §5 optimistic token with no transition.
- **Focus.** The trigger stores `document.activeElement` on open; `onCloseAutoFocus` prevents Radix's default and focuses the stored element if it is still connected, else the header `Search` control (research A3). After `navigate` proceeds, focus goes to the `Search` control (UI-D13). When `navigate` blocks, the guard receives the input as `trigger`, so `Keep answering` returns there.
- **Kept term.** The dialog lifts `term` into the trigger's state for the page session; on reopen the input shows it selected.
- **Frame (X-8, CSS in `globals.css`).** `.quick-find-content` from 768px: 640px wide, `--radius-2xl`, hairline, `--shadow-overlay`, top at `--spacing-header-h-md` plus 48px; the list's `max-height` is the remaining viewport less 48px (replacing the shipped `max-h-[300px]`); below 768px: full screen on `--color-bg-surface`, with the visible title row and `Close`. Reduced motion fades only.
- **Retry.** `Retry search` is a `CommandItem` whose `onSelect` reruns the current term (or reloads the dialog module after a load failure) and keeps focus in the input.
