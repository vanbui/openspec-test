## Recorded planning decisions

- **Readiness.** `validateReleaseReadiness` adds `aiProposalsReviewed` to `missing` when the assessment's parsed `aiProvenance` has a `proposed` field, and `risks[i].aiProposalsReviewed` for each risk whose parsed provenance has one; `projectReleaseReadiness` projects them with the label `Review of AI proposals` and destinations `assessment-details` and `risk-{id}`; a null or malformed envelope adds nothing. The decision workflow's pre-edit readiness (12-11's transition option, used by 12-12) therefore includes it.
- **Badge family.** `statusPresentation.aiReview = { proposed: { label: "AI proposed", tone: "warning", icon: SparklesIcon }, uncited: { label: "No source cited", tone: "warning", icon: UnlinkIcon } }` in the one mapping; notes are not badges (UI-D2).
- **Field labels** for markers, toasts and accessible names come from one map in `ai-assistance-domain.ts`, equal to the editor's visible labels (for example `Issue statement`, `Residual rating`, `Treatment plan`).
- **Hook.** `useAiDecisions({ assessmentId, initial })` keeps optimistic field and suggestion states with `useOptimistic` inside `startTransition`, calls `decideAiProposalsAction` once per user action, shows `toast.success(message, { duration: 5000, action: { label: "Undo", onClick } })` with the X-14 outline pill through the toast's class names, sends `restore` for Undo, rolls back on failure with `toast.error(title, { description: aiDecisionRefusalCopy(failure).text })` plus `Try again` or `Refresh page`, and exposes focus targets for UI-SPEC §6.2. Readiness never updates optimistically; it re-renders from the revalidated page.
- **G-14 in the editor (2026-10-01 confirmation).** The editor offers `Confirm` on an AI-proposed Accept as on any field; the server is the authority, and its refusal shows family J's G-14 addition through `aiDecisionRefusalCopy` (12-13). `treatmentActionNote` adds the note for the `accept-with-suggested-controls` adjustment; neither string is in the UI-SPEC, and both are named here as additions.
- **No lost input.** Risk and assessment forms keep their React keys (the risk documentId) and never reset when provenance props change; the changed-unsaved state compares the form's current value with the loaded value.
