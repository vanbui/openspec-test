## Phase Goal

**As a** Security Analyst or Requestor, **I want to** have the existing request, questionnaire, assessment and administration screens work as they say, **so that** today's flow completes without workarounds, lost input or misleading messages.

This plan's slice: a Requestor who opens an analyst page sees a clear refusal that points to her own work, instead of analyst actions that fail or an error, and no permission message talks about "effective CSRM capabilities".

## Recorded planning decisions

- **One helper, not three inline copies.** `apps/web/src/lib/capabilities/analyst-review-gate.ts` (starts with `import 'server-only'`) wraps the dashboard's four lines in React `cache`, so a route's metadata and page share one session read. It joins the explicit gate list in `server-only-boundary.test.ts`.
- **Refusal variants.** `AssessmentDetail`, `QuestionnaireReview` and `AssessmentEditor` gain an optional `refusal?: 'record' | 'role'` prop (default `'record'`). `'role'` renders UI-SPEC §11.1's Requestor description and "Go to My …" outline link; `'record'` renders the §11.2 analyst variant. The assessment editor's record variant gains the `Back to risk assessments` link it lacks today.
- **The request route still builds its record links** from the same capabilities after the gate; the links are then always analyst links, which is what the gate guarantees.
- **The copy guard's extractor** uses the TypeScript compiler API (`typescript` 5.9.3 is a web devDependency). It collects JSX text, string and no-substitution template literals and template literal text, and ignores comments, identifiers, import and export specifiers, the left operand of `in`, object property names, element-access keys, literal types and directives. A positive-control case proves it finds a term in an in-memory source and ignores the same term in a comment and an identifier, so the guard cannot pass vacuously.
- **Files that still carry terms another plan removes are not listed yet:** `questionnaire-review.tsx` (plans 10-05 and 10-09), `assessment-editor.tsx` and `risk-details.tsx` (10-21), `questionnaire-detail.tsx` (10-05), `released-assessment.tsx` (10-15), `administration-workspace.tsx` (10-17). The new `lib/time` modules and `local-time.tsx` from plan 10-01 carry none of the guarded terms and are not listed either; a later plan that edits one of them adds it.
- **Research numbering.** UI-SPEC §19 names its plans by the research's numbering; rows E1 and E14 and the `states.test.tsx:36` and `questionnaire-workflow.test.tsx` rows are this plan's in both numberings.
