## Phase Goal

**As a** Security Analyst or Requestor, **I want to** have the existing request, questionnaire, assessment and administration screens work as they say, **so that** today's flow completes without workarounds, lost input or misleading messages.

This plan's slice: both actors read the whole request, the actions on it always match what the server will allow, and the submission copy stops calling a reversible step irreversible.

<objective>
Deliver REQ-07 on both request pages. One shared read-only request context shows every submitted field in the form's groups (D-20); the Requestor's actions derive from server state after every transition (D-21); both actors offer Return to draft only when Strapi's rule allows it (D-22, request side); the submission dialogs and notices say what happens next (D-15, request side); the request's instants show the local date (D-19); and the hub and form copy lose their internal terms (D-38).

Purpose: UAT-015, UAT-037, the request halves of UAT-022 and UAT-036, the request dates of UAT-024, and the hub, tile and sponsor copy of UAT-054 (ROADMAP success criterion 2).
Output: `RequestContextDetails` with its test, the predicate, the corrected actions and copy on both pages and the form, updated unit tests, and the journey changes E6 and E15 plus the in-page revert and third-party steps.

Edits Strapi source? No. Runs Playwright? Yes (the request and relationship journeys). Runs alone in its wave, after plan 10-03: every plan in the first four waves runs Playwright on the same E2E ports, SQLite file, Next build and `apps/strapi/dist`, so they run one at a time, ordered by `depends_on` (orchestrator execution note, 2026-09-27).
