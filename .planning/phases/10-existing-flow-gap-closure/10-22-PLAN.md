## Recorded planning decisions

- **Where the titles live.** A new CSRM file, `apps/backend/src/bootstrap/controls/csrm-control-titles.json`, beside the vendored catalogues and outside `CONTROL_CATALOGUE_FILES`. The vendored files stay byte-identical to what was retrieved, so the publisher's data and CSRM's words never mix. The file is a JSON object with: `description` (what the file is and that D-46 governs it); `sources`, keyed by catalogue file name, each `{ "basis": "framework" | "descriptive", "note": … }` (the ISO note says the names are the standard's control names and no control text is loaded; the others say the titles are CSRM's words, each checked against its paragraph, with the clause or section kept as the reference); and `titles`, keyed by the same catalogue file names, each an object mapping control id to title. `sources` and `titles` list exactly the same four files.
- **Seed changes (`seed-csrm-data.ts`).** Extract the existing label chain into `catalogueLabel(control)`; `controlName(control, title)` uses the catalogue's label first and the file's title only where the catalogue has none, still writing `{id} — {label}`. Add `CONTROL_TITLE_FILE`, `parseControlTitles(sourceFile, source, catalogues)`, `readControlLibrary(appRoot)` (reads the twelve catalogues and the title file from `src/bootstrap/controls`, keeping today's duplicate-id checks) and `createControlSeeds(catalogues, titles)`; export the last three with their types, and have `seedCsrmData` use them. `description`, `controlReference`, `framework`, the framework fields and `sourceData` are built exactly as today, so an Annex A control still has no description and every CPS and PSPF control keeps its paragraph as its description and its clause or section as its reference.
- **Validation (the seed throws, naming the file and control).** `parseControlTitles` refuses: a file that is not a JSON object; `sources` and `titles` that do not list the same catalogue files, or a file not in `CONTROL_CATALOGUE_FILES`; a `basis` other than `framework` or `descriptive`; an id not in the named catalogue; an id whose control already has a catalogue label; and a title that is not a string, is not already trimmed, is shorter than 3 or longer than 100 characters, contains an em dash, an en dash or a line break, ends with a full stop, or starts with its own control id. Coverage (every control titled) is proved by the tests, not enforced at boot, so a later catalogue update cannot stop Strapi from starting.
- **Stored name format.** Unchanged `{number} — {title}`: the D-36 label rule strips the repeated number for seeded and imported controls alike (research Open Question 6, settled by D-42).
- **Descriptive titles.** Two to eight words and at most 80 characters; sentence case, keeping role names and acronyms as the paragraph writes them (`Accountable Authority`, `Chief Security Officer`, `APRA`); Australian English with no em or en dash, no trailing full stop and no `must` or `shall` (D-38 voice); a noun phrase naming what the paragraph requires, in CSRM's words, never the paragraph's opening words copied. Title only the operative requirement: some statements carry footnote text or the next heading from the PDF extraction (for example `CPS-230-11` holds a footnote about groups, and `CPS-234-14` ends with the heading `Information security capability`). Where neighbouring paragraphs impose the same obligation on different parties or at different times, name the party or the timing (`PSPF-008` appoints a Chief Security Officer, `PSPF-011` a Chief Information Security Officer). Titles are unique within their framework.
- **How each descriptive title is checked against its paragraph.** First by reading: Task 2 writes a scratch review file under `apps/backend/.tmp/` (git-ignored) with each control's id, clause or section, full paragraph and draft title, and re-reads it row by row after drafting each framework, correcting any title that names something its paragraph does not require, leaves out the paragraph's main obligation, or would fit a neighbour as well. Then by the unit test's anchor check: split the title and its paragraph into lower-case runs of the letters a to z; a title word counts when it has at least four letters and is not one of `with`, `from`, `that`, `this`, `their`, `into`, `must`, `shall`, `each`, `such`, `which`, `where`, `when`, `have`, `than`, `also`, `only`, `under` or `other`; its stem is its first five letters (the whole word when shorter); a stem is generic for a framework when words beginning with it appear in more than half of that framework's paragraphs (measured 2026-09-28: `apra`, `regul`, `entit`, `must`, `infor`, `secur`, `asset` and `with` for CPS 234; `apra`, `regul`, `entit`, `must`, `opera`, `servi`, `provi` and `manag` for CPS 230; `secur` for the PSPF); the check passes when at least one counted, non-generic stem of the title begins a word of the control's own paragraph. A shifted or unrelated title usually fails it; the reading pass catches what a word check cannot, and the orchestrator spot-checks a sample (VALIDATION Manual-Only, plan 10-23 walk).
- **Annex A names.** The 93 names below are the standard's control names (ISO/IEC 27001:2022 Annex A, unchanged by Amd 1:2024), with ISO's own spelling kept (`Organizational`, `synchronization`), because D-43 shows stored data verbatim. Before writing them, confirm each against a second public listing of the control names when one is reachable (for example the contents of ISO/IEC 27002:2022 on ISO's Online Browsing Platform); public listings vary in two wordings, `5.34` and `8.1`, so use the forms below unless that listing shows otherwise, and record in the summary the listing used and any name changed, or that none was reachable. Load names only: no control text, guidance or purpose statement from any ISO standard.
- **The proof word.** `masking` matches only `8.11` across the 2,646 controls once `8.11` carries its name, and nothing before (the Administration search rule, a case-insensitive match on number, name or framework, simulated over the seed data on 2026-09-28). The unit test keeps it honest after the descriptive titles land: it counts the controls the word matches and requires between one and ten, so `8.11` stays on the picker's first page of ten.
- **The dev database** picks up the titles on the orchestrator's next seeded Strapi start, as plan 10-17's corrections do; tests use their own databases. The reconciliation already overwrites seeded names on a seeded start (T-10-42); decision 15's "the Admin can edit titles" belongs to Phase 22's Admin role.
