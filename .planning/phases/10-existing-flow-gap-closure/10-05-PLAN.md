## Phase Goal

**As a** Security Analyst or Requestor, **I want to** have the existing request, questionnaire, assessment and administration screens work as they say, **so that** today's flow completes without workarounds, lost input or misleading messages.

This plan's slice: a Requestor opening a questionnaire is told what it is for before anything else, is shown what needs attention only when it matters and in the order of the form, and is never promised or refused a step the server would decide differently.

<objective>

Make every submission dialog and notice truthful (D-15, questionnaire side) and offer Return to draft and Return to analyst review only when Strapi's rules allow them, through shared zod-free predicates (D-22, questionnaire side).

Purpose: UAT-023, the questionnaire halves of UAT-022 and UAT-036, and the history counts of UAT-024 (QUES-09 criteria 2 and 4, UX-06 criterion 1).
Output: the predicates module and its test, the introduction, the reordered page and renderer, the per-round history, the analyst notice and revert gating, and the journey changes E4 and E5 plus the first-screen and post-draft steps.

Edits Strapi source? No. Runs Playwright? Yes (the questionnaire, performance and release journeys).
</objective>

## Recorded planning decisions

- **Why a new module.** `questionnaire-domain.ts` defines zod schemas (line 156), so zod-free predicates go in `questionnaire-workflow-rules.ts`, whose only imports are types.
- **Rules.** `canRevertQuestionnaireToDraft({ state, assessmentRequest })`: `state === 'submitted'` and the request relation is `available` with `requestStatus === 'questionnaire-in-progress'` (Strapi refuses otherwise: `questionnaire-workflow.ts:278-279`). `canReturnToAnalystReview({ release, assessmentRequest })`: a release exists and the request relation is `available` with `requestStatus` of `submitted` or `questionnaire-in-progress` (`RELEASABLE_REQUEST_STATUSES`). `submittedNoticeVariant(actor, questionnaire)` returns `'requestor-revertible'`, `'requestor-locked'` or `'analyst'`. Anything unknown fails closed.
- **The introduction's count** is the visible-question count the completion card starts from: `getVisibleQuestionKeys(definition, answers)` over the answers the definition carries at load. The conditional sentence is added when any question has a `visibility` rule.
- **The form-level alert keeps only failures** until plan 10-08 retires it: `prepareSubmission` no longer sets its message, and its embedded question list is removed, so the attention region is the one list (UI-D29).
- **The renderer takes the notice variant as a prop** (`submittedNotice`), set by the page from the predicates.
