## Recorded planning decisions

- **List item fields and bounds** (declared in the spec, mirrored exactly by the parser): `documentId` and `riskNumber` (1-255), `riskStatement` (string up to 65,535 or null), `informationSystemImpacted` and `informationAssetImpacted` (`{ documentId, name }` with 1-255 bounds, or null), `inherentLikelihood`, `highestInherentConsequence`, `residualLikelihood`, `highestResidualConsequence` (string up to 65,535 or null), `inherentRating` and `residualRating` (`AssessmentRating` or null), `treatmentAction` (`Accept`, `Treat` or null), `treatmentPlan` (string up to 65,535 or null), `treatmentStatus` (the four statuses or null), `riskOwner` and `treatmentOwner` (`ActiveUserSummary` or null), `targetDate` (date or null).
- **Control summary.** `controlSummary` is required and nullable: `{ documentId, controlNumber, name, framework }` (each 1-255, the Administration control record's bounds) when the populated control has them, else null. Both `projectControlImplementationSummary` functions (`assessment-scope.ts` and `control-implementation-workflow.ts`) build it, and the create and update paths populate `control` with those fields.
- **The analyst's read-only editor** renders the same component with h3 groups. The review page reads the list items only when the assessment is not mutable, using `canMutateAssessment`, which moves from `assessment-editor.tsx` to zod-free `assessment-domain.ts` so the page and the editor share it.
- **Label rule without a framework.** Where a served control carries no framework (the Risk Register's `RiskDetailControl`, the picker's `ControlSummary`), an untitled control's label is its number alone; D-03 caps the API changes, so no framework is added to those shapes.
- **Decided readings (D-42, D-43, D-46).** A control with no title reads `{number} · {framework}` and the catalogue theme is not shown (D-42; no Phase 10 projection serves it); the label joins with the spaced middle dot recorded as X-4 (D-43). Plan 10-22 loads titles for every seeded control (D-46), so after it the fallback serves only a control that still has no title, such as one imported later; the rule and its tests here do not change.
