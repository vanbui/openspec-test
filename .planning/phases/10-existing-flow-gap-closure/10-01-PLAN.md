## Phase Goal

**As a** Security Analyst or Requestor, **I want to** have the existing request, questionnaire, assessment and administration screens work as they say, **so that** today's flow completes without workarounds, lost input or misleading messages.

This plan's slice: every revision timeline and revert summary shows times in the viewer's own zone, labelled UTC only while the zone is not yet known, and the design direction carries the five patterns the rest of the phase builds on.

## Recorded planning decisions

- **Module placement (Planner's Discretion).** `apps/csrm/src/lib/time/format-instant.ts` is pure and zod-free (`formatInstant`, `isValidTimeZone`, `InstantStyle`). `apps/csrm/src/lib/time/viewer-time-zone.ts` starts with `import 'server-only'` and owns the cookie name and the read. `apps/csrm/src/lib/time/time-zone-actions.ts` is a `'use server'` module. `apps/csrm/src/components/csrm/local-time.tsx` is the one `'use client'` module (provider, hook, `LocalInstant`, `ViewerTimeZoneSync`).
- **Cookie attributes.** Name `csrm-time-zone`, `httpOnly`, `sameSite: 'lax'`, `path: '/'`, one-year `maxAge`, and `secure` exactly when the first `x-forwarded-proto` value is `https`, the rule the session cookie already uses (`development-session-adapter.ts:51-54`). An unconditional `secure` cookie would be dropped on the plain-HTTP E2E origin. Research Assumption A5 allowed renaming; the name is kept.
- **Styles.** `InstantStyle` is `'date' | 'date-long' | 'date-time' | 'time'`: `date` is `{ day: 'numeric', month: 'short', year: 'numeric' }` (`27 Sept 2026`, today's request format), `date-long` is `{ dateStyle: 'long' }` (`27 September 2026`, the released view), `date-time` adds `hour: 'numeric', minute: '2-digit'` (`27 Sept 2026, 3:47 pm`), `time` is the hour and minute alone (`3:47 pm`). Locale `en-AU` throughout. The ` UTC` suffix is appended only for `date-time` and `time` when the zone is null.
- **Where the sync runs.** Only in the shell, as UI-SPEC §4.5 specifies ("once per app load when it differs from the cookie, then refreshes the route"). A sign-in page sync was considered and rejected: it would exist only for the development sign-in, and a production sign-in has no such page. The one refresh after the first page of a session is benign: `router.refresh()` keeps client state.
- **`LocalInstant` everywhere, not a hook in shared components.** `RevertAuditSummary` and `RequestHub` are rendered by the Server Component page `app/(app)/app/requests/[documentId]/page.tsx`, so shared components render the client `LocalInstant` rather than calling a hook.
- **Decided (D-41, D-43).** The five extensions are accepted as written, and X-4's spaced middle dot sits beside D-38's spaced hyphen as the UI-SPEC proposes: the hyphen replaces the em dash in prose, and the middle dot joins an identifier to a name or a second fact.
