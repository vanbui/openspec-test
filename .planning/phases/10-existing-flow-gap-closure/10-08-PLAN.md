This plan's slice: a Requestor who types answers and walks away, follows a link or closes the tab no longer loses them without warning.

## Recorded planning decisions

- **Hook contract.** `useAnswerAutosave({ save, getAnswers, debounceMs = 1500 })` returns `{ status, schedule, flush, retry, pause, resume, blocking }`. `status` is `{ kind: 'idle' } | { kind: 'saving' } | { kind: 'saved'; at: string } | { kind: 'failed'; failure: 'retryable' } | { kind: 'failed'; failure: 'blocked'; message: string }`. `blocking` is true while a change waits, a save is in flight, or the last save failed. `schedule` restarts the timer, `flush` saves now (used on blur and by `Save draft`), `pause` and `resume` bracket the submit confirmation. On `pagehide`, `visibilitychange` to hidden and unmount a waiting save is sent at once without a prompt.
- **What the renderer watches.** react-hook-form's `watch` subscription calls `schedule` on any answer change; the field wrappers' `onBlur` calls `flush`.
- **Why autosave revalidates nothing (installed Next 16.3.6, read 2026-09-28).** `revalidatePath` marks the whole action as revalidated whatever path it names (`apps/csrm/node_modules/next/dist/server/web/spec-extension/revalidate.js:221-222`, "TODO: only revalidate if the path matches"), and a cookie write does the same (`…/spec-extension/adapters/request-cookies.js:130`). A revalidated action renders the current page into its response (`…/server/app-render/action-handler.js:990`, `skipPageRendering` is false) and sends `x-action-revalidated` (`action-handler.js:120-123`); the bundled `revalidatePath.md` says a Server Function call "Updates the UI immediately". Revalidating only `/app` and `/app/questionnaires` would therefore still re-render `/app/questionnaires/{id}` on every autosave. So the autosave variant calls no `revalidatePath`, `revalidateTag`, `updateTag` or `refresh` and writes no cookie: its response is the action result alone. The lists need no revalidation: the app layout is `force-dynamic` and `staleTimes.dynamic` defaults to 0 (`staleTimes.md`), so a link navigation reads them fresh.
- **Back and Forward after an autosave.** Because the autosave revalidates nothing, the client router keeps the questionnaire page as it was last rendered, and a history traversal reuses that payload however old it is (bundled glossary "Client Cache": pages "are reused during browser back/forward navigation"; `client/components/segment-cache/bfcache.js` `readFromBFCache` bypasses staleness; only a revalidating action or `router.refresh()` evicts it, `router-reducer/reducers/server-action-reducer.js:221` and `refresh-reducer.js:49`). A restored page would seed the form with answers older than the last save, and the next save would write them back. So `use-answer-autosave.ts` keeps a module-level session record of the last successful save per questionnaire, `rememberSavedQuestionnaire(documentId, { updatedAt, answers })` (the save result's `updatedAt` and `answers` definition), and `savedQuestionnaireAfter(documentId, updatedAt)` returns that record only when its `updatedAt` is later than the given one. The renderer calls `rememberSavedQuestionnaire` after every successful autosave and `Save draft`, and at mount seeds its definition and form values from `savedQuestionnaireAfter(documentId, serverUpdatedAt)` when there is one, else from the page payload; `QuestionnaireDetail` passes `serverUpdatedAt={questionnaire.updatedAt}`. A reload or a link navigation reads the server, whose `updatedAt` is equal or later, so the payload wins. The record holds only the Requestor's own answers, in that tab's memory, and is gone on reload.
- **Guard contract.** `NavigationGuardProvider` holds the current leave state (registered by `useLeaveGuard(blocking, reason)`), owns one controlled `ConfirmDialog`, and exposes `useNavigationGuard()` returning `{ blocking, guardLink(navigationEvent, { href, trigger, onLeave }) }`. Next's `Link` calls `onClick` before `onNavigate` (`apps/csrm/node_modules/next/dist/client/app-dir/link.js:328`, then `linkClicked` at `:339` calls `onNavigate` at `:71`), and `onNavigate` receives only an object with `preventDefault()`, never the DOM event (`link.md` "onNavigate"). So a guarded link records the activated element in its `onClick` from `event.currentTarget`, and passes it as `trigger` from `onNavigate`. When not blocking, `guardLink` does nothing and the link navigates. When blocking, it calls `preventDefault()` and opens the dialog; `Leave questionnaire` runs `onLeave` (if given) and then `router.push(href)`; `Keep answering` closes the dialog and focuses `trigger` when `trigger.isConnected`, else the page's `h1`. Without a provider the hook returns `blocking: false` and a `guardLink` that does nothing, so existing shell tests keep passing. `GuardedLink` wraps `next/link` for single links (the wordmark and the questionnaire page's request link) and records its own trigger. Modifier-key and middle clicks are left to the browser (Next's `onNavigate` does not fire for them, `link.md` "Good to know").
- **The mobile navigation sheet.** `CapabilityNavigation`'s `onClick` today closes the sheet before the guard runs. It now records the activated link and calls the sheet-closing callback only when `guard.blocking` is false (a normal navigation closes the sheet as today, so `mobile-navigation.test.tsx:402-405` passes unchanged); `onNavigate` calls `guardLink` with that callback as `onLeave`, so a blocked link leaves the sheet open, `Keep answering` returns focus to the link inside it, and `Leave questionnaire` closes it and navigates. The leave dialog opens above the sheet, and each Radix layer handles its own `Escape` and focus.
- **Browser Back and Forward** are not intercepted (UI-D11); the waiting save is sent at once on `pagehide`, and the session record above keeps a restored page on the saved answers.
- **`ConfirmDialog` controlled mode.** `trigger` becomes optional and `open` and `onOpenChange` props are added; with no trigger the dialog is controlled. Its anatomy, locked default dismiss label and focus behaviour are unchanged; the leave warning passes `cancelLabel="Keep answering"`.
