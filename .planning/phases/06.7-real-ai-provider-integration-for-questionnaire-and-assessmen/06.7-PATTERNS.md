## Pattern Assignments

### `apps/strapi/src/api/csrm-assessment/services/openai-compatible-assessment-draft-provider.ts` (service, request-response)

**Analog:** `apps/strapi/src/api/csrm-assessment/services/deterministic-assessment-draft-provider.ts` (full file, 169 lines) and its sibling type/parser file `assessment-draft-provider.ts` (full file, 103 lines).

**Interface contract to implement** (`assessment-draft-provider.ts` lines 43-47):
```typescript
export interface AssessmentDraftProvider {
  readonly name: string;
  readonly version: string;
  generate(context: AssessmentDraftContext): Promise<AssessmentDraftProposal>;
}
```

**Existing deterministic provider shape to mirror** (`deterministic-assessment-draft-provider.ts` lines 147-168):
```typescript
export const deterministicAssessmentDraftProvider: AssessmentDraftProvider = {
  name: "deterministic-assessment-draft",
  version: "1",
  async generate(context): Promise<AssessmentDraftProposal> {
    // ... build proposal object ...
    return parseAssessmentDraftProposal({ schemaVersion: 1, summary, overallRating, overallRiskRationale, recommendationsSummary, risks });
  },
};
```
The new `openaiCompatibleAssessmentDraftProvider` must have the same shape (`name`, `version`, `async generate(context)`), but:
- `name` = `strapi.config.get('ai.providerLabel')` (D-06 — a config-supplied label, default `"openai-compatible"`), not a hardcoded string.
- `version` = the configured model ID string (D-06's `providerVersion`).
- Internally: call the shared `openai-compatible-client.ts` helper, `JSON.parse` the response text, and return the **raw unvalidated object** — do NOT call `parseAssessmentDraftProposal` inside the adapter itself. The workflow call site already applies the parser (see `assessment-workflow.ts:667` below), exactly matching how the deterministic provider's result flows through today, so keep that call-site responsibility unchanged and have the new adapter return a plain object of the same rough shape.

**Validation entry point already provided** (`assessment-draft-provider.ts` lines 93-102, unconditional trust boundary — do not duplicate or bypass):
```typescript
export function parseAssessmentDraftProposal(value: unknown): AssessmentDraftProposal {
  if (!isRecord(value) || !hasExactKeys(value, PROPOSAL_KEYS) || value.schemaVersion !== 1) invalid();
  if (!boundedString(value.summary) || !boundedString(value.overallRiskRationale)
    || !boundedString(value.recommendationsSummary) || !isAssessmentRating(value.overallRating)) invalid();
  if (!Array.isArray(value.risks) || value.risks.length > 50) invalid();
  const risks = value.risks.map(parseRiskProposal);
  ...
}
```
This is the exact object shape (`PROPOSAL_KEYS` = `schemaVersion, summary, overallRating, overallRiskRationale, recommendationsSummary, risks`) the model's JSON output must match, and the exact bound (`risks.length > 50`) that D-10's `maxOutputTokens` cap must be generous enough to satisfy.

**Error handling pattern** — throw the existing typed failure class, not a plain `Error` (`assessment-draft-registry.ts` lines 60-65, 88-95):
```typescript
export class AssessmentDraftJobFailure extends Error {
  constructor(public readonly code: string, public readonly safeMessage: string) {
    super(safeMessage);
    this.name = "AssessmentDraftJobFailure";
  }
}
// ...
function safeFailure(error: unknown): { code: string; message: string } {
  if (error instanceof AssessmentDraftJobFailure
    && /^[A-Z][A-Z0-9_]{0,63}$/.test(error.code)
    && nonBlank(error.safeMessage, 255)) {
    return { code: error.code, message: error.safeMessage };
  }
  return { code: "DRAFT_GENERATION_FAILED", message: "Assessment draft generation failed safely." };
}
```
The new adapter must `throw new AssessmentDraftJobFailure("PROVIDER_AUTH_ERROR" | "PROVIDER_RATE_LIMITED" | "PROVIDER_TIMEOUT" | "PROVIDER_OUTPUT_INVALID", "<generic safe message>")` for each D-09 case — a plain `Error` silently degrades to the generic `DRAFT_GENERATION_FAILED` code and loses the required taxonomy. The `safeMessage` regex requires a bounded, non-blank string ≤255 chars — keep messages short and generic per D-09 (no provider diagnostics).

### `apps/strapi/src/csrm/openai-compatible-client.ts` (NEW — shared helper, service, request-response)

**No direct in-repo analog** (first external-HTTP-client module in this codebase); shape is fully specified by RESEARCH.md Pattern 2 and reproduced here since it is load-bearing:

```typescript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: config.baseURL,
  apiKey: config.apiKey ?? "",       // MUST always pass explicit string — omitting throws at construction even for keyless self-hosted backends (openai-node#1464)
  timeout: config.requestTimeoutMs,  // D-10: ~60s
  maxRetries: 0,                     // job registry owns retry (D-11); do not double-retry inside the SDK
});

const response = await client.chat.completions.create({
  model: config.model,
  messages: [
    { role: "system", content: systemPromptFramingUntrustedInput }, // D-08
    { role: "user", content: renderedContext },
  ],
  max_tokens: config.maxOutputTokens, // D-10 — use max_tokens, not max_completion_tokens (self-hosted-compat, see Pitfall 3)
  ...(config.structuredOutputMode ? {
    response_format: { type: "json_schema", json_schema: { name: "<operation>_proposal", strict: true, schema: {} } },
  } : {}),
});
const rawText = response.choices[0]?.message?.content;
if (!rawText) throw new <Operation>JobFailure("PROVIDER_OUTPUT_INVALID", "<generic message>");
let parsedJson: unknown;
try { parsedJson = JSON.parse(rawText); }
catch { throw new <Operation>JobFailure("PROVIDER_OUTPUT_INVALID", "<generic message>"); }
return parsedJson;
```

**Error-mapping table (D-09), verified SDK error class names**:
| SDK error / condition | D-09 code |
|---|---|
| `OpenAI.AuthenticationError` (401), `OpenAI.PermissionDeniedError` (403) | `PROVIDER_AUTH_ERROR` |
| `OpenAI.RateLimitError` (429) | `PROVIDER_RATE_LIMITED` |
| `OpenAI.APIConnectionTimeoutError` | `PROVIDER_TIMEOUT` |
| Any other `OpenAI.APIError`, `APIConnectionError`, non-JSON/schema-invalid output | `PROVIDER_OUTPUT_INVALID` |

Both new adapter files (`openai-compatible-assessment-draft-provider.ts`, `openai-compatible-questionnaire-generation-provider.ts`) should call into this shared helper for the HTTP-call + error-mapping part, then throw their own operation-specific failure class (`AssessmentDraftJobFailure` vs. `QuestionnaireGenerationJobFailure`) around the shared client's result.

## Shared Patterns

### Typed job-failure classes as the D-09 error-taxonomy vehicle
**Source:** `apps/strapi/src/api/csrm-assessment/services/assessment-draft-registry.ts` lines 60-65 (class def) and lines 88-95 (`safeFailure` fallback logic); parallel `QuestionnaireGenerationJobFailure` in `questionnaire-generation-registry.ts`.
**Apply to:** Both new provider adapters — every thrown error in the new HTTP-client code must be one of these two typed classes with one of the four D-09 codes (`PROVIDER_AUTH_ERROR`, `PROVIDER_RATE_LIMITED`, `PROVIDER_TIMEOUT`, `PROVIDER_OUTPUT_INVALID`), never a plain `Error` — a plain `Error` silently collapses to the generic `DRAFT_GENERATION_FAILED`/equivalent code and defeats D-09's differentiation requirement.
```typescript
export class AssessmentDraftJobFailure extends Error {
  constructor(public readonly code: string, public readonly safeMessage: string) {
    super(safeMessage);
    this.name = "AssessmentDraftJobFailure";
  }
}
```

### `config/*.ts` / `env()` convention
**Source:** `apps/strapi/config/admin.ts` (full file).
**Apply to:** `config/ai.ts` — the exact `({ env }: Core.Config.Shared.ConfigParams) => ({...})` default-export-function shape, using `env()`, `env.bool()`, `env.int()` accessors, no other config-loading mechanism.

### Provider interface substitution without touching call-site validation
**Source:** `assessment-draft-provider.ts` (`AssessmentDraftProvider` interface + `parseAssessmentDraftProposal`) and the equivalent questionnaire pair.
**Apply to:** Both new adapters — implement `{name, version, generate(context)}` exactly, return raw unvalidated JSON from `generate()`, and leave the existing parser call at the workflow call site (`assessment-workflow.ts:667`, `questionnaire-generation-workflow.ts:30`) untouched. This is the single most important shared constraint in the phase (D-07).

### Provider-selection read-once-at-module-load
**Source:** `apps/strapi/src/csrm/config.ts` (module convention) extended per RESEARCH.md Pattern 1.
**Apply to:** `assessment-workflow.ts` and `questionnaire-generation-workflow.ts` — both replace a single hardcoded deterministic-provider import with a `CSRM_AI_PROVIDER_MODE`-driven selector, following the identical pattern in both files (same shape, different provider pair).
