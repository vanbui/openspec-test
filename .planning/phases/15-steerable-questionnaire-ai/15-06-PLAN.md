## Phase Goal

**As a** Security Analyst, **I want to** tell the AI what to add, change or remove in a questionnaire and to have it propose follow-up questions without touching answered ones, **so that** the question list keeps up with new information while I stay in control.

This plan's slice: asking the AI works end to end inside Strapi: a job, a recorded run with its instruction and provider, a stored proposal and a timeline entry, with nothing changed on the questionnaire itself.

## Recorded planning decisions

- **State** (`deriveProposalQuestionnaireState({ questionnaire, request, questions, draftJobActive })`): `assessment-started` when the request has an assessment; else `draft-in-progress` when the draft registry's `latestForQuestionnaire` job is queued or running; else `analyst-review` when `releasedAt` is empty; else `submitted` when every active visible question holds a submitted answer envelope (`projectQuestions`' submitted-batch rule); else `awaiting-submission`.
- **Errors.** `QuestionnaireProposalWorkflowError(status: 400 | 403 | 404 | 409, message, reason?: ConflictReason)`; job failures use `ProposalJobFailure(code, safeMessage)` with the registry's safe-code rule (`/^[A-Z][A-Z0-9_]{0,63}$/`).
- **Enqueue order** (15-RESEARCH §K): closed body `{ instruction? }` (else 400) → questionnaire exists (404) → requesting analyst (403 `OWN_REQUEST`) → state: `analyst-review` and `submitted` allowed; `awaiting-submission` → 409 `QUESTIONNAIRE_NOT_SUBMITTED`; `draft-in-progress` → 409 `ASSESSMENT_DRAFT_IN_PROGRESS`; `assessment-started` → 409 `ASSESSMENT_STARTED` → rewrite target: unknown 404, removed 409 `QUESTION_REMOVED`, answered 409 `QUESTION_ANSWERED` → `parseAnalystInstruction` (400 with its reason) → `repeatsRequestorText` (400 `INSTRUCTION_REPEATS_REQUESTOR_TEXT`) → completed proposal runs at 100 → 409 `AI_PROPOSAL_RUN_LIMIT` → AI data policy (409 with Phase 12's reason) → the governance log has a free slot (409 `HISTORY_UNAVAILABLE`) → enqueue.
- **Corpus** (`loadRequestorTextCorpus(strapi, { requestId, questionnaireId })`): the request's text fields from Phase 12's field table, the Requestor-part notes (13-05), answer values of submitted envelopes only, and the text of opted-in files (Phase 14). Analyst notes and draft answers are never in it.
- **Execution** (inside the registry's `execute`): re-check state and the run cap (fail with that code, no run) → policy (fail, nothing sent) → `buildAssessmentContextFor` (`AssessmentContextTooLargeError` → `CONTEXT_TOO_LARGE`, no run) → `createRunningAiRun` (`operation`, `instruction`, `questionnaire`, `assessmentRequest`, `initiatedBy`, `jobId`, `attempt`, provider name and version, the summary with `instruction.source` `analyst`, `plain-language-preset` for a rewrite without an instruction, or `default-task`) → provider and adapter outside any lock → `withQuestionnaireGovernanceLock`: re-read the state; when `draft-in-progress` or `assessment-started`, complete the run and append `lapsed` events for every item (`by: "system"`, `cause: { kind: "questionnaire-frozen" }`); else, for a rewrite completing with an item, append `superseded` events (`by` this run's initiating analyst, `cause: { kind: "newer-rewrite", runId }`) to every older completed rewrite run of the same question that still has the item open; `completeAiRun(strapi, runId, { proposal, questionnaire })`; append the `ai-proposal` event (`by` the initiating analyst, `scope`, `questionKey` and `questionText` for a rewrite, `instruction` or `instructionSource`, provider, `itemCount`) and update `governanceLog`. Any failure after the run exists calls `failAiRun` with a safe code.
- **Lock.** `withQuestionnaireGovernanceLock(strapi, questionnaireDocumentId, work)` is the actor-free core of `runGovernanceMutation` (the same `governanceMutationTails` serialisation and `lockQuestionnaire` row lock in one `strapi.db.transaction`), exported; `runGovernanceMutation` calls it. Never nest it for one questionnaire; inside it use the Document Service or `strapi.db.query`, never raw knex.
- **Registry** (`createProposalJobRegistry<TInput>({ execute, now?, createJobId?, maxTerminal?, terminalTtlMs? })`): jobs keyed by a string (`questionnaire:{id}` for questionnaire-wide, `question:{id}` for rewrites) with `questionnaireId`, `operation`, `questionId`, `input`, `initiatingAnalystDocumentId`, `status` (`queued`, `running`, `completed`, `failed`), `attempt`, `queuedAt`, `startedAt`, `completedAt`, `runId`, `failureCode`, `failureMessage`; `enqueue` returns the active job for the same key; `get`; `retry(jobId, analystDocumentId)` only for a failed job with no active job on its key, as a new attempt initiated by the retrier; `activeFor(questionnaireId)`; terminal jobs kept 1 hour, at most 500. One registry instance per Strapi (`WeakMap`, the generation workflow's pattern).
- **Job projection** (`projectQuestionnaireProposalJob(job, viewer, initiatorName)`): `jobId`, `questionnaireId`, `operation`, `questionId`, `status`, `attempt`, `queuedAt`, `startedAt`, `completedAt`, `runId`, `failureCode`, `failureMessage`, `initiatedBy` (`{ documentId, displayName }` or null), `canRetry` (failed and the viewer may retry). Job read and retry: any human analyst (`humanAnalyst` from the policy, 13-08) who may read the request; a requesting analyst → 403 `OWN_REQUEST`; an unknown or expired job → 404.
- **Harness helpers**: `startQuestionnaireProposalsFixture(analystId, questionnaireId, body?)`, `startQuestionRewriteFixture(analystId, questionnaireId, questionId, body?)`, `getProposalJobFixture(analystId, jobId)`, `retryProposalJobFixture(analystId, jobId)`, `waitForProposalJobFixture(jobId)`, `withHeldQuestionnaireProposalProvider(action, { capture?, failWith? })` (patches the mounted deterministic providers' `propose` and `rewrite`, as `withHeldQuestionnaireGeneration` does, optionally capturing the provider input or throwing a provider failure), `listQuestionnaireRunsFixture(questionnaireId)`.
