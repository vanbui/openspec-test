# Phase 06.2 Plan 05: Replacement Lifecycle Gap Closure Summary

Added bounded browser failure evidence, protected the lifecycle from obsolete poll responses, and corrected the dialog trigger so replacement can only start with an explicit acknowledgement. The required dual-server Playwright replacement journey now passes end-to-end.

## Delivered

- Split the acknowledged replacement leg into named Playwright steps and attach a compact `questionnaire-replacement-state.json` snapshot in a `finally` path when its terminal assertion passes or fails.
- Retained the real completion and populated review-link assertions; the diagnostic path neither retries mutations nor converts a failed replacement into a pass.
- Scoped diagnostic data to the current URL, visible questionnaire lifecycle text, dialog visibility, review-link state, and the last ten console/page-error messages.
- Made polling job-ID aware so an in-flight response for an obsolete job cannot overwrite a newer authoritative replacement job.
- Added a focused regression proving that an obsolete completed response cannot expose a review link for a newer queued job.
- Diagnosed the locally captured browser failure: `AlertDialogTrigger` preserved the wrapped Generate button's `start(false)` handler, so opening the confirmation also submitted an unacknowledged generation request.
- Replaced that trigger with a presentation-only button; only the confirmation callback can now invoke `start(true)`. Added regression coverage for the typed acknowledged action payload and reloaded the authoritative request route before the E2E replacement leg.
