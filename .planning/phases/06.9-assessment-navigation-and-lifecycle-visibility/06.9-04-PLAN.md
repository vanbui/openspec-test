<scope_findings>
Planning decisions, recorded here because no one is available to ask:

- **Queue status sets.** From `collection-scope.ts`, the three action queues read only `submitted`, `questionnaire-in-progress`, `risk-assessment-drafted` and `under-review`. The released queue reads only `approved` and `closed`. No queue reads `draft`. Outside the selected queue therefore means: `draft` in every queue, `approved` or `closed` in an action queue, and any reviewable status in the released queue.
- **Closed is within the analyst assessment scope (G-3).** `buildAssessmentCollectionQuery(..., "analyst")` adds no status predicate, `statusSummary` reads every assessment, and `getAssessment` reads any assessment for an analyst. So `closed` is accepted and filtered normally, with no intersection needed.
- **The owner collection shares the validator.** `GET /v1/my_risk_assessments` uses the same `ASSESSMENT_STATUSES` check. Adding `closed` there changes nothing it can return, because the released-owner predicate is always ANDed, exactly as `draft` and `in-review` already behave. Its published enum is widened too, so the contract never runs narrower than the server. That lets the third `as never` cast in the same file, on the same collection-parameter helper, go as well. This is recorded as a deviation from "remove both casts".
- **TDD seams:** the exported builders (`buildAnalystReviewCollectionQuery`, `buildAssessmentCollectionQuery`), the mounted HTTP routes, the published contract, the web service and route content, and the browser.
</scope_findings>
