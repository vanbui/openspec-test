## Recorded planning decisions

- **`configuration-settings.ts`.** `CONFIGURATION_SETTING_KEYS = ["risk-scale", "risk-appetite", "review-policy", "ai-data-policy", "record-retention"] as const`; `isConfigurationSettingKey`; one TypeScript type per envelope (22-01 "Setting envelopes"); `SETTING_BOUNDS = { descriptionMaxLength: 300, reviewIntervalMonths: { min: 1, max: 24 }, retentionYears: { min: 1, max: 99 } }`; `SCALE_PRODUCTS` (the fourteen distinct products of two scores 1–5, ascending); `SETTING_PROBLEM_CODES` (22-01's codes); `parseSettingValue(key, input) → { ok: true, value } | { ok: false, problems: Array<{ path: string, code }> }` collecting every problem (paths like `bands.moderateMax`, `bands.High.reviewIntervalMonths`, `consequenceDescriptions.Minor.financial`), rejecting unknown keys and a `schemaVersion` other than 1 (`not-allowed`); `defaultSettingValue(key)` from the configuration points' constants plus `treatmentExpected` per decision 8 (Low and Moderate false, High and Critical true) and `{ ceiling: null, unclassifiedDefault: "Internal" }` for the AI policy default (the ceiling then bootstraps, 22-06); `settingFieldChanges(key, before, after) → Array<{ field, before, after }>` listing each changed leaf path in envelope order, nothing when equal; `bandForScore(score, bands) → RiskRating`.
- **Authority order** for the monotonicity check: `risk-owner` < `risk-owner-with-executive-approval` < `executive-exception`.
- **`round-criteria.ts`.** `ROUND_CRITERIA_SCHEMA_VERSION = 1`; `RoundCriteriaV1` (22-01 "Round criteria"); `RoundCriteriaError`; `parseRoundCriteria(json)` returns the typed value or throws `RoundCriteriaError` for anything else (unknown keys, a wrong version, an invalid band or appetite via the setting parsers); `DEFAULT_ROUND_CRITERIA` built from `defaultSettingValue` with every version 0 and `takenAt` `1970-01-01T00:00:00.000Z`; `buildRoundCriteria({ scale, appetite, reviewPolicy, takenAt })` where each input is `{ version, value }`; `criteriaDiffer(a, b)` true when the bands, appetite or policy values differ (versions and `takenAt` ignored).
- **`request-lists.ts`.** `LIST_LABEL_MAX_LENGTH = 100`; `normaliseListLabel(raw) → string | null` (trim, collapse inner whitespace; null when empty or longer than 100); `listLabelKey(label)` (normalised, lower-cased); `findLabelClash(entries, label, exceptId?)`; types `ListEntry { id, label, position, isActive }`, `DivisionEntry` (with `businessUnits` carrying `retiredWithDivision`); `checkRequestListValues({ stored: { division, businessUnit }, next: { division?, businessUnit? }, divisions }) → { ok: true, values: { division, businessUnit } } | { ok: false, reason: "DIVISION_NOT_ON_LIST" | "BUSINESS_UNIT_NOT_ON_LIST", field }` (a value equal by `listLabelKey` to the stored one is accepted unchanged; a new value must match an active entry and is returned as the list's label; null or empty clears); `retireDivisionCascade(units)` returns the ids of active units to retire with `retiredWithDivision: true`; `reinstateDivisionCascade(units)` returns the ids with `retiredWithDivision: true`; `movePosition(entries, id, position)` returns the reordered active ids with positions 0..n-1.
- **`role-assignments.ts`.** `AssignmentState { userDocumentId, displayName, roles: Array<{ documentId, name }>, accountStatus: "active" | "inactive" | "deleted" }`; `diffRoleAssignments(before: AssignmentState[], after: AssignmentState[]) → Array<{ userDocumentId, displayName, action: "roles-changed" | "deleted", fields }>` (a user missing after is `deleted` with roles to `[]` and status to `deleted`; a user missing before is new, from `[]` and `none`; fields `roles` as sorted names and `accountStatus`); `ROLE_HOLDER_KEYS = { Admin: "admin", "Security Analyst": "security-analyst", "Security Analyst Agent": "security-analyst-agent" }`; `ROLE_REVIEW_NOTE_CODES = ["admin-and-security-analyst", "holds-agent-role", "inactive-with-role"]`; `roleReviewNotes({ accountStatus, roleNames }) → Array<{ code, roles? }>`.
- **`change-entry.ts`.** `CHANGE_AREAS`, `CHANGE_SUBJECT_TYPES`, `CHANGE_ACTIONS`, `CHANGE_ORIGINS`, `CHANGE_SYSTEM_SOURCES = ["seed", "unattributed"]` (22-01 "The change log"); `CHANGE_VALUE_MAX_LENGTH = 1000`; `boundChangeValue(value) → { value, truncated }` (strings and joined arrays cut at 1,000 with `…`); `buildChangesEnvelope(fields)` → `{ schemaVersion: 1, fields }`; `parseChangeRow(row) → ConfigurationChangeEntry | null` (closed: any unknown area, action, origin or envelope shape reads null and the read skips it, logged once); `projectChangedBy(row)` → the three `changedBy` kinds.
