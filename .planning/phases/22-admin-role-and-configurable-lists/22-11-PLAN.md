## Recorded planning decisions

- **Registration.** `registerRoleChangeRecording(strapi)` is called unconditionally in `register()` after `registerIdamboxUserProvisioning(strapi)`; both join one transaction (`strapi.db.transaction` nests), so their order changes nothing.
- **Filter.** Pass through unless `uid` is `api::idambox-user.idambox-user` with `action` `create`, `clone` or `delete`, or `update` with `roles` or `accountStatus` in `params.data`; or `uid` is `api::role.role` with `action` `delete`, or `create`, `clone` or `update` with `idamboxUsers` in `params.data`.
- **Diff.** Inside `strapi.db.transaction`: read the affected users through `strapi.db.query` only (never `strapi.documents`, Pitfall 1) as `AssignmentState` (roles `{ documentId, name }`, `accountStatus`), call `next()`, read again (for the role side the users before ∪ after; for a role delete, before only; for a user delete, `deleted`), then call `writeConfigurationChanges` with each `diffRoleAssignments` change: area `role-assignment`, subject `user` / documentId / display name, action `roles-changed` or `deleted`, fields `roles` and `accountStatus`.
- **Origin.** `const state = strapi.requestContext.get()?.state`: strategy `admin` or `admin-token` with `state.user` → origin `identity-platform`, `originDetail.operator` `{ id, name: trimmed "firstname lastname" || username || email, email }`; otherwise origin `system`, `originDetail.source` = `currentChangeSource() ?? "unattributed"`.
- **Source scope (`change-source.ts`).** An `AsyncLocalStorage<string>`; `runWithChangeSource(source, fn)`; `currentChangeSource()`. `index.ts`'s bootstrap runs every seed call inside `runWithChangeSource("seed", …)`.
- **List seed (`seed-request-lists.ts`).** `seedRequestLists(strapi)`, behind `IDAMBOX_SEED_CSRM === "true"`, called in bootstrap after the request seeds: collects the distinct seeded `division` and `businessUnit` pairs, creates each missing division and unit (positions in first-seen order) and never updates an existing entry; it writes no change row (D-12: only the operations and the middleware write rows).
- **Static check.** The test greps `apps/backend/src` for `db.query("api::idambox-user` and `db.query("api::role` write calls (`create`, `update`, `delete`, `updateMany`, `deleteMany`) and allows only provisioning's `externalSubject` update.
