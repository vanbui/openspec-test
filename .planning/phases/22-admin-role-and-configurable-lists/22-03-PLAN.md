## Recorded planning decisions

- **Folders.** Each new type is its `content-types/<name>/schema.json` alone: Strapi 5.51's API loader treats `routes`, `controllers` and `services` as optional (`loadDir` defaults them empty, `@strapi/core/dist/loaders/apis.js`) and CSRM writes through `strapi.documents(uid)`. If the fresh boot shows Strapi needs the core factories, add `createCoreRouter(uid, { only: [] })`, `createCoreController(uid)` and `createCoreService(uid)` files as `csrm-risk-type` does, list them in the summary, and keep the freeze check to schema files.
- **Attributes** exactly as 22-01 "Stored changes"; each new schema carries `"options": { "draftAndPublish": false }` and `"pluginOptions": { "content-manager": { "visible": false }, "content-type-builder": { "visible": false } }`; `info.description` one sentence naming the record. The three existing schemas change only by the added attribute.
- **Registry assertion.** `strapi.service("admin::permission").actionProvider.get(actionId).subjects` for `plugin::content-manager.explorer.create`, `.update`, `.delete` and `.publish` excludes the four UIDs and for `.read` includes them (22-RESEARCH §2; the accessor name is assumption A1: if it differs, find the provider through `strapi.admin.services.permission` and record the accessor used).
- **Reasons.** The ten codes join `CONFLICT_REASONS` (Strapi), both specification enums (the ones 19-02 extended) and the web mirror, in one commit, with `conflict-reasons.unit.test.ts` and `conflict-reasons.test.ts` asserting the four lists equal. Their details keys arrive with the operations that return them (22-05 `problems` and `current`; 22-14 `because`).
