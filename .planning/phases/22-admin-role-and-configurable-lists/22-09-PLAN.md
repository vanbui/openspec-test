## Phase Goal

**As an** Admin, **I want to** own reference data and product configuration, separate from analysts' assessment work, **so that** registers, lists and scales are governed.

This plan's slice: the Admin decides which Risk Types are active; a retired type stops being offered to analysts and the AI and stays on every risk that holds it.

Prove each in the API with matrix rows for every caller.

Purpose: SC2's "the active Risk Types" and decision 14.
Output: two operations through the endpoint chain, the risk-path refusals, the library filter and one integration test.

## Recorded planning decisions

- **Operations** (in `CSRM_ADMINISTRATION_OPERATIONS`): `retireRiskType` `POST:/api/v1/risk_types/{riskTypeId}/retire`, `reinstateRiskType` `POST:/api/v1/risk_types/{riskTypeId}/reinstate`, body `{}` (anything else 400), routes before `/v1/risk_types/:riskTypeId`, `requireAdminScope`; FunctionApis `function.administration.risk_types_manage_api.api.07` and `.api.08` (`Retire Risk Type`: `Stops offering a Risk Type for new choices and to the AI; risks that hold it keep it.`; `Reinstate Risk Type`: `Offers a retired Risk Type again.`). Each answers 200 with the Risk Type read; a no-op answers 200 with no row; a missing type 404.
- **Status filter.** `GET /v1/risk_types` accepts `status` `active`, `retired` or `all` (default `all`), with totals per status in `meta.statusCounts: { active, retired }` for the `Show` control; the picker branch always filters `isActive: true`.
- **Refusal.** In `risk-workflow.ts`, risk create and the inner update refuse with 409 `RISK_TYPE_RETIRED` (`details.riskTypeId`) when the written `riskType` differs from the stored one and is not active; the bulk path refuses the whole batch, as 18's other validation does; `risk-import.ts` reports the row issue `RISK_TYPE_RETIRED`.
- **Library.** `assessment-context-loader.ts` reads `isActive: true` Risk Types only.
