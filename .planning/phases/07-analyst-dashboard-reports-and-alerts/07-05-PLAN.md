## Phase Goal

**As a** Security Analyst, **I want to** have a data-driven dashboard, reports, and alerts covering my review queues, high and critical risks, and overdue treatments, **so that** I can prioritise analyst work from live workload signals.

<objective>
Ship the shared presentation primitives and the Alerts screen, the first Phase 7 surface a user can open (DASH-02). Also ship the navigation and shell changes every Phase 7 route needs.

1. **Primitives in `components/csrm` (D-20), each with its own tests:**
   - `KpiTile` (§5.1, D-18);
   - `BarChart` (§5.2, D-19);
   - `SegmentedControl` (§5.3);
   - `AlertUrgencyBadge` (§5.4, D-11);
   - the chart geometry tokens in `globals.css` (§3.14);
   - the cleared `EmptyState` variant (X-11) and a refresh-on-retry error state.
2. **Navigation (§1.2-§1.4):**
   - groups rendered generically, with the new "Reports" group holding Alerts;
   - one current item by longest match;
   - a scrolling mobile sheet;
   - `scroll-padding-top`.
3. **The Alerts screen (§3):** filters, chips, the table and cards, the shared alert row, the five states, the released marker (D-27) and actor-correct links. The Risk Register marker (UI-D13) and the `#mitigation-controls` anchor (§9 item 5) come with it, because alerts link to them.
4. **Browser proof:** a targeted Playwright run, including the specs that exercise plans 02 and 03.

Output: four primitives, a states extension, the navigation changes, the Alerts route with its loading and error boundaries, and the first slice of `e2e/analyst-insights.spec.ts`.
</objective>

## Recorded planning decisions

- **Navigation items land with their routes.** Alerts in this plan, Reports in plan 07, Analyst dashboard in plan 08. No intermediate build ever shows a link to a route that does not exist yet. The mechanics (generic groups, the "Reports" group, longest-match current item, sheet scrolling, scroll padding) land here, as D-35 assigns.
- **D-27's marker copy is "Released · read-only".** It is text in `--text-caption` / `--color-text-secondary` after the record line. The UI-SPEC's alert row has no released marker, and D-27 requires one.
- **`error.tsx` uses Next 16.3's stable `retry` prop.** The bundled docs recommend it over `reset` "in most cases". It re-fetches the segment. The visible "Try again" button and copy are exactly UI-SPEC §6.1's.
- **The dense marker keeps "Overdue" as its own element, with the icon inside and the hidden prefix outside.** `risk-register-workflow.spec.ts` locates the marker with `getByText('Overdue', { exact: true })` and expects exactly one `svg` inside it, and that proof must keep passing unchanged.
- **Browser proofs grow per screen.** This plan creates `e2e/analyst-insights.spec.ts` with the Alerts proofs. Plans 07 and 08 add theirs, and plan 09 adds the cross-screen journey, accessibility, design-contract and conformance coverage.

## Hard rules (carried forward)

- **Styling.** Semantic tokens only. Feature components carry no hex, px or rem literal, except data-driven inline `inlineSize` percentages for bar lengths.
- **States and colour.** Five states through the shared primitives. Status, urgency and risk are never shown by colour alone.
- **Accessibility and layout.** WCAG 2.2 AA from 375px to 1440px, with no horizontal page scroll.
- **Services and authorization.** Typed services only, with no raw fetch. Navigation visibility is not authorization.
- **E2E sign-in.** Helpers assert the Dashboard heading and the role in the banner, never the URL. Browser tests never assert global totals (D-24).
- **Attribution and staging.** Zero AI or tool attribution. Explicit-path staging.
