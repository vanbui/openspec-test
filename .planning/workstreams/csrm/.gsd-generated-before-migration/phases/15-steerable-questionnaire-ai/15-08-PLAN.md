## Phase Goal

**As a** Security Analyst, **I want to** tell the AI what to add, change or remove in a questionnaire and to have it propose follow-up questions without touching answered ones, **so that** the question list keeps up with new information while I stay in control.

This plan's slice: nothing moves on while a proposal is undecided, replacing a questionnaire can no longer lose anyone's work, the first generation can be steered, and the questionnaire reads tell the analyst what is fixed and what is open.

## Recorded planning decisions

- **Gates module.** `openProposalSummary(strapi, questionnaireId)` reads at most 101 completed runs of the two operations for the questionnaire (fields `documentId`, `operation`, `proposal`, `decisions`), folds each with `parseRunProposalFor`, `parseRunDecisionsFor` and `foldItemStates`, logs a damaged run once and counts it as no open item, and adds `activeQuestionnaireProposalJobs(strapi, questionnaireId).length > 0`; returns `{ openCount, activeJob, damagedRunIds }`. `assertNoOpenProposals(strapi, questionnaireId, refuse)` calls `refuse("AI_PROPOSALS_OPEN")` when `openCount > 0` or `activeJob`.
- **Where each gate runs.** Release: inside `releaseQuestionnaire`'s locked transaction, after `assertReleasable`, throwing `QuestionnaireGovernanceError(409, …, "AI_PROPOSALS_OPEN")`. Draft: `generateAssessment` before enqueueing (409 with the draft error's reason) and `persistAssessmentDraft` inside its transaction (job failure code `AI_PROPOSALS_OPEN`); the draft path keeps locking only the request row (15-RESEARCH §M: no questionnaire lock there). Replacement: `generateQuestionnaire` before enqueueing when `replaceUnansweredQuestionnaire` is true, and the replacing branch of `persistGeneratedQuestionnaire` inside its transaction (job failure codes).
- **Replacement order** (D-09): released → Phase 10's existing refusal; `hasQuestionnaireAnswerEvidence` → `QUESTIONNAIRE_ANSWERED` (unchanged); `countAnalystChangesSinceGeneration(log, generatedDate) > 0` → `QUESTIONNAIRE_HAS_ANALYST_CHANGES`; open set or active job → `AI_PROPOSALS_OPEN`. Phase 10's mounted cases that replaced a questionnaire holding analyst changes are changed to expect `QUESTIONNAIRE_HAS_ANALYST_CHANGES` (named in the summary); the `regenerated` event is unchanged apart from the instruction keys.
- **Generation body.** `{ replaceUnansweredQuestionnaire?: boolean, instruction?: string }`, closed. The controller parses it; the workflow runs `parseAnalystInstruction` and, for a non-null instruction, the requesting-analyst check (403 `OWN_REQUEST`) and `repeatsRequestorText` (400 reasons) before enqueueing. The registry's job input carries `instruction` (a `SlotInstruction` or null); `persistGeneratedQuestionnaire` passes it to `buildAssessmentContextFor` with `instructionSource` `analyst` or `default-task`, `createRunningAiRun` stores it, and a replacement's `regenerated` event carries `instruction` or `instructionSource: "default-task"`. The spec's request body gains `instruction` (`maxLength: 500`), and the operation's 400 response declares `reason`.
- **Reads** (`questionnaire-scope.ts`, analysts only): `projectQuestions` adds `answered: isAnsweredValue(answer)` to each question when the proposal state is `analyst-review` or `submitted`, never `awaiting-submission`; the progress count calls `isAnsweredValue`. The header's `generation` block gains `openProposals` (from `openProposalSummary`, or null when the viewer raised the request); `AiGenerationFacts.openProposals` is optional and nullable so the assessment's block (12-09) is unchanged. `deriveQuestionAiOrigins` ignores a confirmation and its Undo (same `runId` and `itemKey`), and the latest remaining content event decides: an AI-sourced add or edit gives `proposal-confirmed`, or `proposal-edited` with `aiEdited`; Phase 12's rules stand otherwise. `latestCompletedGenerationRun` filters `operation: "questionnaire-generation"`.
- **Web.** `questionnaireQuestionSchema` gains optional `answered: boolean`; `questionAiOriginSchema` gains the two values; `aiGenerationFactsSchema` gains optional nullable `openProposals`; `questionOriginMarker` maps `proposal-confirmed` to `Confirmed AI proposal` (`Check`) and `proposal-edited` to `Edited AI proposal` (`PenLine`) (UI-SPEC §9.2, UI-D24).
