## Recorded planning decisions

- **Generic core, target-specific payloads.** `proposal-items.ts` knows nothing about questions: `parseDecisionEventV2(value, parsers)` takes `DecisionPayloadParsers<TBefore, TApplied>` (`before(value)` and `applied(value)`, each returning the parsed payload or null). The questionnaire supplies `questionnaireDecisionPayloads`; Phase 16's risk items supply their own, with no second mechanism (D-20).
- **Event keys** (closed): `schemaVersion` (2), `at` (ISO instant), `by` (1 to 255 characters, or `system`), `item` (`i-1` to `i-30`), `action`, optional `edits` (at most 10 field names from `questionText`, `helpText`, `answerType`, `choices`, `required`, `section`), optional `reason` (1 to 500), optional `cause`, optional `before`, optional `applied`.
- **Transitions** (`nextState(state, action, { withEdits })`): open + accepted → accepted; open + rejected → rejected; open + superseded or lapsed → that state; open + restored → no-op; accepted + accepted without edits → no-op, with edits → not-open; accepted + restored → open; rejected + rejected → no-op; rejected + restored → open; every other pair → not-open. `foldItemStates` never stores a no-op: a stored event that is not a legal transition marks the run damaged.
- **Fingerprint input** (`QuestionFingerprintInput`): `questionText`, `helpText` (raw row attribute; null when blank), `answerType`, `choices` (array of `{ value, label }` or null), `required`, `section` `{ key, title, order }`, `order`, `visibility` (or null), `removed` (boolean). Canonical JSON sorts object keys recursively; the digest is `sha256:` plus lowercase hex from `node:crypto` `createHash("sha256")`.
- **Staleness input** (`LiveQuestionnaire`): `generatedDate` (string or null) and the questions (active and removed) with `documentId`, `questionKey`, the fingerprint input, `answered` (from `isAnsweredValue`) and `removed`. `isItemStale(item, live)` implements the amendment's rules exactly.
- **Answered rule.** `isAnsweredValue(answer)` reads the answer envelope's `value` (null for a non-object) and is true when the value is not null, not the empty string and not an empty array: today's `questionnaire-scope.ts` `hasValue`, so a whitespace-only draft is answered. Plan 15-08 makes the progress count call it, so the fixed set and "N of M answered" cannot drift.
- **Preservation.** `preservesAnswers(before, after)` takes rows of `{ question: QuestionnaireDefinitionQuestion (removed included), helpText, answer }`: for every active answered question in `before`, it still exists in `after`, is active, every fingerprinted field is equal, `isQuestionnaireValueValid` still accepts its stored answer, and, if it was visible under `getVisibleQuestionKeys` of `before` with the stored values, it is still visible in `after`. `keepsControllerValues(after)` refuses when an active dependent's visibility rule references a value its controller's choices no longer offer (`conditionMatchesType` checks types only).
- **Placement.** `createBatchAllocation(definition)` records every question key (removed included), each section's `{ key, title, order }` and its highest question order (removed included), and the highest section order. `placeAddition(allocation, { kind: "existing", key })` returns that section and order = highest + 1; `placeAddition(allocation, { kind: "new", title })` derives the key with `newSectionKey` (lowercase, every run of other characters becomes `-`, trimmed, `section` when empty, cut to 120 characters, then `-2`, `-3`… until unique across every question's section key), order = highest section order + 1, and reuses the same new section for a second addition with the same title (case-insensitive, trimmed) in the batch. `allocateQuestionKey(text, allocation)` applies `questionKeyFromText`'s rule (lowercase, non-alphanumeric runs to `-`, trimmed, cut to 110, `question` when empty, then `-2`, `-3`…) against every taken key and records the result in the allocation. The server rules equal the browser module's (10-09); the unit test copies 10-09's case table.
- **Instruction.** `parseAnalystInstruction(input)`: undefined or null → `{ ok: true, instruction: null }`; a non-string → throws `InstructionShapeError` (a 400 closed-body refusal at the caller); CRLF and CR → LF; raw length above `INSTRUCTION_MAX_LENGTH` (500, UTF-16 code units, the same unit as the governance log) → `INSTRUCTION_TOO_LONG`; any `\p{Cc}` other than LF, `\p{Cf}`, `\p{Cs}`, `\p{Co}`, U+2028 or U+2029 → `INSTRUCTION_CHARACTERS_NOT_ALLOWED`; trimmed empty → null. `normaliseForQuoteCheck(text)` is NFKC, lower case, every whitespace run to one space, trimmed. `repeatsRequestorText(instruction, corpus)` refuses when any 60-character window of the normalised instruction is a substring of a normalised corpus text. `PLAIN_LANGUAGE_PRESET` is the fixed sentence `Rewrite this question in plain language: one thing per question, plain words, and help text that explains any specialist term. Keep the answer type, the choice values, the required flag, the section and the order.` typed as `SlotInstruction`.
- **Branded slot type.** `SlotInstruction` is `string & { readonly [slotInstructionBrand]: true }` with a module-private `unique symbol`; only `parseAnalystInstruction` and `PLAIN_LANGUAGE_PRESET` produce it (D-17's "by construction").
- **Scorer.** `tokenSetSimilarity(a, b)` is |A ∩ B| / |A ∪ B| over `tokenize` sets (0 when both are empty); `isNearDuplicate(a, b)` uses `normaliseForQuoteCheck` equality when either set has fewer than `NEAR_DUPLICATE_MIN_TOKENS` (3), else `tokenSetSimilarity >= NEAR_DUPLICATE_THRESHOLD` (0.8).
