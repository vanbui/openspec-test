# Phase 06.8 Plan 04: Questionnaire Governance Summary

Implemented analyst-only question add, edit, and deletion mutations using the existing locked
questionnaire governance transaction. Deleted questions now retain their database row and answer in
a version-2 options envelope, while one active-definition helper removes them from active
questionnaire, submission, progress, and assessment paths.

## Accomplishments

## Deviations from Plan

The implementation followed the specified design. The suites could not run in the execution
sandbox (`spawn EPERM` for every test child process) and were run afterwards outside it. That
external run found two defects:

1. **An edit to an unanswered question appended a spurious `answer-cleared` event.** The clearing
   branch treated "no stored answer" the same as "stored answer that no longer validates", so the
   common case — editing a question during analyst review, before any Requestor has answered —
   logged a loss that never happened and contradicted the plan's rule of one answer-cleared event
   per answer actually cleared. Clearing is now conditional on a stored answer existing.
2. **The mounted test drove shared fixtures other tests had already moved.** The governance
   fixture seeder memoizes its records, so the questionnaire this test tried to add a question to
   had been released by the earlier release test, and the questionnaire it used to prove the
   analyst-review gate had been returned to review by the return test. Two dedicated fixtures were
   added: `EDITABLE`, which this test owns end to end, and `GATED`, which stays released for the
   whole run so the gate refusal is proved against a genuinely released questionnaire.

## Coverage strengthened during verification

The mounted test as written exercised only the happy path on an already-correct questionnaire. It
now also proves the four denied actors, the gate refusal for both add and delete against a
released questionnaire, that a valid answer survives a question-text edit, that an answer-type
change clears the answer with a plain-language explanation, that an edit to an unanswered question
reports no cleared answer, that a second delete is refused, and the exact ordered governance log
across the whole add, release, answer, return, edit, edit, delete sequence.
