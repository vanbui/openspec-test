## Top 3 Priority Fixes

1. **BLOCKER — Fix Select-to-non-select question edits** — Analysts cannot complete a normal type change because the UI omits `choices` while the server retains and rejects old choices — explicitly clear choices for non-select edits and add a component/browser regression case. See `apps/web/src/features/questionnaires/questionnaire-governance.tsx:57-61` and `06.8-REVIEW.md` CR-03.
2. **BLOCKER — Prevent an empty questionnaire workflow** — The UI permits deleting the final active question, after which the questionnaire can be released/submitted with no Requestor input — disable/delete-guard the last active question and enforce the same rule server-side. See `apps/web/src/features/questionnaires/questionnaire-governance.tsx:72` and `06.8-REVIEW.md` CR-01.
3. **WARNING — Make the lifecycle and governance forms meet the density contract** — Eight small, equal cards obscure workflow progress and governance cards are under-padded/unbounded — use a progressive/scrollable stepper at constrained widths, apply 16px card padding, and constrain the form to 640px. See `apps/web/src/features/requests/request-lifecycle-stepper.tsx:39-55` and `apps/web/src/features/questionnaires/questionnaire-governance.tsx:65-87`.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING:** Cleared-answer feedback labels an item with `questionKey`, an implementation identifier that may not be comprehensible to an Analyst, rather than the question text promised by D-08's plain-language explanation. `apps/web/src/features/questionnaires/questionnaire-governance.tsx:68`. Return the display question text (or resolve it from the definition) and render it as the list item's name.
- Positive evidence: lifecycle labels, next-action copy, destructive confirmations, and queue labels are specific to the user task rather than generic. `request-lifecycle-stepper.tsx:36-60`, `questionnaire-governance.tsx:66-75`, `assessment-list.tsx:103-106`.

### Pillar 2: Visuals (2/4)

- **WARNING:** The lifecycle uses an `xl:grid-cols-8` grid of equal-weight bordered cards. Completed/current/future cues exist, but at 1440px each step is narrow and the repeated card treatment competes with the one intended focal point, the current step. `apps/web/src/features/requests/request-lifecycle-stepper.tsx:39-55`. Keep a compact horizontal progression with a visually prominent current step, or group completed/future steps at desktop; retain the current two-column mobile behavior.
- **WARNING:** Request-hub information-system and information-asset summaries are plain text, despite D-10 requiring available related-record summaries to link to their authoritative detail views. `apps/web/src/features/requests/request-hub.tsx:87-88`. Supply authorised detail hrefs and render `RecordLink` for each available record.
- No screenshots were available, so visual hierarchy, overflow, and final responsive behavior could not be confirmed in a browser.

### Pillar 3: Color (3/4)

- **WARNING:** The code correctly uses semantic classes and no hard-coded color literals were found in the audited feature files. Current, completed, and future lifecycle states also pair colour with icon and text. `apps/web/src/features/requests/request-lifecycle-stepper.tsx:5-23`.
- The required 60/30/10 distribution cannot be verified from source alone; a running-screen capture is required before awarding a full score. The current state applies the interactive primary tint to all of its card surface (`bg-primary-subtle`), so validate it remains the single accent focal point once rendered. `request-lifecycle-stepper.tsx:15`.

### Pillar 4: Typography (3/4)

- **WARNING:** The audited features use the intended semantic heading tokens and only `font-medium`/`font-semibold`, but the governance form's "Question details" and "Question editor" headings use only `font-medium`, without the contract's `text-heading-sm` sizing/line-height. `apps/web/src/features/questionnaires/questionnaire-governance.tsx:71,81`. Apply `text-heading-sm text-foreground` for panel/form headings.
- Distribution: `text-xs`, `text-sm`, `text-base`, `text-lg`, and semantic heading tokens appear; the raw size count is broader than the abstract four-size heuristic, but aligns with the documented token system. No weights above 600 were found.

### Pillar 5: Spacing (2/4)

- **WARNING:** The contract requires cards/panels to use 16–20px padding. The governance panel, cleared-answer notice, question rows/form, timeline entries, and lifecycle step cards use `p-3` (12px), creating an inconsistent, overly dense operational surface. `apps/web/src/features/questionnaires/questionnaire-governance.tsx:65,68,72,80`; `questionnaire-revision-timeline.tsx:32,47,70`; `request-lifecycle-stepper.tsx:46`. Replace card/panel `p-3` with `p-4` unless a documented compact-density exception applies.
- **WARNING:** The governance editor is full-width with no `max-w-[640px]`, violating the single-column form limit. `apps/web/src/features/questionnaires/questionnaire-governance.tsx:80-87`. Add `max-w-[640px]` to the form container and keep fields single-column.
- The broader spacing scale is otherwise consistent with the supplied 2/4/8/12/16/20/24/32px tokens; the most common feature spacings are `gap-2` (62), `gap-3` (41), `gap-4` (20), and `p-4` (18).

### Pillar 6: Experience Design (1/4)

- **BLOCKER:** Changing an existing Single/Multi select question to Text, Boolean, or Date cannot succeed. The editor deliberately omits `choices` for non-select types, while the server retains old choices and rejects the result; the core Analyst edit flow therefore presents an action that fails. `apps/web/src/features/questionnaires/questionnaire-governance.tsx:57-61`; confirmed by `06.8-REVIEW.md` CR-03. Send an explicit clear instruction or change the server to clear choices when the type changes, then test the full transition.
- **BLOCKER:** The visible Delete control permits removal of the last active question. The resulting empty questionnaire can subsequently be released and submitted, defeating the Requestor-input task. `apps/web/src/features/questionnaires/questionnaire-governance.tsx:72`; confirmed by `06.8-REVIEW.md` CR-01. Disable or hide the destructive control for the last active question with explanatory copy, while retaining the authoritative server validation.
- **WARNING:** Core list/dashboard surfaces do implement loading, empty, error, permission, disabled, confirmation, and retry patterns. `apps/web/src/features/assessments/assessment-list.tsx:207-226`, `apps/web/src/features/dashboard/requestor-dashboard.tsx:269-286`, `apps/web/src/features/questionnaires/questionnaire-governance.tsx:67-75`. This coverage does not offset the two task-completion blockers.
- **WARNING:** The review queue can silently hide work after its first 1,000 records, so pagination and total counts misrepresent the actionable queue. `06.8-REVIEW.md` CR-04. Correct the server projection/counting behavior before relying on the UI queue for operational work.
