# Phase 06.8 Plan 03: Questionnaire Return to Review Summary

Implemented `POST /api/v1/questionnaires/:questionnaireId/return_to_review` as a
resource-authorized, Analyst-only governance operation. It validates the shared mandatory
reason shape, serializes and locks the questionnaire, refuses ineligible request states or
linked assessments, restores submitted answer envelopes to drafts, clears the dedicated
release facts, and appends a `returned-to-review` audit event in the same transaction.

The existing answer-envelope parser is now exported as `parseAnswerEnvelope` without a
behaviour change. Direct governance tests cover the analyst-review gate's accepted and
refused states, returned submitted/draft/null answer handling, and parser compatibility.
Mounted coverage exercises authorization denials, invalid reason bodies, audit ordering,
answer preservation, Requestor access removal, and the absence of an implicit request
lifecycle regression.

## Deviations from Plan

The default Node test runner isolates each test file in a child process, which the execution
sandbox does not permit. Focused unit suites were run there with `--test-isolation=none`; the
full `pnpm test` suite was run afterwards outside the sandbox and passed 198/198.

That full run exposed one defect the focused suites could not: the governance fixture seeder
memoizes its records, so the new mounted return test and the existing mounted release test
shared one questionnaire, and the release the return test performs as setup returned 409
because the earlier test had already released it. A third `RETURNABLE` governance fixture was
added to `apps/strapi/tests/helpers/strapi-http-harness.ts` and the return test now drives the
whole release, answer, submit and return cycle on records no other test mutates. Depending on
declaration order between tests in one file is not an acceptable substitute.
