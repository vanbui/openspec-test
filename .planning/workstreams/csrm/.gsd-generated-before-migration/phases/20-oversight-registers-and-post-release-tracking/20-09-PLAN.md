## Phase Goal

**As a** risk manager, **I want to** registers by assessment type that stay current after release, and as a risk or treatment owner I want to track each treatment to completion on evidence, **so that** oversight reflects what is actually being done.

This plan's slice: a risk, treatment or control owner can list and open exactly what they own, with due and review flags, the acts open to them and the post-release history, and nobody else can see any of it.

<objective>
Serve the owner reads (D-03 item 1): "My risks and treatments" with its summary and export, the owner risk read, and the owner history read (D-19, D-20), scoped by Strapi through 20-05's repository and SQL twin and refused per D-21. Publish, grant and prove the five operations (D-02).

Purpose: SC3 ("a risk owner sees their risks, their risks' treatments and the decisions awaiting them or due for review; a treatment owner sees their treatments with due dates; neither sees anybody else's") and SC6's "by any route", in the API; UAT-058's ask.
Output: the list repository, the owner read module, routes, controller, the export view, the contract chain and the integration proof.

Edits Strapi source? Yes (dev servers stopped). Changes the specification? Yes. Runs Playwright? No.
</objective>

## Recorded planning decisions

- **Query (`parseMyRisksQuery`, closed).** `show` (`needs-you` | `open` | `closed`, default `open`), `part` (one of `RISK_PARTS`), `status` (`Not Started` | `In Progress` | `Overdue` | `Complete` | `not-tracked`), `dueState` (`overdue` | `due-soon` | `later` | `no-target-date`), `stage` (`under-assessment` | `released`), `assessment` (documentId; the participant page's "Track this risk" read), `q` (1–200, number or statement), `sort` (`needs-you` default, `risk`, `residual-rating`, `resolve-by`, `review-by`, each `:asc` or `:desc`; `resolve-by` empty last), `page`, `pageSize` (`MY_RISKS_PAGE_SIZE = 25`, `MY_RISKS_PAGE_SIZE_MAX = 100`); anything else 400.
- **Population.** Released: `applyRiskPersonPredicate(query, viewer)`, withdrawn excluded. Before release: risks of assessments whose gate is open (17's participant SQL) where the viewer is `riskOwner` or `executiveApprover`, with 17.1's `acceptanceState` naming the act awaiting them. A viewer never sees a risk they hold no part on.
- **Item.** `MyRiskItem = { id, riskNumber, riskStatement, parts, residualRating, stage, closed, tracking: { applicable, status, progress, dueState, resolveDate } | null, treatmentOwner: { documentId, displayName, isViewer } | null, decisionReview: { date, state } | null, nextStep, assessment: { id, assessmentNumber }, destination }`; `nextStep` ∈ `decide`, `approve`, `decide-again`, `update-treatment`, `review-acceptance`, `renew-exception`, or null; `destination` ∈ `owner-page` (released), `decision-view` (before release). The server words nothing in prose; the web labels.
- **Needs you and summary.** `needs-you` = pending decision acts for the viewer (before release) ∪ tracked treatments the viewer owns as treatment owner with due state `overdue` or `due-soon` ∪ reviews where the viewer is an allowed reviewer and the state is `due-soon`, `due` or `overdue`. `summariseMyRisks` → `{ needsYou, overdueTreatments, dueSoonTreatments, reviewsDue }` with `needsYou = overdueTreatments + dueSoonTreatments + reviewsDue` (decisions stay on "My risk assessments", D-20).
- **Owner read (`readOwnerRisk`).** Order: `loadRiskPeople` (missing or unreadable → 404); unreleased → 409 `RISK_NOT_RELEASED`; no part → 403 `NOT_RISK_PERSON`; else `OwnerRiskDetail = { id, riskNumber, assessment: { id, assessmentNumber }, request: { title }, parts, risk: <the participant risk projection with the decision block, override reasons and control implementations (control, owner, status, due date, implemented on)>, tracking: TreatmentTracking, notes: ProgressNote[] (oldest first, at most 200), decisionReview: { date, state, outcome, opensOn, reviewer: { required, person: { documentId, displayName } | null }, intervalMonths, lastConfirmation, earlier[] } | null, residualReview: { reviewedBy, reviewedAt, rationale } | null, closure: { closedOn, closedBy, reason } | null, allowedActs }`. `projectTrackingFacts` and `projectDecisionReview` are exported for 20-10's register detail.
- **History (`readOwnerRiskHistory`).** The same order of refusals; `readRiskHistory` gains an option `postReleaseOnly: true` returning the `release-baseline` row and later rows whose source is `post-release` or `scheduled-run`, newest first, Phase 16's pagination; each actor `{ documentId, displayName }` when the viewer's own read shows that person (participants and the risk's people), else null with `actorPart`; `scheduled-run` rows read `actor: null, sourceKind: "scheduled-run"`.
- **Export.** `export-views.ts` gains view `my-risks` over `listMyRisks`'s query (all pages, Phase 19's 10,000-row cap and formats), columns: risk number, statement, your part, residual rating, treatment status, progress, resolve by, due state, treatment owner, review by, review state, assessment number, stage.
- **Routes** (`routes/my-risks.ts`; summary and export before the id route): `GET /v1/my_risks` → `api::csrm-risk.my-risks.list`; `GET /v1/my_risks/summary` → `summary`; `GET /v1/my_risks/export` → `export`; `GET /v1/my_risks/:riskId` → `findOne`; `GET /v1/my_risks/:riskId/history` → `history`.
- **Contract.** Spec tag `my-risks`; operationIds `my-risks/list`, `/summary`, `/export`, `/find-one`, `/history`; components `MyRiskItem`, `MyRisksListResponse`, `MyRisksSummaryResponse`, `OwnerRiskDetail`, `OwnerRiskDetailResponse`, `OwnerRiskHistoryResponse` (reusing 16's history event schema with `actorPart`). Catalogue `function.risk_register.my_risks_api` per 20-01 (`.api.01` `List My Risks and Treatments`, `.api.02` `My Risks and Treatments Summary`, `.api.03` `Export My Risks and Treatments`, `.api.04` `Get My Risk`, `.api.05` `Get My Risk History`).
