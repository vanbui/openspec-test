**Known infrastructure facts.**
1. **Shared `dist`.** The orchestrator's dev Strapi (1337) and Next (3000) run during planning. Everything that compiles Strapi shares `apps/backend/dist` and `apps/backend/.tmp/tests-dist`: the Strapi suite, a single Strapi file, `served-operations:write` and Playwright. All of these wait until the servers are stopped, and after wave 1 the plans run one at a time (D-39). A task executed while the servers run records those proofs as pending for the plan's end.
2. **No live AI.** Every suite pins `CSRM_AI_PROVIDER=deterministic`. From plan 12-02, both harnesses (`apps/backend/tests/helpers/strapi-http-harness.ts` and Playwright's Strapi `webServer` env) also pin `CSRM_AI_DATA_CLASSIFICATION_CEILING=''` (D-31). No proof calls a model. The hosted provider is exercised only by the operator's manual check.
3. **Environment for the policy.** Both harnesses run Strapi with `NODE_ENV=development` and `CSRM_ENVIRONMENT=development`, so an unset ceiling means no ceiling. Refusal proofs set the ceiling in their own harness boot (`ai-data-policy.integration.test.ts`), or test the pure policy module with injected configuration. `apps/backend/.env.example` documents the ceiling with its owner, the deployment administrator (12-02).
4. **Jobs are process-local** (R-08-36). No E2E relies on a job outliving a restart. Interrupted-run reconciliation is proved in Strapi integration by booting with a `running` run seeded in the database.
5. **Generated files.** `apps/csrm/next-env.d.ts` is untracked and ignored.
6. **Windows vitest** can fail with `EPERM: rename`. Rerun that file alone before treating it as a real failure.
7. **Fixtures (the 06.9 lesson).** The new journey creates its own UAT-A-like request, systems and assets through the UI or its own seed. The one-shot release fixture ("Customer portal security assessment") keeps serving the existing release journey.
8. **The base changes first.** Phase 10 (plans 10-05 to 10-23) and Phase 11 execute before Phase 12 and change the files this phase edits. Re-run the plan check before executing.

## Sampling Rate

- **After every task commit:**
  - run the touched web test files by path;
  - run `typecheck` when types change, and `api:check` after any spec change;
  - run the touched Strapi files by path, dev servers stopped.
- **After every plan wave:**
  - run the full web suite, `typecheck` and `api:check`;
  - run the full Strapi suite after every plan that edits Strapi: 12-02 to 12-14 and 12-16;
  - run each plan's targeted Playwright specs once at its end: 12-06, 12-14, 12-15, 12-16, 12-17 and 12-18; 12-19 runs the whole suite. These plans run one at a time (waves 5 and 13 to 18).
- **Before `/gsd-verify-work`:** the full suite must be green. That is the phase gate above (plan 12-19), recorded with counts, duration, the flaky count and the clean tree.
- **Max feedback latency:** 90 seconds for a task-level quick run. The tasks that close a Strapi change run the full Strapi suite, and the production-build E2E runs only at plan level.
