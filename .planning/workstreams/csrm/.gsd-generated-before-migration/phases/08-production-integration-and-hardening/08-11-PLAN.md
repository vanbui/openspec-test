## Recorded planning decisions

- **Mechanism (planner's discretion, D-14, research §F5.3):** two projects in `playwright.config.ts`: `desktop` (`devices['Desktop Chrome']`, viewport `1440×900`) runs every spec; `mobile` (`viewport 375×812`, `hasTouch: true`, `isMobile: false` to keep Chromium's layout engine predictable) runs only tests whose title contains `@journey` in the four re-runnable files (`testMatch` on the four files plus `grep: /@journey/`), so the mobile project costs four tests rather than the files' other tests. `workers: 1` and `fullyParallel: false` stay; projects run desktop first (Pitfall 10).
- **Primary width comes from the project:** each `@journey` test reads `test.info().project.use.viewport` for its starting width instead of a hard-coded `setViewportSize(375)`, keeps its deliberate sweeps (reversal dialogs at both widths, the register geometry loop, the import overflow loop), and uses width-aware helpers: `openFromNavigation` (sidebar link when visible, else the `Menu` sheet), card-list locators below 768 (`getByRole('list', { name })` / `listitem` and `article`) versus table rows and sort buttons at or above 768, and the `Filters (n)` sheet below 768 versus `More filters`.
- **Sorting in the Risk Register at 375 is exercised through the URL** (`?sort=targetDate:desc` then `:asc`) because the card list has no sort headers; the order assertion on `visibleRiskNumbers` reads the cards' links.
- **The CSV suffix is `dylan-test-${process.pid}-${test.info().project.name}`**, computed inside the test, so the second project's preview still reads Create 1 / Update 1 / Unchanged 1 (Pitfall 5).
- **Journeys 2 and 3 are not made self-seeding**: the in-spec checkpoints are the cheaper D-41 choice and are recorded in VERIFICATION as "both widths in one pass because the fixtures are one-shot".
