Move the Playwright suite from `next dev` to a production Next build and make that build sign in only inside the attested E2E runtime, while a test run stops modifying tracked files and the accessibility sweep stops scanning mid-navigation. This is research plan P02 (research wave 0): the production-build E2E is the vehicle for the later header, CSP, journey and performance proofs, and D-12 must hold from here on.

Edits Strapi source? No. Runs Playwright? Yes: one full run at the end (Task 4), dev servers stopped, to prove the build, the clean tree and to measure the build time and suite duration (D-46, D-51 Open Question 1).

Purpose: INT-04 verification on the real production artefact, fail-closed development sign-in (T-08-R02, R03), and a harness that no longer needs a restore step.
Output: the attestation and runtime-resolver modules with unit tests, fail-closed session adapters and the sign-in unavailable card, the transport gate, the build-then-start webServer with a `desktop` project, `tsconfig.e2e.json`, the cleaned `tsconfig.json`, the untracked `next-env.d.ts`, the `next typegen` typecheck script, the settle helper, and the unattested-server proof in `e2e/production-hardening.spec.ts`.

## Recorded planning decisions

- **D-12 mechanism (planner's discretion, confirmed by research §F2.1-§F2.3 against the installed Next 16.3.3 source and docs):** `writeConfigurationDefaults` returns before writing when the configured tsconfig has an `extends` key, and `writeAppTypeDeclarations` rewrites `next-env.d.ts` whenever the dist directory changes, so the rewrite is stopped by configuration (`tsconfigPath` → a tracked `tsconfig.e2e.json` that extends the base) and by untracking `next-env.d.ts`, exactly as `apps/web/node_modules/next/dist/docs/01-app/03-api-reference/06-cli/next.md` ("`next typegen` options") and `.../05-config/01-next-config-js/typescript.md` ("`tsconfigPath`") describe. Restoring files after a run was rejected: it hides regressions and contradicts "stopped at the source".
- **The attestation module is extracted, not duplicated.** `isAttestedE2eRuntime(env)` moves the root/path/nonce/age body out of `e2e-ui-state.ts` into `src/lib/testing/e2e-runtime-attestation.ts`; `e2e-ui-state.ts` composes it with the `CSRM_E2E_UI_STATE_HARNESS === '1'` check, which stays a fixture-state concern only (research §F2.5, Pattern 1).
- **Only the `desktop` Playwright project is declared here** (`devices['Desktop Chrome']`, viewport unchanged), so every existing spec runs exactly as today under the production build. The `mobile` project and the 1440 viewport arrive with the journeys in plan 08-11.
- **`/sign-in` stays the web readiness URL.** With the attested gate it returns 200; without it Playwright's readiness check (status 200-403) would wait the whole timeout, so the first test in `production-hardening.spec.ts` asserts `GET /sign-in` is 200 with a message naming the gate (research Pitfall 1).
- **The unattested proof spawns `next start` of the same build** on a spare port (`48_000 + process.pid % 10_000`) with `CSRM_NEXT_DIST_DIR` set to the run's dist directory, `CSRM_ENVIRONMENT=development` and `CSRM_DEV_IDENTITY=true` present but no `CSRM_E2E_RUNTIME_*` variables, so the attestation gate alone is proven to fail closed. The config exposes `process.env.CSRM_E2E_NEXT_DIST_DIR ??= isolatedNextDistDir` and `process.env.CSRM_E2E_DEVELOPMENT_API_TOKEN ??= developmentApiToken` for specs, the way it exposes the origins.
- **Sign-in page tests live under `src/`** (`src/lib/auth/sign-in-page.test.tsx` importing `../../../app/sign-in/page`), because `vitest.config.ts` includes only `src/**/*.test.{ts,tsx}`; the alerts page test uses the same relative import pattern.
- **File count accepted under D-49 (plan check, 2026-09-25):** the plan lists 24 files across four tasks, above the 15-file guideline, because its edits are mechanical multi-site changes of one kind (the resolver wired through every session gate, the harness configuration files, and the settle helper's call sites) and the executor runs with a large context; it is not split, and one owner per file per wave still holds.
