## Recorded planning decisions

- **Measurement method (planner's discretion, D-24, research §F7.1 and the "Bundle-size table" row of the pattern table):** browser network accounting on the production build is the primary method and the analyzer is corroboration. Reason: `next build` no longer prints per-route sizes (research, Next 16.0.0 note), the analyzer's data files are undocumented (research A7), and network accounting measures exactly what a browser downloads.
- **The HTTP cache is disabled through CDP for the measured page** (`Network.setCacheDisabled`). Reason: a measured navigation follows a sign-in landing on `/app` that already fetched the shared chunks, and `request.sizes()` reports zero bytes for a cache hit, so without this the shared chunks would be silently excluded. The spec header says so, and a completeness self-check compares the document's `/_next/static/` script sources with the accounted responses.
- **Sizes recorded:** `responseBodySize` from `request.sizes()` is the delivered (encoded) size, which is gzip because `next start` compresses by default; the decoded size is `(await response.body()).byteLength`. Both are recorded; the budgets apply to the delivered size, matching the research's "gzip" ceiling.
- **Budgets:** the research ceilings are the initial budgets: delivered JavaScript ≤ 300,000 bytes per route, TTFB ≤ 500 ms, LCP ≤ 2,500 ms (research A8: record, then tune). A route whose median exceeds a ceiling after the first run is investigated: a real defect is fixed at its source and recorded; an inherent cost gets a route-specific override at 1.5 × the measured median, rounded up to the nearest 10,000 bytes or 50 ms, with a one-line reason next to it and in the record. No budget is loosened without a written reason.
- **Shape of the spec:** one `test` per route, the `desktop` project only (the file is outside the mobile project's `testMatch`, so it never runs twice), a fresh browser context per sample, five samples, medians through the pure module.
- **The analyzer writes to `apps/web/.next/diagnostics/analyze`**, not under `apps/web/.tmp/`: `build/analyze/index.js` hard-codes `distDir = join(dir, '.next')`, so `CSRM_NEXT_DIST_DIR` has no effect on it (a correction to the research's placement). `.next/` is ignored by `.gitignore`. The dev servers must be stopped because `.next` is also where `next dev` writes.
- **LCP is the buffered candidate at settle time**, recorded through a `PerformanceObserver` registered by `addInitScript`; the record says "candidate" because the browser finalises LCP only on interaction or hide.
