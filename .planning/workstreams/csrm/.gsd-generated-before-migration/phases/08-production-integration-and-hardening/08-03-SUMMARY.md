### D-38: `GET /api/roles`, as observed

The collision the research anticipated does not exist on this Strapi. The users-permissions plugin's role routes carry no `config.prefix`, so they mount under `/api/users-permissions/roles`, `/api/users-permissions/roles/:id`, `/api/users-permissions/roles/:role`; only its `auth.*` and `user.*` routes (`config.prefix: ''`) mount at `/api/auth/*` and `/api/users*`. Before D-36 `GET /api/roles` had exactly one koa layer, `api::role.role.find`, which answered **200 with the IdamBox roles** to the full-access token plus the analyst identity (`data[]` with `documentId`). After D-36 the path has no layer and answers **404**. The inventory records this under `probes`; `collisions` (any path and method with more than one koa layer) is empty before and after, and the inventory test asserts it stays so. The koa stack (140 route layers) was also matched one-to-one, in registration order, against the route registries.

### The unmounted bases, as observed after D-36 and D-44

For `/api/idambox-users`, `/api/roles`, `/api/functions`, `/api/function-apis`, `/api/applications`, `/api/csrm-information-systems` and `/api/csrm-information-assets`, with the token and the analyst identity: `GET` **404**; `POST`, `PUT /{id}`, `DELETE /{id}` **405 with `Allow: HEAD, GET`**; `OPTIONS` 200. `/api/does-not-exist` answers identically, so an unmounted base is indistinguishable from a path that never existed (the 405 is koa's generic `allowedMethods` answer under Strapi's default middleware stack, not a surviving route). Without the token, `GET /api/idambox-users` answers 404 where it answered 403. `POST /api/v1/information_systems/selected` still answers 200 for the owner.

### D-37: the registration probe

Anonymous `POST /api/auth/local/register` with `{ username, email, password }`: **200 and a new users-permissions account before** (`0d15f0f` RED log), **400 and no account after** (`allow_register: false` read back from the `advanced` store; the account count is unchanged). `POST /api/auth/local` and `GET /api/users/me` stay mounted by the plugin and are recorded as the accepted residual; plan 08-05's no-identity actor probes them.

## Decisions Made

- **The `/api/roles` record is a `probes` entry, and `collisions` stays truthful.** The plan's Task 1 acceptance criterion expected one two-layer `collisions` entry; the mounted server shows one layer (see D-38 above). Fabricating a second layer would have falsified the inventory, so the D-38 record lives under a dedicated top-level key with the same row shape (`method`, `path`, `layers`, `observedResponder`), and the inventory test asserts the probe's layers and status directly.
- **Mutations on an unmounted base are 404 or 405.** My first RED expectation in `contract-catalogue` demanded 404 for every method; the probe of `/api/does-not-exist` showed koa's generic 405 with `Allow: HEAD, GET`, so the GREEN commit corrected that one expectation to the plan's own wording. The inventory test had accepted 404 or 405 from the start.
- **The harness gained `countUsersPermissionsUsers()`** beyond the two accessors the plan named, so "creates no users-permissions user" is proven by an account count rather than inferred from a failed login.
- **`specOnly` reasons are derived by rule** (generic core CRUD; IAM D-36; mounted by a plugin at the documented path; documented as a plugin operation this Strapi mounts under the plugin's prefix), and an operation matching no rule fails `SPEC_ONLY_WITHOUT_REASON`; likewise every allow-list is pruned by a stale-entry assertion.
- **`authStrategies: null`** records a route that relies on Strapi's default content-API strategies (51 of the 103 routes before D-36, 26 of the 76 after: the questionnaire and core assessment-request routes), `["content-api-token"]` a route restricted to the API token; no route has `auth: false` (`PUBLIC_ROUTE` never fired).
- **Targeted web runs use `pnpm --filter @csrm/web exec vitest run <pattern>`**, as 08-02 recorded; the plan's `test -- <pattern>` form runs the whole suite.
- **INT-01 stays unchecked** (see key decisions).
