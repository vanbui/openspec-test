# Phase 06.3 MVP Goal Validation

**Validated:** 2026-09-07
**Phase:** 06.3 — Correctness, Search, and Selection
**Authoritative source:** `.planning/ROADMAP.md`, Phase 06.3 `**Goal:**` line

## Authoritative goal

> As a signed-in CSRM user, I want to see my records, open entitled released assessments, and search lists and pickers within my authorised scope, so that I can work accurately as data volumes grow.

The goal above is the Roadmap value, not a phase-local substitute.

## Reproducible validation

Extract the goal from the Roadmap, then run the centralized validator against that extracted value:

```powershell
$goalLine = (Select-String -Path .planning/ROADMAP.md -Pattern '^\*\*Goal:\*\*' | Where-Object { $_.LineNumber -gt 282 } | Select-Object -First 1).Line
$goal = $goalLine -replace '^\*\*Goal:\*\*\s*', ''
gsd_run query user-story.validate --story "$goal"
```

Result:

```json
{
  "valid": true,
  "errors": [],
  "slots": {
    "role": "signed-in CSRM user",
    "capability": "see my records, open entitled released assessments, and search lists and pickers within my authorised scope",
    "outcome": "I can work accurately as data volumes grow"
  }
}
```

The authoritative goal is explicitly validator-accepted (`"valid": true`). The validator supplied no date or version.

## Plan correction

Plan 06.3-10 named a literal candidate beginning `I want my records`, but the
centralized validator requires the canonical `I want to [capability]` form and
rejected that candidate. With operator approval, the authoritative Roadmap uses
the validator-compatible `I want to see ...` wording above. This is a Rule 3
blocking-plan correction: it preserves the approved UX-01 through UX-03 scope
and does not introduce any implementation or product-scope change.

## UX requirement traceability

| Requirement | Goal clause | Covered outcome |
| --- | --- | --- |
| UX-01 | “see my records” and “within my authorised scope” | Every actor’s My Requests, My Questionnaires, and My Risk Assessments remain owner-scoped. |
| UX-02 | “search lists and pickers within my authorised scope” | Information System, Information Asset, and Risk-owner selection remains bounded and server-backed. |
| UX-03 | “open entitled released assessments” and “search lists and pickers” | Released assessments open for an authorised owner; collection search and status filtering remain server-authoritative. |

## Scope fence

This validation records UX-01 through UX-03 only. It does not extend Phase 06.3 into Phase 06.4 cross-record navigation, assessment risk-count tiles, release-readiness wording, or interface consistency. It does not change source, state, UI, API, authorization, actor roles, CSRM data-model terminology, AI advisory-only release authority, plans 01–06, or completed summaries. The accepted story preserves the phase decisions: owner scoping (D-01), bounded server-backed selection (D-02), server-side search/filtering (D-03), and diagnosable released-assessment reads with schema parity (D-04).
