# Phase 06.6 Context: Cross-Surface UI Consistency

This phase fixes defects that exist only when two surfaces are compared. Each list
screen renders correctly on its own; the same kind of thing is presented differently
from one screen to the next. The ROADMAP scope decisions (operator-confirmed
2026-09-10) stand; the decisions below make them implementable and are locked.

`docs/design/csrm-design-direction.md` remains the sole design authority (06.5 D-01).
This phase does not create a UI-SPEC: a second document restating design values is
the defect 06.5 removed. Where a decision below changes a design rule, the change is
made **in the design direction document** and referenced from here.

Source findings: `.planning/APP-UI-REVIEW.md` §3.1, §3.2, §3.3, §3.6, §3.7 (§3.4 and
§3.5 are retracted or already resolved by 06.5 and are out of scope).

## D-01 — One record-link treatment, visible at rest

A record link is any link whose text is a record identifier or title and whose target
is that record (list cells, mobile cards, dashboard lists, related-record and back
links on detail pages). Buttons rendered as links for actions ("Clear filters",
"Try again") are **not** record links and keep `variant="link"`.

- Add one shared component, `src/components/csrm/record-link.tsx` (`RecordLink`),
  wrapping `next/link`. Every record link in scope renders through it; no feature
  file styles a record link itself.
- Treatment: colour `--text-link`; weight 500; underline **at rest** with a quieter
  decoration colour from a new token `--text-link-decoration` (the link accent at 40%
  alpha, defined in `globals.css` and in the design direction §3.2); 1px thickness;
  offset 3px. On hover and `:focus-visible` the decoration becomes the full link
  colour and the text moves to `--primary-hover`. Transition colour and
  decoration-colour only, `--duration-micro` with `--ease-standard`.
- Rationale, to be recorded in design direction §3.2 and a new §4 "Record links"
  subsection: the link colour is 3.3:1 against `--foreground`, and the at-rest
  underline adds a non-colour cue, so the affordance survives touch (no hover) and
  WCAG 1.4.1 without relying on colour. The current "underline on hover" wording in
  §3.2 is superseded.
- Size follows the context it sits in (table cells use the table size token, cards
  and prose use body). Size is not part of the link contract; colour, weight and
  decoration are.

## D-02 — One layout per record type at a given breakpoint

- Every list surface in the table above renders through `DataTable`: a table at
  `md` and wider, the DataTable card list below `md`. This includes
  `questionnaire-list.tsx`, `questionnaire-review-list.tsx`, the released assessment
  list, and both lists in `assessment-list.tsx` (the assessment-list `DataTable`
  migration carried over from 06.5).
- The first column is always the record identifier, rendered as a `RecordLink`.
  Keep each surface's existing fields; do not fetch new data or change any service
  contract.
- `DataTable` may be extended, never forked. Permitted, backwards-compatible
  extensions: make `onSortingChange`, `onPageSizeChange`, and `filters` optional
  (no sort affordance, no rows-per-page control, or no chip row when the surface's
  server contract does not support them), and add `stickyFirstColumn` (D-04). The
  surfaces keep their existing URL-driven search and status controls; DataTable
  callbacks navigate the same URL state those controls already use.
- Loading on migrated surfaces uses the DataTable skeleton (it mirrors the final
  layout), replacing the bespoke skeletons.
- The two structural assertions in `assessment-review-workflow.test.tsx` that bind
  to the old testids and responsive classes are updated deliberately to the
  DataTable structure, not deleted.

## D-03 — Feature components render states through the shared primitives

- Extend `src/components/states/states.tsx` rather than creating new state
  components. The primitives own structure, typography, icon, and the copy
  template; a surface supplies only the record noun and whether filters are active.
  - `EmptyState({ noun, filtered, onClearFilters | clearFiltersHref })`:
    first-use "No {noun} yet" with the surface's single next action if one exists;
    filtered "No {noun} match these filters" with a "Clear filters" action (never a
    dead end, per design direction §4 Empty states).
  - `ErrorState({ noun, retry })`: "We couldn't load {noun}" with "Try again".
  - `PermissionDeniedState({ area })`.
  - An optional `description` is allowed **only** where a domain fact must be
    stated (for example, that assessments appear here after an analyst releases
    them); each such use is listed in the plan that introduces it.
  - Called with no props, each primitive keeps its current copy, so route-level
    uses and their tests are unaffected.
- State headings render at `--text-heading-sm` (16px/24px/600/-0.01em) with a
  configurable heading level so the page outline stays correct. The off-contract
  `text-lg` (18px) state headings in `request-table.tsx`, `assessment-list.tsx`,
  `questionnaire-review-list.tsx` and the administration states disappear with
  the migration.
- Each primitive carries a quiet 20px icon above the heading (empty: inbox; error:
  alert, in the danger foreground; permission: lock), `aria-hidden`, with meaning
  carried entirely by the text. The primitives expose a stable `data-slot="state"`
  plus `data-state-kind` for the harness.
- End state: no file under `src/features/` hand-rolls an empty, error,
  permission, or loading block. Add a static guard test that fails if one does
  (the planner chooses the detection rule; it must catch a hand-rolled block
  reintroduced in any feature file).

## D-04 — Risk Register keeps row identity while scrolling

- `DataTable` gains `stickyFirstColumn`. When set, the first header and body cell
  are `position: sticky; left: 0`, keep the row's background in every row state
  (rest, hover, selected), and carry a 1px `--border` right hairline. No shadow.
- The desktop scroll container becomes a labelled, keyboard-scrollable region:
  `role="region"`, an `aria-label` naming the table and that it scrolls
  horizontally, `tabIndex={0}`, and the standard focus ring. This satisfies the
  "deliberate, labelled table scroll container" requirement in `01-UI-SPEC.md:58`,
  which the review did not verify.
- Only the Risk Register sets `stickyFirstColumn` in this phase. The statement
  column stays line-clamped to two lines so eight columns remain usable at 1440px.

## D-05 — No disabled control is an anchor

- All list pagination moves to the DataTable footer, whose Previous/Next are
  `<button disabled>`. `questionnaire-pagination.tsx` is retired by D-02.
- The shadcn `PaginationPrevious`/`PaginationNext` anchors must not be used to
  represent a disabled state anywhere. If any non-DataTable pagination remains,
  its disabled Previous/Next render as `<button disabled>`.

## D-06 — Heading tracking is implemented

- Define the heading and display type tokens from design direction §3.10 in the
  Tailwind v4 `@theme` block with their line-height and letter-spacing
  sub-values, so a single utility carries size, line-height, and tracking
  together: heading-sm -0.01em, heading-md -0.015em, heading-lg -0.02em,
  display -0.02em.
- Replace ad hoc heading classes (`text-2xl font-semibold`, `text-xl`, `text-lg`
  and similar on headings) in `src/` with the token utilities. Existing CSS classes
  that already set tracking keep working.
- Widen the 06.5 conformance assertion from the uppercase micro token to every
  token that specifies tracking.

## D-07 — The regression harness is comparative

`apps/web/e2e/design-contract.spec.ts` is part of the deliverable. It runs inside the
existing isolated Playwright harness (per-run ports and SQLite, attested fixture
states) and asserts, at 375px and 1440px:

1. Record links on every list surface resolve to the same computed colour,
   font-weight, text-decoration-line, and text-decoration-color at rest. Surfaces
   are compared **against each other** (the first surface is the reference), then
   the reference is checked against the token read from the document root.
2. At 1440px every list surface shows the DataTable table and no card list; at
   375px every surface shows cards.
3. Every fixture-driven empty, error, and permission state on every list surface
   renders through `data-slot="state"`, and their headings share one computed
   font-size, weight, line-height, and letter-spacing.
4. With the Risk Register scroll region scrolled fully right, the first-column
   cell of every visible row is still within the region's visible bounds. The
   region is focusable and labelled.
5. No `a[aria-disabled]` and no `a[href="#"]` exists on any list surface.
6. Phase 06.5's type and casing contract, including heading letter-spacing from
   D-06.

The suite must fail when any one surface regresses. Prove that during execution by
temporarily breaking one surface and recording the failure in the plan summary,
then reverting.

## Constraints

- No Strapi changes are expected. Content-type schemas are frozen; do not change
  service contracts, authorization, or the typed service layer.
- Server authorization stays authoritative; presentation changes must not reorder
  a capability check after a data read (06.5 D-fixture rules still apply).
- Semantic tokens only; WCAG 2.2 AA; no horizontal page overflow at 375px; axe
  clean; no console errors.
- Unit tests that assert exact state copy or DOM structure are updated
  deliberately, with the reason in the commit message.
