## Phase Goal

**As a** Security Analyst, **I want to** pick up a request and exchange notes with the Requestor on it, **so that** ownership is clear and new information has a home at any point.

This plan's slice: on the request page, an analyst picks up, assigns, reassigns or returns a request with one click and an Undo, sees who holds it and its history, and both actors read who holds it on the hub.

<objective>
Build the X-15 assignee control on the analyst's request page: the Assignment section with its states, optimistic actions, Undo toasts, rollback and focus (D-05, D-16; UI-SPEC §5.2, §7), the picker with a kept reason (D-06; UI-SPEC §6, UI-D31), and the history (D-09; §5.3); relabel the hub for both actors (D-16, D-17; §5.1); and extend the pick-up journey.

Purpose: success criterion 1 begins on the request page; REQ-08 criterion 1 in the UI.
Output: four client components, one session store, hub rows, journey steps at both widths.

Edits Strapi source? No. Changes the specification? No. Runs Playwright? Yes.
</objective>
