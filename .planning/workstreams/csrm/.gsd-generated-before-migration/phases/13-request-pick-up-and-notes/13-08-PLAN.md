## Phase Goal

**As a** Security Analyst, **I want to** pick up a request and exchange notes with the Requestor on it, **so that** ownership is clear and new information has a home at any point.

This plan's slice: every Security Analyst on a request can follow and retry its generation jobs and sees who started them, so handing a request to a colleague never strands its work.

Purpose: REQ-08 criterion 3 and success criterion 2's second half; UAT-014's job-visibility half and UAT-041.
Output: widened access end to end, two cards, one register line, one new spec.

</objective>

## Recorded planning decisions

- **Access.** The questionnaire workflow's `actor()` and the draft workflow's `draftActor()` take `{ documentId, humanAnalyst }` from the controller (`ctx.state.idamboxUser.documentId`, `ctx.state.csrmAuthorization.humanAnalyst`) and pass `canReadAllQuestionnaireGenerationJobs` and `canReadAllDraftJobs` equal to `humanAnalyst`, never a constant, so a later route reusing a workflow cannot widen by accident.
- **canRetry.** In `latestForRequest` and `latestForQuestionnaire`, `canRetry = job.status === "failed" && viewerMayRetry` with `viewerMayRetry` the `humanAnalyst` fact. Both job components gain `canRetry: boolean` (the same rule on the by-id reads), `initiatedBy: ActiveUserSummary | null` and `initiatedByViewer: boolean`; the generation-jobs read's wrapper `canRetry` keeps the same value for 10-13's parser.
- **Attribution.** Both registries' `retry(jobId, actor)` set `job.initiatingAnalystDocumentId = actor.documentId` before `launch`, so `execute` writes the retrier as `generatedBy` and Phase 12's new run names them as `initiatedBy`.
- **Name.** The controllers resolve the initiator with `resolvePeople` (13-03) at projection time, one bounded read per response; the registry keeps only the documentId.
- **Bounds.** `jobId` path parameters on `/v1/questionnaire_generation_jobs/{jobId}`, its retry, `/v1/assessment_draft_jobs/{jobId}` and its retry declare `minLength: 1, maxLength: 255`, as do the response `jobId` fields (the server's `nonBlank` and the web's `documentIdSchema`); the parity guard's `narrowedPaths` entries citing "Phase 13" are deleted.
- **Catalogue.** In both copies: `Returns an initiating analyst's retained questionnaire generation job.` becomes `Returns a retained questionnaire generation job.`, and `Retries an initiating analyst's failed questionnaire generation job.` becomes `Retries a failed questionnaire generation job.`; the draft job FunctionAPIs' descriptions lose the same words if 12-10 left them. No `roleIds` change.
- **Cards** (UI-SPEC §13): `Started by {name}.` replaces `Started by another Security Analyst.` whenever `initiatedByViewer` is false (queued, running or failed); a failed job offers `Retry questionnaire generation` or `Retry draft generation` whenever `canRetry` is true; `Only the Security Analyst who started it can retry it.` is removed; after the viewer's own retry the card shows no `Started by` line. Polling and the `Attempt {n}` tag are unchanged.
- **Register.** R-08-36's row gains: `Phase 13 widened job access to every human Security Analyst who may read the request; storage unchanged (D-19).` Its trigger column is unchanged.
- **E2E.** New `apps/csrm/e2e/request-pick-up.spec.ts` (`@journey`), the spec later plans extend: test `REQ08_COLLEAGUE_FOLLOWS_JOB`.
