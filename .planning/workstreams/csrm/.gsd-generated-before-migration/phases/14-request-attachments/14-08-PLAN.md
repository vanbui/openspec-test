## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: Jane removes a file she added by mistake and restores it, Bob removes a file after submission, and each removal is on the record with who and when. The request itself says how many files it holds and whether this viewer may add one now, and a request holding files cannot be deleted.

<objective>
Serve `PUT /api/v1/assessment_requests/{requestId}/attachments/{attachmentId}/removal` with soft, recorded removal and restore and their actor rules (D-19 to D-21), add the viewer's attachment summary to the request read (D-04 item 7) and the `REQUEST_HAS_ATTACHMENTS` refusal on the request delete (D-04 item 11), with the grant, contract, matrix and inventory (D-03, D-38) and the web's parsers.

Purpose: COLLAB-02 criterion 4 and ROADMAP success criterion 4 at the API; the figures the request pages show.
Output: one operation end to end to the typed service, one read block, one refusal on an existing operation.

Edits Strapi source? Yes. Changes the specification? Yes. Runs Playwright? No. Regenerates `served-operations.json`? Yes.
Scope note: 18 files: six Strapi sources (the removal operation's five API files and the request controller's read block and delete refusal); five the contract chain; three the Strapi proofs (the matrix rows, the rules unit test and the integration test); four the web's attachment schema and service, the request schema and the parity guard. ## Recorded planning decisions

- **Operation**: `CSRM_REQUEST_ATTACHMENT_OPERATIONS.setRemoval = "PUT:/api/v1/assessment_requests/{requestId}/attachments/{attachmentId}/removal"`; route `PUT /v1/assessment_requests/:requestId/attachments/:attachmentId/removal`, handler `setRemoval`; body `{ data: { removed: boolean } }` with exact keys (else 400); 200 `{ data: RequestAttachment }`.
- **Rules** (`attachment-rules.ts`): `canRemoveAttachment({ request, caller, attachment })` → `null | reason`: window `closed` → `ATTACHMENTS_CLOSED`; window `intake` and the caller is not the requestor → `REQUEST_NOT_SUBMITTED`; the caller is the uploader → allowed; the caller is a human analyst who is not the requestor and the window is `after-submission` → allowed; otherwise `NOT_UPLOADER`. `canRestoreAttachment` → `ATTACHMENTS_CLOSED`, `REQUEST_NOT_SUBMITTED` as above, then `NOT_REMOVER` unless `removedBy` is the caller, then `ATTACHMENT_BLOCKED` for a blocked file, then `ATTACHMENT_LIMIT_REACHED` when restoring would exceed 20 active. Removing an already removed file, or restoring one that is not removed, returns the current projection and writes nothing.
- **Service** `setRequestAttachmentRemoval({ strapi, request, caller, attachmentId, removed })` under `withRequestLock`: re-reads the record (it must belong to the request, else 404), applies the rule, then sets `removedAt` and `removedBy` (remove) or clears both (restore); on remove of an included file also sets `aiTextIncluded: false` and `aiText: null` and appends `ai-excluded`; appends `removed` or `restored` (a full or malformed log → 409 `HISTORY_UNAVAILABLE`, nothing written); logs `attachment.removed` or `attachment.restored` (and `attachment.ai_inclusion_changed` with `from: true, to: false` when inclusion ended). The bytes and the plugin file record are never touched.
- **Request read** (`findOne`): when the request loads and `canUseRequestNotes` holds for the caller, `data.attachments = requestAttachmentSummary(...)` = `{ count, ...projectAddFacts(...) }` (`count` = files not removed); otherwise no `attachments` key. Spec: `ApiCsrmAssessmentRequestCsrmAssessmentRequestDocument` gains optional `attachments: RequestAttachmentSummary` (closed; `count` plus `RequestAttachmentAddFacts`'s fields).
- **Delete**: the core `delete` counts every attachment of the request with `strapi.db.query` and refuses with 409 `REQUEST_HAS_ATTACHMENTS` (after 13-06's `REQUEST_HAS_NOTES` check).
- **Catalogue**: `function.risk_assessment_requests.attachments_api.api.04` `Set Assessment Request Attachment Removal`.
- **Spec**: path `/v1/assessment_requests/{requestId}/attachments/{attachmentId}/removal` `put`, operationId `assessment-workflow/set-request-attachment-removal`, request `RequestAttachmentRemovalRequest` (closed), responses 200 `RequestAttachmentResponse`, 400, 403, 404, 409.
- **Web**: `attachments-schema.ts` adds the removal request and reuses `requestAttachmentResponseSchema`; `attachments-service.ts` adds `setRequestAttachmentRemoval(requestId, attachmentId, removed)`; `request-schema.ts` parses the optional `attachments` summary (closed).
