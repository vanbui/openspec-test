## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: Bob opens Jane's request and downloads her security pack; Jane removes a file, undoes it and removes it again, and both see who removed it and when; Maya, another Requestor, finds nothing of Jane's files anywhere.

## Recorded planning decisions

- **Actions** (`attachments-actions.ts`): `downloadAttachmentAction({ requestId, attachmentId, fileType })` calls `downloadRequestAttachment` and returns `{ ok: true, fileName, contentType, bytes }` (a `Uint8Array`) or `{ ok: false, kind, message }` through `attachmentFileRefusal("download", …)`, a failed file check giving `downloadCheckFailedMessage`; `setAttachmentRemovalAction({ requestId, attachmentId, removed })` returns the projection or family O; neither calls `redirect`; both revalidate nothing (the list refreshes with `router.refresh()`).
- **Save** (`lib/files/save-file.ts`, client-only use): `saveFile({ fileName, contentType, bytes })` creates `URL.createObjectURL(new Blob([bytes], { type: contentType }))`, clicks an anchor with `download = fileName` and `rel = "noopener"`, and revokes the URL on the next tick.
- **List** (`files-list.tsx`, `'use client'`): `FilesList({ requestId, attachments, viewer, aiPolicy })` holds the server list in `useOptimistic`; from 768px a `DataTable` (density toggle, no sorting or pagination, `Name` sticky in its labelled scroll region) with §3.2's columns and an Actions column (visually hidden header `Actions`); below 768px X-21 cards with `Download` full width and the icon-only `More actions for {name}` (`Ellipsis`) opening an X-13 bottom sheet titled with the file's name, holding `Remove` and `Close actions for {name}`; state badges from `StatusBadge` with §3.4's lines; `Download` (outline small, `Download` icon, `Download {name}`, `Downloading…` with the inline spinner, a visually hidden status `{name} downloaded.`); `Remove` (ghost small, `Remove {name}`) applies at once at the pending opacity, then the X-14 toast `{name} removed.` (plus ` Its text is no longer included in the AI inputs.` when the file was included) with `Undo`, whose success shows `{name} restored.` (plus ` Include its text again if the AI should use it.`); a failure rolls back with a danger toast titled `File not removed` and family O with `Try again` or `Refresh page`; the removed group: `Show removed files ({n})` / `Hide removed files` (outline small, `aria-expanded`, `aria-controls`, `ChevronDown`/`ChevronUp` swapped with no transition), an `ul` named `Removed files` with `Added by {name} · {instant}`, `Removed by {name} · {instant}` and `Restore {name}` for the remover only; restore failures titled `File not restored`; focus rules of §3.5; print rules of §3.7 (`data-print="hidden"` on controls).
- **Section** (`files-section.tsx`): exports `filesSectionFor(read)`, which returns the section's props only when the request read carries `attachments` (both pages call it, so a participant's or another Requestor's view renders nothing of the files), renders `FilesList`, keeps 14-12's field and queue for the draft, the §1.2 and §3.6 lines for limit, lifetime, not configured, paused and closed, the §3.7 empty states and the compact error `We couldn’t load the files` with `Try again` when the page's list read failed.
- **Status mapping** (`status-badge.tsx`): family `attachment` with `available` (`ShieldCheck`, `Available`), `pending` (`ShieldEllipsis`, `Waiting for malware check`), `blocked` (`ShieldX`, `Blocked`), `unavailable` (`FileX`, `File unavailable`), `removed` (`ArchiveX`, `Removed`), every tone `neutral` (UI-D14).
- **Hub** (`request-hub.tsx`): a `Files` row after `Notes`: a figure link (X-10) `{n} {file|files}` → `#files`; with none and `canAdd`, the link `Add files` → `#files`; otherwise `No files`; absent when the read has no `attachments`.
- **Pages**: the analyst request page renders `FilesSection` before Notes as the Requestor page does; both `loading.tsx` files gain a `Files` block before their `Notes` block (a heading line, three rows at the list's density, cards below 768px, and a field-height block).
- **Copy guard**: `interface-copy-guard.test.ts` covers `src/features/attachments` and `src/lib/files`, and asserts no visible string there contains `Accept` (UI-D33).
