## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: Bob includes the vendor security pack's text in what the AI may read, sees exactly how much is kept, and can read the stored text before generating. Only a Security Analyst who did not raise the request can do it, only for files whose text can be read, and never above the request's approved classification.

<objective>
Serve `PUT …/attachments/{attachmentId}/ai_input` and `GET …/attachments/{attachmentId}/ai_text` as human-analyst-only operations with their rules, extraction on opt-in, caps and policy check (D-30, D-31, D-33), their grant in a second Function, the `HUMAN_ANALYST_ONLY_OPERATIONS` entries, contract, matrix and inventory (D-03, D-38), the analysts' AI facts in the list, and the web's typed calls.

Purpose: COLLAB-02 criterion 5's opt-in at the API; ROADMAP success criterion 5's first half ("the analyst includes one file's text").
Output: two operations end to end to the typed service, one new Function.

Edits Strapi source? Yes. Changes the specification? Yes. Runs Playwright? No. Regenerates `served-operations.json`? Yes.
Scope note: 19 files: seven Strapi sources (the two operations' six API files and the `HUMAN_ANALYST_ONLY_OPERATIONS` entries in `csrm-authorization.ts`); five the contract chain; four the Strapi proofs (the matrix rows, the catalogue test for the new Function, the rules unit test and the integration test); three the web's schema, service and parity guard. ## Recorded planning decisions

- **Operations**: `setAiInput = "PUT:/api/v1/assessment_requests/{requestId}/attachments/{attachmentId}/ai_input"` (body `{ data: { included: boolean } }`, exact keys; 200 `RequestAttachmentResponse`), `getAiText = "GET:/api/v1/assessment_requests/{requestId}/attachments/{attachmentId}/ai_text"` (200 `{ data: { text, facts: { available, kept, truncated, extractor, extractedAt } } }`); handlers `setAiInput`, `getAiText`.
- **Rule** `aiInputRefusalFor({ request, caller, attachment, policy, including })` → `null | { status, reason }`, in order: the caller is the requestor → 403 `OWN_REQUEST`; window `intake` → 409 `REQUEST_NOT_SUBMITTED`; window `closed` → 409 `ATTACHMENTS_CLOSED`; state `removed`, `blocked`, `pending`, `unavailable` → 409 `ATTACHMENT_REMOVED`, `ATTACHMENT_BLOCKED`, `ATTACHMENT_QUARANTINED`, `ATTACHMENT_UNAVAILABLE`; type not in `TEXT_BEARING_ATTACHMENT_TYPES` → 409 `ATTACHMENT_NOT_TEXT_BEARING`; when `including`, a refusing `evaluateAiDataPolicy` → 409 with its reason. The readers rule (404) runs first in the controller; the grant and the human-only set run in the policy (403) before it.
- **Service** `setRequestAttachmentAiInput({ strapi, request, caller, attachmentId, included })`: an unchanged value returns the projection and writes nothing; including reads the bytes through the storage port and calls `extractAttachmentText({ type, bytes, cap: 20_000 })` outside the lock (unavailable → 409 `ATTACHMENT_TEXT_UNAVAILABLE`), then under `withRequestLock` re-checks the rule and writes `aiTextIncluded: true`, `aiText`, `aiTextFacts: { available, kept, truncated, extractor, extractedAt }` and the `ai-included` event; excluding writes `aiTextIncluded: false`, `aiText: null`, `aiTextFacts: null` and `ai-excluded`; both log `attachment.ai_inclusion_changed` with `from` and `to` (a full log → 409 `HISTORY_UNAVAILABLE`). `readRequestAttachmentAiText` applies `OWN_REQUEST`, then returns the stored text and facts, or 409 `ATTACHMENT_TEXT_UNAVAILABLE` when the file is not included; it has no window check (a read of the record).
- **Projection for analysts** (`projectAttachment(record, viewer)` when `viewer.humanAnalyst` and the viewer is not the requestor, and for a requesting analyst without `canChange`): `ai: { included, facts: { available, kept, truncated } | null, unavailableReason: "ATTACHMENT_NOT_TEXT_BEARING" | "ATTACHMENT_QUARANTINED" | null, canChange }`; list `meta.aiPolicy: { canChange, refusal: "OWN_REQUEST" | "AI_CLASSIFICATION_ABOVE_CEILING" | "AI_POLICY_NOT_CONFIGURED" | "ATTACHMENTS_CLOSED" | "REQUEST_NOT_SUBMITTED" | null, classification, ceiling }` for analysts only. A Requestor's response has neither key.
- **Policy**: `HUMAN_ANALYST_ONLY_OPERATIONS` gains `CSRM_REQUEST_ATTACHMENT_OPERATIONS.setAiInput` and `.getAiText` (imported); the matrix's mirror set gains both.
- **Catalogue**: `function.risk_assessment_requests.attachment_ai_input_api` (`Assessment Request Attachment AI Input API`, `Security Analyst choice of which attachment text the AI may read. This API-only Function intentionally has no menuPath.`, `roleIds: ["role.security_analyst"]`) with `.api.01` `Set Assessment Request Attachment AI Input` and `.api.02` `Read Assessment Request Attachment AI Text`.
- **Spec**: the two paths with operationIds `assessment-workflow/set-request-attachment-ai-input` and `assessment-workflow/get-request-attachment-ai-text`; components `RequestAttachmentAiInputRequest`, `RequestAttachmentAiFacts`, `RequestAttachmentAi`, `RequestAttachmentAiPolicy`, `RequestAttachmentAiTextResponse`; `RequestAttachment` gains optional `ai` and `RequestAttachmentListMeta` optional `aiPolicy`; responses 200, 400, 403, 404, 409.
- **Web**: `attachments-schema.ts` gains the AI shapes; `attachments-service.ts` gains `setRequestAttachmentAiInput(requestId, attachmentId, included)` and `getRequestAttachmentAiText(requestId, attachmentId)`.
