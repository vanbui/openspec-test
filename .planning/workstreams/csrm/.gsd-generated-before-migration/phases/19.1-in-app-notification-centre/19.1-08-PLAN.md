## Phase Goal

**As a** Requestor, a risk owner or a Security Analyst, **I want to** be told in the app when work waits for me and to open it in one step, **so that** nothing waits unseen between the people in the flow.

This plan's slice: from the header, the person opens their latest notifications and goes to the record in one step, at every width and by keyboard.

## Recorded planning decisions

- **Actions.** `notifications-actions.ts` (`'use server'`): `getNotificationSummaryAction()`, `listNotificationsAction(input: unknown)` (zod `.strict()`: `view` in `all`, `unread`; `page` 1 to 10,000; `pageSize` in 10, 25, 50), `markNotificationsAction(input: unknown)` (`ids` 1 to 50 unique strings of 1 to 255 characters, `read` boolean). Each reads the session, calls the typed service, and returns `{ ok: true, data } | { ok: false, status: number | null, formError: string }`; none calls `revalidatePath`. Registered in `parser-free-modules.ts` with `delegatesTo('notifications-service')`.
- **Store.** `notification-count.tsx` (`'use client'`): `notificationCountReducer` over `{ unread: number | null; asOf: string | null; overlays: Record<string, number> }` with actions `adopt({ unread, asOf })` (applied only when no `asOf` is held or the incoming one is later), `fail()` (unread null), `overlay(token, delta)`, `settle(token, result?)` (drops the overlay, adopts the result) and `rollback(token)`; the shown count is `unread` plus the overlays, never below 0, and null shows no capsule. `NotificationCountProvider({ summary, children })` holds the reducer and seeds it from `use(summary)` inside `<Suspense fallback={null}>`, adopting each new promise a later layout render passes. `useNotificationCount()` returns `{ shown, adopt, fail, beginOptimistic(delta) }`. `AppShell` wraps the header and `main` in the provider, so the page's marks (19.1-10) move the same count.
- **Trigger.** Gains `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` while open, the open state, the frame (shadcn `Popover` from 768px, `Sheet` below, chosen with `window.matchMedia('(min-width: 768px)')` at open and closed when it flips), and `next/dynamic(() => import('@/features/notifications/notification-panel'), { ssr: false, loading: <four skeleton items> })` prefetched with `import()` on `onPointerEnter` and `onFocus`; a failed import shows the error state whose `Try again` imports again. The capsule reads `useNotificationCount().shown`.
- **Panel.** `NotificationPanel({ onClose, frame })`: on mount calls `listNotificationsAction({ view: 'all', page: 1, pageSize: 10 })` and adopts the returned `unread` and `asOf` into the store; title `h2` `Notifications` (`tabindex="-1"`, focused on open); below 768px a `Close` circle after it; status row: while unread, the figure link `{n} unread` to `/app/notifications?view=unread` (accessible name `{n} unread notifications`); otherwise `No unread notifications`; the `ul` named `Latest notifications`; the footer link `View all notifications` to `/app/notifications`, hidden when there are none. States per UI-SPEC §4.3 with the exact copy; the skeleton appears only after 300ms. `Mark all as read` arrives in 19.1-09.
- **Item.** `NotificationItem({ item, onOpened, showMark? })`: an `li` holding one `next/link` block link to `item.destination` (sentence as text, `<time dateTime>` through `LocalInstant`, ` · ` and the X-17 `New` marker while unread, trailing `ChevronRight`), the kind icon per UI-SPEC §3.3 (`UserRoundCheck`, `ClipboardList`, `ClipboardCheck`, `ShieldCheck`, `MessageSquareText`), weight 500 unread and 400 read. `onClick` records the trigger and, for a Ctrl, Meta or Shift click, marks only; `onAuxClick` for button 1 marks only; `onNavigate` calls `guardLink(event, { href, trigger, onLeave: open })` while the guard blocks, else `open()`. `open()` applies the item's read state and a −1 overlay, closes the panel (the sheet only once the guard lets the navigation go ahead), and dispatches `markNotificationsAction({ ids: [documentId], read: true })` without awaiting; on failure it rolls back and shows T5 with the item's `recordNumber · recordTitle`; a 404 is silent (UI-D19). The page's mark control (`showMark`) arrives in 19.1-10.
- **Refusal family T.** In `refusal-copy.ts`: `notificationRefusal(code: 'T1' | … | 'T7', record?: { recordNumber; recordTitle })` returning the UI-SPEC §6.2 title, description, tone and action exactly.
