## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: the round trip in the API. A Security Analyst imports a spreadsheet of risks or controls through a preview and one commit, and exports the table's current view, each granted, refused and logged exactly as the records say.

## Recorded planning decisions

- **Operations and routes** (`CSRM_RISK_TABLE_OPERATIONS`, router `routes/risk-table.ts`, controller `controllers/risk-table.ts`): `previewRiskImport`, `commitRiskImport`, `downloadRiskImportTemplate`, `downloadRiskImportErrorReport` and `exportRiskTable` with 18-01's paths; `:table` resolved by `parseRiskImportTable` (unknown: 404).
- **Handlers.** Preview (multipart `file`, `timeZone?`): the analyst's assessment scope (404 when unreadable), then `assessmentEditability` for the actor (refusing with its reason and status 409), then `readImportFile(bytes, { sheetName })`, `classifyRiskImport`, `issueRiskImportPreview`; 200 `{ data: { previewDigest, fileName, table, summary, rows, warnings, notes, limits } }`. Commit (multipart `file`, `previewDigest`, `confirmed: "true"`): the record (409 `IMPORT_REVIEW_EXPIRED`), the digest (400 `IMPORT_PREVIEW_CHANGED`), then `saveRiskChanges(strapi, { assessmentDocumentId, actor, body: riskImportChanges(record), source: { kind: "import" }, assertBeforeWrite: (loaded) => assertNoRiskImportDrift(record, loaded) })`; a `RISK_CHANGES_CONFLICT` from the core maps to `RISK_IMPORT_DRIFTED`; on success `issueRiskImportResult` and one `import.committed` line (`kind: "assessment-risks"` or `"assessment-mitigation-controls"`, counts, batch id); 200 `{ data: { resultToken, batchId, counts: { created, updated, unchanged, rejected } } }`. Template (`format` required): the file, no event. Error report (multipart `file`, exactly one of `previewDigest` and `resultToken`, `timeZone?`): the file with `X-CSRM-Row-Count`, no event. Export (JSON `RiskTableExportRequest`): the analyst read of the assessment (404 when unreadable), `buildRiskTableExport`, `sendExportFile`; refusals through `sendExportError`.
- **Core hook.** `saveRiskChanges` gains an optional `assertBeforeWrite(loaded)` called inside the transaction right after the named risks are loaded (step 3), so drift is decided under the lock.
- **Specification.** Five paths; components `RiskImportPreviewResponse`, `RiskImportCommitResponse`, `RiskImportDriftedErrorResponse` (`error.status` 409, `error.details.reason` `RISK_IMPORT_DRIFTED`, `error.details.driftedRiskNumbers` 1 to 1,000 strings), `RiskTableExportRequest` (18-08's body); multipart bodies and binary 200s as 19-13, 19-14 and 19-05 publish theirs; errors 400, 401, 403, 404, 409, 413 and Phase 19's file refusals.
- **Catalogue and grants.** `function.risk_table.import_api` (`Import Risk Table Rows`; `.api.01` preview, `.api.02` commit, `.api.03` template, `.api.04` error report) and `function.risk_table.export_api` (`Export Risk Table View`; `.api.01`), API-only, `role.security_analyst` only, docs copy then byte-identical bootstrap copy. Five literals in `HUMAN_ANALYST_ONLY_OPERATIONS` and its matrix mirror; `POST:/api/v1/risk_assessments/{assessmentId}/risks/export` in `SERVICE_IDENTITY_REFUSED_OPERATIONS` with `underlyingRead: "GET:/api/v1/risk_assessments/{assessmentId}"`. Five matrix rows, each for all seven callers.
