## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: finding and views. A Security Analyst sorts, filters and searches the risks, chooses, orders and sizes the columns, and saves the arrangement as a view of their own or shares it with the analyst team.

<objective>
Mirror 18-02's filter-and-sort module in the web with a parity test (D-08), build the toolbar's search, `Show`, column menus, filter popovers and chips, sort and the address (D-08), the grid's column chooser with reorder and resize (D-07, X-61), the views menu with built-in and saved views through the typed API layer (D-09, X-59), and the grid's empty states. Prove them in Vitest and the phase spec.

Purpose: ASSESS-15 criteria 1 and 2.
Output: the web view module, the views menu, the column menu and filters, the saved-views feature and their tests.

Edits Strapi source? No. Changes the specification? No. Runs Playwright? Yes (dev servers stopped).
</objective>

## Recorded planning decisions

- **View module (`risk-table-view.ts`, zod-free).** The semantics of 18-02's module, line for line (no `localeCompare`): `applyRiskTableView(rows, { definition, search, show })`, `parseViewDefinition(raw, offeredKeys)` (fail safe), `serialiseViewDefinition`; `riskTableRowFromRisk(risk, scale)` building `RiskTableRow` from the parsed analyst or participant risk (scale tags through `ratingReading`, people names, `present` markers for AI values to confirm, contest points and open decisions); `BUILT_IN_VIEWS` keyed `standard`, `treatment-plan`, `ratings-review`, `owners-and-dates`, `acceptance` with UI-SPEC §5.2's columns and sort (Acceptance joins the default columns while a round is open, §7.1); the address grammar: `q`, `show` (`active` | `withdrawn`), `view` (`builtin:{key}` or a saved view id), `sort` (`key:asc,key:desc`), repeatable `filter` (`{key}:{kind}:{value}`, `oneOf` values joined by `|`, `dateRange` as `{from}..{to}`, values URI-encoded), `cell`, `risk`, `changes=1`; `viewFromSearchParams(params, offeredKeys)` and `searchParamsFromView(state)`. `risk-table-view.test.ts` reads the backend fixture by relative path and asserts every `views` case, plus address round trips.
- **Toolbar (`risk-table.tsx`).** In UI-SPEC §2.2's order: `Search risks` (36px, `Search` icon, debounced 150ms), `Show` (analysts), `View: {name}` with `Modified`, `Columns` (`Columns3`, the X-61 chooser with `Reset to view`, resizable), density, the counts (`output`). Header menus (`Alt+ArrowDown` on a header, or its menu button): `Sort ascending`, `Sort descending`, `Add to sort` (also `Shift+Enter`), `Filter`, `Hide column`. Sort buttons with reserved-space chevrons and numbered secondary sorts. `column-filter-popover.tsx`: `Contains` (text), a checklist (closed vocabularies, people, ratings; `Not on the scale` as its own item), `From` and `To` (dates), `Is empty` for every column. Chips `{column header}: {value}` with `Clear filters`. The URL updates with `router.replace` (no scroll), never adding history entries per keystroke.
- **Resize (X-61).** Each header's end edge renders `role="separator"` named `Resize {header}` (24px target, 2px ink line on hover and focus); `ArrowLeft`/`ArrowRight` ±16px, with Shift ±64px, clamped 96 to 448px; double-click or Enter fits the content; widths live in the view's `columns[].width`.
- **Views menu (X-59).** `ViewsMenu({ views, current, modified, owner, onSelect, onUpdate, onSaveAs, onReset, onRename, onShare, onDelete })` (`next/dynamic`): groups `Built-in`, `Your views` (`Share2` 12px after shared ones), `Shared by analysts` (owner in `--text-caption`), then the actions only where they apply. `Save as new view` and `Rename view` open a 480px `Dialog`: `View name` (required; family X4's `You already have a view called “{name}”.`), switch `Share with analysts` (off), primary `Save view`. `Delete view` applies at once with the toast `Deleted view “{name}”.` and `Undo` (re-creating it with the same name, visibility and definition). A 404 on a saved view reads X4's `That view is no longer available. Showing Standard.` The last view used is stored at `csrm:risk-table-view:{userId}` inside try and catch.
- **Saved views feature.** `saved-views-schema.ts` (zod, server): list, item and request schemas from 18-10's components. `saved-views-service.ts` (`server-only`): `listSavedViews(viewKey)`, `createSavedView(input)`, `updateSavedView(id, input)`, `deleteSavedView(id)` through the generated client; `responseParserModule`. `saved-views-actions.ts` (`'use server'`): the four actions returning `{ ok: true; data } | { ok: false; status; reason; message }`; registered in `parser-free-modules.ts`. The Risks page lists views server-side for the first render.
- **Empty states.** In the grid's `stateSlots`: first use, filtered and withdrawn per UI-SPEC §13 (read-only modes show no action).
