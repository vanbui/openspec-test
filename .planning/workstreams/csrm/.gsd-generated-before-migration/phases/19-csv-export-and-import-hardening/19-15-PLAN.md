## Phase Goal

**As a** Security Analyst or risk manager, **I want to** export any list I can see and to import spreadsheets without fighting the format, **so that** CSRM fits the Excel work around it.

This plan's slice: the import a spreadsheet user can trust, and the phase gate. Bob imports the files people actually make, reads a fix for any file CSRM cannot read, decides every near-match name himself, and corrects his own rows in Excel; then the whole phase is proven on the production build.

<objective>
Rework the web import flow onto Strapi's tolerant import (D-25 to D-32): retire the client parser, show file refusals with fix-it steps, warnings and notes, the similar-row decisions (X-32), template and error-report downloads; add the sixth import row state to the one status mapping; put Export on the reference lists and rename `Import CSV` to `Import` (D-33; UI-D1); prove criteria 3 to 5 in Playwright with the existing import journey's deliberate changes named (D-39); then run the full gate with the freeze, catalogue, Keycloak, dependency, approval and journey checks, and record the API coverage declaration (D-40).

Purpose: CSV-02 and CSV-03 in the UI; UAT-049, UAT-051 and UAT-052 closed.
Output: the reworked import flow, the reference-list export, the import journeys and the green gate.

Edits Strapi source? No. Changes the specification? No (served-operations.json gains web callers). Runs Playwright? Yes, the full suite.

Scope note: 16 files at four tasks; the import flow, its actions, service, badge and journeys change together because the server's shapes changed in 19-13 and 19-14.
</objective>
