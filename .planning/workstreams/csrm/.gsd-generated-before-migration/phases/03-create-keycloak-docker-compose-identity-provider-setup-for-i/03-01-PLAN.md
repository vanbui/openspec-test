<objective>
Add a top-level local Keycloak identity provider setup for IdamBox with a repeatable Docker Compose service, imported `idambox` realm, Jane/Bob local users, an `idambox-csrm` OIDC client for the future CSRM Next.js app, developer documentation, and static verification.
</objective>

<context>
Phase 3 depends on Phase 2 sample identity decisions and the existing Keycloak template in `example-projects/idambox_old/keycloak`. Keycloak authenticates users only in this phase. Product authorization remains in Strapi's IdamBox model and must continue to derive through `IdamBoxUser -> Role -> Entitlement -> Application`.
</context>

<threat_model>
**Assets:** Local Keycloak admin credentials, Jane/Bob local test accounts, CSRM OIDC client secret, IdamBox realm import JSON, Strapi-owned product authorization boundary.

**Threats:**
- HIGH: Committed local credentials are mistaken for production credentials or reused outside local development.
- HIGH: Keycloak roles/groups are added for CSRM and create a second authorization source that conflicts with Strapi.
- MEDIUM: Realm JSON updates appear not to work because the named Docker volume preserves the already-imported realm.
- MEDIUM: CSRM client redirect/origin values do not match the future Auth.js callback path, forcing Phase 6 rework.
- MEDIUM: Docker startup cannot run in some environments, leaving Phase 3 with unverifiable runtime behavior.

**Mitigations:**
- Add explicit local-only warnings in root `README.md` and `idp/README.md`.
- Keep the realm import limited to users and OIDC client basics; verify no CSRM roles/groups are defined.
- Document `docker compose down -v` as the reset path for re-importing checked-in JSON.
- Use the locked Auth.js-style values from CONTEXT.md.
- Add `scripts/verify-keycloak-idp.mjs` for static verification and document Docker startup as optional runtime verification.

**Residual Risk:** Static verification cannot prove the container starts on the developer's machine. Runtime verification remains a documented manual step when Docker is available.
</threat_model>
