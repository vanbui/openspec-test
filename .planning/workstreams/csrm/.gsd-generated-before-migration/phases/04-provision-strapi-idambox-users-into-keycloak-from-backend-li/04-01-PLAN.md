# Plan 04-01: Keycloak Admin Client Seed And Provisioning Configuration

<objective>
Add the local Keycloak service-account client and environment/documentation contract Strapi will use for Admin API user provisioning.
</objective>

<requirements>
- IDP-06: Keycloak provisioning is idempotent and configured through environment values rather than hard-coded secrets.
</requirements>

<threat_model>
## Threat Model

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-04-01 | Production code accidentally uses committed local Keycloak secrets or bootstrap `admin/admin` credentials. | high | Keep committed client secret local-only in docs, require env vars in backend docs, and forbid `admin/admin` as the Strapi Admin API credential path. |
| T-04-02 | Dedicated admin client receives broader Keycloak authorization than needed. | medium | Use a service-account client for user-management only; do not add CSRM authorization roles/groups or browser login settings. |
</threat_model>

<tasks>
<task id="04-01-01" type="execute">
  <title>Add Strapi admin service-account client to Keycloak realm seed</title>
  <read_first>
    - idp/keycloak/import/idambox-realm.json
    - .planning/phases/04-provision-strapi-idambox-users-into-keycloak-from-backend-li/04-CONTEXT.md
    - .planning/phases/04-provision-strapi-idambox-users-into-keycloak-from-backend-li/04-RESEARCH.md
  </read_first>
  <files>
    - idp/keycloak/import/idambox-realm.json
  </files>
  <action>Add a second client object with clientId `idambox-strapi-admin`, name `IdamBox Strapi Admin API`, description containing `Local-only service account client for Strapi Keycloak Admin API provisioning.`, enabled `true`, protocol `openid-connect`, publicClient `false`, clientAuthenticatorType `client-secret`, secret `idambox-strapi-admin-local-secret`, standardFlowEnabled `false`, implicitFlowEnabled `false`, directAccessGrantsEnabled `false`, serviceAccountsEnabled `true`, authorizationServicesEnabled `false`, empty redirectUris, empty webOrigins, and no CSRM authorization roles/groups. Add the service-account user/mapping required by Keycloak realm import so the client can manage users in the `idambox` realm, granting only `realm-management` client roles needed for lookup/create/update user operations: `view-users`, `query-users`, and `manage-users` if supported by the current import shape.</action>
  <verify>
    <automated>yarn verify:keycloak-idp</automated>
    <manual>Inspect `idp/keycloak/import/idambox-realm.json` and confirm it still contains exactly the existing `idambox-csrm` client plus the new `idambox-strapi-admin` client.</manual>
  </verify>
  <acceptance_criteria>
    - `idp/keycloak/import/idambox-realm.json` contains `"clientId": "idambox-strapi-admin"`.
    - `idp/keycloak/import/idambox-realm.json` contains `"secret": "idambox-strapi-admin-local-secret"`.
    - `idp/keycloak/import/idambox-realm.json` contains `"serviceAccountsEnabled": true` for `idambox-strapi-admin`.
    - `idp/keycloak/import/idambox-realm.json` does not add CSRM realm roles or CSRM groups.
  </acceptance_criteria>
</task>

    - `apps/backend/.env.example` contains `KEYCLOAK_ADMIN_CLIENT_SECRET=idambox-strapi-admin-local-secret`.
    - `apps/backend/README.md`, `idp/README.md`, and `README.md` each mention `idambox-strapi-admin`.
