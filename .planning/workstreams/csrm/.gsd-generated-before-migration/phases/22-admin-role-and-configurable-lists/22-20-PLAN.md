**As an** Admin, **I want to** own reference data and product configuration, separate from analysts' assessment work, **so that** registers, lists and scales are governed.

This plan's slice: the Admin edits the scale, the appetite, peer review, the AI data policy and retention in the app, sees exactly what changes before applying it, and gives a reason.

## Recorded planning decisions

- **Routes.** `/app/admin/configuration` and `/app/admin/configuration/[settingKey]` (an unknown key renders `notFound()`); Server Components gated by `configuration:manage` before any read (UI-SPEC §2's configuration state); titles from UI-SPEC §1.2; the editors load with `next/dynamic` and a skeleton after 300ms.
- **Service, schema, actions.** `configuration-service.ts` (`import 'server-only'`): `listConfigurationSettings()`, `getConfigurationSetting(key)`, `updateConfigurationSetting(key, { value, expectedVersion, reason })`, registered for parity; `configuration-schema.ts` closed zod parsers for the five envelopes and both reads; `configuration-actions.ts` `'use server'` `updateSettingAction` returning `{ ok: true, data } | { ok: false, kind: "conflict", current } | { ok: false, kind: "invalid", problems } | { ok: false, formError }`, then `revalidatePath`. The transport keeps `problems` and `current` beside `CONFIGURATION_INVALID` and `CONFIGURATION_CHANGED` only.
- **Domain (`configuration-domain.ts`, zod-free, client-safe).** Mirrors 22-02's rules for on-blur checks (bands increasing and non-empty over `SCALE_PRODUCTS`, appetite monotonicity, months 1–24, years 1–99, descriptions 1–300, reason 1–500), `settingChanges(key, before, after)` for the comparison rows (UI-SPEC's row names), `scoresChangingBand(before, after)`, the summary line per key, and `SETTING_LABELS` (`Scale and rating bands`, `Risk appetite`, `Peer review`, `AI data policy`, `Records retention`); the server's parser stays authoritative.
- **Components.** `SettingPage` (header, meta line, `Edit {short name}`, `History` opening `ChangeHistorySheet`, read and edit modes, X-54's bar, `Recent changes` with `Open in the change log`, the conflict and invalid alerts); `ChangeConfirmation` (complex dialog, full-screen sheet below 768px, `Now` and `After this change`, the forward-effect paragraph per key, `Reason for this change`, `Apply change` with a 16px spinner, `Keep editing`, Ctrl or ⌘ Enter applies, Esc keeps editing); `BandPreviewMatrix` (a native table captioned `Rating bands on the 5 × 5 matrix`, likelihood rows highest first, cells as the matrix picker's cell, `Preview` label when editing); `ScaleEditor` and `AppetiteEditor` (`scale-and-appetite-editors.tsx`); `PeerReviewEditor`, `AiDataPolicyEditor` (the source line's four states) and `RetentionEditor` (`policy-editors.tsx`).
- **Copy.** Every string from UI-SPEC §5, §6 and family AA1 in `refusal-copy.ts` (`CONFIGURATION_CHANGED`, `CONFIGURATION_INVALID`, the reason messages, 403 `CSRM’s configuration is maintained by the Admin.`, the retryable message); values from the direction only.
