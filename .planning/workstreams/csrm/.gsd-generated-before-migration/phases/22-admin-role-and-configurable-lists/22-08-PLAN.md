## Recorded planning decisions

- **Change rows.** Each write runs in `strapi.db.transaction`; area and subject type per kind (`risk-types`/`risk-type`, `controls`/`control`, `information-systems`/`information-system`, `information-assets`/`information-asset`); `subjectRef` the documentId; `subjectLabel` the record's name (a control: `{controlNumber} {title}`); create → `created` with every set field from null; update → `updated` with the changed fields only (none changed → no row); import apply → `imported` per created or updated record, one UUID `batchId` per apply, fields as create or update; relations written as display values (owner display name; applicable controls as sorted control numbers).
- **Asset owner.** `administration-config.ts` adds `owner` to the asset's writable fields; the query parser accepts a documentId or null; the repository resolves it to an `isEligiblePerson` user (else 400 `CSRM Administration record is invalid.` naming `owner`) and populates `owner` on detail and list as `{ documentId, displayName, accountStatus } | null`; the asset export gains `Owner` (display name) after `Name`; the asset import contract does not gain the column.
- **Active column.** The Risk Type import contract and export vocabulary gain `Active` (flag values `Yes`/`No`, optional on import: a blank keeps the stored state, a new type defaults to Yes); a row changing it writes a `retired` or `reinstated` change row besides any field change; Risk Type reads gain `isActive`.
- **Seeds.** In `seed-csrm-data.ts` remove `controlNeedsUpdate` and the update branch of `seedCsrmControls` (log `{n} controls ({created} created, {existing} existing)`); in `seed-assessment-workflow.ts` the Risk Type loop creates only missing names. Neither writes change rows.
