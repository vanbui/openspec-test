## Phase Goal

**As a** Requestor or a nominated risk owner, **I want to** see the assessment once it is released for response and tell the analyst which controls we have or plan, and as a Security Analyst I want to nominate each risk's owner and have the AI reassess residual risk from the responses, **so that** the final assessment reflects the business's real mitigations and the people who must accept it have seen it.

This plan's slice: participants read the whole assessment from the gate on, and nobody else does. One predicate, opened by the never-cleared gate fact, widens the three existing read routes and Phase 19's record-read check in its one place, and the matrix proves it for a seventh caller.

Split Phase 19-10's one record-read check into "readable now" and "released" in its one place, in both forms (D-29, D-30), with the SQL twin proven equal to `participationOf` (research Pattern 1). Retire `RequestorReleasedAssessmentDetail` for `ParticipantAssessmentDetail` with the web parser, page and report loader in the same plan (06.9 lesson). Add the matrix's seventh caller (D-75).

Purpose: SC2's read half, SC5's refusal half, UAT-025 (the Requestor and owners see the risks once released for response, and nothing before), ASSESS-22 criteria 1, 2 and 4. Rounds do not exist yet: the gate fact is written directly by test fixtures until 17-09.

- **The check (`released-assessment-read.ts`).** `AssessmentViewer` becomes `{ kind: "participant"; documentId: string } | { kind: "analyst" }` (every caller switches from `requestor`). `PARTICIPATION_POPULATE` loads the request's `requestor`, every risk's `riskOwner` and withdrawal facts, the gate pair and the release facts. `findReadableAssessment({ documents, viewer, documentId, populate })` returns `{ document, participation, stage } | null`: one `findOne` with the merged populate, `participationFactsFrom`, then for a participant viewer `participationOf(...).mayReadNow` or null, and for an analyst the document with an empty participation. `isReleasedAssessment(document)` is the in-memory released half (today's facts; Phase 17.1 widens it). `findReadableReleasedAssessment` keeps its name and callers and becomes "readable and released". SQL: `whereAssessmentReadable(builder, { assessmentAlias, viewerId })` delegates to the participation module; `whereAssessmentReleased(builder, { assessmentAlias, requestAlias })` holds 19.1-03's released conditions; `whereReleasedAssessmentReadable` composes both, keeping 19.1's callers. `readableAssessmentFilters` survives only for 19-10's My list until 17-08 replaces it, with a comment saying so. - **SQL twin (`assessment-participation.ts`).** `whereViewerMayReadAssessment(qb, { viewerId: number, assessmentIdColumn: string })` and `whereViewerParticipates(qb, { viewerId, assessmentIdColumn, part? })`, as `EXISTS` subqueries over the request's requestor link and the risks' `riskOwner` link of active risks (`activeRiskSql`), the gate column, and for legacy the requestor plus the released conditions.
