## Phase Goal

**As a** Requestor or a nominated risk owner, **I want to** see the assessment once it is released for response and tell the analyst which controls we have or plan, and as a Security Analyst I want to nominate each risk's owner and have the AI reassess residual risk from the responses, **so that** the final assessment reflects the business's real mitigations and the people who must accept it have seen it.

This plan's slice: once the controls are recorded, the analyst asks the AI to reassess residual risk, per risk or for the whole assessment, and confirms each proposed value; the AI changes nothing by itself.

Serve "Reassess residual risk" (D-46) as a new operation on Phase 16's risk proposal job family and Phase 15's registry (D-47), with a run per provider call, the AI data policy at enqueue and execution, the analyst instruction slot, the context (D-48), the two units per risk with derived ratings, citations, the inherent cap and planned controls named (D-49), decisions through Phase 12's operation with Phase 16's supersession and staleness (D-50), and the deterministic and hosted providers (D-51). Publish, grant and prove the operation (D-02, D-64).

Purpose: ASSESS-13, SC4 ("'Reassess residual risk' proposes new residual values citing the accepted controls, and the analyst accepts them per field") and UAT-026 (no AI write-up of residual risk after mitigations are recorded).
Output: one AI pipeline module pair, one operation on the existing job and decision machinery, its contract chain and three test files.

Edits Strapi source? Yes (dev servers stopped). Changes the specification? Yes. Runs Playwright? No. Live AI? Never: every suite uses the deterministic provider or the fake server.
</objective>

## Recorded planning decisions

- **Pure module (`residual-reassessment.ts`).** `RESIDUAL_REASSESSMENT_RISKS_MAX = 50`. `residualEligibility(risk)`: active, `inherentLikelihood` and `highestInherentConsequence` set, at least one control implementation; returns `{ eligible, reason? }`. `buildResidualContextPart(risks)`: a `<referenceData>` block `targetRisks` with per risk a short key (`risk-1…`), statement, cause and impact, inherent and current residual likelihood, consequence and rating, its control implementations as short keys `control-1…` with number, title, status, effectiveness, due date and evidence statement, and the submitted response comments and decided items on it; every business-written value inside Phase 12's untrusted data block; no person's display name, email or user id. `residualReassessmentWireSchema` (the portable subset): `{ schemaVersion: 1, risks: [{ key, residualLikelihood, highestResidualConsequence, residualRatingRationale, citedControls: string[] }] }`; ratings never on the wire. `toResidualReassessmentProposal({ wire, keys, risks })`: map keys back; drop unknown control keys (adjustment `sources-dropped`); derive the rating with `deriveRating`; drop the scores unit when `riskScore(residual) > riskScore(inherent)` (adjustment `residual-above-inherent-dropped`); flag a rationale citing no control (`uncitedClaims`); list the cited controls whose status is `Planned` as `plannedControlsCounted`; build two units per risk with Phase 16's `field-units.ts`: `residualLikelihood` + `highestResidualConsequence` + `residualRating`, and `residualRatingRationale`, capturing base values.
- **Providers (`residual-reassessment-providers.ts`).** `selectResidualReassessmentProvider()` follows `selectRiskProposalProvider`. `deterministicResidualReassessmentProvider`: for each target risk with at least one `Existing` or `Implemented` control rated `Effective`, residual likelihood one step lower (floored at `Rare`), citing that control; with only `Planned` controls, one step lower citing them all; with only `Ineffective` controls, the current values and a rationale citing none; with only `Retired` controls, a consequence one step above inherent (which the adapter drops). `openAiCompatibleResidualReassessmentProvider` sends the system instructions, the context and the instruction slot with the wire schema as the response format, as 16-08's rewrite provider does.
- **Operation.** `CSRM_ASSESSMENT_OPERATIONS.startResidualReassessment`. Enqueue order in `risk-proposal-workflow.ts`'s `startResidualReassessment`: parse `{ riskIds?: string[] (1–50, unique), instruction?: string }` (400); the assessment (404); `OWN_REQUEST` for the requesting analyst (16); the guard (not editable, round open, owner); the target risks (named ones must each be eligible, else 409 `RESIDUAL_REASSESSMENT_NOT_ELIGIBLE` naming the first; none named → every eligible active risk up to 50, none → 409); the instruction (Phase 15's 400s and Requestor-text guard); the policy (409 with its reason); then enqueue on the shared registry instance with target `residual:{assessmentId}`, answering 202 with `RiskProposalJob`. Execution follows 16-09's: re-check the guard and policy, build the context, `createRunningAiRun` with `operation: "residual-reassessment"`, `risk` set for a single-risk run, the instruction and the context summary, call the provider outside locks, complete under the assessment lock (lapse every unit with cause `assessment-not-editable` when no longer editable), and on completion record `superseded` on every open residual unit of the same risks in earlier completed reassessment runs and on every open rewrite unit touching `residualLikelihood`, `highestResidualConsequence`, `residualRating` or `residualRatingRationale` of those risks; a later rewrite proposing those fields supersedes the reassessment's open units the same way (16-09's rule widened in both directions). Job read and retry are 16's routes unchanged.
- **Read and decisions.** `AI_RUN_OPERATIONS` gains `residual-reassessment` with its context summary section; `risk-proposals-read.ts` folds the operation's units into `GET …/ai_proposals` per risk; `risk-proposal-decisions.ts` applies its units through `applyRiskProposalDecisions` (stale → `AI_PROPOSAL_STALE`; restore for Undo), so `aiProposalsDecided` counts them. The run never clears Phase 13's "AI inputs changed" signal.
- **Contract.** Path `POST /v1/risk_assessments/{assessmentId}/residual_reassessments` (`risk-ai-proposals/start-residual-reassessment`), component `ResidualReassessmentRequest`, response `RiskProposalJobResponse` (202); `AiRun.operation` gains `residual-reassessment`; the proposals read's item schema gains `plannedControlsCounted` and the `residual-above-inherent-dropped` adjustment code. Catalogue `function.risk_ai_proposals.residual_reassessment_api` (`Residual Reassessment API`, human Security Analyst only, `.api.01` `Start Residual Reassessment`); the literal in `HUMAN_ANALYST_ONLY_OPERATIONS` and its mirror; the matrix row `humanAnalystOnly(202)` with a mounted proof (`riskOwner` 403).
