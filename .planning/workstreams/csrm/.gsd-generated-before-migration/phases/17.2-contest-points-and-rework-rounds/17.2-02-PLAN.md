## Recorded planning decisions

- **Placement.** Seven modules flat in `apps/backend/src/csrm/` (17.2-PATTERNS); no Strapi import; inputs are plain values so services and tests pass facts in. Each test file is `node:test` with `assert/strict`, compiled by `tests/tsconfig.json`.
- **Vocabulary** (`contest-targets.ts`). `CONTEST_TARGET_KINDS = ["assessment-field", "risk", "risk-field", "control-implementation"]`; `ASSESSMENT_TARGET_FIELDS` and `RISK_TARGET_FIELDS`, frozen arrays of `{ key, label, covers: readonly string[] }` exactly as 17.2-01 lists them; `CONTROL_IMPLEMENTATION_TARGET_COVERS` (the participant projection's control-implementation keys); `CONTEST_TARGET_EXCLUSIONS = [{ key: "treatmentStatus", why: "written only at release (17.1 D-43)" }]`. `parseContestTarget(input)` returns `{ ok: true, target }` or `{ ok: false, reason }` with reason `unknown-kind`, `unknown-field`, `missing-risk`, `missing-control-implementation` or `unexpected-field` (all 400 at the service). `contestTargetKey(target)` returns `assessment:{field}`, `risk:{riskId}`, `risk:{riskId}:{field}` or `control:{controlImplementationId}` (the per-target count key the projections and markers use). `contestTargetLabel(target, names)` returns `Assessment details · {label}`, `{riskNumber}`, `{riskNumber} · {label}` or `{riskNumber} · {controlName}` (17.2-UI-SPEC "Targets are named as the reader saw them").
- **Snapshot** (`contest-snapshot.ts`). `CONTEST_SNAPSHOT_SCHEMA_VERSION = 1`, `CONTEST_FIELD_SET_VERSION = 1`; `cutContestSnapshot({ target, projection })` takes the participant projection object (`ParticipantAssessmentDetail` as 17-07 and 17.1-09 shape it) and returns `{ ok: true, snapshot }` or `{ ok: false, reason: "not-readable" | "no-executive-approver" }` (the service maps `not-readable` to 404 and `no-executive-approver` to 400); `parseContestSnapshot(value)` returns the envelope or `null` on any unknown version, kind or shape, never throwing.
- **Status** (`contest-point-status.ts`). `CONTEST_POINT_STATUSES = ["open", "answered", "resolved", "withdrawn"]`, `CONTEST_ENTRY_KINDS = ["reply", "answer", "resolved", "withdrawn", "undo"]`; `deriveContestPointStatus(entries)` folds entries ordered by `sequence`: `answer` → `answered` (from `open` or `answered`), `resolved` → `resolved`, `withdrawn` → `withdrawn`, `reply` → unchanged, `undo` → the status before the entry it undoes (`sequence - 1`); `lastContestEntry(entries)`.
- **Rules** (`contest-rules.ts`). Constants: `CONTEST_REASON_MAX_LENGTH = 2_000`, `CONTEST_ANSWER_MAX_LENGTH = 2_000`, `CONTEST_REPLY_MAX_LENGTH = 5_000`, `SEND_BACK_MESSAGE_MAX_LENGTH = 2_000`, `CONTEST_POINTS_PER_PERSON_PER_ROUND = 20`, `CONTEST_POINTS_PER_ROUND = 100`, `CONTEST_REPLIES_PER_POINT = 100`, `CONTEST_POINTS_PAGE_DEFAULT = 25`, `CONTEST_POINTS_PAGE_MAX = 100`, `CONTEST_THREAD_PAGE_DEFAULT = 20`, `CONTEST_THREAD_PAGE_MAX = 50`, `CONTEST_UNDO_WINDOW_MS = 120_000`, `CONTEST_PARTS = ["requestor", "risk-owner", "executive-approver", "security-analyst"]`. `parseContestText(value, max)` trims and returns `{ ok, text }` or `{ ok: false, reason: "empty" | "too-long" }`. Each decision function takes a plain facts object and returns `{ allowed: true }` or `{ allowed: false, status: 400 | 403 | 404 | 409, reason, details? }`:
  - `raiseDecision({ viewer: { isServiceIdentity, mayRead, isParticipant }, openRoundNumber, roundNumberSeen, released, raisedByViewerThisRound, raisedThisRound })`: service 403 → unreadable 404 → `ASSESSMENT_NOT_MUTABLE` → `NOT_A_PARTICIPANT` 403 → `ACCEPTANCE_ROUND_NOT_OPEN` → `ACCEPTANCE_ROUND_CHANGED` → `CONTEST_POINT_LIMIT` (`per-person` at 20, `per-round` at 100).
  - `replyDecision({ viewer: { isServiceIdentity, mayRead, isParticipant, isHumanAnalyst }, released, status, expectedSequence, lastSequence, replyCount })`: 403 → 404 → `ASSESSMENT_NOT_MUTABLE` → 403 (neither participant nor human analyst) → `CONTEST_POINT_CLOSED` (resolved or withdrawn) → `CONTEST_POINT_CHANGED` → `CONTEST_POINT_LIMIT` (`replies` at 100). A round need not be open (D-07).
  - `answerDecision({ viewer: { isServiceIdentity, mayRead, isHumanAnalyst, isRequestorOfRequest, isRiskOwnerOnAssessment, isExecutiveApproverOnAssessment }, released, status, outcome, roundOpen, expectedSequence, lastSequence })`: 403 → 404 → 403 (not a human analyst) → `ASSESSMENT_NOT_MUTABLE` → `OWN_REQUEST` 403 → `ACTOR_IS_RISK_OWNER` → `ACTOR_IS_EXECUTIVE_APPROVER` → `CONTEST_POINT_CLOSED` → `CONTEST_POINT_CHANGED` → `ACCEPTANCE_ROUND_OPEN` when `outcome` is `changed` and a round is open. Answers are never capped (research Pitfall 2) and never withdraw a review (D-08).
  - `closingActDecision({ act: "resolve" | "withdraw", viewer: { isServiceIdentity, mayRead, isParticipant, isRaiser }, released, status, expectedSequence, lastSequence })`: 403 → 404 → `NOT_A_PARTICIPANT` 403 (an analyst) → `CONTEST_POINT_NOT_RAISER` 403 → `ASSESSMENT_NOT_MUTABLE` → `CONTEST_POINT_CLOSED` → `CONTEST_POINT_CHANGED` → for resolve `CONTEST_POINT_NOT_ANSWERED` unless `answered`.
  - `undoDecision({ now, viewer: { isServiceIdentity, mayRead, isParticipant }, released, lastEntry, callerId, expectedSequence, viaUndoRaise?: { raisedAt, raisedById, entryCount } })`: 403 → 404 → `NOT_A_PARTICIPANT` → `ASSESSMENT_NOT_MUTABLE` → `UNDO_NOT_AVAILABLE` unless the caller authored the last entry, it is `resolved` or `withdrawn` (never `undo`), `expectedSequence` equals its sequence and `now - postedAt <= CONTEST_UNDO_WINDOW_MS`; for the raise's Undo (`viaUndoRaise`), only with `entryCount` 0, `expectedSequence` 0, the caller the raiser and `now - raisedAt` inside the window.
  - `sendBackDecision({ viewer: { isServiceIdentity, mayRead, isParticipant, isRiskOwnerOrApprover }, released, openRoundNumber, roundNumberSeen, ownOpenPointsInRound })`: 403 → 404 → `NOT_A_PARTICIPANT` 403 → `SEND_BACK_NOT_PERMITTED` 403 → `ASSESSMENT_NOT_MUTABLE` → `ACCEPTANCE_ROUND_NOT_OPEN` → `ACCEPTANCE_ROUND_CHANGED` → `SEND_BACK_NEEDS_OPEN_POINT` when `ownOpenPointsInRound` is 0.
  - A former participant reads as not `mayRead` (404) and cannot act (D-09).
- **Readiness** (`contest-readiness.ts`). `hasOpenContestPoint(points)` (true when any point's status is `open`, whichever round raised it); `openContestPointItems(points, labels)` returns `[{ number, targetLabel }]` ordered by `number`. 17.2-06 calls it from `readiness.ts`.
- **Comparison** (`snapshot-comparison.ts`). `FIELD_SETS: Record<number, { assessment: readonly string[]; risk: readonly string[]; controlImplementation: readonly string[] }>` with `1` built from the vocabulary's covered keys; `FINGERPRINT_TO_FIELD_SET = { 1: 1 }`. `normaliseDecisionSnapshot({ snapshot, fingerprintVersion, labels })` maps 17.1's canonical `decisionSnapshot` (relations as documentId strings) to the contest envelope's field list, resolving labels from a batched `labels` map. `compareSnapshot({ before, now, currentFieldSetVersion })` returns `SnapshotComparison { fields: [{ key, state: "unchanged" | "changed" | "not-recorded", before, after }], controlImplementations: [{ id, controlNumber, controlName, state: "added" | "removed" | "changed" | "unchanged", fields }], nothingChanged: boolean }`; a key in `before` absent from the current set is omitted (research A3); people compare by `documentId` and show `before`'s recorded label against today's; dates compare as `YYYY-MM-DD`. The web formats values but never diffs (D-14).
- **History windows** (`history-windows.ts`). `HISTORY_EVENT_KINDS` (closed): `response-round-opened`, `response-submitted`, `response-round-closed`, `acceptance-round-opened`, `acceptance-round-recalled`, `acceptance-round-returned`, `acceptance-round-completed`, `decision-recorded`, `decision-voided`, `contest-point-raised`, `contest-point-replied`, `contest-point-answered`, `contest-point-resolved`, `contest-point-withdrawn`, `contest-point-undone`, `review-logged` and `rework-risks-changed` (the last two analyst-only, `HISTORY_ANALYST_ONLY_KINDS`). `HISTORY_RECENT_WINDOWS = 2`, `HISTORY_EVENTS_PER_READ_MAX = 5_000`. `buildHistoryWindows({ rounds, now })` sorts rounds of both kinds by `openedAt` and returns windows `{ index, round, from, to }`; `placeHistoryEvent(windows, at)`; `splitAnalystWindow(window, closedAt)` returns the round part and a `between` part labelled with the next round's number; `selectHistoryWindows({ windows, mode: "recent" | "all", eventCounts })` returns `{ selected, earlierWindowCount }`, adding whole windows newest first until the next would pass 5,000, always at least one.
- **D-21 static scan** (in `contest-rules.unit.test.ts`): walk `apps/backend/src` and assert that no file whose path contains `ai-`, `openai`, `prompt` or `/ai/` imports a module whose name starts with `contest-`, imports `snapshot-comparison`, or contains `api::csrm-contest-point`.
