# Phase 06.4 Plan 08: Return to draft consistency Summary

The four established workflow-reversal surfaces now use one primary `Return to draft` trigger while retaining their record-specific destructive confirmations and authorised state gates.

## Accomplishments

- Made the portalled `ConfirmDialog` content responsive at `min(480px, calc(100vw - 32px))` and gave its header, reason group, and footer the full usable width.
- Preserved required-reason validation, the 500-character counter, pending protection, focus behavior, destructive confirm labels, semantic overlay, and existing server actions.
- Made the analyst request, requestor request, requestor questionnaire, and analyst questionnaire reversal triggers standard primary shared Buttons.
- Ordered each trigger as the first eligible workflow action, with 16px separation before the following content; ineligible states omit the trigger.
- Added focused component and workflow coverage for dialog width, primary treatment, order, and eligibility omission.

## Decisions Made

- The fixed dialog width belongs on the portalled shared dialog content rather than at individual triggers or on a local textarea override, because the portal owns the layout constraint.
- The request workflow's 16px following spacing is composed from its existing `gap-3` plus the trigger wrapper's `mb-1`, preserving its existing compact stack while meeting the placement contract.
- Plan 06.4-04 remains blocked by its independently documented typed request-relationship contract gap; reversal consistency does not depend on reading or inferring that relation and was completed independently.

## Deviations from Plan

None - plan execution was completed without changing server actions, workflow rules, generated declarations, Strapi content types, or dependencies.
