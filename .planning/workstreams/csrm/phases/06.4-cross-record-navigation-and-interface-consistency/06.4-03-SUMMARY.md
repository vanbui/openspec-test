# Phase 06.4 Plan 03: Typed client boundary Summary

The related-request relation is published as a discriminated union and parsed as
one, so no consumer can reach an identifier for a relation it should not link.

## Accomplishments

- `QuestionnaireAssessmentRequestSummary` became a `oneOf` with an `availability`
  discriminator and three closed member schemas, and the web declarations were
  regenerated from it rather than hand-edited.
- The client parser is the matching `z.discriminatedUnion`, and
  `availableAssessmentRequest` is the only route to the identifier.
- Eight consumers that had assumed a request is always present were surfaced as
  compile errors and each now states what it shows when the relation is absent or
  protected.

## Notes

The contract parity guard failed this change while the parser had moved and the
contract had not, which is exactly the drift class it was built for in 06.3. It
passed once the contract was published and the declarations regenerated.

The narrowing helper was first placed in the service module, which is
`server-only`; importing it into client components and their tests failed at
runtime and in a mocked test. It belongs in the domain module, which is what the
client may import.

Verified together: Strapi 146/146, web 355/355, both typechecks clean.
