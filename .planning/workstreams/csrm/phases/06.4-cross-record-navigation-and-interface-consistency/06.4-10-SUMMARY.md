# Phase 06.4 Plan 10: Questionnaire request backlink browser coverage Summary

The serial questionnaire workflow now checks the authorised Requestor and Security Analyst request backlinks at mobile and desktop widths, including their distinct destinations, usable target size, persistent underline, source order, overflow, and an actual navigation round trip.

## Accomplishments

- Added a shared browser assertion for the seeded questionnaire's assessment-request link.
- Proved the Requestor link uses only `/app/requests/[documentId]` at 375px and 1440px.
- Proved the Security Analyst link uses only `/app/review/requests/[documentId]` at 375px and 1440px.
- Asserted the link appears after the questionnaire heading and before following workflow content, remains at least 44px high, preserves its underline, and does not introduce horizontal overflow.

## Non-interactive Decision

The E2E harness seeds only authorised questionnaire-to-request relationships. It provides no route, fixture, or safe test-data mutation mechanism for an absent relationship or an identity-free unavailable relationship. This plan therefore did not alter Strapi fixtures, frozen content types, or unrelated server sources merely to manufacture those states. Plan 06.4-05's component coverage verifies the absent neutral text and unavailable omission; browser proof for those two states remains outstanding until a dedicated browser fixture exists.

## Resolution

The blocker recorded above was the absent response contract, not missing
fixtures. Once the request relationship and readiness contracts were published
and Plans 06.4-04 and 06.4-06 completed, both states proved reachable from the
existing seed as the owning Requestor:

- `RAR-DEV-QUES-DRAFT-001` has a questionnaire and no assessment, giving the
  absent state.
- `RAR-DEV-QUES-001` has a questionnaire and an assessment still in review, so
  its own Requestor may not open it — the unavailable state, with no fixture
  work needed.
- `RAR-RELEASED-33SAEN` has no questionnaire and a released assessment, giving
  the named absence alongside a populated tally.

`apps/web/e2e/request-relationship-states.spec.ts` covers all three at 375px and
1440px, including that an unavailable assessment leaks no identifier and is
never presented as an absence. Six checks pass.

Records are opened by clicking a title rather than by a hardcoded document id:
the browser harness seeds its own database and Strapi generates fresh document
ids per seed, so only the seeded numbers and titles are stable. An earlier draft
of this coverage failed for exactly that reason.
