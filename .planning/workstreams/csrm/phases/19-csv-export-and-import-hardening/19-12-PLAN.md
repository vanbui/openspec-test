## Phase Goal

**As a** Security Analyst or risk manager, **I want to** export any list I can see and to import spreadsheets without fighting the format, **so that** CSRM fits the Excel work around it.

This plan's slice: the released Risk Assessment as a file and as paper. Jane exports her own released assessment and prints it as a clean A4 report; nobody else can reach either.

Scope note: 17 files at four tasks; six are the two routes' page, loading and error files.

## Recorded planning decisions

- **Loader (`released-assessment-report.ts`, `import 'server-only'` for the loaders; W5, pilot ruling 2026-10-16).**
  - The cached read moves here: `readReleasedAssessment = cache(getReleasedAssessment)` (today page.tsx:20) is exported from this module, and the page's `generateMetadata` and the loader both use it, so each request still makes one detail read.
  - `loadRequestorReleasedAssessment(documentId)` makes exactly the reads and branches the released page makes today (page.tsx:57-84): the detail, the risks, then each Risk's control implementations through the existing `loadReleasedDescendants` logic.
  - It returns a discriminated result: `{ state: 'not-found' }` (any 404, or a detail without data), `{ state: 'contract-mismatch', operation }`, `{ state: 'permission' }` (403), `{ state: 'error' }`, `{ state: 'unavailable' }` (risks without data) or `{ state: 'populated', assessment, risks, controlsByRisk }`.
  - The released page maps each result to exactly what it renders today: `notFound()`, the `contract-mismatch` state after the same `console.error` line, `permission`, `error`, `unavailable` and `populated`. The switch is behaviour-neutral.
  - The Requestor report route calls `notFound()` for `not-found` and `permission`, because an unreadable assessment reads as missing. It throws for `error`, `contract-mismatch` (after the same log line) and `unavailable`, so its `error.tsx` renders.
  - `loadAnalystReleasedAssessment(documentId)` gates with `canViewerReviewAssessments()`, then makes the analyst detail read through its own `cache(getAnalystAssessment)` (as the analyst page does at :45). It returns `null` when the read is refused or missing or `released` is false.
- **Model (`toAssessmentReportModel(input)`, pure, exported for tests).** It maps either loader's data into one `AssessmentReportModel` holding only fields the released projection discloses: identifiers, request number and title, release date and released by, overall rating, rationale, summary, recommendations, overall control effectiveness, next review date, risks (number, statement, inherent and residual ratings, treatment action label, the §15.2 fields) with their control implementations, and the AI disclosure flag.
- **Active Risks only (W4, pilot ruling 2026-10-16).** The report applies the same active-risk rule as the released read.
  - The Requestor's risk list read is active-only in Strapi: `ACTIVE_RISK_FILTER` in `listAssessmentRisks` (controllers/csrm-assessment.ts:368) and the Requestor's `isActiveRisk` check (:395), both held by `apps/backend/tests/active-risk-readers.unit.test.ts`.
  - The analyst detail's `risks` keep withdrawn Risks for the Phase 16 cards. So the model drops every Risk whose `withdrawal` is not null, the two actors' models stay equal, and the scope sentence's `{r}` counts active Risks only. This plan adds no Strapi reader, so that guard is unchanged.
  - Fixtures: every `AnalystRiskDetail` fixture carries its required `withdrawal` (`null` for an active Risk). An `AssessmentRiskListItem` fixture carries it only if the executed schema has gained the field (it has none at `bdd0f698`).
- **Routes.** Each `report/page.tsx` is a Server Component: load, `notFound()` on a not-found or null result (see Loader), read the viewer's zone, render `PageHeader` with `data-print="hidden"` (eyebrow the assessment number, title `Print report`, description `This is the released assessment as an A4 report. Print it, or save it as a PDF from your browser’s print dialog.`, actions `ReportToolbar` and `Back to the risk assessment`, an outline link with `ArrowLeft` to the released view), then `AssessmentReport`. `loading.tsx` renders the toolbar shape and `AssessmentReportSkeleton`; `error.tsx` renders `We couldn’t load this report` with `Try again` (Phase 11 §2.4 anatomy). Route titles `Print report {number} | IdamBox CSRM`. Each new route directory joins `routesWithoutClientValidation` in `src/lib/performance/zod-client-boundary.test.ts`, whose coverage test fails on a route directory under `app/(app)` that neither list names. `ReportToolbar` is the routes' one client module and imports no zod.
