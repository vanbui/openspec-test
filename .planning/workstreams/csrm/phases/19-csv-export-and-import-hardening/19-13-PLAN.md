This plan's slice: the import reads files the way people make them. Bob's "Name" file with an extra Owner column previews with a warning; Excel's default CSV gets a reason the UI can turn into a fix; a lower-case copy of an existing name waits for Bob's decision.

## Recorded planning decisions

- **Upload (`administration-workflow.ts`).** The extension check accepts `.csv` and `.xlsx`; the bytes go to `readImportFile({ bytes, fileName, mimeType })`; an `ImportFileRefusal` becomes the HTTP status it carries (413, 415 or 422) with `details: { reason, found }` in the `AssessmentWorkflowErrorResponse` envelope. `AdministrationWorkflowError`'s status union and `importError`'s gain `422` (neither allows it at `bdd0f698`), and the controller maps it. The file digest stays SHA-256 of the bytes.
- **Test uploads.** XLSX uploads use a sibling of `harness.createCsvMultipart`, `createXlsxMultipart({ filename, bytes, digest?, confirmed?, decisions? })` with the XLSX media type `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, in `tests/helpers/strapi-http-harness.ts`; `createCsvMultipart` gains the same optional `decisions` field (Task 3).
- **Keys (`administration-query.ts`).** `administrationExactKey(value) = value.trim().normalize("NFC")`; `administrationSimilarKey(value) = value.trim().normalize("NFKC").toLocaleLowerCase("en-AU").replace(/\s+/gu, " ")`; `normalizeAdministrationNaturalKey` stays as it is and keeps guarding uniqueness, so a create never adds a case-only duplicate (D-30; 19-RESEARCH Pitfall 20).
- **Classification (`csv-import.ts`).** `csvRowStates` gains `"similar"`; `CsvImportRow` gains `matchedName: string | null`; `classifyRows` indexes existing records by exact and similar key: an exact hit classifies as today; a similar-only hit is `similar` with `matchedDocumentId`, `matchedUpdatedAt` and `matchedName`; two rows of the file sharing a similar key stay `ambiguous`. Headers through `matchHeaders` with `importColumns(kind)` (labels and fields) and `knownIgnored` `{ issuesHeader: "Issues", readOnlyLabels }`; cells through `convertCell` with `mode` from the row's tier; a row whose natural key equals the collection's `exampleKey` (trimmed, NFC) is skipped and adds the note `example-row`; a row whose `byteLength` exceeds 65,536 is `rejected` with `VALUE_TOO_LONG` (field null). The preview returns `warnings` (ignored headers as typed, at most 50 of at most 200 characters), `notes` (`issues-column`, `read-only-columns`, `example-row`), `readOnlyColumns` (their labels), its existing `summary` object (the field is `summary`, not "counts"; administration-workflow.ts:190) with a count per state, six once `similar` joins in Task 3, and each row's `matchedName`.
- **Preview record.** Each retained row gains `issues: readonly { code: string; field: string | null }[]` (at most 20) and `matchedName`; a record whose retained issue data exceeds 1,048,576 bytes is refused at preview with `IMPORT_WORKBOOK_TOO_LARGE` (the bound keeps the 256-record cap's memory bounded).
- **Commit.** A multipart `decisions` field, optional, a JSON object of row number (string of 1 to 5 digits) to `update` or `skip`, at most 5,000 entries, parsed closed (else 400). Every `similar` row of the retained preview needs a decision (else 409 `IMPORT_DECISION_MISSING`); a decision for a row that is not `similar` is 400.
  - Expired preview. An expired, unknown, other-actor or other-collection preview token is 409 `IMPORT_PREVIEW_CHANGED` today (`previewRecordForCommit`, administration-workflow.ts:256). It becomes 409 `IMPORT_REVIEW_EXPIRED`. This is a deliberate behaviour change: a test names it, and the summary records it. A file whose digest differs from the reviewed one (:279) keeps 409 `IMPORT_PREVIEW_CHANGED`.
  - Drift: the commit re-classifies; a row whose state or match changed since preview is rejected as drifted, as today. `update` applies the row's values except the natural key (the existing name is kept) in the row's transaction; `skip` writes nothing.
  - Response. It adds `resultToken`. The result's state-keyed `summary` (today `resultCounts`) holds the six Results figures under today's keys `create`, `update`, `unchanged`, `rejected` and `ambiguous`, plus `skipped`: a similar row decided `update` counts under `update`, and one decided `skip` under `skipped`. `previewChanged` stays. Each result row carries its `state` (a similar row keeps `similar`) and, for a similar row, its `decision`.
- **Result record.** `issueResultRecord({ actorDocumentId, kind, fileDigest, fileName, format, rows })` mirrors `issuePreviewRecord` (5-minute TTL, 256 global, 16 per actor and collection, prune on issue) and returns `resultToken` (`sha256:` plus 64 hex of 32 random bytes); `resultRecordFor(token, actorDocumentId, kind)` returns the record or null; rows hold `{ rowNumber, outcome, decision, issues }`. `IMPORT_RESULT_TTL_MS = 300_000`.
- **Event.** After the commit's transactions, `logSecurityEvent(strapi.log, { name: "import.committed", actor, collection: kind, fileName, sha256: fileDigest, format, counts, outcome: "committed" })`.
- **Specification and web parsers.** The preview response, commit request and commit response schemas of the eight import operations gain the fields above; the error responses gain 413, 415 and 422 with the `AssessmentWorkflowErrorResponse` envelope and 409 for `IMPORT_DECISION_MISSING` and `IMPORT_REVIEW_EXPIRED`. `csv-import-schema.ts`'s closed parsers gain `warnings`, `notes` and `readOnlyColumns` (Task 1), then `similar` in `csvRowStates` and in the preview `summary`, `matchedName`, `resultToken`, the result `summary`'s `skipped` and the result rows' `decision` (Task 3). The preview and result summaries become two closed schemas, because they no longer share keys. The client parser's counts derive from `csvRowStates`, so it stays valid until plan 19-15 retires it.
- **Import row badges off the shared first-load map (B4 and B5, pilot ruling 2026-10-16).**
  - Why. `status-badge.tsx` ships on every route that renders a status. That includes `/app/risks/{documentId}` (289 bytes left at Phase 16's close) and `/app/requests/{documentId}` (558) (16-15-SUMMARY), and one lucide icon cost about 273 bytes gzipped (16-12-SUMMARY:168). So the sixth state must add zero bytes there. And as soon as `similar` joins `csvRowStates`, the family's `satisfies Record<CsvRowState, StatusPresentation>` (status-badge.tsx:134) fails the web typecheck unless the entry lands in the same task.
  - The move. The whole import row family leaves `status-badge.tsx`, with its `satisfies` clause, for a new import-only module `apps/csrm/src/features/administration/import-row-status.tsx` (no directive, no zod). Only `csv-import-flow.tsx` imports it, so only `/app/admin/[collection]/import` loads it.
  - The module holds `importRowPresentation`: the five entries unchanged, plus `similar` with label `Matched by similar name`, tone `warning` and lucide's `CaseSensitive`. It also holds `importRowLabel(state)`, with the shared mapping's unknown-value fallback (the G-13 seam), and `ImportRowBadge({ state, className? })`.
  - `status-badge.tsx` loses the family, its `StatusValues` member and the `CsvRowState` type import, plus any icon only that family used. It keeps every other family as it is. It exports its existing tone rendering as `PresentedStatusBadge({ presentation, className?, live? })`, which `StatusBadge` itself renders through, and its `unknownStatusPresentation`. So no second tone-to-variant mapping or fallback exists, and the shared module shrinks on every route.
  - `csv-import-flow.tsx` renders rows with `importRowLabel` and `ImportRowBadge`. Its tiles and filter, which map `csvRowStates`, show the sixth state with its label until plan 19-15 shapes the flow.
  - Tests. `status-badge.test.tsx` drops the family's rows and vocabulary. `import-row-status.test.tsx` pins the six states (label, tone and icon; `Ambiguous` keeps `CircleQuestionMark`) and checks the same forbidden severity and urgency icons. `interface-copy-guard.test.ts` lists the new module, sorted.
  - Choice. The other option was to reuse an icon already in the shared bundle. It was rejected: it would change UI-D16's `CaseSensitive`, and the label still adds bytes to the shared map. The badge contract (label, icon, tone; 19-UI-SPEC §5.6, UI-D16, X-32) is unchanged.
