# Phase 16 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Analyst, Requestor and service agent → Strapi curation and risk AI routes | Untrusted until Role → Function → FunctionAPI (API-only Functions on `role.security_analyst`), `HUMAN_ANALYST_ONLY_OPERATIONS`, the analyst assessment scope and, for AI proposals, the requesting-analyst rule (`OWN_REQUEST`) pass. Navigation and hidden controls are courtesy only. | Risk ids, reasons, Undo flags, instructions, focus, decisions |
| Client body → closed parsers | Curation, start, retry and decision bodies are closed shapes with server bounds; withdrawal facts are never client-writable. | Batch ids (1 to 200), reasons (500), `undo: true`, run ids and item keys |
| Analyst mutation → assessment aggregate and history | Every change passes the one editable guard inside the locked transaction and writes its history row in the same transaction; history is append-only and no Risk is ever deleted. | Risk fields, withdrawal facts, control implementations, history rows |
| Strapi reads → Requestor | A withdrawn Risk never reaches a Requestor's list, count, figure or control implementations; it reads as the unknown record's 404. Requestors hold no risk AI or history grant. | Released assessment, active Risks, counts and ratings |
| CSRM → AI provider | Only data within the classification ceiling leaves CSRM; policy is checked at enqueue, at retry and again before the one provider call. Listed text is escaped data with short keys only. | Request, answers, marked notes and files, listed Risks (capped), withdrawal and rejection reasons, instruction |
| Model output → proposal → risk record | Wire output is untrusted until the adapter, the Accept rule and the duplicate tiers run; nothing reaches a Risk without a human decision that passes the stale and Accept checks in the transaction. AI output cannot release. | Proposal envelope v1, decision events v2 |
| Strapi response → web, rendered text → browser | Closed zod parsers registered in the parity guard; reasons, values, proposals and diff marks render as React text nodes. | JSON responses, user and model text |
