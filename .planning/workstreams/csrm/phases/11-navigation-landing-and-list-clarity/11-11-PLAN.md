## Phase Goal

**As a** Requestor or Security Analyst, **I want to** have a sectioned sidebar and a Home that leads with my next action, **so that** I always know where my work is and what to do next.

This plan's slice: My requests says, row by row, whose turn it is and what happens next, and filters to the requests that need the viewer.

## Recorded planning decisions

- **Holder labels (UI-D25).** `requestHolderPresentation = { requestor: { label: 'Needs your action' }, analyst: { label: 'With the Security Analyst' }, none: { label: 'No action needed' } } satisfies Record<RequestHolder, { label: string }>` in the zod-free `request-domain.ts`; the `Show` options prepend `All requests`.
- **Query.** `RequestListQuery` gains `holder: RequestHolder | undefined`; `parseRequestListQuery` reads `holder` and drops an unknown value (catch to undefined), as it does for `status`.
- **Row type.** `RequestTable` rows become `MyRequestItem`; the `Request ID`, `Title`, `Status` and `Due date` columns keep their keys; `Next step` (long-text) renders the holder line in `.micro-label` with `text-foreground-secondary` and the sentence through `nextActionPresentation`; `Updated` renders `Updated <LocalInstant style="date" …>`.

Delete `formatRequestDate` and `updatedDateLabel` if nothing else reads them.
