This plan's slice: the Risk register says, row by row, whether a Risk is released or still under assessment and whether it was accepted, and filters by both.

## Recorded planning decisions

- **Branch functions.** `applyReleasedParent(query)` and `applyUnderAssessmentParent(query)` each add one `whereExists` over `csrm_risks_assessment_lnk` joined to `csrm_assessments` with today's branch body; `applyDisclosableParent(query)` adds one `whereExists` whose `where` holds the mutable branch `orWhere` the released branch, built from shared private builders `mutableParent(parent)` and `releasedParent(parent)` so each branch's SQL exists once.
- **Row stage.** From the populated assessment, as `parentLock` decides: `released` when `isReleased`, `under-assessment` when mutable; a row whose parent is neither is already excluded by the scope.
- **Parser.** `RISK_REGISTER_STAGES = ['released', 'under-assessment']`, `RISK_REGISTER_TREATMENT_ACTIONS = ['Accept', 'Treat']`; the allowed key set gains `stage` and `treatmentAction`; any other value is a `RiskRegisterQueryError` (400).
- **Accepted marker (web).** `isAcceptedRiskRow(row) = row.stage === 'released' && row.treatmentAction === 'Accept'` in `risk-domain.ts`: it marks the recorded decision on a released Risk; the exposure counts (server) add the open-Risk condition.
- **Copy (UI-SPEC §11.1).** `app/(app)/app/risks/page.tsx:13` (and its loading and error boundaries) → `Search and manage Risks from released risk assessments and from those still under assessment.`; `risk-register-filters.tsx:208`'s description → `Search and filter Risks.`
