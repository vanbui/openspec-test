## Phase Goal

**As a** Requestor or Security Analyst, **I want to** have a sectioned sidebar and a Home that leads with my next action, **so that** I always know where my work is and what to do next.

This plan's slice: the Security Analyst triages the request queue from its columns, finds a request by its number, and can see every request in review scope in one view.

<objective>
Deliver D-02 item 1 through the full endpoint chain: the queue projection gains the requestor's display name, assessment type, business criticality, due date and days since submission; `filters[q]` matches number or title; `filters[queue]=all` reads reviewable and released requests. Then render the nine triage columns, sorting, mobile cards, the local Submitted date and the `All requests` view on the Requests list (D-29, D-30, D-55, UI-SPEC §7.1), with a self-contained browser journey.

Purpose: UAT-035 (the queue lacked the columns to triage) and UX-09 criterion 1.
Output: the Strapi projection, filters and bucket with unit and integration proofs; the specification and generated client; the closed web parser registered in the parity guard; the list columns and cards; a new `review-lists.spec.ts` and a UI request-creation helper reused by later plans.

Edits Strapi? Yes (dev servers stopped for Strapi tests). Changes the specification? Yes, so it runs alone in its wave (D-05). Runs Playwright? Yes.
</objective>

## Recorded planning decisions

- **Server.** `REVIEW_QUEUE_BUCKETS` gains `all`; `reviewQueueStatuses('all')` is `REVIEWABLE_REQUEST_STATUSES` plus `RELEASED_REQUEST_STATUSES` (never `draft`); `applyBucket(query, 'all', …)` adds no lifecycle predicate. `safeReviewFilters` accepts `q` (`safeReviewText`, 1 to 200 characters) and `applyCriteria` adds `(LOWER(r.request_number) LIKE LOWER(?) ESCAPE '!' OR LOWER(r.title) LIKE LOWER(?) ESCAPE '!')` with `literalContains(q)` bound twice. The existing `title` and `requestNumber` filters stay for compatibility. `REVIEW_QUEUE_ITEM_FIELDS` gains `assessmentType`, `businessCriticality`, `dueDate`; `hydrate` populates `requestor` with `fields: ['displayName']` only (no email, username or roles). `projectAnalystReviewRequest(document, today)` adds the five fields; `daysSinceSubmission` is `daysBetween(submittedDate's UTC date, today)` when a submitted date exists, never negative, else null. The controller passes `utcToday(new Date())` (from `apps/backend/src/csrm/insights/utc-date.ts`).
- **Sanitizer.** If `sanitizeOutput` drops the computed keys (they are not content-type attributes), sanitise the hydrated documents first and project after; the integration test decides.
- **`all` stays analyst-scoped.** The route keeps `requireAnalystRequestCollectionScope`; `all` widens only the statuses inside that scope.
- **Web.** `requestReviewQuerySchema.queue` gains `all`; `listAssessmentRequests` sends `filters[q]` when `q` is set (no longer `filters[title]`). Queue label `all: 'All requests'`. Column keys and `densityUserId` (`assessment-review-requests`) are unchanged so each viewer's density survives.
- **E2E helper.** `apps/csrm/e2e/helpers/requests.ts` exports `createSubmittedRequest(page, { title, assessmentType, businessCriticality, dueDate })` that, signed in as the Requestor, fills the request form with the fields `requestor-request-workflow.spec.ts` fills before it submits, submits, and returns `{ requestNumber, documentId }` read from the request page. Later plans reuse it.
- **Seams.** Phase 13's assignee column is one more entry in the column list. "Assigned to me" is Phase 13's to model, not this plan's: per 13-CONTEXT D-13 and D-14 (and its 2026-10-01 Orchestrator Confirmations) it is a `filters[assignee]=me` filter, orthogonal to the lifecycle bucket, over Phase 13's `open` bucket, on its own route headed `Assigned to me`; it is not a `REVIEW_QUEUE_BUCKETS` value. This plan's `all` bucket and `q` filter neither anticipate nor constrain it: no assignee filter, no `open` bucket and no reserved queue option are added here, and `safeReviewFilters` stays a closed key list that a later key extends.
