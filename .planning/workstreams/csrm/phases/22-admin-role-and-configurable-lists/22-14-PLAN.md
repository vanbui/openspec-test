This plan's slice: when the Admin's AI data policy refuses a request, or generation fails, the assigned analyst can still start the work by hand, and CSRM records that it started without AI.

## Recorded planning decisions

- **Availability (`manual-start.ts`).** `manualStartAvailability(strapi, { kind: "questionnaire" | "assessment-draft", request, questionnaire? })` returns `{ available, reason, because }`: `because: "record-exists"` when the questionnaire (or assessment) exists; `"job-running"` when the questionnaire registry's `hasActiveJob` (or the draft registry's new `hasActiveDraftJob(questionnaireDocumentId)`) is true or the latest run is `running`; otherwise `available` when `evaluateAiDataPolicy` refuses (reason its code), or `latestAiRunFor(strapi, requestDocumentId, operation)` is `failed` or `interrupted` (`GENERATION_FAILED`, `GENERATION_INTERRUPTED`; latest by `startedAt` then `id` descending), or building the context as the enqueue does throws its too-large error (`CONTEXT_TOO_LARGE`); else `because: "generation-allowed"`. `MANUAL_START_REASONS` lists the five reason codes; `manualQuestionnaireTitle(requestNumber)` returns `Security questionnaire for {requestNumber}`.
- **Operations** (in `CSRM_QUESTIONNAIRE_OPERATIONS`): `startQuestionnaireWithoutAi` `POST:/api/v1/assessment_requests/{requestId}/start_questionnaire_without_ai`, `startAssessmentWithoutAi` `POST:/api/v1/questionnaires/{questionnaireId}/start_assessment_without_ai`, body `{}` (else 400); routes beside their generation routes; operationIds `assessment-workflow/start-questionnaire-without-ai`, `assessment-workflow/start-assessment-without-ai`; 201 with the questionnaire summary or the assessment summary the generation operations' completed jobs point to.
- **Refusal order.** 404 when the record is not readable to the caller; 403 for the service identity and any non-human analyst (policy); `OWN_REQUEST`, `REQUEST_UNASSIGNED`, `NOT_ASSIGNED_ANALYST` through `assertAssignedAnalyst`; generation's own eligibility function (`REQUEST_NOT_ELIGIBLE` or the draft's 409) without restating its gate; then `MANUAL_START_NOT_AVAILABLE` with `details.because`; every check re-run inside the locked transaction.
- **Questionnaire start (`startQuestionnaireWithoutAi`).** Under generation's request lock: `createWithQuestionnaireNumber`, `title` from `manualQuestionnaireTitle`, `assessmentRequest`; no `generatedDate`, `generatedBy` or provider fields; the governance log gains `{ kind: "started-without-ai", at, by, reason }` (`GOVERNANCE_EVENT_KINDS` extended in the same task); the request unchanged; all inside `withStageRecording({ cause: "manual-start" })`.
- **Draft start (`startAssessmentWithoutAi`).** Under `lockAssessmentRequest`: `assessmentNumber`, `assessmentStatus: "draft"`, `assessmentRequest`, `aiProvenance` `{ schemaVersion: <12's version + 1>, start: { origin: "manual", by, at, reason } }` (the parser extended in the same task to read the member and the previous version); the request to `risk-assessment-drafted`; inside `withStageRecording({ cause: "manual-start" })`; no risks, no run.
- **Catalogue.** `function.generation.manual_start_api` per 22-01 (`role.security_analyst` only); `STAGE_CAUSES` gains `manual-start` (21's coverage test's act map lists both starts).
