This plan's slice: the Admin changes a setting with a reason, the change is recorded with who, when and the old and new values, and every other caller is refused.

## Recorded planning decisions

- **Store (`configuration-store.ts`, imports types only).** A module-level `Map<ConfigurationSettingKey, StoredSetting>`, `StoredSetting = { key, value, version, changedAt, changedBy: { documentId, displayName } | null }`; `storedSetting(key)` (or undefined), `storedSettingValue(key)` (the parsed value or undefined), `replaceStoredSetting(stored)`, `resetConfigurationStore()` (tests only; a header comment says so). The configuration points import this module only, so `risk-scale.ts` stays Strapi-free and no import cycle forms.
- **Service (`services/configuration-settings.ts`).** `CONFIGURATION_SETTING_LABELS` (`Scale and rating bands`, `Risk appetite`, `Peer review`, `AI data policy`, `Records retention`); `settingSnapshot(key)` (the stored setting, else the default with `version: 0`, null `changedAt` and `changedBy`); `aiPolicySource()` (`setting` when a row exists, `deployment` when `ai.dataClassificationCeiling` is non-empty, else `none`); `loadConfigurationStore(strapi)` reads every row through `strapi.db.query`, parses each with `parseSettingValue` and stops bootstrap with `CONFIGURATION_INVALID: {key}` if one fails (write discipline makes it unreachable); `listConfigurationSettings()`; `readConfigurationSetting(strapi, key)` (adds `recentChanges`: the latest five change rows for the key, newest first); `updateConfigurationSetting(strapi, { key, body, actor })`.
- **The write.** Body closed `{ value, expectedVersion, reason }` (any other key, or a missing one, is `CONFIGURATION_INVALID` at that path). Reason through `parseReasonText` (problem `{ path: "reason", code: "required" | "too-long" }`). Value through `parseSettingValue`. Then `strapi.db.transaction(async ({ onCommit }) => …)`: read the row `forUpdate`; current version = the row's or 0; `expectedVersion` different → 409 `CONFIGURATION_CHANGED` with `details.current` = `settingSnapshot(key)`; `settingFieldChanges(key, current value, new value)` empty → 200 with the current read and nothing written; otherwise create or update the row with `version + 1`, `changedBy` the actor and `changedAt` now (a concurrent first create that meets the unique `key` index maps to `CONFIGURATION_CHANGED`), call `writeConfigurationChanges` with area `configuration`, subject `setting` / key / label, action `updated`, the fields and the reason, and register `onCommit(() => replaceStoredSetting(…))`. Answer 200 with the new read.
- **Writer (`csrm-configuration-change/services/change-log.ts`).** `writeConfigurationChanges(strapi, entries)` throws unless `strapi.db.inTransaction()`; each entry `{ area, subjectType, subjectRef, subjectLabel, action, fields, reason?, actorDocumentId?, origin, originDetail?, batchId? }` becomes one row through `strapi.documents(CHANGE_UID).create`, values bounded by `boundChangeValue`, `changes` from `buildChangesEnvelope`. It is the only module that creates change rows (a static test greps `apps/backend/src` for the change UID's `create(` elsewhere).
- **Operations** (`operations.ts`, `CSRM_CONFIGURATION_SETTING_OPERATIONS`): `listConfigurationSettings` `GET:/api/v1/configuration_settings`, `getConfigurationSetting` `GET:/api/v1/configuration_settings/{settingKey}`, `updateConfigurationSetting` `PUT:/api/v1/configuration_settings/{settingKey}`; router `routes/configuration-settings.ts`, each route `auth: { strategies: ["content-api-token"] }` and `{ name: "global::csrm-authorization", config: { operation, requireAdminScope: true } }`; an unknown `settingKey` is 404 `CSRM configuration setting was not found.`.
- **Specification.** Tag `configuration`; operationIds `configuration/list-configuration-settings`, `configuration/get-configuration-setting`, `configuration/update-configuration-setting`; components `ConfigurationSettingKey`, the five `…SettingValue` envelopes, `PersonSummary` reuse, `ConfigurationSetting` (`key`, `value`, `version`, `changedAt`, `changedBy`, optional `source`), `ConfigurationChange` (22-01's read shape, reused by 22-12), `ConfigurationSettingDetail` (with `recentChanges`), `ConfigurationSettingUpdateRequest`, the list and detail responses; `AssessmentWorkflowErrorResponse.error.details` gains closed optional `problems` (`[{ path, code }]`) and `current` (`ConfigurationSettingDetail`) beside their reasons only; errors 400, 401, 403, 404, 409.
- **Catalogue.** `function.configuration.settings_api` per 22-01, `role.admin` only, docs copy then byte-identical bootstrap copy; three matrix rows, each with all eight callers (`admin` 200, every other caller 403, `noIdentity` 403).
