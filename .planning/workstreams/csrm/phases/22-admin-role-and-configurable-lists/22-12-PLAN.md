This plan's slice: the Admin sees who holds which role and every recorded change, and exports both for an access review.

## Recorded planning decisions

- **Operations** (`operations.ts`, `CSRM_ACCESS_REVIEW_OPERATIONS`): `listRoleHolders`, `exportRoleHolders`, `listConfigurationChanges`, `exportConfigurationChanges` (22-01 URLs); router `routes/access-review.ts` with each export before any parametrised sibling, `requireAdminScope`, exports with `underlyingRead` set to their list; operationIds `access-review/list-role-holders`, `access-review/export-role-holders`, `access-review/list-configuration-changes`, `access-review/export-configuration-changes`.
- **Role holders.** Query and shape as 22-01 "Role holders"; `roles` summary rows for `Admin`, `Security Analyst`, `Security Analyst Agent` (catalogue descriptions) and `Requestor only` (active users with no explicit role); `since` from the newest `role-assignment` row whose `roles` field gains that role name for the person; `sinceBefore` = `recordingStartedAt` (the earliest `role-assignment` row's `createdAt`, else the read's instant) when no row records the grant; `identityLinked` = `externalSubject` set; sorted by display name; `pageSize` 10, 25, 50 or 100 (default 25), unknown parameters 400.
- **Change log.** Query `area` (repeatable, 22-01's areas), `subject` (1–100, case-insensitive contains on `subjectLabel`), `subjectType` and `subjectRef` (together, exact; used by setting pages and record history), `changedBy` (a user documentId, `identity-platform` or `system`), `from` and `to` (`YYYY-MM-DD`, inclusive, UTC), `batch`, `page`, `pageSize`; ordered `createdAt` then `id` descending; rows through `parseChangeRow` (an unreadable row is skipped and logged once); `subjectExists` resolved per page with one bounded query per subject type (settings always true).
- **Exports.** Views `role-holders` (columns `Name`, `Username`, `Email`, `Status`, `Roles`, `Held since`, `Identity link`, `Review notes`) and `change-log` (`When`, `Changed by`, `Area`, `Subject`, `Change`, `Before`, `After`, `Reason`, `Import batch`; `Before` and `After` one `{field}: {value}` line per field) in both vocabulary copies, registered in `registeredExportViews`, each honouring the list's filters and `EXPORT_ROW_CAP`.
- **Specification.** Tag `access-review`; components `RoleHolderRoleSummary`, `RoleHolderRole`, `RoleHolderReviewNote`, `RoleHolderPerson`, `RoleHoldersResponse`, `ConfigurationChangeListResponse` (reusing `ConfigurationChange`); the two exports as 19-05's binary shape; errors 400, 401, 403.
