## Phase Goal

**As a** Security Analyst or Requestor, **I want to** have the existing request, questionnaire, assessment and administration screens work as they say, **so that** today's flow completes without workarounds, lost input or misleading messages.

This plan's slice: an analyst who comes back to a request mid-generation sees the job's progress instead of an invitation to start another one.

## Locked decisions this plan implements

| Decision | How this plan honours it |
| --- | --- |
| D-26 | Queued, running and failed jobs seed the panels (completed jobs do not); a seeded job replaces the Generate or Replace action; the Next action line is overridden while a job is queued or running; Retry stays with the initiator (`canRetry`); another analyst sees the failure and may start a new job; after a Strapi restart the read is empty and nothing is seeded. |
| D-47 | Every human Security Analyst who opens the request sees its job status, including a job another analyst started (research assumption A4 is closed); a Requestor never reaches the hub or the read. |
| D-27 | Jobs another analyst started are polled by request through `getRequestGenerationJobsAction`, never by id. |
| D-38 | UI-SPEC §12.1, §12.2 and §12.5 copy replaces the job cards' internal wording. |
| D-39 | Unit tests fail first for every §12 state; the journey returns mid-job. |

## Recorded planning decisions

- **Stable seeding.** Each panel's reset effect keys on the seeded job's `jobId` and `status`, not on the object, because `router.refresh()` hands it a new object with the same content.
- **Lifting the running state.** Each card reports its current job status through an `onJobStatusChange(status)` callback; `AssessmentDetail` derives the §12.3 override and passes `nextActionOverride` to `RequestHub`, which renders it as plain text after the unchanged `Next action: ` prefix.
- **Read failure.** The page passes `jobsReadFailed` to `AssessmentDetail`, which shows §12.5's line once per card above the idle action.
- **Polling by request** reuses each card's timing (1-second interval, 30-second timeout) and picks the matching job from the read.
