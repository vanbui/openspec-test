- A waiting answer save sent on `pagehide` (reload, close, an external address) may never reach the server (code review IN-304)
  status: open
  **What:** found by the Phase 10 code review (`10-REVIEW.md`, IN-304). The autosave hook sends a waiting save at once on `pagehide` and on unmount, as a Server Action request; the browser may cancel that request as the document unloads. A tab switch (`visibilitychange` to hidden) completes. UI-SPEC §6.2 says the save is sent at once, which holds, but it is not guaranteed to arrive. The leave guard's `beforeunload` warning (D-12) is the protection for reload, close and external navigation, so a Requestor is asked before leaving with a save waiting. The limit is recorded beside the hook (`use-answer-autosave.ts`) and next to UI-D11.
  **Where to resolve:** a save that survives unload needs a `keepalive` or `sendBeacon` endpoint. A web route would be a frontend API facade (AGENTS.md non-negotiable), so it needs a Strapi endpoint that accepts a beacon request with the session's authorisation, decided by the pilot as an API change in a later phase (no roadmap phase owns it yet). Until then this stays a recorded limit.
