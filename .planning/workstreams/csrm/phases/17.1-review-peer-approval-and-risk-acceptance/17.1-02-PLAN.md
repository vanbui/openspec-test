## Phase Goal

**As a** risk owner, **I want to** decide each of my risks, accepting it or approving its treatment, within my authority once the analyst submits the final assessment, and as a Security Analyst I want an explicit review, a colleague's approval for the most serious outcomes, and one confirmed step that releases the assessment and closes the request, **so that** every closed request carries accountable acceptance and independent review.

This plan's slice: every rule the operations will enforce, as pure, tested modules: who decides a risk under what authority and until when, when a decision stands, when a review counts, who may approve, what submission and release need, and what release writes. Nothing is served yet; plans 17.1-04 to 17.1-12 call these and nothing else.

## Recorded planning decisions

- **Placement.** `apps/backend/src/csrm/acceptance/` holds `decision-sequence.ts`, `review-currency.ts`, `eligibility.ts`, `readiness.ts` and `release-mapping.ts`; `decision-fingerprint.ts` and `review-policy.ts` sit beside `risk-scale.ts`. None imports Strapi; inputs are plain values, so every service and test passes facts in.
- **Appetite (research Code Example 1).** `type AcceptanceAuthority = "risk-owner" | "risk-owner-with-executive-approval" | "executive-exception"`; `type RiskAppetiteEntry = { authority; reviewIntervalMonths; exception: boolean; executiveApproverRequired: boolean }`; `DEFAULT_RISK_APPETITE` = Low and Moderate `{ risk-owner, 12, false, false }`, High `{ risk-owner-with-executive-approval, 6, false, true }`, Critical `{ executive-exception, 3, true, true }`, frozen. `reviewDateFor(rating, today, appetite?)` returns `addUtcMonths(today, interval)` as `YYYY-MM-DD`. `acceptProposalAllowed` is unchanged and independent (an Admin widening owner authority must not let the AI propose Accept for High).
- **Sequence.** Pure row shape `DecisionRowFacts = { id, act, part, actorId, choice, revision, supersedesId, approvesId, voidsIds, fingerprint, fingerprintVersion, roundNumber, reviewDate, recordedAt }`. `standingActs(rows)` drops superseded rows (any row whose id another row's `supersedesId` names) and voided rows (named in a `void` row's `voidsIds`). `allowedActFor({ rating, standing, actor: { isOwner, isExecutive }, act, appetite? })` returns `{ allowed: true }` or `{ allowed: false, reason, because }` with reason `DECISION_NOT_PERMITTED` or `DECISION_NOT_AVAILABLE` and `because` one of `owner-has-not-decided`, `executive-has-decided`, `owner-proposal-missing`, `not-this-rating`, `revision-limit`. `deriveAcceptanceState({ rating, rows, currentFingerprint: (version) => string, appetite? })` returns `awaiting-owner`, `awaiting-executive` or `decided`. `validDecisionOf(...)` returns the completing act (the owner's decide for Low and Moderate, the owner's decide with its approval for High, the executive's decide for Critical) with its authority and review date, or null.
- **Fingerprint (research "Fingerprints and Voids"; Pitfall 6).** `DECISION_FINGERPRINT_VERSION = 1`; `DECISION_SCOPE_V1` and `REVIEW_SCOPE_V1` are frozen field lists. Canonical form: sorted keys, absent and `null` both `null`, relations as documentId strings (a populated relation normalised to its `documentId`), dates `YYYY-MM-DD`, control implementations sorted by `documentId`; `JSON.stringify`; `sha256:` plus lowercase hex through `node:crypto`. `decisionSnapshot(risk)` returns the canonical object the hash covers (17.2's before-and-after view diffs it). `reviewFingerprints({ assessment, risks })` returns `{ assessment, risks: [{ riskId, riskNumber, fingerprint }] }` over active risks.
- **Policy.** `REVIEW_POLICY_THRESHOLDS = ["critical", "high", "all", "off"]`; `peerApprovalRequirement(activeRiskRatings, policy?)` returns `{ required, reason: { threshold, riskNumbers } }`; `high` means High or Critical; `all` means any active risk; `off` never.
- **Currency.** `reviewCurrency({ reviewedAt, reviewedById, reviewWithdrawnAt, assigneeId, latestAcceptanceRoundClosedAt })` returns `{ state }` with state `not-reviewed`, `current`, `withdrawn`, `reviewed-before-reassignment` or `reviewed-before-recall`. `parseReviewLog(value)` is the closed v1 parser that returns an empty log on an unknown version or action (fails safe, never throws to a reader). `changedSections({ latestReviewed, current })` returns `{ assessmentChanged, changedRiskNumbers, addedRiskNumbers, withdrawnRiskNumbers }`. `peerApprovalState({ required, peerApproverId, peerApprovalRequestedAt, peerApprovedById, peerApprovedAt, reviewedAt, reviewIsCurrent, approverEligible })` returns `not-required`, `not-asked`, `asked` or `approved`; the ask counts only when `peerApprovalRequestedAt` is at or after `reviewedAt` (research Open Question 5, Orchestrator Confirmation).
- **Eligibility.** `peerApproverEligibility({ candidate, facts })` with `facts = { requestorId, assigneeId, reviewerId, riskOwnerIds, executiveApproverIds }` returns `{ eligible: true }` or `{ eligible: false, reason }` with reason `own-request` (checked first, mapped to `OWN_REQUEST`), `assigned`, `reviewer`, `participant`, `not-analyst`, `inactive`, `service-identity`; the candidate is Phase 13's `EligibilityUser` (it holds the human analyst grant test). `executiveApproverEligibility({ candidate, riskOwnerId, facts })` composes `isEligiblePerson` and returns the detail `is-risk-owner`, `is-assigned-analyst`, `is-reviewer`, `is-peer-approver`, `inactive` or `service-identity`. The Requestor may be named.
- **Readiness.** Keys and labels per 17.1-01; `projectSubmissionReadiness(facts, { forReview?: boolean })` and `projectReleaseAndCloseReadiness(facts)` return `{ ready, requirements }` in the published `{ scope, key, label, state, destination, riskNumber }` shape; risk requirements' destination is the risk card anchor, as `projectReleaseReadiness` builds it today; `recommendation` is outstanding when `treatmentAction` or the advice text in `treatmentPlan` is missing or when Accept is recommended with any `Planned` control implementation; release-and-close risk items carry `waitingOn` display names.
- **Release mapping.** `mapDecisionToRiskFields({ decision, rating, appetite? })` returns the D-43 field set; `exemptionReviewDate` is `utcDateToInstant(reviewDate).toISOString()`; `nextReviewDateAtRelease({ analystNextReviewDate, reviewDates })` compares `YYYY-MM-DD` strings.
