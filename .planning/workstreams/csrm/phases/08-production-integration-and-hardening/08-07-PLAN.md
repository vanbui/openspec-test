## Recorded planning decisions

- **`StatusBadge` keeps the existing `status` prop for the request family** so `request-table.tsx`, `request-form.tsx`, `assessment-detail.tsx`, the request badges in `assessment-list.tsx` and the Requestor dashboard's request badges stay byte-identical; new call sites use `family` and `value`. Every rendered badge carries `data-tone` (`neutral | info | warning | success | danger`) so tests and browser proofs can assert the tone without reading class names.
- **Neutral is the shipped request-draft treatment** (`border-border bg-surface-muted text-foreground-secondary` on the outline variant), not the `muted` Badge variant, because the direction names `--color-text-secondary` for neutral text and the request draft badge already passes the contrast check.
- **`assessmentStatusPresentation` in `assessment-domain.ts` is replaced by the shared mapping** (re-export the assessment family from `status-badge.tsx` or delete it and migrate its three importers: `assessment-list.tsx`, `assessment-editor.tsx`, `request-hub.tsx`), so the request hub's assessment tile also says `Released`.
- **The question list groups through `orderQuestionnaire(definition)`** from `questionnaire-domain.ts`, which already returns sections with their questions in order; no second grouping rule.
- **Optional UI-D13 (`Generated by` → `Draft initiated by` on the released detail) is not taken.**
- **The plan ends with one full Playwright run rather than a targeted set** because the badges change on every collection surface the design-contract and conformance suites scan; a full run costs about the same as the eight-spec targeted set and leaves nothing unproven.
- **The Risk detail Alert retitle is taken (plan check, 2026-09-25):** `risk-details.tsx` line 110 becomes `Released assessment - read only` in Task 2, and the one-line text edit to `risk-register-workflow.spec.ts` line 8 (`releasedNoticeHeading`) lands in Task 4 before the full run, so the surface and the spec change together; plan 08-08 then extends that spec on top of it (text edits precede the geometry work, as the research serialisation table orders it).
- **File count accepted under D-49 (plan check, 2026-09-25):** the plan lists 26 files across four tasks, above the 15-file guideline, because its edits are mechanical multi-site changes of one kind (every status call site migrated to the shared badge, the copy strings, and the assertions that follow them) and the executor runs with a large context; it is not split, and the four tasks keep disjoint file sets.
