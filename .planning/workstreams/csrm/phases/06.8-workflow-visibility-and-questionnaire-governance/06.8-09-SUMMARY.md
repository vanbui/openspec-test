# Phase 06.8 Plan 09: Workflow Visibility and Questionnaire Governance Summary

The analyst request queue now defaults to work requiring analyst action, with explicit
Awaiting Requestor, Generation in progress, and Released buckets. Bucket selection stays
inside the existing authorised collection scope; the controller loads that bounded scope,
filters it with the lifecycle projection, then derives paging totals from the filtered set.
The five-field queue projection is unchanged.

The Requestor dashboard now shows an accessible My Assessment Requests region with one
card per request status. Each card uses the shared status label, exposes an accessible
count, states when its count is zero, and opens the existing owner-scoped list with the
matching status filter. The dashboard reads the existing typed list capability once per
status and uses its pagination total; any failed lifecycle read preserves the dashboard's
existing permission-denied or error behavior.

## Defects found and fixed after execution

1. **The status filter vocabulary was widened for every queue.** Adding the released statuses to
   the one shared reviewable set let the action queue be asked for `approved` work, which the
   mounted denial test forbids as query expansion. The permitted statuses are now chosen from
   the selected bucket, so the released bucket can filter by `approved` and `closed` while the
   action queue still refuses them.
2. **The queue read the whole reviewable scope with no bound.** Three of the four buckets are
   decided by facts no Strapi filter can express — a derived lifecycle step and the volatile
   generation-job registry — so the scope is classified in the application. That is defensible;
   an open `for (;;)` scan is not. The scan is now explicitly bounded, and pushing the
   classification into the database is recorded as Phase 8 hardening work.
3. **Presentation:** a single request read "1 requests".

Two existing assertions changed deliberately. The mounted queue test asserted that a request
whose released questionnaire is still being drafted appears in the unfiltered queue; under D-12
that request is waiting with the Requestor, so it is now asserted absent from the default action
queue and present under the awaiting-requestor filter — visible, but not diluting the queue. The
dashboard's status-badge assertions are now scoped outside the new lifecycle cards, which name
the same states; the rule they protect is unchanged, and the empty-state note is asserted over
every card rather than once.
