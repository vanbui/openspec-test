| Boundary | Description | Data Crossing |
|----------|-------------|---------------|

| Public HTTP → Strapi static and plugin routes | Anything served without CSRM's record rule | `/uploads/`, `/csrm-private/`, `/api/upload*` |
| Strapi → object store | Stored bytes and short-lived signed reads | File bytes, presigned GET URLs (60 s) |
| Multipart parser → OS temp directory | Untrusted bytes are written to disk before any policy runs | Formidable temporary files |
| Web server → attachment operations | An authenticated caller names a request (and a file, a note) and sends a file or a change | Request id, attachment id, note id, file, `removed`, `included` |
| Requestor birthright → attachments grant | Every identity, the service agent included, holds the Requestor grant, so the readers rule decides | The request's files |
| Concurrent writers → one request's counts | Uploads, restores and removals must keep the active (20) and stored (60) bounds exact | Active and stored counts, event log |
| Storage → Strapi | Stored bytes may be altered outside CSRM | Stored bytes, recorded SHA-256 |
| Scanner verdicts → availability | A later verdict changes what readers can reach | `scanStatus`, detection |
| Strapi → web server → browser | Stored bytes leave the system as a download | Verified bytes, name, media type |
| Request read → every caller | The summary reveals whether files exist and how many | `attachments` summary, `files` counts |
| Analyst → AI inputs | A human choice decides which untrusted text the AI may read | `included`; extracted text (up to 20,000 characters) |
| Attachment text → prompt | Untrusted file content enters the model's input | Escaped `<attachment>` blocks inside `<requestorData>` |
| Run record → readers | What the AI used is recorded and shown to analysts | v3 context summary (ids, digests, counts) |
| Strapi error body → web server | Reason and detection strings cross into rendered copy | Closed reason, detection name |
| Browser → Server Action | A chosen file and request id cross into the web server | Multipart body up to 26 MB on four pages, 6 MiB elsewhere |
| Browser memory → tab | Unsent files are kept for the tab without persistence | `File` objects |
| Server list → client controls | Server-provided actions decide which controls render | `actions`, `ai.canChange` |
| Extracted text → browser | Untrusted file text is displayed to the analyst | Preview text |
| Repository → deployment | Operators configure storage, scanning and the reverse proxy from the README | S3 bucket settings, IAM policy, clamd limits, proxy body limits |
