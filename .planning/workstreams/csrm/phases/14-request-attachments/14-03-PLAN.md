## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: CSRM can decide whether a file may be kept. One screening call checks the name, the size and the content against the allow-list, digests the bytes and asks a malware scanner, each refusal with its closed reason, and every outcome becomes a security event line that never holds the file's name or content.

<objective>
Build the screening pipeline Phase 14's upload and Phase 20's evidence files share: the attachment policy (types, limits, names, retention), the content check (D-09), the scanner port with its development double and its ClamAV adapter (D-12, D-14), the attachment configuration with boot validation and the `.example` settings (D-15), and the security event log Phase 19 and Phase 17 reuse (D-37).

Purpose: COLLAB-02 criterion 2 at the module level; the shared modules of Orchestrator Confirmations.
Output: seven Strapi modules, a fake `clamd`, the hostile fixture builders, five unit test files, the settings in `apps/backend/.env.example`.

Edits Strapi source? Yes (no route). Changes the specification? No. Runs Playwright? No. Regenerates `served-operations.json`? No.
Scope note: 16 files: seven screening modules (the screen entry, the policy, the content check, the scanner port, the ClamAV adapter, the configuration and the security event log); `index.ts`'s boot validation and the `.env.example` settings; two test helpers (the fixture builders and the fake `clamd`); and five unit test files. They change together because `screenAttachment` composes the policy, the content check and the scanner and logs every outcome, and the configuration chooses the scanner, so one tracer proves them as one pipeline; a split would leave a scanner with no screen, or a screen with no scanner (accepted, as 14-06).
</objective>

## Recorded planning decisions

- **Policy** (`attachment-policy.ts`): `ATTACHMENT_TYPES = ["pdf", "docx", "xlsx", "pptx", "csv", "txt", "png", "jpeg"]`; `ATTACHMENT_MEDIA_TYPES` (`application/pdf`, the three `application/vnd.openxmlformats-officedocument.*` types, `text/csv`, `text/plain`, `image/png`, `image/jpeg`); `ATTACHMENT_EXTENSIONS` (`.pdf .docx .xlsx .pptx .csv .txt .png .jpg .jpeg`); `MACRO_ENABLED_EXTENSIONS` (`.docm .xlsm .pptm .dotm .xltm .potm`); `LEGACY_OFFICE_EXTENSIONS` (`.doc .xls .ppt`); `TEXT_BEARING_ATTACHMENT_TYPES` (all but `png` and `jpeg`); `ATTACHMENT_LIMITS = { maxBytes: 26_214_400, maxActivePerRequest: 20, maxStoredPerRequest: 60, noteWindowMinutes: 60, textCapCharacters: 20_000, eventLogMaxEvents: 200 }`; `ATTACHMENT_RETENTION_YEARS_AFTER_CLOSURE = 7`; `storageExtensionFor(type)` (`.jpg` for `jpeg`); `sanitiseAttachmentName(raw) → string | null` (takes the part after the last `/` or `\`, removes C0 and C1 controls and U+200E, U+200F, U+061C, U+202A to U+202E and U+2066 to U+2069, trims, and when longer than 255 characters shortens the stem and keeps the extension; an empty result is `null`); `claimedTypeFor(name) → { type } | { refusal: "ATTACHMENT_MACRO_ENABLED" | "ATTACHMENT_LEGACY_OFFICE" | "ATTACHMENT_TYPE_NOT_ALLOWED" }`.
- **Content check** (`content-check.ts`): `sniffSignature(bytes) → "pdf" | "png" | "jpeg" | "zip" | "cfb" | "text" | "binary"` (`%PDF-`; `89 50 4E 47 0D 0A 1A 0A`; `FF D8 FF`; `50 4B 03 04`; `D0 CF 11 E0 A1 B1 1A E1`; text is UTF-8 decoded with `fatal: true` after an optional BOM, or UTF-16 after its BOM; a NUL outside UTF-16 or an `MZ`/`\x7fELF` start is `binary`). `checkAttachmentContent({ fileName, bytes }, { probePdf }) → Promise<{ ok: true, type } | { ok: false, reason }>` in the order: claimed type from the extension; CFB → `ATTACHMENT_ENCRYPTED` when its directory holds the UTF-16LE name `EncryptedPackage`, else `ATTACHMENT_LEGACY_OFFICE`; ZIP → `readZipDirectory` (flag bit 0 → `ATTACHMENT_ENCRYPTED`; any other bound → `ATTACHMENT_CONTENT_MISMATCH`), then `ooxmlMainPart` (macro → `ATTACHMENT_MACRO_ENABLED`; a main type for another claimed type or no `[Content_Types].xml` → `ATTACHMENT_CONTENT_MISMATCH`); PDF → `probePdf` (`password` → `ATTACHMENT_ENCRYPTED`, `invalid` → `ATTACHMENT_CONTENT_MISMATCH`); PNG, JPEG and text must equal the claimed type; `binary` → `ATTACHMENT_CONTENT_MISMATCH`. The OOXML main types are 14-RESEARCH's (`…wordprocessingml.document.main+xml`, `…spreadsheetml.sheet.main+xml`, `…presentationml.presentation.main+xml`), confirmed by the fixtures.
- **Scanner** (`scanner.ts`): `type ScanVerdict = { kind: "clean"; engine } | { kind: "infected"; engine; detection } | { kind: "not-scanned"; engine; cause: "unavailable" | "timeout" | "limits" | "error" }`; `interface MalwareScanner { readonly name: string; scan(bytes: Uint8Array, signal?: AbortSignal): Promise<ScanVerdict> }`; `CSRM_TEST_MALWARE_SIGNATURE = "CSRM-TEST-MALWARE-SIGNATURE-7c1e4a"`; `createDevelopmentScanner()` (name `csrm-development-double/1`; detections `Eicar-Test-Signature` and `Csrm.Test.Signature`); `selectMalwareScanner(config, { connect? })`. The EICAR bytes are stored as `EICAR_XOR_5A_HEX` (the 68 bytes XOR 0x5A as hex) and decoded at module load; the executor computes that hex once in memory with `node -e` and never writes the plain string to any file, commit message, summary or test.
- **ClamAV** (`clamav-scanner.ts`): `createClamavScanner({ host, port, timeoutMs, connectTimeoutMs = 2_000 })` with `name` `clamav`; `zINSTREAM\0`, 65,536-byte chunks each prefixed by a 4-byte big-endian length, then four zero bytes; `zVERSION\0` gives the engine string, cached for 10 minutes; `parseClamdReply(reply)`: `stream: OK` → clean; `stream: {name} FOUND` → infected, except a name starting `Heuristics.Limits.Exceeded` → `not-scanned` `limits`; a reply containing `size limit exceeded` → `limits`; `ERROR` → `error`; `ECONNREFUSED`, `EPIPE` or `ECONNRESET` → `unavailable`; the timeout → `timeout`.
- **Screening** (`screen-attachment.ts`): `screenAttachment({ fileName, bytes }, { scanner, probePdf, signal })` → `{ outcome: "clean" | "not-scanned", name, type, byteSize, sha256, engine, cause? }` or `{ outcome: "refused", reason, detection?, engine?, name?, type?, byteSize, sha256? }`: name (`null` → `ATTACHMENT_TYPE_NOT_ALLOWED`), empty → `ATTACHMENT_EMPTY`, over `maxBytes` → `ATTACHMENT_TOO_LARGE`, the content check, the SHA-256 (`node:crypto`), then the scan (`infected` → `ATTACHMENT_MALWARE_FOUND` with the detection). It stores nothing and logs nothing; the caller logs.
- **Configuration** (`attachment-config.ts`): settings `CSRM_ATTACHMENT_STORAGE` (`local`, `s3`), `CSRM_ATTACHMENT_LOCAL_DIR`, `CSRM_ATTACHMENT_S3_BUCKET`, `CSRM_ATTACHMENT_S3_REGION` (default `ap-southeast-2`), `CSRM_ATTACHMENT_S3_KMS_KEY_ID`, `CSRM_ATTACHMENT_S3_ENDPOINT`, `CSRM_ATTACHMENT_SCANNER` (`development`, `clamav`), `CSRM_CLAMAV_HOST`, `CSRM_CLAMAV_PORT`, `CSRM_CLAMAV_TIMEOUT_MS` (default 60,000; 1,000 to 600,000). `readAttachmentConfig(env, { appRoot }) → { storage, scanner, available, unavailableReason }`; the development key is `NODE_ENV === "development" && CSRM_ENVIRONMENT === "development"` (the first two terms of `development-identity-enabled.ts`), whose defaults are `local` at `.tmp/attachments` and `development`; elsewhere unset storage or scanner gives `available: false` with `ATTACHMENTS_NOT_CONFIGURED`; invalid values, an incomplete S3 block (bucket or KMS key missing) or ClamAV block (host or port missing, port outside 1 to 65,535), a local directory resolving inside `public/`, and `development` scanning outside the key throw `AttachmentConfigurationError` with the variable's name. `assertAttachmentConfiguration(strapi)` stores the result with `strapi.config.set("csrm.attachments", config)` and logs one info line naming storage and scanner kinds (never a bucket or host); `attachmentConfigOf(strapi)` reads it.
- **Security events** (`security-event-log.ts`): `SECURITY_EVENT_SCHEMA_VERSION = 1`; event names `attachment.uploaded`, `attachment.refused`, `attachment.quarantined`, `attachment.scan_verdict`, `attachment.blocked`, `attachment.downloaded`, `attachment.integrity_failed`, `attachment.removed`, `attachment.restored`, `attachment.ai_inclusion_changed`; `type AttachmentSecurityEvent = { name; actor: { documentId, displayName } | { system: "rescan" }; requestId; attachmentId?; fileType?; byteSize?; sha256?; outcome; reason?; detection?; from?: boolean; to?: boolean }` (no name, content or text field exists); `type SecurityEvent = AttachmentSecurityEvent` (Phase 19 adds export and import members, Phase 17 its people-search member); `SECURITY_EVENT_LEVELS` (warn for `attachment.blocked`, `attachment.integrity_failed`, and `attachment.refused` with `ATTACHMENT_MALWARE_FOUND`; info otherwise); `formatSecurityEventLine(event, at)` returns `csrm.security_event ` followed by JSON with keys in a fixed order plus `schemaVersion` and `at` (UTC ISO); `logSecurityEvent(logger, event, at = new Date())`.
- **`.env.example`** gains a commented block: the development defaults (`# CSRM_ATTACHMENT_STORAGE=local`, `# CSRM_ATTACHMENT_LOCAL_DIR=.tmp/attachments`, `# CSRM_ATTACHMENT_SCANNER=development`), then a commented production block (`s3` with bucket, `ap-southeast-2`, KMS key and endpoint; `clamav` with host, port 3310 and 60000 ms), with a line pointing to `apps/backend/README.md` (14-17 writes the deployment section). No value is set uncommented.
