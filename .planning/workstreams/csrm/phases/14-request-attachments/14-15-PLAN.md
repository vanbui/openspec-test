## Recorded planning decisions

- **Store scope**: the composer's files live in `file-store.tsx` under scope `composer` for the owner and request; a posted note's rows move to scope `note:{noteId}`; `handOffToComposer(files)` adds chosen files to the composer scope (used by the Files section).
- **Composer** (`note-composer.tsx`): `Attach files` (outline small, `Paperclip`) before `Add note` opens the file chooser; the composer is an X-19 drop target while files are dragged over it; chips in an `ul` named `Files to add with this note` (`FileChip` with the size and `Remove {name} from the list`); §1.3's pre-checks on choosing; the hint `Files are checked for malware, then added with your note.` when files are attached; on `Add note` with files and no text, the §4 Forms error `Write a note to say what these files are.` under the textarea. Posting: the optimistic note (13 §9.1) appears with `Adding…` and its files as X-20 rows at `Waiting`, the composer clears; on the note's success the queue sends each file with `noteId` one at a time; on the note's failure the note is removed and its text and files return to the composer. The composer arms the beforeunload-only guard while it holds files.
- **Note item** (`note-item.tsx`): under the body, an `ul` named `Files with this note`: settled files as `FileChip`s (icon, name as a record link to `#file-{id}`, size, `Download {name}` icon-only through `downloadAttachmentAction` and `saveFile`, or the file's badge for a pending, blocked, unavailable or removed file); unsettled rows as X-20 rows; a row refused with `ATTACHMENT_NOTE_INVALID` offers `Add with a new note: {name}` (outline small), moving the file to the composer scope.
- **Chip** (`file-chip.tsx`): X-21's chip exactly (1px `--color-border-default`, `--radius-md`, 8px by 12px padding, the name on one line with an ellipsis beyond 28rem and the full name in the DOM and the accessible names); only a chip shows the neutral `Removed` badge.
- **Thread wiring**: both request pages group the attachment list by `note.documentId` and pass `filesByNote` to `NotesSection`, which passes each note's files to `NoteItem` through `NotesThread`.
- **Files section** (`files-section.tsx`): after submission, for the requestor and a human analyst with `canAdd`, the field labelled `Add files with a note` with the hint line `Files are added with a note, so everyone knows what they are.` before the type list; choosing or dropping calls `handOffToComposer`, scrolls to `#note-composer`, focuses its textarea and shows `Write a note to say what these files are, then add it.` above the chips (UI-D6).
- **Closed notes** (`unsent-note-well.tsx`): with unsent files, the well lists their names beneath the text, and `Discard text` reads `Discard note` and discards both under the same Undo toast.
