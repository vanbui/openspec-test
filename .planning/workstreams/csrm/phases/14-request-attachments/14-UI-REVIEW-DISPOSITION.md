# Phase 14 UI review disposition

The independent UI audit (`14-UI-REVIEW.md`, 2026-10-11, committed in `170b5315`) scored 21/24 against `14-UI-SPEC.md` and the design direction. It found no blocker and raised six warnings, UI-01 to UI-06. It was a code-only audit at `598bca87`, after the stage B review and walk fixes. The pilot ruled on all six on 2026-10-11:
- UI-01: below 768px a chip's state badge takes its own line. Prove it in the browser at 375 with the longest badge, `Waiting for malware check`, extending the seeded file-state fixture behind its existing gates if no note carries the waiting file.
- UI-02: Phase 14's own sheets take the direction's drawer motion, the phone preview's slide included. The shared Sheet primitive is app-wide, so it is left unchanged and recorded in `.planning/WINDOWS.md`.
- UI-03: the design direction wins. Below 768px the composer chip's `Remove {name} from the list` and the note chip's `Download {name}` get the touch-target height, and 14-UI-SPEC records a dated amendment where it allowed 24px.
- UI-04: a row-level hook in DataTable, if it is small and leaves the other tables unchanged, and a pending row reads as pending in every cell.
- UI-05: the reading spinner is 16px.
- UI-06: the queue row's block padding is 16px, and the removed group's rows take it if the Spacing table's "card row" covers them.

Every fix was made test-first: the new test failed on the code before the fix and passes after it. Each row names the test and its failure. Where jsdom cannot lay out the page, the row also gives the browser proof, which failed before the fix and passes after. Dated `14-UI-SPEC.md` amendments (2026-10-11) record every changed value: §3.5, §4.3, the Accessibility contract (2.5.8), Spacing and Motion.

Each fix was checked with its focused tests. The final checks were run once:
- web typecheck: clean.
- focused web runs: 70 files and 1,268 tests, all passed. The run covered `src/components`, `src/features/attachments`, `src/features/request-notes` and `src/lib/performance`, plus the DataTable callers' `administration-workflow`, `assessment-list`, `released-assessment`, `questionnaire-workflow` and `shared-list-states-guard` tests. The other callers' tests made a second run of 19 files and 424 tests, all passed: `alert-list`, `questionnaire-list`, `request-table`, `risk-register`, `src/features/questionnaires` and `src/features/administration`.
- Strapi: `request-attachment-states-seed.integration.test.ts`, 2 of 2, run twice after the seed change. The source typecheck is clean.
- Playwright: 57 passed, desktop 35 and mobile 22. `request-attachments.spec.ts` passed 14 on desktop and 12 on mobile (its two desktop-only tests stay out of the mobile project). `request-notes.spec.ts` passed 10 on desktop and 10 on mobile.
- `performance.spec.ts` on desktop: 11 passed, with no override. Delivered JavaScript against each budget: `/app` 229,641 of 300,000 for both actors; `/app/requests` 251,953 of 300,000; `/app/requests/{documentId}` 295,889 of 300,000; `/app/questionnaires/{documentId}` 358,514 of 500,000; `/app/review/assessments/{documentId}` 318,810 of 460,000; `/app/risks` 263,182 of 300,000; `/app/risks/{documentId}` 293,710 of 300,000; `/app/reports/risk-exposure` 255,478 of 300,000; `/app/admin/controls` 250,377 of 300,000.
