## Recorded planning decisions

- **ZIP reader** (`zip-archive.ts`, no dependency): `readZipDirectory(bytes, bounds = ZIP_UPLOAD_BOUNDS)` finds the end-of-central-directory record (searching at most the last 65,557 bytes), refuses the ZIP64 locator or any `0xFFFF`/`0xFFFFFFFF` sentinel (`ZIP64_UNSUPPORTED`), reads every central entry (`name`, `method`, `flags`, `compressedSize`, `uncompressedSize`, `localHeaderOffset`), and refuses before inflating: more than `maxEntries` 10,000 (`ZIP_TOO_MANY_ENTRIES`), a declared total over `maxDeclaredTotal` 1,073,741,824 (`ZIP_TOO_LARGE`), any entry over `maxRatio` 200 (`ZIP_RATIO`), flag bit 0 (`ZIP_ENCRYPTED`), a method other than 0 or 8 (`ZIP_METHOD_UNSUPPORTED`), and offsets outside the buffer (`ZIP_MALFORMED`). `readZipEntry(bytes, entry, { maxOutputLength })` reads the local header, slices the data and returns stored bytes or `zlib.inflateRawSync(span, { maxOutputLength })`; `ERR_BUFFER_TOO_LARGE` becomes `ZIP_INFLATE_LIMIT`. `ZIP_EXTRACTION_MAX_INFLATED = 134_217_728`. `findZipEntry(directory, name)` is exact and case-sensitive. `ZipArchiveError` has a closed `code`.
- **OOXML scanner** (`ooxml-text.ts`, about 150 lines, not a general XML parser): `tokenizeXml(xml)` yields tags and text, decodes the five predefined entities and numeric references, and throws `OoxmlTextError("DOCTYPE_REFUSED")` on `<!DOCTYPE` or `<!ENTITY`. `ooxmlMainPart(directory, bytes)` inflates `[Content_Types].xml` with a 1 MiB cap and returns `{ mainType, macro }` where `macro` is true for a `macroEnabled` main type or any `vbaProject.bin` entry. `docxText` reads `word/document.xml`: `w:t` text, `w:p` ends a paragraph, `w:tab` a tab, `w:br` and `w:cr` line breaks, table cells joined by a tab and rows ended by a line break, `w:ins` kept, `w:delText` and `w:instrText` never read, `mc:Fallback` skipped. `pptxText` reads slides in `p:sldIdLst` order through `ppt/_rels/presentation.xml.rels`, `a:t` runs and `a:p` paragraphs, never `ppt/notesSlides/*`.
- **XLSX reader** (`csrm/spreadsheets/xlsx-reader.ts`, the only importer of `read-excel-file`): `readWorkbookSheets(bytes, { maxInflated = ZIP_EXTRACTION_MAX_INFLATED })` first checks with `readZipDirectory` that the declared size of `xl/worksheets/*` plus `xl/sharedStrings.xml` is at most `maxInflated`, then calls `read-excel-file/universal`'s default export with `trim: false` and returns `[{ name, rows }]`; `xlsxCellText(cell)` gives dates as `YYYY-MM-DD`, booleans as `TRUE`/`FALSE`, numbers as `String(n)`. `XlsxReadError` wraps every failure. If `tsc` cannot resolve `read-excel-file/universal` under the backend's module resolution, import the entry the package's README names for Node buffers and record which in the summary.
- **Worker** (`extraction-worker.ts`): reads `workerData` `{ op: "probe-pdf" | "extract", type, bytes: ArrayBuffer, cap }` and posts `{ ok: true, kind: "ok" | "password" | "invalid" }` for a probe or `{ ok: true, text, available }` for an extraction, else `{ ok: false, code }`. PDF: `getDocumentProxy(new Uint8Array(bytes), { isEvalSupported: false, verbosity: 0 })`, pages read one at a time through `getTextContent()` (each item's `str`, plus a line break after `hasEOL` items and after each page), `page.cleanup()`, keeping the first `cap` characters and counting the rest, then `pdf.loadingTask.destroy()`; never `unpdf`'s `extractText` (it loads every page at once). pdf.js `PasswordException` → `password`; any other open failure → `invalid`. DOCX and PPTX through `ooxml-text.ts`; XLSX: a `Sheet: {name}` line, then rows of `xlsxCellText` joined by tabs with trailing empty cells dropped; CSV and TXT through `TextDecoder("utf-8", { fatal: true })`, or UTF-16LE/BE after their BOM.
- **Runner** (`extraction.ts`): `EXTRACTION_LIMITS = { heapMb: 768, wallClockMs: 30_000, pdfProbeMs: 10_000 }`; one extraction at a time through a single-slot promise queue; `new Worker(path.join(__dirname, "extraction-worker.js"), { workerData, transferList: [buffer], resourceLimits: { maxOldGenerationSizeMb } })`; a timer calls `worker.terminate()` on overrun. `probePdf(bytes, limits?) → Promise<"ok" | "password" | "invalid">` (a timeout or crash is `invalid`). `extractAttachmentText({ type, bytes, cap = 20_000 }, limits?) → Promise<{ ok: true, text, available, kept, truncated, extractor } | { ok: false, reason: "ATTACHMENT_TEXT_UNAVAILABLE" }>`; empty text after normalisation is unavailable. `normaliseExtractedText(text)` removes C0 and C1 controls other than `\t` and `\n`, converts CRLF and CR to LF and applies NFC. `EXTRACTOR_VERSION = "csrm-extract/1 unpdf/1.8.1 read-excel-file/9.3.10"`. `limits` defaults to `EXTRACTION_LIMITS`; tests pass smaller ones to prove the timeout and heap paths.
- **Fixtures** (`tests/helpers/attachment-fixtures.ts`, deterministic builders with a CRC-32 and a stored/deflated ZIP writer, a minimal PDF writer with correct cross-reference offsets, a PNG writer and a JFIF signature stub): `buildPdf(pages)`, `buildPasswordPdf()` (an `/Encrypt` dictionary `/Filter /Standard /V 1 /R 2` with fixed 32-byte `/O` and `/U` that pdf.js cannot open with an empty password), `buildScannedPdf()` (a page with no text operators), `buildDocx(paragraphs, { table?, deletedText?, comment?, doctype? })`, `buildXlsx(sheets)` (with a formula cell carrying a cached value), `buildPptx(slides, { notes? })`, `buildPng()`, `buildJpegStub()`, `buildZipBomb()`, `buildZip64Archive()`, `buildEncryptedFlagZip()`, and `writeAttachmentFixtures(directory)`. The committed fixtures are written once by `writeAttachmentFixtures`; their known text includes `The vendor's offshore support team has administrator access.` in the PDF (UAT-013's fact). `.gitattributes` gains `apps/backend/tests/fixtures/attachments/** binary` so `core.autocrlf` never rewrites them. 14-03 adds the hostile builders the content check needs.
