## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: a file can be kept privately. Its bytes go into private storage under a generated key and come back identical through Strapi only; nothing is served from `/uploads/`, the upload plugin's own public routes are gone, and no temporary file survives a request.

<objective>
Build the storage port over the upload plugin with a CSRM private local provider and the private S3 configuration (D-06, D-07), unmount the upload plugin's content-API routes with their matrix and inventory records (D-08), add the global multipart cleanup (14-RESEARCH Pitfalls 2 and 3), and pin storage and scanning in the Strapi test harness (D-15).

Purpose: ROADMAP success criterion 2 begins with storage nobody can reach directly; Phase 20's evidence files reuse the port.
Output: three storage modules, one middleware, a fake object store, harness pins and options, three test files, the matrix and inventory updated.

Edits Strapi source? Yes. Changes the specification? No. Runs Playwright? No. Regenerates `served-operations.json`? Yes (the upload plugin's content-API routes leave the inventory). Runs after 14-01's approval (D-40).
</objective>

## Recorded planning decisions

- **Private local provider** (`private-local-provider.ts`): `createPrivateLocalProvider(directory)` returns `{ upload, uploadStream, delete, checkFileSize, isPrivate, getSignedUrl }`: `upload(file)` writes `file.buffer` to `path.join(directory, file.hash + file.ext)` after checking `file.hash` matches `STORAGE_KEY_PATTERN` or the plugin's own hash form (admin Media Library uploads keep working), creating the directory with `recursive: true`, and sets `file.url = "/csrm-private/" + file.hash + file.ext`; `uploadStream` pipes the stream to the same path; `delete(file)` unlinks it (missing is not an error); `checkFileSize` is a no-op (CSRM enforces its own bound); `isPrivate()` returns `true`; `getSignedUrl(file)` returns `{ url: file.url }`, which no middleware serves. `/csrm-private/` is never routed.
- **Registration** (`register-attachment-storage.ts`): `registerAttachmentStorage(strapi)` runs in the application's `register()` after `assertAttachmentConfiguration(strapi)` (Strapi runs plugin registers first, `Strapi.js:328-329`): when `strapi.config.get("plugin::upload").provider` is `local`, it calls `strapi.plugin("upload").provider.extend(createPrivateLocalProvider(directory))` with the configured local directory, or `{appRoot}/.tmp/attachments` when attachments are unconfigured, so the Media Library is private too; when it is `aws-s3` and `providerOptions.baseUrl` is set, it throws `AttachmentConfigurationError("CSRM attachments refuse an upload baseUrl")`; then it sets `(strapi.plugin("upload").routes["content-api"] as { routes: unknown[] }).routes = []`. `attachmentUploadPluginConfig(env)` returns `{}` unless `CSRM_ATTACHMENT_STORAGE` is `s3`, then `{ provider: "aws-s3", providerOptions: { rootPath: "csrm/attachments", s3Options: { region, ...(endpoint ? { endpoint, forcePathStyle: true } : {}), params: { Bucket, ACL: undefined, signedUrlExpires: 60 } }, providerConfig: { encryption: { type: "aws:kms", kmsKeyId } } } }` (14-RESEARCH Code Example 3); credentials come from the SDK's default chain.
- **Storage port** (`storage-port.ts`): `STORAGE_KEY_PATTERN = /^csrm_[0-9a-f]{32}$/`; `createAttachmentStorage(strapi)` returns `{ put(bytes, { type }), read(fileId), remove(fileId) }`. `put` makes `hash = "csrm_" + randomUUID().replaceAll("-", "")`, `ext = storageExtensionFor(type)`, calls `provider.upload({ name: hash + ext, hash, ext, mime: ATTACHMENT_MEDIA_TYPES[type], buffer, size, sizeInBytes })`, then `strapi.db.query("plugin::upload.file").create({ data: { name: hash + ext, hash, ext, mime, size (KB, two decimals), sizeInBytes, url, provider: strapi.config.get("plugin::upload").provider, provider_metadata, folderPath: "/" } })` and returns `{ fileId, hash, ext }`. `read(fileId)` loads the record (missing → `AttachmentStorageError("STORAGE_FILE_MISSING")`), checks `hash` against `STORAGE_KEY_PATTERN` (else `STORAGE_KEY_INVALID`), then for `local` reads `path.join(directory, hash + ext)` and for `aws-s3` gets `provider.getSignedUrl(record)`, refuses a URL without `X-Amz-Signature` (`STORAGE_URL_UNSIGNED`), fetches it with `redirect: "error"`, refuses a status other than 200 or a `content-length` above 26,214,400 (`STORAGE_READ_FAILED`), and returns the bytes; the URL never leaves the function and is never logged. `remove(fileId)` calls `provider.delete(record)` and deletes the record. `AttachmentStorageError` has a closed `code`.
- **Cleanup middleware** (`csrm-multipart-cleanup.ts`): the factory shape of `csrm-development-identity.ts`; `await next()` in `try`, and in `finally` every `filepath` (or `path`) under every key of `ctx.request.files`, arrays included, is unlinked with errors swallowed. `config/middlewares.ts` lists `'global::csrm-multipart-cleanup'` directly after the `strapi::body` entry. It also removes the CSV import's leaked `file` part.
- **Harness** (`strapi-http-harness.ts`): before boot it sets `CSRM_ATTACHMENT_STORAGE=local`, `CSRM_ATTACHMENT_LOCAL_DIR` to `{appDir}/.tmp/authorization-http/attachments-{pid}` (removed on `close()`), `CSRM_ATTACHMENT_SCANNER=development`, and adds both to the restored-variable list; new options on `AuthorizationHttpHarnessOptions`: `attachmentScanner?: { kind: "clamav"; host: string; port: number; timeoutMs?: number }` and `attachmentStorage?: { kind: "s3"; endpoint: string; bucket: string; kmsKeyId: string }` (also setting dummy `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_REGION` for the boot only); a harness helper `attachmentStorage()` returns `createAttachmentStorage(strapi)` loaded from `dist/src/csrm/files/storage-port.js`, as the harness already loads `seed-development-api-token.js`; `attachmentStorageDirectory()` returns the pinned directory.
- **Fake object store** (`fake-object-store.ts`, modelled on `fake-openai-compatible-server.ts`): an HTTP server implementing path-style `PUT`, `GET` and `DELETE` on `/{bucket}/{key}`, storing bodies (decoding `content-encoding: aws-chunked` framing), answering `GET` only when the query has `X-Amz-Signature`, recording each request's method, path, headers (`x-amz-acl`, `x-amz-server-side-encryption`, `x-amz-server-side-encryption-aws-kms-key-id`) and status. Fake-store tests use files under 5 MiB (14-RESEARCH Pitfall 6).
- **Matrix and inventory**: the five upload rows in `authorization-matrix.ts` (`POST:/api/upload`, `GET:/api/upload/files`, `DELETE:/api/upload/files/:id`, `GET:/api/upload/files/:id`, `GET:/api/upload/files/page`) keep their ids and now expect every caller, the full-access token included, to get 404 on `GET` and 405 on `POST` and `DELETE` (`strapi-http-hardening.md` "Unmounted paths"). `served-operations.integration.test.ts` asserts no `pluginRoutes` entry has a path starting `/api/upload`, and that an admin upload route still answers 401 without an admin session (the executor reads `@strapi/upload/dist/server/routes/admin.js` for a `GET` route path and names it in the test).
