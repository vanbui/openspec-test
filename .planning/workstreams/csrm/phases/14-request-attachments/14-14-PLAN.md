**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: Jane creates the payroll SaaS request with the vendor's security pack, the data-flow document and the completed security questionnaire, and they arrive with the draft; nothing she chose is lost if a file fails or she leaves, and she cannot submit while files are still on their way.

## Recorded planning decisions

- **Gate** (`lib/security/action-body-limit.ts`, no directive): `DEFAULT_ACTION_BODY_LIMIT_BYTES = 6_291_456`; `ATTACHMENT_ACTION_BODY_LIMIT = "26mb"`; `ATTACHMENT_ACTION_PATHS = [/^\/app\/requests\/[^/]+$/, /^\/app\/requests\/[^/]+\/edit$/, /^\/app\/review\/requests\/[^/]+$/]` (the first also matches `/app/requests/new`); `exceedsActionBodyLimit(request)` is true only for a `POST` carrying the `next-action` header, on a path outside the list, whose `content-length` is missing, not a number or above the default. `proxy.ts` calls it first and answers `new NextResponse(null, { status: 413 })`; its matcher is unchanged.
- **Next config**: `experimental: { serverActions: { bodySizeLimit: ATTACHMENT_ACTION_BODY_LIMIT }, proxyClientMaxBodySize: ATTACHMENT_ACTION_BODY_LIMIT }` with a comment naming Pitfall 1 (without the second, bodies over 10 MB reach the action truncated).
- **Actions**: `createRequestAction(input, options?: { stayOnPage?: boolean })` and `updateRequestAction(input, options?)` keep today's redirect without options; with `stayOnPage: true` they return `{ ok: true, data: { documentId } }` and neither revalidate nor redirect.
- **Form** (`request-form.tsx`): a `FormSection` `Supporting files` after `Scope and timing` with §2.1's description (create) or §2.3's (edit); in create mode the queue runs deferred (rows stay "chosen, not yet sent"); on `Save draft` with rows: validate as today (rows stay on errors); call the create (or, once the draft exists, the update) with `stayOnPage: true`; on success `window.history.replaceState(null, "", "/app/requests/{id}/edit")`, the X-1 status `Draft saved at {time}`, `Save draft` showing `Adding files…` with the inline spinner and not re-entrant while the queue sends; all added or pending → `router.replace("/app/requests/{id}")`; any not added → the §2.2 danger `Alert` (focused, `tabIndex={-1}`) with `Go to draft` → `/app/requests/{id}`. Without rows, Save draft behaves as today. In edit mode the section renders `FilesList` and the field with immediate adding. The form's leave guard covers unsaved fields or rows chosen before the draft exists with §10's `Leave this request?` dialog copy.
- **Queue** (`upload-queue.tsx`): a `mode: "immediate" | "deferred"` prop; `deferred` rows wait until the form calls the queue's `sendAll(requestId)`; a `settled` callback reports `{ added, pending, notAdded }`.
- **Submit dialog** (`request-workflow-actions.tsx`): reads `useFilesInFlight(ownerKey, requestId)` and the kept rows; in flight → the line `Wait until your files are added, then submit.` under the description and the confirm disabled; kept not-added rows → `{k} {file wasn’t|files weren’t} added. Submit anyway, or retry {it|them} first.`; confirming clears the request's kept rows (§1.5).
- **Pitfall 17 guard**: a unit test reads `request-form.tsx` and `files-section.tsx` and asserts each imports the queue module that imports `uploadAttachmentAction`.
