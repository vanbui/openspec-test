## Phase Goal

**As a** Requestor or Security Analyst, **I want to** attach supporting files to a request at any point, **so that** the assessment can use the vendor pack, data flows and spreadsheets the business already has.

This plan's slice: on the questionnaire and the assessment he is working on, Bob sees how many files the request holds and how many feed the AI, and he is told when a file has been included, excluded or removed since the last generation.

## Recorded planning decisions

- **Counts** (`attachmentAnalystCounts({ strapi, requestId })` → `{ count, included }`): `count` is files not removed; `included` is files with `aiTextIncluded`, `scanStatus: "clean"` and `removedAt` null. The analyst reads' request summary gains `files: { count, included }`.
- **Signal** (`changedAttachmentInputs({ strapi, requestId, baseline })` → `[{ documentId, fileName, change }]`): `baseline` is `{ kind: "run", includedIds } | { kind: "generated", generatedAt } | null` from the same latest completed context-wide run Phase 12 resolves for `generation`; with a run, `included` for current included ids not in `includedIds`, and for each id in `includedIds` not currently included `removed` when the file is removed, else `excluded`; with only `generatedAt`, `included` for files whose `aiTextFacts.extractedAt` is later; with `null`, none. Ordered by `uploadedAt`. `attachment-ai-signal.ts` never imports `ai-inputs-signal.ts` (no cycle).
- **Merged signal (S-1)**: the merge lives in `apps/backend/src/csrm/ai/ai-inputs-signal.ts`. Its `AiInputsChanged` type becomes `{ count, notes, files }`; the pure `aiInputsChanged({ markedNotes, changedFiles, baseline })` returns `null` when `baseline` is `null` or when neither notes nor files changed, and otherwise `{ count: notesChanged + filesChanged, notes, files }`, where `notes` may be `[]` when `files` is not (and the reverse), each list sorted (notes by `sequence`, files by `uploadedAt`) and sliced at 500 while `count` counts every change. `loadAiInputsChanged` derives the file baseline from the same run it already reads (the v3 summary's `attachments.included` ids, a v1 or v2 run including none) or the same `generatedDate` fallback, calls `changedAttachmentInputs`, and passes the result in. All three producers reach `loadAiInputsChanged`: `questionnaire-scope.ts` (`questionnaireAiInputsChanged`), `assessment-scope.ts` (`assessmentAiInputsChanged`) and the request read controller `csrm-assessment-request.ts`, whose `requestQuestionnaireAiInputs` and `requestAssessmentAiInputs` delegate to those two for `RequestAiInputs` on `GET /csrm-assessment-requests/{id}` (true at `0e04b71`; if a producer builds the signal itself, it calls the merged loader instead, and the summary records which). The merge's cases live in `apps/backend/tests/ai-inputs-signal.unit.test.ts`; `attachment-ai-signal.unit.test.ts` holds the file rule (`changedAttachmentInputs`) only.
- **Spec**: the analyst questionnaire and assessment detail components gain `assessmentRequest.files` (`{ count, included }`, closed); the Requestor shapes are unchanged. The signal changes once, in the shared `AiInputsChanged` component that both `AiGenerationFacts` and `RequestAiInputs` reference: it gains a required `files` array of a new closed component `AiInputsChangedFile` (`{ documentId (minLength 1), fileName (minLength 1, maxLength 255), change: "included" | "excluded" | "removed" }`, `additionalProperties: false`) with `maxItems: 500`, `notes` drops `minItems: 1` (keeps `maxItems: 500`), `count` keeps `minimum: 1`, `required` becomes `["count", "notes", "files"]`, `additionalProperties` stays `false`, and the description states the count and non-null rule above.
- **Web parsers and types (S-1)**: `ai-generation-facts-schema.ts` adds `aiInputsChangedFileSchema` (`.strict()`) and `aiInputsChangedSchema` becomes `{ count: int ≥ 1, notes: array max 500, files: array of aiInputsChangedFileSchema max 500 }` `.strict()` with a refinement that fails when both lists are empty; `ai-assistance-domain.ts`'s `AiInputsChanged` type gains `files: { documentId: string; fileName: string; change: 'included' | 'excluded' | 'removed' }[]` so the `SameType` check holds; `request-schema.ts`'s `requestAiInputsSchema` keeps reusing `aiInputsChangedSchema` (its doc comment names files too), so the request read follows. 14-11 adds no web module; if the executor adds one, `zod-client-boundary.test.ts` gets its row (Z-1).
- **Renderer (S-1)**: `ai-inputs-changed.tsx`'s `aiInputsChangedSlot` and `AiInputsChangedBlock` show the block when `signal.notes.length + signal.files.length > 0` (today they test notes only), and render the file items after the note items; the heading and closing caption stay Phase 13's.
- **Line** (`assessment-request-link.tsx`, server component): after Phase 13's notes line, a third line in `--text-caption` / `--color-text-secondary`: a figure link (X-10) `{n} {file|files}` → `/app/review/requests/{id}#files`, then ` · {k} included in the AI inputs` when `k > 0`; with `n = 0`, `No files` (plain text).
- **Signal items** (in the changed-inputs list `AiInputsChangedBlock` renders, the slot the provenance header and the hub's cards are handed): one item per file after the note items, a record link `{name}` → `/app/review/requests/{id}#file-{fileId}` and the caption `Included since`, `Excluded since` or `Removed since` in `--text-caption`; the heading and closing caption are Phase 13's.
