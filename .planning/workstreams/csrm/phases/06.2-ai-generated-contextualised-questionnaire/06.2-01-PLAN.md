## Trust Boundaries
| Boundary | Description |
|---|---|
| analyst request→Strapi | Untrusted request ID and replacement acknowledgement cross into an authorised mutation. |
| provider→workflow | Proposed question data is untrusted until closed parsing completes. |
| job ID→registry | Opaque status identifiers can be guessed, replayed, or polled aggressively. |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-062-01 | Elevation | generation routes | high | mitigate | Separate FunctionAPI grants, authenticated analyst identity, and Strapi request scope; service role has no grant. |
| T-062-02 | Tampering | provider proposal | high | mitigate | Closed parser plus existing definition validator before any transaction write. |
| T-062-03 | Information Disclosure | job status | medium | mitigate | Actor-scoped registry reads, opaque IDs, populated public projection, and safe error mapping. |
| T-062-04 | Denial of Service | job execution | medium | mitigate | Request-keyed single flight, failed-only retry, TTL/cap cleanup, and bounded polling in the later UI plan. |
