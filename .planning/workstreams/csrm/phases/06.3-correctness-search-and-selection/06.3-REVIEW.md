# Phase 06.3: Code Review Report

**Reviewed:** 2026-09-07T21:44:45Z
**Depth:** standard
**Files Reviewed:** 62
**Status:** issues_found

## Summary

The owner/reviewer authorization path and the selector/hydration boundary were reviewed in context. The submitted selection API reports materially false pagination values, the assessment summary silently truncates at 1,000 records, and malformed review-list sort parameters are propagated to a server-side 400 instead of being normalized. The selector predicate replacement also left dead authorization code behind.

## Warnings

### WR-01: Selector pagination metadata is false after the first page

**File:** `apps/strapi/src/api/csrm-information-system/services/csrm-information-system.ts:34`; `apps/strapi/src/api/csrm-information-asset/services/csrm-information-asset.ts:21`

**Issue:** The selector returns `total: rows.length`, which is only the number of records in the current page, rather than the number matching the query. It also fabricates `pageCount` from whether the current page is full. For example, a 50-record result set with `pageSize=25` reports `total=25` on both pages and advertises a third page from page two. This violates the served pagination contract and will make any consumer that uses the returned metadata display incorrect result counts and enable navigation to an empty page.

**Fix:** Run a matching `count({ filters })` query and return `total` and `Math.ceil(total / pageSize)`, or remove pagination metadata and paging parameters until an authoritative count can be supplied. Apply the same shared implementation to systems and assets.

### WR-02: Assessment status summary silently omits records beyond the first thousand

**File:** `apps/strapi/src/api/csrm-assessment/controllers/csrm-assessment.ts:147`

**Issue:** `statusSummary` queries only `limit: 1_000` and then computes all status totals in memory. Once more than 1,000 assessments exist, the displayed `draft`, `inReview`, `approved`, and `total` values exclude the remaining records without signalling a partial response. The endpoint's contract represents these as complete summaries.

**Fix:** Obtain per-status counts (and total) through filtered `documents().count` calls, or use an aggregate query supported by the data layer. Do not derive a global summary from a capped `findMany` result.

### WR-03: Invalid review-list sort parameters produce an avoidable error page

**File:** `apps/web/src/features/assessments/assessment-service.ts:176`

**Issue:** `requestReviewQuerySchema` accepts every trimmed string up to 100 characters for `sort`, then `listAssessmentRequests` sends it unchanged. The server allowlist rejects unknown fields/directions, so a bookmarked or manually entered URL such as `?sort=title:sideways` turns the otherwise valid review page into its generic error state. The adjacent assessment parser normalizes sort to its allowlist instead.

**Fix:** Use `z.enum` for the server-supported values (`dueDate`, `submittedDate`, `requestNumber`, `title`, `requestStatus`, and `updatedAt`, each with `asc`/`desc`) and `.catch('submittedDate:desc')` before issuing the request.

## Info

### IN-01: Obsolete picker-query authorization helper remains unused

**File:** `apps/strapi/src/policies/csrm-authorization.ts:145-155`

**Issue:** `isCanonicalPickerPaginationQuery` is no longer referenced after authorization switched to `isSelectorQuery`. It is a duplicated, obsolete definition of selector classification that can drift from the policy/controller predicate if later revived.

**Fix:** Delete `isCanonicalPickerPaginationQuery` and retain `isSelectorQuery` as the sole selector-shape definition.
