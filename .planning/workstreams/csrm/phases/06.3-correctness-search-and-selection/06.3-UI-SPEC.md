# Phase 06.3 — UI Design Contract

> Visual and interaction contract for the Correctness, Search, and Selection phase. This contract extends the existing CSRM design direction; it does not introduce a new visual language.

| Token | Value | Usage |
|-------|-------|-------|

| sm | 8px | Input/button groups, selected-item chips |
| md | 16px | Control-group and card padding |
| lg | 24px | Page-section separation and mobile gutters |
| xl | 32px | Desktop page gutters and form-section separation |
| 2xl | 48px | Empty/error-state vertical padding |
| 3xl | 64px | Reserved page-level separation only |

Exceptions: controls have a minimum 36px visual height and a 44px target where the existing shell supplies it; table-row internal targets remain at least 24px. At 375px, controls stack with 16px page gutters; at 768px and above, search and status controls may share a row.

## Typography

Use the existing Inter token scale; this phase declares four display roles and only two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dense table/result metadata | 13px (`--text-table`) | 400 | 18px |
| Body, inputs, buttons, labels | 14px (`--text-body`) | 400 | 20px |
| State and panel heading | 16px (`--text-heading-sm`) | 600 | 24px |
| Page heading | 24px (`--text-heading-lg`) | 600 | 32px |

Use tabular numerals for result totals, page values, record identifiers, and counts. Long titles wrap in cards; desktop table titles truncate only after preserving the full value via accessible name/tooltip. Selected-item names truncate within their chip but remain available to assistive technology and in the remove control’s accessible name.

## Interaction and Responsive Contract

### Server-backed collections

- Apply the existing My Requests control pattern to My Questionnaires, My Risk Assessments, analyst Request review, analyst Questionnaire review, and analyst Risk Assessment review: labelled `type="search"` input, explicit **Search** submit button, record-specific **Status** select, active-filter chips, result count, and **Clear filters** only while a query or status filter is active.
- Search/filter submits reset to page 1. Sort and page-size changes reset to page 1; next/previous preserves active search, status, sort, and page size in URL query state. The visible total is the server-returned total, never the length of the current page.
- Status options are record-specific: questionnaire `Not started`, `Draft`, `Submitted`; request and assessment review controls expose only their declared endpoint status vocabulary. Never create a shared cross-record status vocabulary.
- Desktop uses the established 44px table rows, sticky 40px headers, horizontal-only row dividers, and no zebra/vertical rules. At widths below `md`, render equivalent cards in one column; identifiers, title, status icon+label, and essential metadata remain visible. Search and status controls stack below `sm`.
- List loading waits 300ms then renders a skeleton matching the eventual table/cards and current density. Use no full-page spinner. A retryable load failure is an alert state with **Try again**; an authorisation failure is a distinct permission state and must not masquerade as zero results.

### Searchable relation selection

- Information Systems and Information Assets use one reusable, controlled, server-backed multi-select based on `RelationMultiSelect`/`OwnerCombobox`; values are selected record summaries keyed by `documentId`, while form submission persists only document IDs. Do not display exhaustive inventory checkboxes or accept arbitrary typed values.
- The field has a visible label, `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`, and an active option via `aria-activedescendant`; result containers use labelled `role="listbox"` and options use `role="option"`.
- Debounce only after input (300ms); ignore stale responses. Arrow keys move the active option, Enter selects the active option (or first returned option), Escape clears the query and closes results, Tab closes results, and selection returns focus to the input. Mouse selection must not steal focus before selection completes.
- Search results are bounded by the server. Selected records remain displayed and removable even when they do not occur on the present result page. Announce `{n} selected` with a polite status region. Each selected item has a named **Remove {record name}** button; removing it changes only the controlled selection and does not imply deleting the record.
- The Risk owner picker retains the same bounded active-user combobox behavior, but is single-select. The visible selection reads `Selected owner: {name}` with **Clear Risk owner** where allowed; submit only its `documentId`, never the query text.
- Picker popovers match trigger width and are at most viewport width minus 32px. On narrow screens they remain anchored below the input, stay within the viewport, and never obscure the selected-item list.

### Released assessment diagnostic

- A successful Requestor released assessment view renders only after the typed client parser accepts the complete server projection. Do not substitute an incomplete or guessed release fact in the UI.
- In development, distinguish response-schema mismatch from transport/permission/not-found failure in an in-context `Alert`: headline **“This risk assessment response does not match the published contract.”** Body explains that the development response is incomplete or invalid and offers **Retry**. It may identify the failed projection field only in development.
- In production, retain the safe generic error: **“We couldn’t load this risk assessment.”** Body: **“Try again. If the problem continues, contact your administrator.”** Do not expose schema details, raw payloads, or authorisation facts.

### Accessibility and motion

- Visible labels remain present for search, status, owner, Information Systems, and Information Assets; placeholders never replace labels. Validation occurs on blur and pairs error icon, text, `aria-invalid`, and `aria-describedby`.
- Preserve `:focus-visible` focus rings and ensure sticky headers do not hide focused controls. All actions available on hover remain available through keyboard focus. Live result counts/loading messages use `role="status"`; failed lookup uses `role="alert"`.
- Use existing token motion only: control state 80ms, popover 180ms, and no layout-property animation. With reduced motion, popovers/status changes degrade to the existing 0.01ms reduced-motion behavior and skeletons are static.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Search` |
| Collection result count | `{n} result(s) found` using singular at one result |
| Filtered empty heading | `No records match these filters` |
| Filtered empty body | `Try a different search or clear the active filters.` |
| Filtered empty CTA | `Clear filters` |
| First-use questionnaire empty | `No questionnaires assigned` — `Questionnaires for your authorised assessment requests will appear here when they are ready.` — `View my requests` |
| Analyst review empty | `No {record type} to review` — `Authorised work will appear here when it is ready.` |
| Picker empty | `No matching records.` / `No matching active owners.` |
| Picker failure | `{lookup error}` with `Retry search` or `Retry owner search` |
| Service error | `We couldn’t load {record type}.` — `Try again. If the problem continues, contact your administrator.` — `Try again` |
| Permission error | `You don’t have permission to {view/review} {record type}.` — `Access is enforced by your effective CSRM capabilities and record scope.` — `Return to workspace` |
| Development contract error | `This risk assessment response does not match the published contract.` — `The development response is incomplete or invalid. Retry after correcting the server projection.` — `Retry` |
| Destructive confirmation | None in this phase. Removing a selected system, asset, or owner only updates the unsaved form selection and requires no confirmation. |
