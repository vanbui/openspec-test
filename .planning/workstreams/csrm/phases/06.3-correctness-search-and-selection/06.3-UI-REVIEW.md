## Top 3 Priority Fixes

1. **Make `Clear filters` and an active-filter indicator visible whenever a query or status filter is active, not only when the result set is empty** — a user who filters to a populated result set currently has no on-screen way to see or clear that filter state; add active-filter chips and a persistent `Clear filters` action to `questionnaire-list.tsx`, `questionnaire-review-list.tsx`, `assessment-list.tsx` (both `AssessmentRequestList` and `AssessmentList`), and `released-assessment.tsx`.
2. **Implement the declared desktop-table / mobile-card equivalence for My Questionnaires, Questionnaire Review, and Released Assessments** — these three surfaces are still `grid grid-cols-1 gap-4 lg:grid-cols-2` card grids at every width, while `assessment-list.tsx` already demonstrates the correct 44px-row table above `md` and one-column cards below it; port that pattern to the remaining three.
3. **Normalize collection copy against the single approved contract strings** — replace `"{n} questionnaire(s) found"` with `"{n} result(s) found"` in `questionnaire-list.tsx:192` and `questionnaire-review-list.tsx:143`; replace the review empty body `"…will appear here when available"` in `questionnaire-review-list.tsx:102` with the contract's `"Authorised work will appear here when it is ready."`; and replace `"No released risk assessments match these filters"` in `released-assessment.tsx:95` with the shared `"No records match these filters"` heading.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

- **WARNING — result-count copy diverges from the contract on both questionnaire surfaces.** `questionnaire-list.tsx:192` and `questionnaire-review-list.tsx:143` render `"{n} questionnaire(s) found"`; the contract's Copywriting Contract table declares one shared string, `"{n} result(s) found"`, and `assessment-list.tsx` and `released-assessment.tsx` already use it correctly. This is an unresolved inconsistency, not a new regression.
- **WARNING — analyst questionnaire-review empty body still uses unapproved wording.** `questionnaire-review-list.tsx:102` reads `"Questionnaires for authorised assessment requests will appear here when available."` The contract's Analyst review empty body is `"Authorised work will appear here when it is ready."` `assessment-list.tsx`'s `CollectionState` (line 46) already uses the correct string for the other two analyst-review surfaces, so the questionnaire review list is the outlier.
- **WARNING — released-list filtered-empty heading introduces an unapproved variant.** `released-assessment.tsx:95` reads `"No released risk assessments match these filters"`; the contract's Filtered empty heading is the shared `"No records match these filters"`, which `assessment-list.tsx`'s `NoMatch` component (line 102) and the questionnaire lists (line 186/137) already use correctly. Released assessments is the one remaining divergent surface.
- **PASS — picker copy matches the contract exactly.** `owner-combobox.tsx:110` (`"No matching records."`), `owner-combobox.tsx:231` (`"No matching active owners."`), and the named retry labels (`"Retry search"`, `"Retry owner search"`) match the Copywriting Contract's Picker empty/failure rows verbatim.

### Pillar 2: Visuals (2/4)

- **WARNING — three of five collections remain card grids at all widths.** `questionnaire-list.tsx:193`, `questionnaire-review-list.tsx:144`, and `released-assessment.tsx:101` all use `grid grid-cols-1 gap-4 lg:grid-cols-2` with no `<table>` element anywhere in these files. The contract requires 44px desktop table rows with sticky 40px headers from `md` upward and one-column cards below `md`.
- **PASS — the analyst review surfaces demonstrate the correct pattern.** `assessment-list.tsx` renders a `hidden … md:block` `<table>` (lines 124-129, 152-153) alongside a `md:hidden` card list (lines 113-123, 149-150) for both `AssessmentRequestList` and `AssessmentList`. This is the reference implementation the other three surfaces should be brought in line with.
- **needs_human_review: true — no rendered evidence is available for the required 375px, 768px, and 1440px checks.** Confirm filter-row stacking, table horizontal-overflow containment, and long-title/chip wrapping in a running browser once a dev server is available.

### Pillar 3: Color (3/4)

- **PASS — semantic tokens used consistently in audited scope.** Collection controls use `bg-surface`, `border-input`, `ring`, and status badges pair an icon with a text label (`questionnaire-list.tsx:78-81`, `assessment-list.tsx:30-34`). No raw hex/rgb literals were found in the audited TSX files under `features/questionnaires`, `features/assessments`, or `features/requests`.
- **needs_human_review: true — rendered 60/30/10 distribution and focus-ring contrast cannot be established from source alone.** Confirm in a browser once available.

### Pillar 4: Typography (2/4)

- **WARNING — undeclared sizes recur across the audited feature tree.** A grep of `features/{questionnaires,assessments,requests,risks}` finds 24 uses of `text-xs` (12px), 21 of `text-lg` (18px), and 7 of `text-xl` (20px) — none of which are in the phase's declared 13/14/16/24px role set. Examples: `questionnaire-list.tsx:68` (`text-xs`), `questionnaire-list.tsx:131/143/153` (`text-lg` state headings), `released-assessment.tsx:212,229` (`text-xl` section headings).
- **WARNING — `font-medium` (500 weight) is used 85 times across the same scope**, outside the phase's declared 400/600 weight pair, e.g. `questionnaire-list.tsx:85,90`.

### Pillar 5: Spacing (2/4)

- **WARNING — off-scale spacing recurs across collection cards and controls.** `gap-3` (12px) appears 45 times, `py-5`/`px-5`/`p-5` (20px) 19 times combined, and an isolated `m-9` (36px) once, none of which are in the declared 4/8/16/24/32/48/64px scale. Examples: `questionnaire-list.tsx:65-66` (`gap-4 py-5`, `gap-3 … px-5`), `released-assessment.tsx:81,99,104,213` (`gap-3`, `gap-5`).
- **needs_human_review: true — validate practical 44px touch targets and control/chip wrapping at 375px in a running browser.**

### Pillar 6: Experience Design (2/4)

- **WARNING — `Clear filters` and active-filter visibility are available only in the zero-result branch.** Across all five collections (`questionnaire-list.tsx:186`, `questionnaire-review-list.tsx:137`, `assessment-list.tsx:108,139`, `released-assessment.tsx:95`), the `Clear filters` action and any indication of active filters render exclusively when `resolvedState === 'empty' && filtered`. A user with an active search/status filter and a non-empty, populated result set has no on-screen control to see or clear that filter — this is a direct contract miss (`"Clear filters only while a query or status filter is active"` — not "only while results are also empty"). No active-filter chip markup exists anywhere in the audited scope (`grep -r "chip"` returns nothing).
- **WARNING — no 300ms delayed-skeleton behavior is implemented for collection loading.** A repo-wide search for the `300` debounce constant only finds it in `owner-combobox.tsx:24` (search debounce); no collection list component gates its skeleton behind a 300ms delay. The contract requires collection loading to wait 300ms before rendering a layout-matched skeleton, with no full-page spinner.
- **WARNING — keyboard-close behavior is inconsistent between the two combobox implementations.** `OwnerCombobox` (`owner-combobox.tsx:216`) closes results on `Tab`; `RelationMultiSelect`, used for Information Systems/Assets on the Request form, has no equivalent `Tab` handler, relying only on Popover's own blur/outside-click behavior. The contract requires `Tab closes results` explicitly for the reusable relation multi-select.
- **PASS — the reusable relation combobox mechanics are strong.** `RelationMultiSelect` and `OwnerCombobox` both implement debounced (300ms) search, stale-response rejection via an incrementing sequence ref (`owner-combobox.tsx:63-71,137-151`), arrow-key navigation, Enter-selects-active-or-first, Escape-clears-and-closes, bounded/viewport-clamped popover width (`w-(--radix-popover-trigger-width) max-w-[calc(100vw-2rem)]`), a polite `{n} selected` status region, and named `Remove {name}` / `Clear {label}` controls that return focus to the input after selection or removal (`requestAnimationFrame(() => inputRef.current?.focus())`). `RequestForm` is confirmed wired to `RelationMultiSelect` (`request-form.tsx:124-141`), resolving the prior review's flagged stub at `request-form.tsx:106`.
- **needs_human_review: true — execute keyboard-only search/select/remove flows, retry paths, and narrow-viewport popover anchoring against real server latency; confirm sticky headers never hide a focused control.**
