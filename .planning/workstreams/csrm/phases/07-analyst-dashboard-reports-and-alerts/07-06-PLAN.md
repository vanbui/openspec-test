## Phase Goal

**As a** Security Analyst, **I want to** have a data-driven dashboard, reports, and alerts covering my review queues, high and critical risks, and overdue treatments, **so that** I can prioritise analyst work from live workload signals.

<objective>
Serve the report index and the four closed reports end to end (D-13). Each report is one server-computed read built from database aggregates:
- `risk-exposure`: open contextual Risks by residual and by inherent rating, residual crossed with treatment status, and the most exposed Information Systems.
- `treatment-performance`: due state within a 30-day window, treatment status, and the most overdue treatments as shared alert rows.
- `assessment-throughput`: releases per calendar month over 6 or 12 months, the median days from submission to release, and requests by lifecycle state.
- `control-effectiveness`: Control Implementations by implementation status and by effectiveness rating.

The contract, the regenerated client, the closed per-branch parsers and a copy-map contract test land in the same plan (D-08, UI-D19).

Purpose: DASH-02's reports. Plan 07 renders them.

Output:
- the report definitions, query parser, repository, controller and routes;
- the published union contract;
- the web report schema, service and copy map;
- exact integration proofs.
</objective>

## Recorded planning decisions

- **KPI figures reuse section fields.** No report carries a separate `totals` object: the KPI tiles read the matching fields, such as `byResidualRating.total` and `.Critical`, `dueState.overdue` and `effectivenessRating.ineffective`. The DTOs stay minimal, and the tile always equals its section.
- **`period`** is published as an integer enum `[6, 12]` with `minimum: 6`, so the parity guard synthesises a legal value. The response echoes `period` the same way.
- **Throughput month rules.**
  - A release counts when its assessment has the complete release triple and `approval_date` falls in `[monthStart, nextMonthStart)`. Both bounds are bound as JS `Date` values, because `approval_date` is an INTEGER epoch-ms column in SQLite (research pitfall 1).
  - The current month is last and `partial: true`.
  - The median uses releases in the period whose request has a `submittedDate`. It drops negative gaps and rounds to one decimal.
- **Requests by lifecycle state** counts the six review-scope statuses (07-RESEARCH A3). Drafts are outside the analyst scope and are not returned.
- **The canonical copy map lives in the web as JSON.** Next can import it (`resolveJsonModule` is on), and the Strapi test can read it the way `contract-catalogue.integration.test.ts` already reads the web's generated `schema.d.ts`.
