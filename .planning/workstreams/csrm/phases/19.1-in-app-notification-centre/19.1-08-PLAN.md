## Phase Goal

**As a** Requestor, a risk owner or a Security Analyst, **I want to** be told in the app when work waits for me and to open it in one step, **so that** nothing waits unseen between the people in the flow.

This plan's slice: from the header, the person opens their latest notifications and goes to the record in one step, at every width and by keyboard.

## Recorded planning decisions

- **Actions.** `notifications-actions.ts` (`'use server'`): `getNotificationSummaryAction()`, `listNotificationsAction(input: unknown)` (zod `.strict()`: `view` in `all`, `unread`; `page` 1 to 10,000; `pageSize` in 10, 25, 50), `markNotificationsAction(input: unknown)` (`ids` 1 to 50 unique strings of 1 to 255 characters, `read` boolean). Each reads the session, calls the typed service, and returns `{ ok: true, data } | { ok: false, status: number | null, formError: string }`; none calls `revalidatePath`. Registered in `parser-free-modules.ts` with `delegatesTo('notifications-service')`.
- **Store (pilot ruling 2026-10-18: no client store provider wraps the page content, and the count's Suspense boundary wraps only the bell).** `notification-count.tsx` (`'use client'`, zod-free): `notificationCountReducer` over `{ unread: number | null; asOf: string | null; overlays: Record<string, number> }` with actions `adopt({ unread, asOf })` (applied only when no `asOf` is held or the incoming one is later), `fail()` (unread null), `overlay(token, delta)`, `settle(token, result?)` (drops the overlay, adopts the result), `rollback(token)` and `reset()`; the shown count is `unread` plus the overlays, never below 0, and null shows no capsule. One module-level store holds that state (`subscribe`, `getSnapshot`, `dispatch`). It is written only from effects and event handlers, never during render, and its server snapshot is the unseeded state, so a server render never reads a value another request wrote. `useNotificationCount()` reads it through `useSyncExternalStore` and returns `{ shown, adopt, fail, beginOptimistic(delta) }`, where `beginOptimistic` returns `{ settle(result?), rollback() }`. `NotificationCount({ summary })` is the bell's count, which the trigger renders inside its own `<Suspense fallback={null}>` and nowhere else: it reads `use(summary)` as its seed; on mount it resets the store and adopts the seed (19.1-07 keys the control by `searchKey`, so another person remounts it); a test in `notification-count.test.tsx` pins the reset on a sign-out or identity change (pilot ruling 2026-10-18, Phase 11's `identityKey` pattern): mounted for Jane with an unread count, then remounted under another `searchKey` (Maya) or after the control unmounts on sign-out, the count shows only the new seed, or the unseeded state, never Jane's value, so one person's count never shows to the next on a shared browser, and it adopts each new promise a later layout render passes through the `asOf` rule; until it has adopted on this mount it renders from the seed, so it never shows an older or another person's value. It renders 19.1-07's visually hidden `, {n} unread` and `aria-hidden` capsule, moved here from the trigger. The panel (this plan), the marks hooks (19.1-09) and the page (19.1-10) import the same module, so every mark moves the one count. `app-shell.tsx` does not change in this plan.
