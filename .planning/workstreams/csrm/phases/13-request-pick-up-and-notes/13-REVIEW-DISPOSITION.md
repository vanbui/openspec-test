# Phase 13 review disposition

The merged review (`13-REVIEW.md`, committed in `2082f20`, diffed from `ab000f6`) is dispositioned here in stage B, under the pilot's rulings in `13-PILOT-RULINGS.md`; a ruling overrides a lane's proposed fix. Every confirmed Warning, and every Info that is fixed, is fixed test-first: the new or corrected test was seen failing on the code before the fix and passing after it. Where the code was right and the finding was a test that could not fail, the corrected test was proven able to fail by breaking the guarded code once locally, and the code was then restored byte for byte (an empty `git diff` for that file). When a failing test shows a finding is not real, the row says "Not reproduced" with the test that proves today's behaviour. Every other Info has a disposition with its reason.

A row lists its commits in commit order: a `test(13)` commit holds tests and a `fix(13)` commit holds the fix, sometimes with its tests; `Fixed (test only)` means no production code changed (a docs commit may come with it). Test files are named without their folder: Strapi tests are in `apps/backend/tests/`, web unit tests sit beside their modules in `apps/csrm/src/`, and Playwright specs are in `apps/csrm/e2e/`. The before, after and break logs were kept outside the repository, in the stage B session's scratchpad, so this file records their results rather than linking them. The fix groups append their rows in finding order within their own rows.

All 60 findings of `13-REVIEW.md` (0 Critical, 28 Warning, 32 Info) have a disposition: 25 are fixed with a code change (IN-102's change is to the catalogue's design note), 27 are fixed test-only (IN-601 and IN-603 by comments in the browser harness alone), and 8 are accepted; none is deferred. A finding with several rows counts once, by its largest change. Of the pilot's 8 walk items, D1 to D5 and O1 are fixed with a code change, O2 is fixed test-only and O3 is accepted. The browser proofs that fix group 3 added for the earlier groups' fixes are rows of their own, marked "(browser half)", "(browser proof)" or "(browser re-verification)", and change no count. Group 3's browser evidence comes from one run of the touched specs on the code before any break (both projects), five break runs on the desktop project, each break restored byte for byte (md5) after its run, and the final run of the eight touched specs in both projects: 115 passed (desktop 83, mobile 32), none flaky, the tree clean after it.
