## Phase Goal

**As a** Security Analyst, **I want to** pick up a request and exchange notes with the Requestor on it, **so that** ownership is clear and new information has a home at any point.

This plan's slice: the team's Requests queue shows who holds each request, lets an analyst pick one up from its row, and flags requests with notes new to the viewer.

<objective>
Extend the review queue contract and SQL with the `open` bucket, the `assignee` and `notes` filters and three item fields (D-13, D-24), and the Requests page with the `Assigned to` column, row and card pick-up, the filters, the unread line and the relabels (UI-SPEC §2.2, §2.3); extend the journeys.

Purpose: success criteria 1 (the queue) and 3 (the analyst sees a new note flagged on the queue); REQ-08 criterion 1; COLLAB-01 criterion 2.
Output: queue predicates with exact totals, a column with an inline action, filters, journey steps.

Edits Strapi source? Yes. Changes the specification? Yes. Runs Playwright? Yes. Regenerates `served-operations.json`? No.
</objective>

## Recorded planning decisions

- **Item fields** (Planner's Discretion within D-13's "three item fields"): `assignee: ActiveUserSummary | null`, `pickUp: "allowed" | "own-request" | "not-offered"` and `unreadNotes: integer ≥ 0`. `pickUp` is one closed field saying whether this viewer may pick the request up and, when the viewer raised it, why not, so the queue can say `You raised it` without a fourth field; `pickUp === "allowed"` is the UI-SPEC's `canPickUp`. `pickUpState({ requestStatus, requestorDocumentId, assigneeDocumentId }, viewer)` in `request-assignment-policy.ts` returns it from `allowedAssignmentActions` (13-03).
- **Buckets and filters.** `REVIEW_QUEUE_BUCKETS` gains `open` (statuses `REVIEWABLE_REQUEST_STATUSES`, no lifecycle predicate; `applyBucket` `case "open": return;`). `safeReviewFilters` accepts `assignee` (`me` | `unassigned`) and `notes` (`unread`); anything else is 400. `parseAnalystReviewQuery` reads `csrmAuthorization.viewerId` and `humanAnalyst` from the state and refuses `assignee` or `notes` when the viewer id is missing.
- **SQL** (constant identifiers, bound values, 13-RESEARCH "Queue and count SQL"): `assignee=me` → `whereExists` on `csrm_assessment_requests_assigned_analyst_lnk as aa` with `aa.csrm_assessment_request_id = r.id` and `aa.idambox_user_id = ?`; `assignee=unassigned` → `whereNotExists` on the same link; `notes=unread` → `whereExists` over `csrm_request_notes as n` joined through `csrm_request_notes_assessment_request_lnk as nl` to `r.id` and `csrm_request_notes_author_lnk as na`, where `na.idambox_user_id <> ?`, `n.author_part <> <viewer part>` and `n.sequence > COALESCE((select rs.last_read_sequence from csrm_request_note_read_states as rs join csrm_request_note_read_states_reader_lnk as rr … join csrm_request_note_read_states_assessment_request_lnk as rl … where rr.idambox_user_id = ? and rl.csrm_assessment_request_id = r.id), 0)`; the viewer part is `requestor` when `csrm_assessment_requests_requestor_lnk` links `r.id` to the viewer, else `security-analyst`, expressed as a `CASE WHEN EXISTS (…)`. Counts use `countDistinct("r.id")` and `Number(row?.total ?? 0)`.
- **Page projection.** `hydrate` populates `assignedAnalyst` with `fields: PERSON_FIELDS` and `requestor` with `documentId` and `displayName`; one grouped unread-count query over the page's ids (never one query per row) feeds `unreadNotes`; `projectAnalystReviewRequest(document, today, viewer, unreadByRequestId)` adds the three fields.
- **Oracle.** `selectReviewQueueBucket` gains `open`, and the integration test's oracle composes `assignee` and `unread` membership from the seeded facts; every bucket × assignee × notes combination's total equals the oracle's.
- **Spec.** `filters[queue]` enum gains `open`; new parameters `filters[assignee]` (enum `me`, `unassigned`) and `filters[notes]` (enum `unread`); `AssessmentRequestQueueItem` gains the three fields, required, closed.
- **Web.** `assessment-schema.ts` parses the fields and the query; `assessment-service.ts` `listAssessmentRequests` sends `filters[assignee]` and `filters[notes]`, and `countReviewQueue(queue, { assignee? })` gains the option (used by 13-13); `QueuePickUpButton` (`'use client'`, outline small, accessible name `Pick up {request number}`, the 24px minimum in compact density) calls `changeAssigneeAction` with `expectedAnalyst: null`, shows the viewer's name in the cell at the pending opacity, toasts per §7.1 through Phase 12's X-14 `successToast` with an `Undo` built by 13-09's `toastAction` (never `toast.success` directly), rolls back with family K, and moves focus to the next `Pick up` in DOM order or the row's request number link. The Requests page parses `queue`, `assignee` and `notes` from its search params and passes the viewer's display name from the session for the optimistic cell.
- **Requests UI** (`assessment-list.tsx`): the `Assigned to` column after `Status` (Requests only; a prop hides it for 13-13's view); the unread line under the title outside its clamp (`{n} new {note|notes}`, an X-17 count marker linking to `/app/review/requests/{id}#notes`, named `{n} new {note|notes} on {request number}`); the queue select options `Requires attention`, `Awaiting Requestor`, `Generation in progress`, `All open`, `Released`, `All requests`; the `Assigned to` select (`Anyone`, `Me`, `Not picked up`) with chips `Assigned to: Me` and `Assigned to: Not picked up`; the `Notes` select (`All requests`, `With new notes`) with chip `Notes: New notes`; `Clear filters` resets them; mobile cards gain the unread line and `Assigned to {name}` or `Not picked up` with a full-width `Pick up` last; the description per UI-D30.
