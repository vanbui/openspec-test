## Phase Goal

**As a** Security Analyst, **I want to** pick up a request and exchange notes with the Requestor on it, **so that** ownership is clear and new information has a home at any point.

This plan's slice: on the hub, the questionnaire page and the assessment editor, the analyst sees who holds the request, how many notes are new, and which marked notes the AI has not yet seen; the run sheet says which notes a generation used.

## Recorded planning decisions

- **Signal block** (`ai-inputs-changed.tsx`, a Server Component: no `'use client'`, no hooks, imported only by the three record pages; its copy functions `aiInputsChangedHeading(target)`, `aiInputsChangedItem(note)` and `aiInputsChangedCaption` live in this module, verbatim from §10.2): `AiInputsChangedBlock({ target: "questionnaire" | "draft", requestId, signal })` renders nothing for `null`; otherwise the heading line (`--text-body` at 500 with a 16px `Sparkles`, `aria-hidden`) `AI inputs changed since this {questionnaire|draft} was generated`, a `ul` named by the heading with one item per note (a `RecordLink` `{Requestor|Security Analyst} note · {LocalInstant}` to `/app/review/requests/{requestId}#note-{noteId}`, then `Marked since` or `Unmarked since` in `--text-caption`), then `The AI hasn’t seen these changes.`. At 1440 each item is one line with ` · ` before the caption; at 375 each item stacks, the link wrapping anywhere.
- **Placement, as slots.** The three record pages are Server Components and render the block; every module between them and the place it shows is a client module, so it travels as a `ReactNode` prop, the same way as `requestContext` below. The questionnaire review page renders it from `generation.aiInputsChanged` and passes `aiInputsChanged?: ReactNode` through `QuestionnaireReview` to the provenance header (12-13), which renders the slot as its last block; the assessment page does the same through `AssessmentEditor`. The request hub page (`app/(app)/app/review/requests/[documentId]/page.tsx`) renders it from `request.aiInputs.questionnaire` and `request.aiInputs.assessment` and passes `questionnaireAiInputs?: ReactNode` and `draftAiInputs?: ReactNode` through `AssessmentDetail` to the questionnaire and draft cards, which render the slot above their idle action or state line. No client module imports `ai-inputs-changed.tsx`.
- **Sheet group.** `ai-run-sheet.tsx` (the lazily loaded body) gains a `Notes` group after `Request`, its copy (`sheetNotesHeading(n)`, `sheetNoteRow(note)`, verbatim from §10.3) kept in that module: `{n} {note|notes} included` and one row per `contextSummary.notes.included` entry, `{part} note · {LocalInstant} · {characters} characters`, its first part a link that closes the sheet and then navigates to the note; `None included` when empty (including v1 runs).
- **Request context lines** (`request-context-lines.tsx`, a Server Component): `RequestContextLines({ requestId, assignment, notes })` renders, in `--text-caption` / `--color-text-secondary`, `Assigned to {name}`, or `Not picked up` followed by ` · ` and the link `Pick up on the request page` to `/app/review/requests/{id}#assignment` when `pickUp === "allowed"`; then a figure link `{n} {note|notes}` with the X-17 `{k} new` to `#notes`, or `No notes`. It renders nothing when `assignment` and `notes` are null (a Requestor's read). The questionnaire and assessment pages (Server Components) render it and pass it to `AssessmentRequestLink` and the questionnaire's request relationship through a `requestContext?: ReactNode` prop, so no client module imports it.
- **No change to `ai-assistance-domain.ts`.** It is in `/app/risks/{documentId}`'s client graph through `risk-editor.tsx`, so the signal's copy lives in `ai-inputs-changed.tsx` and the sheet's in `ai-run-sheet.tsx` (see above); 13-17's `type AiInputsChanged` there is a type only and emits no code.
