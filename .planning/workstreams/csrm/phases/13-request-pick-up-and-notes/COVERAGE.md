# API Coverage — OpenAI-compatible chat completions

Full coverage: every capability of the provider surface that Phase 13 touches has a decision and a reason, re-decided from Phase 12's matrix for Phase 13's use rather than copied. Nothing is left undecided. Phase 13 adds no provider capability and no provider call. The notes a Security Analyst marks as changing the AI inputs travel inline, as untrusted data, inside the existing chat-completion requests of Phase 12's two AI operations, questionnaire generation and the assessment draft (D-27; `13-16-SUMMARY.md`). Each marked note is rendered as escaped `note.part`, `note.sequence` and `note.body` values in the last section of the one untrusted Requestor block, with no name, time, id or request number. Unmarked notes never reach the provider. Each run's v2 context summary names the notes it used, without their text (D-28). The adapter is still the Phase 06.7 chat-completions integration, and no `CSRM_AI_` setting was added, removed or renamed (`13-19-SUMMARY.md`, static check 6; the pilot's WR-601 ruling in `13-PILOT-RULINGS.md`).

| capability | decision | reason |
| --- | --- | --- |
| chat completion with strict JSON schema response format | INTEGRATE | Both operations still ask for one closed JSON object and parse it against Phase 12's strict schema before anything is stored. Marked notes only add input. They add no output field, and they are not citable sources, so a proposal can never cite a note (13-16). |
| request timeout and safe failure taxonomy | INTEGRATE | Unchanged: a slow or failing provider ends the job with a closed failure code and a plain message, and nothing partial is stored. Before any provider call, Phase 13 adds one refusal: `CONTEXT_TOO_LARGE`, which names the marked notes, when more than 50 notes are marked or the notes take the prompt over its budget (13-16). |
| reasoning effort and max output tokens settings | INTEGRATE | Unchanged operator settings (`CSRM_AI_*_MAX_OUTPUT_TOKENS`, `CSRM_AI_REASONING_EFFORT`), sent with each request. Marked notes count against the existing prompt budget, and Phase 13 adds no setting. |
| tool or function calling | OPT-OUT | A marked note is data, never an instruction. The model is still given no tools (Phase 12 D-05), and a hostile note stays one escaped `note.body` value that cannot close or open a tag (`ai-provider-guardrails.unit.test.ts`). |
| streaming responses | OPT-OUT | Not needed: notes do not change the response shape. One closed JSON object is parsed whole, and the job reports progress, not partial text. |
| embeddings | OPT-OUT | Not needed: a marked note's body joins the deterministic lexical relevance query that ranks Risk Types and the control shortlist (13-16), so no vector search is used. |
| files, assistants, batch, fine-tuning, moderation, images and audio | OPT-OUT | Out of scope for Phase 13: notes are plain text, sent inline as data, never as files or stored assistants. Attachments are Phase 14's (COLLAB-02). Untrusted note text is contained by escaping and by the analyst's mark, not by a moderation call. The classification ceiling still refuses a request above it when notes are marked (G-3). |
