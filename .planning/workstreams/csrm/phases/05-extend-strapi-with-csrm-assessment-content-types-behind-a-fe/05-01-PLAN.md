# Plan 05-01: CSRM Content-Type Schemas

<objective>
Create the seven first-class Strapi CSRM collection types and relationship graph locked in Phase 5 context.
</objective>

<requirements>
- CSRM-02: Backend can manage CSRM Assessment Request records.
- CSRM-03: Backend can manage CSRM Assessment Questionnaire records associated with assessment requests.
- CSRM-04: Backend can manage CSRM Assessment records associated with assessment requests and release state.
</requirements>

<threat_model>
## Threat Model

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-01 | CSRM domain data is mixed into the core IdamBox authorization model or Strapi admin user model. | high | Create CSRM-specific content types and relate user ownership fields only to `api::idambox-user.idambox-user`. |
| T-05-02 | Workflow state uses generic `status`, conflicting with Strapi document publication status semantics. | medium | Use `requestStatus`, `assessmentStatus`, and `treatmentStatus`; do not add `status` attributes. |
| T-05-03 | Relation graph prevents Phase 6 from querying request-centered workflows. | medium | Make `csrm-assessment-request` the central aggregate with bidirectional relations to assets, systems, questionnaire, and assessment. |
</threat_model>
