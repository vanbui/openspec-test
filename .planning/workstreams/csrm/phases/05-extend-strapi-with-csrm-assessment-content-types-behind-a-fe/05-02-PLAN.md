# Plan 05-02: CSRM Feature Flag Guarding

<objective>
Gate application-facing CSRM collection behavior behind the exact `csrmAppIsEnabled` environment flag while leaving schema files registered in the Strapi project.
</objective>

<requirements>
- CSRM-01: Administrator can enable CSRM backend collections through the `csrmAppIsEnabled` environment flag.
</requirements>

<threat_model>
## Threat Model

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-04 | CSRM APIs expose active application-facing behavior while `csrmAppIsEnabled=false`. | high | Add one reusable route policy and apply it to all generated CSRM core router actions. |
| T-05-05 | Different CSRM route files implement inconsistent flag checks. | medium | Centralize flag parsing in `apps/backend/src/csrm/config.ts` and route blocking in `apps/backend/src/policies/csrm-app-enabled.ts`. |
| T-05-06 | Implementation tries to dynamically unregister schema files and breaks Strapi startup/admin behavior. | medium | Keep schema registration static; guard routes/services only, per the locked context decision. |
</threat_model>
