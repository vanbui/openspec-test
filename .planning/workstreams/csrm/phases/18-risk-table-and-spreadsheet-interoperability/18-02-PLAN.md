## Recorded planning decisions

- **Scale reading (`risk-scale.ts`).** `type ScaleKind = "likelihood" | "consequence" | "rating"`; `readScaleValue(kind, stored: unknown): ScaleReading` with `ScaleReading = { state: "empty" } | { state: "on-scale"; label; score } | { state: "off-scale"; raw }` (score for ratings is the band's ordinal 1 to 4). `RATING_STAGES = ["inherent", "residual"] as const`; `RATING_FIELDS` maps each stage to `{ likelihood, consequence, rating, overrideReason }`: `inherentLikelihood`, `highestInherentConsequence`, `inherentRating`, `inherentRatingOverrideReason`; `residualLikelihood`, `highestResidualConsequence`, `residualRating`, `residualRatingOverrideReason`. `OVERRIDE_REASON_MAX_LENGTH = 500`.
- **Rating write rules.** `resolveRatingWrite({ stage, current, incoming })` where `current` and `incoming` hold the stage's four fields (`incoming` only the keys the write carries) returns `{ ok: true; write; overrideCleared: string | null }` or `{ ok: false; field; reason }` with reason `SCALE_VALUE_INVALID`, `RATING_SCALE_VALUES_REQUIRED`, `RATING_OVERRIDE_REASON_REQUIRED` or `VALUE_TOO_LONG`, in this order: (0) an incoming field equal to its current stored value (trimmed; empty string as null) counts as not carried, so a form that resends unchanged values, a legacy off-scale value among them, never trips the rules; (1) an incoming likelihood or consequence that is not null and not exactly a canonical label, or an incoming rating that is not null and not a rating label, is `SCALE_VALUE_INVALID` on that field; (2) a write that carries none of the four fields writes nothing (legacy values stay); (3) effective inputs are incoming over current; when either is empty or off the scale, an incoming non-null rating is `RATING_SCALE_VALUES_REQUIRED` and otherwise the write sets the rating and reason to null; (4) with both on the scale, `derived = deriveRating`; when the write changes an input, the current reason is reported in `overrideCleared` and dropped; the effective rating is the incoming rating, else the derived; the effective reason is the incoming reason when carried, else the current one unless dropped; an incoming reason that is empty or null with no incoming rating sets the rating to the derived one; (5) when the effective rating differs from `derived`, the trimmed reason must be 1 to 500 characters (`RATING_OVERRIDE_REASON_REQUIRED` when empty, `VALUE_TOO_LONG` when longer); when it equals `derived`, the reason is written null. `ratingsFollowScale(values)` returns `{ follows; stages: [{ stage, offScale: string[], overriddenWithoutReason: boolean, derivable: boolean, derived: RiskRating | null }] }` for 17.1's readiness and the web.
- **Compare-and-set (`risk-table/compare-and-set.ts`).** `normaliseBaseValue(value)`: `undefined` and `""` become null; strings trimmed; a relation object becomes its `documentId`; a date or datetime string becomes its `YYYY-MM-DD` calendar date for date fields named in `DATE_FIELDS` (`targetDate`, `treatmentResolveDate`, `exemptionReviewDate`). `compareCellBases({ current, bases })` compares every key of `bases` (and only those) after normalising both sides and returns `RiskCellConflict[]` `{ field, base, current }`.
- **Bulk body (`risk-table/risk-changes-body.ts`).** `RISK_CHANGES_MAX_ENTRIES = 1000`, `RISK_CHANGES_MAX_CONTROLS_PER_ROW = 50`, `RISK_CHANGES_MAX_CONTROLS = 1000`, `RISK_CHANGES_KEY_MAX_LENGTH = 64`, `RISK_CELL_REASONS` (18-01's list, frozen). `parseRiskChangesBody(body, { writableFields, controlFields })` returns `ParsedRiskChanges` `{ updates: RiskUpdateEntry[]; creates: RiskCreateEntry[]; controls: RiskControlEntry[] }` or throws `RiskChangesBodyError` (`status` 400, `reason` `RISK_CHANGES_TOO_LARGE` for bounds, none for shape). Shape rules: a plain object with only those three arrays; every `riskId` and `controlId` a non-empty string ≤ 64; `fields` and `bases` plain objects whose keys are in `writableFields` (or `controlFields` for controls); `bases` keys a subset of `fields` keys; `newRowKey` names a `creates[].key`; exactly one of `riskId` and `newRowKey` per control entry. Value validation is not here: the bulk core runs the one closed parser per row.
- **Filter and sort (`risk-table/risk-table-view.ts`).** `RISK_TABLE_VIEW_SCHEMA_VERSION = 1`, `RISK_TABLE_VIEW_KEYS = ["assessment-risks"]`, `RISK_TABLE_FILTER_KINDS = ["contains", "oneOf", "dateRange", "isEmpty", "present"]`, the 18-01 bounds as constants, `OFF_SCALE_TAG = "__off_scale__"`. `RiskTableRow = { id; riskNumber; withdrawn; values: Record<string, { text: string | null; sortKey: number | string | null; date?: string; tags?: string[]; present?: boolean }>; people: string[] }`. `applyRiskTableView(rows, { definition, search, show })`: `show` `active` keeps non-withdrawn rows, `withdrawn` keeps withdrawn ones; `search` (trimmed, case-folded with `toLowerCase()` after NFC) matches a substring of `riskNumber`, the `riskStatement` and `riskCause` texts or any `people` name; `contains` matches the case-folded text; `oneOf` matches when any of the cell's `tags` (else its text) equals a listed value; `dateRange` compares `date` with inclusive `from` and `to`; `isEmpty` matches a null text; `present` matches `present: true`; sort keys apply in order, numbers before strings, strings compared by code unit after NFC and `toLowerCase()`, nulls last in either direction, ties by `riskNumber` ascending. Never `localeCompare` (the web and Node must agree). `parseRiskTableViewDefinition(raw, { offeredKeys })` returns the definition with unknown keys, unknown filter kinds and out-of-bound entries dropped, or null for a non-object, an unknown `schemaVersion` or more than 16,384 serialised bytes; `serialiseRiskTableViewDefinition` writes the canonical form.
- **Converters (`spreadsheets/value-convert.ts`).** `ImportValueColumn.kind` gains `date`, `likelihood`, `consequence`, `rating`, `person`, `record`, `controls`; `convertCell(raw, column, { mode, lookups? })` with `lookups` `{ person(name): LookupResult; record(kind, name): LookupResult; control(number): LookupResult }`, `LookupResult = { kind: "match"; id; label } | { kind: "none" } | { kind: "many" }`. Dates: `d/m/yyyy`, `dd/mm/yyyy`, `yyyy-mm-dd`, a `Date` read at its UTC calendar date, and a number 1 to 2,958,465 as an Excel serial (19-RESEARCH Pitfall 5) give `YYYY-MM-DD`; else issue `DATE_INVALID` `Enter a date as dd/mm/yyyy, for example 30/11/2026.` Scales: a label in any case or an integer score 1 to 5 gives the canonical label; ratings: a label in any case; else `SCALE_VALUE_INVALID` `Choose a level from the scale.` Person: `none` gives `PERSON_NOT_FOUND` `No one eligible is called “{value}”.`, `many` gives `PERSON_AMBIGUOUS` `More than one person is called “{value}”. Choose in the cell after pasting.` Record: `none` or `many` gives `RECORD_NOT_FOUND`. Controls: tokens split on `;` or line breaks, each a control number or `{number} · {title}` (the number before ` · `), each looked up; any `none` gives `CONTROL_NOT_FOUND` `{value} isn’t a control in the library.`; the value is the array of control ids. Every new kind keeps `CLEAR_TOKEN` and mark stripping as 19-03 defines them.
