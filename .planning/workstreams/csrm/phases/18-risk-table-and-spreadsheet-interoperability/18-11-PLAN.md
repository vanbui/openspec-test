## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: saving. The table's unsaved changes save in one request, conflicts and invalid cells come back to their cells with a choice, nothing typed is lost on a refusal, and a save can be undone without overwriting anyone.

## Recorded planning decisions

- **Typed layer.** `risk-table-schema.ts` (zod, server): `riskChangesRequestSchema` (18-01's body with the bounds), `riskChangesResultSchema`, `riskCellConflictSchema`, `riskCellErrorSchema`. `risk-table-service.ts` (`server-only`): `saveRiskChanges(assessmentId, body)` through the generated client's `POST /v1/risk_assessments/{assessmentId}/risk_changes`, parsing 200 with the result schema and registering `responseParserModule` for the parity test. `server-client.ts`: `TransportError` gains `conflicts?: RiskCellConflict[]` and `cells?: RiskCellError[]` read from `error.details` when present. `risk-table-actions.ts` (`'use server'`): `saveRiskChangesAction({ assessmentId, body })` validates input, calls the service, `revalidatePath` for the record's routes, and returns `{ ok: true; result } | { ok: false; status; reason; conflicts?; cells?; message }`; registered in `parser-free-modules.ts`.
- **Domain additions (`risk-table-domain.ts`).** `changeSetToRequest(set, rows)` (updates with `fields` and `bases`: every edited field's base, plus, for an edited stage whose override reason is set, that stage's rating and reason bases; creates by key; controls); `REQUEST_BYTE_LIMIT = 1_000_000`, `projectedRequestBytes(body)` (`TextEncoder`), `exceedsRequestLimit(set, rows)`; `applyConflicts(set, conflicts)` and `applyCellErrors(set, cells)` (marks); `keepMine(set, cellRef, current)` (rebases the edit on the current value, one undo step), `takeTheirs(set, cellRef, current)` (drops the edit, one undo step), `keepAllMine`, `takeAllTheirs`; `inverseOfSavedBatch(result, before)` (updates only, with saved values as bases); `saveToastText(result)` and `undoToastText`.
- **Bar (X-54).** `UnsavedChangesBar({ selection, changes, review, onSave, onDiscard, onUndo, onRedo })`: the sticky footer bar that slides as the DataTable's bulk-action bar; the changes group (`PenLine` 16px, `{n} unsaved {change|changes} to {r} {risk|risks}`, icon-only `Undo` and `Redo` with X-7 hints and tooltips, ghost `Discard changes`, primary `Save changes` with hint `Ctrl S`, pending `Saving…` with the inline spinner); the review line `Saving withdraws {name}’s review of {assessment number}.` (`Info` 14px, `--text-caption`) while 17.1's review stands. `Discard changes` asks nothing and toasts `Discarded {n} unsaved {change|changes}.` with `Undo` (amendment 3). The selection group arrives in 18-12.
- **Save flow (`risk-table.tsx`).** `Save changes` and Ctrl+S build the body, mark changed cells pending (opacity 0.6), call the action once; on success replace the touched rows with `result.risks`, empty the change set and undo stack, announce `Saved {n} changes.` and toast `Saved {n} {change|changes} to {r} {risk|risks}.` with `Undo` and, when risks were created, the second line `{c} new {risk stays|risks stay} if you undo. Withdraw {it|them} from {its|their} detail sheet if needed.`; Undo calls the action with `inverseOfSavedBatch`. On `RISK_CHANGES_CONFLICT`: `applyConflicts`, the X-56 warning alert above the grid (focus to its title), cell lines and pills. On `RISK_CHANGES_INVALID`: `applyCellErrors`, the danger alert (focus to its title). On any other refusal: the X1 danger toast; the change set kept. The cell line of a rating whose input edit will clear an override reads `Changing likelihood or consequence clears the override “{reason}”.`
- **Family X (`refusal-copy.ts`).** `riskTableSaveRefusal(reason, context)`, `riskCellReasonCopy(reason, context)`, `riskTablePasteCopy(case, context)`, `riskImportRefusal(reason, context)`, `savedViewRefusal(reason, context)` returning `{ kind, title?, body, action? }` with UI-SPEC §12 X1 to X4's exact sentences and kinds; the import's `imported` wording for the round and release cases.
- **Spec test.** `risk-table.spec.ts` `describe('saving')` (desktop) on a 5-risk fixture: edit a statement, `Save changes`, assert exactly one browser request carrying a `next-action` header during the save, the toast text, markers cleared, and after reload the value persisted; Undo restores the old value; `Discard changes` and its toast's Undo restore the change set.
