## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: the grid itself. A Security Analyst can move through risks by keyboard, select ranges, edit text cells, fill and clear, undo and redo, all in the browser; and the three review lists gain a column chooser.

<objective>
Build the risk table's grid on the installed TanStack Table 9.2.4 as the DataTable's grid mode (D-04's lean, research Answer 1), with the APG keymap (D-17), the unsaved change set with undo and redo held in memory (D-12, D-16), and the X-53 cell states. Add the X-61 column chooser as a DataTable capability and give it to the Requests queue, Questionnaires and Risk assessments lists (D-10). Prove all of it in Vitest.

Purpose: D-04's measured spike (18-05) needs this grid on the real route; D-30 places the grid before the rest of the UI.
Output: the grid component and its zod-free domain, the column chooser, three lists adopting it, and three test files.

Edits Strapi source? No. Changes the specification? No. Runs Playwright? No.
</objective>

## Recorded planning decisions

- **Grid module.** `components/csrm/data-grid.tsx` (client) declares `dataGridFeatures = tableFeatures({ columnFilteringFeature, rowSortingFeature, cellSelectionFeature, columnPinningFeature, columnSizingFeature, columnResizingFeature, columnOrderingFeature, columnVisibilityFeature })` and `DataGrid<TRow>` so list routes do not load the grid's features (research Answer 1). It imports from `data-table.tsx` the density hook and toggle, `tableHeaderMicroClassName`, the skeleton and the mobile-card wrapper, which `data-table.tsx` exports (renamed exports only; list behaviour unchanged). `DataGrid` props: `ariaLabel`, `caption`, `columns` (`{ id, header, size, pinned?, readOnly?, numeric? }`), `rows`, `getRowId`, `renderCell(row, columnId, state)`, `onGridKeyDown`, `cellSelection` state and setter, `columnOrder`, `columnVisibility`, `columnSizing` and setters, `densityUserId`, `renderMobileCard`, `state` and `stateSlots`, `footer`. `useTable` sets `autoResetCellSelection: false`, stable `getRowId`, no manual paging, no pagination (X-60). `<table role="grid" aria-rowcount aria-colcount aria-readonly={!editable}>`; headers `role="columnheader"` with `aria-sort`; the Risk number cell `role="rowheader"`; range cells `aria-selected="true"`; the active cell is the only `tabIndex={0}` (`getTabIndex()`); the grid is its own two-axis scroll container at least `20rem` tall with sticky header and pinned column, drawing the focus ring inset (`--focus-ring`, offset −2px). Below 768px it renders `renderMobileCard` cards instead (18-18 supplies the card).
- **Domain (`risk-table-domain.ts`, zod-free).** Types `CellRef { rowId; columnKey }`, `PendingEdit { value; base; label }`, `ChangeSet { schemaVersion: 1; assessmentId; edits: Record<rowId, Record<field, PendingEdit>>; newRows: { key; fields }[] }`, `UndoStep { label; before; after }`, `UndoStack { past; future }`, `GridKeyAction` (the action names below). Functions: `emptyChangeSet(assessmentId)`; `applyCellEdits(set, edits: { rowId; field; value; current; label }[])` (an edit equal to the current value removes that entry); `fillSelection(set, { field, value, cells, isEditable })`; `clearCells(set, { cells, isEditable })` returning `{ set, skipped }`; `pushUndo`, `undoChange`, `redoChange`; `changedCellCount`, `changedRowCount`; `gridKeyAction({ key, ctrlKey, metaKey, shiftKey, altKey }, { editing, editable })` returning one of `move-up`, `move-down`, `move-left`, `move-right`, `row-start`, `row-end`, `grid-start`, `grid-end`, `page-up`, `page-down`, `extend-up`, `extend-down`, `extend-left`, `extend-right`, `select-row`, `select-column`, `select-all`, `edit`, `edit-replace`, `cancel`, `commit-down`, `commit-right`, `commit-left`, `commit-fill`, `clear`, `copy`, `cut`, `paste`, `undo`, `redo`, `save`, `cell-menu`, `column-menu`, `shortcuts`, `leave`, `read-only`, `none` (`metaKey` stands for Ctrl on Apple, X-7); `announcement(event)` returning UI-SPEC §2.5's exact sentences with written plurals.
- **Columns (`risk-table-columns.ts`, zod-free).** `RiskTableColumnKind = "identifier" | "text" | "longText" | "pickList" | "person" | "record" | "date" | "likelihood" | "consequence" | "rating" | "controls" | "computed"`; `RiskTableColumn { key; header; kind; editable(row): boolean; display(row): string | null; field?: string }`; `DEFAULT_COLUMN_KEYS` (UI-SPEC §2.3 in order); `riskTableColumns({ actor: "analyst" | "participant", released })` with headers from 16-11's `RISK_FIELD_LABELS` and, before release, 17.1 §2.6's recommendation labels for the treatment columns; exception fields not offered before release (17.1 D-44); dates displayed as X-3 calendar dates (`30 Nov 2026`) with no due or overdue marker (G-16). Later plans add kinds' editors and columns the reads gain (18-06, 18-12).
- **Risk table (`risk-table.tsx`, client).** Props `{ assessment: { documentId; assessmentNumber }; rows; columns; mode: { editable; reason }; densityUserId }`. It owns the cell selection, the change set and undo stack in React state, renders `DataGrid` with a visible caption that takes focus on arrival (amendment 4; the first arrow key enters the first row), the cell line (X-53: `{risk number} · {column header}` then the full value, error or reason, wrapping to three lines, as an `output` referenced by the active cell's `aria-describedby`), one polite live region (selection announcements debounced 250ms), and the footer counts (X-60). Editors load with `next/dynamic` from `cell-editors/basic-cell-editors.tsx` (this plan: the single-line text editor, which commits on Enter and Tab and cancels on Escape; printable keys start an edit replacing the value). Cells are `React.memo` on `(rowId, columnKey, value, state)`.
- **Column chooser (X-61).** `ColumnChooser({ columns: { id; header; fixed? }[]; visible; order; onChange; resetLabel; onReset; resizable? })`: a `Popover` from 768px, a full-screen `Sheet` below, titled `Columns`, holding 19-06's `ColumnChoice` checklist (legend, `{k} of {n} columns`, `Select all`) in display order, each row with `Move {header} up` and `Move {header} down` 24px icon buttons (`ArrowUp`, `ArrowDown`) and a `GripVertical` pointer handle (native pointer events, no library); the identifier column first, checked and fixed. `DataTable` gains `columnChoice?: { listKey; offered: { id; header; defaultVisible }[] }`, storing `{ visible, order }` in local storage at `csrm:data-table-columns:{listKey}:{userId}` inside try and catch (falling back to the defaults), rendering `Columns` (outline small, `Columns3`) beside the density toggle with `Reset to default`, and passing the visible column ids to 19-06's export slot so each list's Export dialog opens with them checked.
