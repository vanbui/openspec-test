## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: the spreadsheet round trip's server logic. A file of risks or mitigation controls is read, previewed and turned into one bulk save; the table's current view is written to CSV or XLSX. Both reuse Phase 19's modules, proven without HTTP.

## Recorded planning decisions

- **Tables.** `RISK_IMPORT_TABLES = ["risks", "mitigation-controls"]`; URL segments `risks`, `mitigation_controls` (`parseRiskImportTable(segment)`, else 404); sheet names `Risks`, `Mitigation controls`. Vocabulary (`export-vocabulary.json`, both copies byte-identical): import kinds `assessment-risks` (columns `Risk number` then every writable risk field with its Risk form label, `Also accepted as` aliases including the API name, kinds per 18-02's converters, override reasons included) and `assessment-mitigation-controls` (`Risk number`, `Control number`, then the control implementation's writable fields); view `assessment-risks` whose columns are the risk table's column keys, one per `RISK_DETAIL_FIELDS` field (relations by field name, both override reasons included) plus `mitigationControls`, `decision`, `contestPoints`, `responsesAwaitingDecision`, `aiValuesToConfirm`, `notOnScale` and `status`, with labels and cell types (dates typed as dates, ratings and scale levels as text).
- **Reading.** `readImportFile(bytes, { sheetName? })`: for XLSX, `readNamedSheet(bytes, sheetName)` when a sheet of that name exists (case-insensitive), else `readFirstSheet`; CSV ignores the option. Every Phase 19 refusal and bound applies unchanged.
- **Classification.** `classifyRiskImport({ table, rows, headerMatch, assessment, lookups, now })` where `assessment` holds `{ assessmentNumber, riskCount, risks: [{ documentId, riskNumber, withdrawn, updatedAt, values, controls: [{ controlId, implementationId, values, updatedAt }] }] }`. Rows whose Risk number is `Example (CSRM skips this row)` are skipped. Risks: blank number creates (requires the statement, `VALUE_REQUIRED`); a number not among the assessment's active risks is `rejected` with `{value} isn’t an active risk in {assessment number}.`; each cell converts through `convertCell`; each stage passes `resolveRatingWrite` (its reason becomes the row's issue); no changed field is `unchanged`. Mitigation controls: both keys required; an unknown risk or control is `rejected`; an existing implementation of that control on the risk is `update` or `unchanged`, else `create`. Creates beyond 1,000 minus the risk count refuse the whole preview with 409 `ASSESSMENT_RISK_LIMIT`. Output `RiskImportPreview` `{ table, rows: [{ rowNumber, state, riskNumber, changes: [{ field, label, old, new }], issues: [{ column, code, message }] }], counts, warnings, notes }`.
- **Records.** `issueRiskImportPreview({ actorDocumentId, assessmentDocumentId, table, fileDigest, rows })` keeps per row `{ rowNumber, state, riskId, riskUpdatedAt, implementationId, implementationUpdatedAt, changes }` and returns a `sha256:` token (5-minute TTL; 256 global; 16 per actor, assessment and table; pruned on issue); `riskImportPreviewForCommit(token, actor, assessment, table)` returns it or throws 409 `IMPORT_REVIEW_EXPIRED` (absent, expired, another actor, assessment or table) and the caller compares the digest (400 `IMPORT_PREVIEW_CHANGED` on mismatch); `issueRiskImportResult` and `riskImportResultFor` mirror 19-13's result record.
- **Drift and commit body.** `assertNoRiskImportDrift(record, current)` throws 409 `RISK_IMPORT_DRIFTED` with `driftedRiskNumbers` when any target risk's or implementation's `updatedAt` differs from the record, or a target risk is now withdrawn. `riskImportChanges(record)` returns a `ParsedRiskChanges`: updates with the changed fields and their preview old values as `bases`, creates keyed `row-{n}`, control entries by `riskId` or `newRowKey`; rejected and unchanged rows excluded.
- **Templates and reports.** `buildRiskImportTemplate(table, format)` per 19-14's template rules with sheet names above and a `Notes` sheet that adds, after the column rows, the scale from `publishedRiskScale()` (each likelihood and consequence label, score and description, and the bands); file `{table slug}-import-template.{csv|xlsx}`. `buildRiskImportErrorReport({ table, actorDocumentId, assessmentDocumentId, upload, previewDigest?, resultToken?, timeZone? })` per 19-14's report rules; file `{assessment number}-{table slug}-import-issues-{local date}.{ext}`; no export event.
- **Export.** `parseRiskTableExportBody(body, { offeredKeys })` accepts `{ format: "csv"|"xlsx", timeZone, columns: string[] (1 to 60, unique, offered), sort, filters, show: "active"|"withdrawn", search?, viewName? }` (sort and filters through `parseRiskTableViewDefinition`, refusing rather than dropping on write: 400 for an unknown key or kind). `riskTableRowFromProjection(risk, { scale })` builds 18-02's `RiskTableRow` from the analyst risk projection (scale levels and ratings tagged by `readScaleValue`, off-scale as `OFF_SCALE_TAG`, people names, AI-pending, contest and decision markers as `present`). `buildRiskTableExport({ assessment, risks, body, actor, now, log })` applies `applyRiskTableView`, then calls `runFixedTableExport({ viewKey: "assessment-risks", slug: "{assessment number}-risks", heading: "Risks", tables: [risks table with the chosen columns, mitigation controls table], format, table: format === "csv" ? "risks" : undefined, timeZone, actor, now, log, about: [View, Filters in words, Search, Show] })`. Withdrawn risks appear only when `show` is `withdrawn`.
