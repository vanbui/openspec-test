## Phase Goal

**As a** Security Analyst, **I want** an assessment's risks in a table I can edit, copy and paste like Excel or a SharePoint list, **so that** reviewing and updating many risks takes minutes rather than a long scroll.

This plan's slice: named views. A Security Analyst saves the columns, sort and filters they use as a view of their own, shares it with the analyst team, and nobody else can change or delete it.

<objective>
Serve `CsrmSavedView` (18-04's type) through four operations (D-09) with ownership, sharing, uniqueness and bounds, a strict write parser and a fail-safe read (18-02), and the one sharing decision Phase 22 can take over. Publish them through the endpoint chain with `function.saved_views.manage_api`, human-only, and seven matrix rows (D-02, D-25). Prove ownership, sharing and every refusal in the API (D-29).

Purpose: ASSESS-15 criterion 2's saved views, personal by default and shareable with analysts.
Output: the saved-view API folder and its integration test.

Edits Strapi source? Yes (dev servers stopped). Changes the specification? Yes. Runs Playwright? No.
</objective>

## Recorded planning decisions

- **Operations** (`apps/backend/src/api/csrm-saved-view/operations.ts`, `CSRM_SAVED_VIEW_OPERATIONS`): `listSavedViews` `GET:/api/v1/saved_views` (query `viewKey`, required, in `RISK_TABLE_VIEW_KEYS`, else 400), `createSavedView` `POST:/api/v1/saved_views`, `updateSavedView` `PATCH:/api/v1/saved_views/{viewId}`, `deleteSavedView` `DELETE:/api/v1/saved_views/{viewId}`; router `routes/csrm-saved-view.ts` (no core router), controller `controllers/csrm-saved-view.ts` (`list`, `create`, `update`, `delete`).
- **Service (`services/saved-views.ts`).** Constants `SAVED_VIEW_UID`, `SAVED_VIEW_NAME_MAX_LENGTH = 80`, `SAVED_VIEWS_PER_OWNER_AND_KEY = 50`, `SAVED_VIEW_DEFINITION_MAX_BYTES = 16_384`, `SAVED_VIEW_VISIBILITIES = ["personal", "analysts"]`. `savedViewSharePolicy(actor)` returns true for a human Security Analyst (the comment names Phase 22 and decision 1). `offeredKeysFor(viewKey)` returns the vocabulary view's column keys. `listSavedViews(strapi, { actor, viewKey })` returns the actor's views and others' `analysts` views, each `{ id, viewKey, name, visibility, owner: { documentId, displayName }, mine, definition, updatedAt }` with `definition` from `parseRiskTableViewDefinition` (null when unreadable), ordered own views by name, then shared ones by owner then name. `createSavedView` trims the name (1 to 80), refuses a definition that does not parse to itself (400 `SAVED_VIEW_INVALID`), `analysts` without `savedViewSharePolicy` (403), a case-insensitive duplicate name for the owner and key (409 `SAVED_VIEW_NAME_TAKEN`) and a 51st view (409 `SAVED_VIEW_LIMIT`); it stores the canonical serialisation. `updateSavedView` and `deleteSavedView` load by `documentId`: absent, or another owner's `personal` view, is 404 `CSRM saved view was not found.`; another owner's `analysts` view is 403 `NOT_VIEW_OWNER`; then the same validation. Delete answers 204; the web's Undo re-creates the view with the same content.
- **Specification.** Paths `/v1/saved_views` (`get`, `post`) and `/v1/saved_views/{viewId}` (`patch`, `delete`); components `SavedViewDefinition` (18-01's envelope), `SavedView`, `SavedViewListResponse`, `SavedViewResponse`, `SavedViewCreateRequest`, `SavedViewUpdateRequest`; errors 400, 401, 403, 404, 409.
- **Catalogue and grants.** `function.saved_views.manage_api` (`Manage Saved Views`, API-only, `role.security_analyst` only): `.api.01` list, `.api.02` create, `.api.03` update, `.api.04` delete; docs copy then byte-identical bootstrap copy. Four literals in `HUMAN_ANALYST_ONLY_OPERATIONS` and its mirror; four matrix rows, each for all seven callers (the record rule is ownership, proven in the integration file).
