## The authorization gap, and how it was closed

The fixture resolver could replace an authorization decision. On four of six routes it was
consulted before the authorized service ran, so with the harness enabled a base-capability
actor would be shown the analyst review shell rather than a denial. No records leaked — the
fixture branches render empty collections — and the harness is inert in production, but the
server-side authorization call was skipped, which the project rules do not permit
regardless of reachability.

One invariant now holds on all six routes: **authorize and load first, then substitute only
presentation**. Risk Register and Administration already worked this way and were the
reference. A denied or failed authoritative result always renders its own state and is
never wrapped in a fixture boundary.

The environment-only switch is replaced by a runtime attestation: the resolver additionally
requires a runtime root contained under the Playwright temp parent, an attestation file in
that root whose nonce matches the environment, and a creation time under ten minutes.
Playwright writes it `0600` per invocation and removes it on exit.

**Proven three ways.** Unit tests spy on call order to show each service precedes its
fixture, and on a 403 show no fixture boundary renders, the real alert surface does, and
the resolver is never called. In the browser, a Requestor on the review and administration
routes receives the genuine permission surface — *"You don't have permission to review risk
assessments"* — with zero fixture boundaries. A separately spawned Next server without the
attestation ignores `__e2eState` entirely.

## Defects found in review, not by the executing agent

**Product (1).** The My Requests empty fixture zeroed pagination but passed the real rows;
`RequestTable` derives its own state from `requests.length` when `state` is undefined, so it
rendered populated and the empty state never appeared. Only a browser run surfaces this.

**Test (8).** `normalize()` called inside `page.evaluate` but defined in Node scope; a
sign-in helper asserting only the URL and racing the session cookie; the same race in the
Requestor helper, which silently ran the denial proof as a Security Analyst — the page
snapshot showed analyst navigation, so a passing assertion would have certified the
authorization fix without ever testing an unauthorized actor; a token parser dropping the
document's inline weight exceptions and its §4 nav-item size; a tracking assertion widened
beyond what the application implements; a widget locator walking up one parent too few;
recovery assertions expecting links where routes render buttons; and desktop-table
assertions run at 375px where `DataTable` renders cards.

**Earlier in the phase (4).** Header weight applied to `<thead>` where each raw `<th>`
carries the user-agent bold; an E2E harness reaching into six production route components;
and the two spec defects above, first found then lost in a refactor.

The nav-item exception is now read from the design direction and throws
`DESIGN_DIRECTION_NAV_ITEM_TYPOGRAPHY_MISSING` if the document stops declaring it, so it
cannot be silently dropped again — which is exactly how it was lost.

## Deferred to 06.6, with reasons

- **`assessment-list.tsx` onto `DataTable`.** Three list renderings, two raw tables, nine
  required props, two structural tests bound to current testids. 06.6 rewrites these anyway.
- **Heading letter-spacing.** The design direction specifies negative tracking on the
  heading and display tokens; the application renders none, on every heading. Pre-existing,
  not a regression, so the tracking assertion is scoped to the uppercase micro token until
  06.6 implements it.
- **State headings at 18px.** `text-lg` across four features, which the sweep misses because
  it audits default route states rather than fixture states.

## Standing reservation

Test branching still lives in production route components. It is now provably safe and it
delivers the five-state coverage criterion 6 requires, which nothing else provides — but the
authorization defect it produced originated in that placement. If a future phase can drive
these states from seeded data instead, the harness should be retired.
