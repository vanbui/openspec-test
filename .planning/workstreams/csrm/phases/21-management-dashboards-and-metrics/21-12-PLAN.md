## Phase Goal

**As a** risk manager or leader, **I want** trends, ageing, cycle times and a heat map, **so that** I can see whether risk and the assessment process are improving.

This plan's slice: Strapi serves a likelihood-by-consequence heat map of inherent and residual positions for any register filter, each cell's count equal to the register list with that cell's position filters, to Security Analysts only.

<objective>

Output: the published read, the filters, the typed layer and their tests.

Edits Strapi source? Yes (dev servers stopped). Changes the specification? Yes. Runs Playwright? No.

## Recorded planning decisions

- **Filters (`risk-register-query.ts`).** `RiskRegisterQuery` gains `inherentLikelihood`, `inherentConsequence`, `residualLikelihood`, `residualConsequence` (each one of the served scale's labels, read from `LIKELIHOODS` or `CONSEQUENCES` through `publishedRiskScale()`, or `not-on-scale`) and `exception` (`yes`). An on-scale value filters `field = label` (stored values are canonical or off-scale, 18 D-21); `not-on-scale` filters `field IS NULL OR field NOT IN (labels)` as Document Service filters (`$or` of `$null` and `$notIn`); `exception=yes` filters `isExempted: true`. Fields: `inherentLikelihood`, `highestInherentConsequence`, `residualLikelihood`, `highestResidualConsequence`. Any other value throws the query error with `reason: "LIST_FILTER_INVALID"`.
- **Aggregate (`risk-register.ts`).** Extract the list's filter construction into `riskRegisterWhere(query)` (the list keeps calling it); `riskHeatMap(strapi, query)` reads the matching risks' four position fields and `withdrawnAt` through `strapi.db.query(UID).findMany({ where, select, orderBy: { id: "asc" }, limit: 1_000, offset })` pages up to `HEAT_MAP_RISK_CAP` (25,000; added to `insight-constants.ts`), returns `{ available: false }` beyond it, else `{ available: true, total, scale: publishedRiskScale(), inherent, residual }` from `foldHeatMap`.
- **Operation and route.** `CSRM_RISK_OPERATIONS.heatMap = "GET:/api/v1/risks/heat_map"`; route `GET /v1/risks/heat_map` → `api::csrm-risk.csrm-risk.heatMap` with `riskRegisterPolicies(CSRM_RISK_OPERATIONS.heatMap, CSRM_RISK_OPERATIONS.listRegister)`, placed directly before `GET /v1/risks/:riskId`; the literal joins `HUMAN_ANALYST_ONLY_OPERATIONS` (`humanAnalystDenialMessage` returns the insight message) and `SERVICE_IDENTITY_REFUSED_OPERATIONS`. Handler `heatMap(ctx)`: `assertRiskRegisterScope(ctx.state)`, `parseRiskRegisterQuery(ctx.query)` (pagination and sort keys accepted and ignored, so the register's URL can be passed as is), `riskHeatMap`.
- **Catalogue.** `function.risk_register.heat_map_api` (`Risk Heat Map API`, description `Human analyst-only likelihood and consequence counts over the register's filters. This API-only Function intentionally has no menuPath.`, `roleIds: ["role.security_analyst"]`), `.api.01` `Get Risk Heat Map`, `sourceEntities` `CsrmRisk`; design note.
- **Spec.** Path `/v1/risks/heat_map` (`get`, operationId `risk-register/get-heat-map`) with the register's query parameters plus the five new ones (also added to the list operation); 200 `RiskHeatMapResponse { data: RiskHeatMap }` with `RiskHeatMap = { available, total, scale: RiskScale, inherent: RiskMatrixCounts, residual: RiskMatrixCounts }` and `RiskMatrixCounts = { cells: { likelihood, consequence, band, count }[], offScale: { likelihood, consequence, total } }`; 400 with `LIST_FILTER_INVALID`; 403.
- **Web typed layer.** `risk-schema.ts`: the five filter values in the register query schema and `riskHeatMapResponseSchema` (closed); `risk-service.ts`: `getRiskHeatMap(query)` registered in `responseParserModule`.
