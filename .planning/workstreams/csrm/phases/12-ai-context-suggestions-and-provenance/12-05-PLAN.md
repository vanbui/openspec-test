## Phase Goal

**As a** Security Analyst, **I want to** have the AI work from everything the Requestor gave and show where each proposal came from, **so that** I can trust, check and correct its output quickly.

This plan's slice: a generated questionnaire that a non-expert Requestor can answer, built from the whole request, with every provider call on the record.

<objective>
Move questionnaire generation onto the assessment context (D-04, D-16), give it the wire v2 shape and adapter inside the portable schema subset (D-06), persist help text (D-17), guarantee "Not sure" on choice questions, rebuild the deterministic provider to exercise every rule, and record one `CsrmAiRun` per provider call (D-19, D-20).

Purpose: UAT-043 and QUES-10. Today every generated question is required, technical and long text, with no help text, and the model never sees regulatory requirements, systems or assets.
Output: the v2 questionnaire pipeline, its wire fixtures and tests. Read projections of help text and provenance come in plan 12-08; the policy's enqueue refusal and its proofs come in plan 12-07.

Edits Strapi source? Yes. Changes the specification? No (job failure codes are free strings; read shapes change in 12-08). Runs Playwright? No (`questionnaire-generation-workflow.spec.ts` does not answer the generated questions; plan 12-18 changes it).
</objective>

## Recorded planning decisions

- **Provider input.** `QuestionnaireGenerationProvider.generate(input: { context: AssessmentContext; records: AssessmentContextRecords })`. The OpenAI-compatible provider uses `context.userPrompt` and `context.systemInstructions`; the deterministic one reads `records`. `QuestionnaireGenerationContext` (the seven-field type) is removed.
- **Internal proposal.** Stays `schemaVersion: 1`; each question gains optional `helpText: string | null` (at most 2,000 characters). The wire shape is `schemaVersion` 2 (one-value `enum: [2]`).
- **Not sure detection.** A select already offers an equivalent when a choice label, trimmed and lowercased, is `not sure`, `unsure`, `don't know`, `don’t know` or `unknown`; otherwise `{ value: "not-sure", label: "Not sure" }` is appended last.
- **Deterministic questionnaire** (`name: "deterministic-questionnaire-generation"`, `version: "2"`), seven questions in two sections, each with one or two sentences of help text: `security-objectives` (Long text, required); `business-criticality` (Single select Low, Moderate, High, Critical, Not sure; required); `third-party-involvement` (Single select Yes `yes`, No `no`, Not sure `not-sure`; required); `third-party-details` (Long text, visible when `third-party-involvement` equals `yes`, required when the request records third-party involvement); `regulatory-obligations` (Long text, optional, its text quoting the request's regulatory requirements); `asset-protection` (Long text, required, naming the first selected asset, else "the information this service handles"); `recovery-tested` (Single select Yes, No, Not sure; required; plan 12-06's draft reads it).
- **Execution order in `persistGeneratedQuestionnaire`:** load and check eligibility → `buildAssessmentContextFor` (a `AssessmentContextTooLargeError` becomes `QuestionnaireGenerationJobFailure("CONTEXT_TOO_LARGE", safeMessage)`, no run) → if `policy.status` is `refused`, `QuestionnaireGenerationJobFailure(policy.reason, aiPolicyRefusalMessage(policy))`, no run → `createRunningAiRun` (operation `questionnaire-generation`, `initiatedBy`, provider name and version, `jobId`, `attempt`, `assessmentRequest`, the summary) → provider → transaction: persist questions with `helpText` and `completeAiRun(strapi, runId, { proposal, questionnaire })` → on any failure after the run exists, `failAiRun` with the failure's safe code (`QUESTIONNAIRE_GENERATION_FAILED` when unknown) and rethrow. The registry already passes `jobId` and `attempt` to `execute`.
- **Harness helpers.** `withQuestionnaireProviderFailureCode(code, safeMessage, action)` patches the mounted deterministic questionnaire provider like `withProviderFailureCode` does for the draft; `listAiRunsForRequest(requestId)` returns the request's runs oldest first.
