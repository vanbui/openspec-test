## Phase Goal

**As a** Security Analyst, **I want to** have the AI work from everything the Requestor gave and show where each proposal came from, **so that** I can trust, check and correct its output quickly.

This plan's slice: the two rules every AI operation in the phase obeys. Ratings are derived from the 5 × 5 scales, never chosen by a model, and no request data reaches a provider above its approved classification ceiling.

Purpose: ASSESS-08 criterion 3 (Accept only for Low or Moderate residual risk) and INT-05 criterion 4 (refusal above the ceiling) both rest on these two pure modules; later plans call them and never re-derive either rule.
Output: two new modules with unit tests, the configuration contract, the transcript gate, and the harness pins.

Edits Strapi source? Yes. Changes the specification? No. Runs Playwright? No. Wave 1 alongside docs-only 12-01 (no shared file, and 12-01 runs no tests).
</objective>

## Recorded planning decisions

- **Placement of the vocabularies.** `DATA_CLASSIFICATIONS` moves from `assessment-workflow.ts` into `csrm/ai/data-policy.ts` (exported), and `assessment-workflow.ts` imports it; `ASSESSMENT_RATINGS` and `AssessmentRating` stay exported from `assessment-workflow.ts` under the same names, defined as `RISK_RATINGS` and `RiskRating` from `risk-scale.ts`, so no caller changes.
- **Policy signature.** `evaluateAiDataPolicy({ assets, ceiling, developmentRuntime })` is pure; `readAiDataPolicyConfiguration(strapi)` returns `{ ceiling, developmentRuntime }` from `strapi.config.get("ai").dataClassificationCeiling` and `isDevelopmentRuntime()`. `isDevelopmentRuntime(env = process.env)` is `NODE_ENV === "development" && CSRM_ENVIRONMENT === "development"` (the first two keys of `developmentIdentityEnabled`, which is not changed).
- **Decision shape.** `AiPolicyDecision = { status: "allowed" | "refused"; reason: "AI_POLICY_NOT_CONFIGURED" | "AI_CLASSIFICATION_ABOVE_CEILING" | null; requestClassification: DataClassification; classificationSource: "assets" | "default"; ceiling: DataClassification | null }`. The same shape is served later as `aiPolicy` (plan 12-14).
- **Plain messages.** `aiPolicyRefusalMessage(decision)` returns the plain Strapi-side message naming the request's classification and the ceiling (D-28): `This request's information is classified {level}, above the {ceiling} limit the AI provider is approved for.` and `The AI provider has not been approved for any information classification.` The web shows its own copy (UI-SPEC §11).
- **Not pinned:** `keycloak-provisioning.integration.test.ts` boots its own Strapi but never generates; it is left untouched so the phase's Keycloak diff check stays empty.
