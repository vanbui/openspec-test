This plan's slice: every AI-generated questionnaire and assessment says who asked for it, when, with which provider and model, and opens a side sheet showing exactly what the AI was given; the Requestor learns that AI assisted and an analyst reviewed.

## Recorded planning decisions

- **Server slot.** The editor, `assessment-editor.tsx`, and `questionnaire-review.tsx` are Client Components, so each page renders `<AiProvenanceHeader … />` on the server and passes it as a `provenanceHeader?: React.ReactNode` prop, which the client component places directly below `AssessmentRequestLink` and the lifecycle stepper (or the questionnaire's request link), above every alert and panel.
- **Header inputs.** The page derives `AiProvenanceHeaderProps` with `ai-assistance-domain.ts`: `{ kind: "assessment" | "questionnaire", generation, released, review: { kind: "counts", outstanding, firstDestination } | { kind: "questionnaire-counts", generated, edited, added } | { kind: "untracked" } | { kind: "none" } }`. For the assessment, `outstanding` sums the served `aiProvenance.outstanding` of the assessment and its risks; `firstDestination` is `#assessment-details` when the assessment details hold a proposed field, else `#risk-{id}` of the first risk in editor order with one. For the questionnaire, the counts come from `aiOrigin` and show only in analyst review.
- **Sheet.** `AiRunSheetTrigger` (client) renders `Show what the AI used` (outline, small, `FileSearch`) and imports `AiRunSheet` with `next/dynamic` (`ssr: false`); `AiRunSheet` composes the shipped `Sheet` (side from 768px at the form dialog width, full screen below with a visible `Close` named `Close what the AI used`), shows nothing for 300ms then the skeleton, and keeps its result per open.
- **Notice.** `AiAssistanceNotice` is a tiny presentational component (no data fetching, zod-free) rendered first under the Requestor's `Assessment overview` heading when `aiAssisted`; it prints.
- **Copy guard.** Its file list gains `src/features/ai-assistance/*.tsx`; its forbidden terms gain `provenance`, `run record`, `context summary` and `ceiling` for user-visible strings in those files.
