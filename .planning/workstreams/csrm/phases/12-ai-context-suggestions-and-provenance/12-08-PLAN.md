## Recorded planning decisions

- **Shared schema.** `AiGenerationFacts` = `{ generatedAt: string (date-time) | null, generatedBy: ActiveUserSummary | null, providerName: string | null, providerVersion: string | null, runId: string | null }`, closed, all keys required; plan 12-09 reuses it for the assessment.
- **Where each field appears.** `QuestionnaireQuestion.helpText` required and nullable (`maxLength: 2000`); `QuestionnaireQuestion.aiOrigin` optional, `enum: ["generated", "generated-edited", "analyst-added"]` or null. `QuestionnaireSummary.aiAssisted` required boolean; `QuestionnaireSummary.generation` optional `AiGenerationFacts`, emitted by the analyst's header read only (the list omits it to keep the list's reads bounded).
- **aiAssisted** is true when the questionnaire has `generatedDate` and a `providerName`; seeded questionnaires are false.
- **Origin rule.** Only when the latest generation has a completed run: a question with a `question-added` event after `generatedDate` is `analyst-added`; one with a `question-edited` event after it is `generated-edited`; any other active question is `generated`. Malformed log: no `aiOrigin` on any question.
- **Projection signatures.** `projectQuestionnaire(document, actor, generation?)` and `projectQuestions(questions, actor, origins?)`; the controller resolves the latest run and the generator's name with one bounded read each (the 08 D-31 batched-name pattern), only for analysts.
