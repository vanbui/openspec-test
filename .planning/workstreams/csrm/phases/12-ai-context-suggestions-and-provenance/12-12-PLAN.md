## Recorded planning decisions

- **Body.** `{ decisions: [{ target: { kind: "assessment" } | { kind: "risk", riskId: string }, action: "accept" | "dismiss" | "restore", fields?: string[], suggestion?: string }] }`, 1 to 200 items (`AI_PROPOSAL_DECISION_BATCH_MAX = 200`); `fields` and `suggestion` are mutually exclusive; `fields` are names from `RISK_AI_FIELDS` or `ASSESSMENT_AI_FIELDS` (12-04); `dismiss` needs `suggestion`. Response 200 `{ data: { applied: integer, unchanged: integer } }`. In this plan a decision with `suggestion` answers 400; 12-13 implements it without changing the body.
- **Field state table** (`applyFieldDecision`, pure, in `ai-proposal-decisions.ts` so the envelope module of 12-04 and 12-09 is unchanged). Accept: `proposed` → `accepted` (content change); `accepted` → no-op; `edited` → 409 `AI_PROPOSAL_ALREADY_DECIDED`. Restore: `accepted` → `proposed` (content change); `proposed` → no-op; `edited` → 409. A field with no AI fact → 400.
- **G-14 check.** `PLANNED_CONTROL_STATUS = "Planned"`; `riskHasPlannedControl(implementations)` is true when any implementation has `controlStatus` `Planned`. After every decision of the batch is applied inside the mutation, and before anything is written, for each risk whose `treatmentAction` fact this batch moves from `proposed` to `accepted` while the risk's `treatmentAction` is `Accept`, the workflow reloads the risk's control implementations inside the transaction; if `riskHasPlannedControl` is true it throws `AssessmentWorkflowError(409, "An AI-proposed Accept cannot be confirmed while the risk has a planned control.", "AI_ACCEPT_WITH_PLANNED_CONTROL")`. Because it runs after the whole batch, the order of decisions in a batch does not matter, and an implementation created earlier in the same batch (12-13) counts. Phase 16 reuses `riskHasPlannedControl` for its adapter's planned-control condition (Phase 16 D-38).
- **Transition.** `decideAiProposals` passes `transition: (outcome) => outcome.contentChanged ? "accepted-edit" : "none"` (12-11).
- **Grant.** `function.ai_proposals.decide_api` (name `Decide AI Proposals API`, description `Human analyst-only AI proposal decisions. This API-only Function intentionally has no menuPath.`, `roleIds: ["role.security_analyst"]`), FunctionApi `function.ai_proposals.decide_api.api.01` named `Decide AI Proposals`, sourceEntities `CsrmAiRun`, `CsrmAssessment`, `CsrmRisk`, `CsrmControl`, `CsrmControlImplementation`.
- **Spec.** Path `/v1/risk_assessments/{assessmentId}/ai_proposal_decisions` (operationId `assessment-workflow/decide-ai-proposals`), components `AiProposalDecisionRequest`, `AiProposalDecision`, `AiProposalDecisionResponse`; 400, 403, 404 and 409 responses reference `AssessmentWorkflowErrorResponse`.
- **Web.** `aiProposalDecisionResponseSchema` (closed) in `ai-assistance-schema.ts`, added to the module's `responseParserModule.parsers` (registered by 12-10); `decideAiProposals(assessmentId, decisions)` in `ai-assistance-service.ts` with parser label `decideAiProposals` and component `AiProposalDecisionResponse`. The Server Action, the service's unit case and the refusal copy come in 12-13.
