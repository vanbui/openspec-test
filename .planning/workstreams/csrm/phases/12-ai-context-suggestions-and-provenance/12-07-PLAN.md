## Phase Goal

**As a** Security Analyst, **I want to** have the AI work from everything the Requestor gave and show where each proposal came from, **so that** I can trust, check and correct its output quickly.

This plan's slice: no request data goes to a provider above its approved classification, with a plain reason at the point of asking; and an analyst's edit of an AI value is recorded as an edit.

<objective>
Refuse both AI operations at enqueue when the data policy refuses (D-28), carrying the closed reasons through Strapi, the specification and the web's refusal copy (D-02), and prove the enqueue and execution refusals on a mounted Strapi with a pinned ceiling. Then mark AI-proposed values `edited` when the risk or assessment update path changes them (D-21).

Purpose: INT-05 criterion 4 and INT-06 criterion 1 ("marked until accepted or edited").
Output: enqueue checks, two closed reasons end to end, the refusal copy, a policy integration file, and edit marking on both update paths.

Edits Strapi source? Yes. Changes the specification? Yes (two enum values). Runs Playwright? No.
</objective>

## Recorded planning decisions

- **Error reasons.** `AssessmentDraftWorkflowError` gains the optional third constructor argument `reason?: ConflictReason` (the 10-06 pattern), and the questionnaire controller's `generateAssessment` handler puts it in `error.details.reason` exactly as 10-06 does for `generateQuestionnaire`. The message is `aiPolicyRefusalMessage(decision)`.
- **Proof of "not configured" at mount level is not possible without changing the development identity's environment**, so `AI_POLICY_NOT_CONFIGURED` is proven by the pure grid of plan 12-02 and by a unit case that the enqueue maps any refused decision to its reason; the mounted file proves `AI_CLASSIFICATION_ABOVE_CEILING` for both operations, the default Internal classification and an allowed Public request.
- **Copy.** `aiPolicyRefusalCopy(reason, policy?)` in `refusal-copy.ts` returns the UI-SPEC §11.1 description for the reason, filling `{level}` and `{ceiling}` from the served `aiPolicy` when the caller has it (plan 12-14 passes it); when `AI_CLASSIFICATION_ABOVE_CEILING` arrives without policy values, it returns the §11.2 sentence for that code (the contract's only unparameterised wording). Family I's generation rows (both job cards) call it for these two reasons.
- **Edit comparison.** Strings compare exactly; relations (`riskType`, `informationSystemImpacted`, `informationAssetImpacted`) compare by documentId; an AI fact in state `proposed` or `accepted` whose value changes becomes `edited`; the event is `{ schemaVersion: 1, kind: "edited", at, by, target: <risk documentId or "assessment">, fields }` on the run named by `aiProvenance.runId`.
- **Harness helpers.** `runQuestionnaireGenerationJobFixture(requestId, analystId)` and `runAssessmentDraftJobFixture(questionnaireId, analystId)` call the two persist functions directly; `withProviderCallRecorder(action)` counts calls to both deterministic providers.
