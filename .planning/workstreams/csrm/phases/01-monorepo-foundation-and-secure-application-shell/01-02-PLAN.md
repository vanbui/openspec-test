<objective>
Implement the strict-TypeScript Next.js App Router shell, semantic BProton-led light theme, centralized development session/capability seam, and capability-driven responsive navigation.

Purpose: provide a usable, accessible foundation without treating a frontend development role as security authority.
Output: `apps/web` application shell, state components, session/capability adapters, and responsive desktop/mobile navigation.
</objective>

<threat_model>
## Threat Model

| Threat | Mitigation | Verification |
|---|---|---|
| Client role tampering | Keep development role selection server-contained in `DevelopmentSessionAdapter`; feature UI consumes capabilities, not role strings; never send the flag as API authority. | Unit test rejects direct role-string imports outside the adapter and navigation projection uses `can()`. |
| Open redirect after Keycloak sign-in | Validate `returnTo` as an internal relative path before redirect; fall back to the authorised landing route. | Unit test rejects absolute/protocol-relative paths. |
| Token leakage | Use HTTP-only, Secure/SameSite session-cookie seam; never use `localStorage` or `NEXT_PUBLIC_*` secrets. | Source assertion and session tests confirm cookie flags/no localStorage access. |
| UX mistaken for authorization | Mark route/nav checks as optimistic UX only; production backend authority stays Strapi. | Shell documentation/tests do not claim role switch grants API access. |
</threat_model>
