### The Contract Decision

The fix is an intersection, not a widening (06.9-04 locked decisions G-1 to G-7):

- Both filters keep the complete labelled vocabularies (D-1), and queue and status stay orthogonal.
- `filters[requestStatus]` on `GET /v1/assessment_requests` accepts all seven request statuses in every queue.
  - Outside the selected queue means: `draft` in any queue; `approved` or `closed` in an action queue; a reviewable status in the Released queue.
  - A status outside the queue returns HTTP 200 with an empty page and a total of 0, and the server issues no query for it.
  - An unknown, malformed or repeated value is still HTTP 400.
- `status` on `GET /v1/risk_assessments` accepts `closed`. Closed assessments are within the analyst assessment scope: the analyst collection adds no status predicate, and an analyst can read any assessment.
- `GET /v1/my_risk_assessments` shares the status validator. It keeps its released-owner bound, so `closed` returns an empty page there. Its published enum was widened to match the server.
- The mounted assertion `filters[requestStatus]=approved` → 400 was retired as part of this decision, not weakened. Its replacement proves the intersection.
