# Phase 06.6 Plan 01: Shared Record-Link and Typography Contracts Summary

**Token-owned record navigation and complete heading/display type utilities with document-backed tracking coverage.**

## Performance

- **Duration:** 18min
- **Tasks:** 2/2
- **Files modified:** 5

## Accomplishments

- Added `RecordLink`, which forwards record destinations while retaining consumer layout classes and protecting the shared link treatment.
- Added semantic link-decoration, typography size, line-height, tracking, and weight tokens to the global Tailwind v4 theme.
- Updated the design direction with record-link, DataTable scrolling, and shared state guidance.

## Task Commits

The plan landed as one reviewed commit: the execution environment cannot write repository metadata, so changes are reviewed and committed per plan from the controlling workspace (see STATE.md, Phase 06.6 decisions).

## Files Created/Modified

- `apps/web/src/components/csrm/record-link.tsx` — reusable Next record-navigation wrapper.
- `apps/web/src/components/csrm/record-link.test.tsx` — destination and class-composition coverage.
- `apps/web/app/globals.css` — semantic RecordLink and type utility contracts, with the reason the record-link declarations are `!important`.
- `docs/design/csrm-design-direction.md` — sole-authority guidance updates.

## Decisions Made

- Record links own colour, weight, underline, focus treatment, and transitions; consumers retain only layout composition. The declarations are `!important` so a feature class cannot restyle a record link.
- The design direction remains the single value-bearing authority for the new contracts.

## Deviations from Plan

- **The widened tracking assertion moved to 06.6-08.** Removing the uppercase-only guard made the conformance suite fail on every audited route: page titles render at 24px/600 with normal tracking because feature headings adopt the new heading utilities only in 06.6-08. Landing the assertion here would have left the suite red for six plans, so `design-system-conformance.spec.ts` is unchanged in this plan and 06.6-08 Task 3 now carries the widening alongside the heading migration it depends on.

## Issues Encountered

- The first browser run failed for the reason above (1 failed, 1 did not run, 1 passed). With the assertion deferred, the unchanged suite passes against the new tokens.
- Strapi emitted an EPERM warning inside the restricted execution environment when opening its user-level configuration file; the same suite run outside that environment shows no such warning.
- Running the isolated browser harness rewrites `apps/web/next-env.d.ts` and `apps/web/tsconfig.json`; those generated edits are discarded, not committed.
