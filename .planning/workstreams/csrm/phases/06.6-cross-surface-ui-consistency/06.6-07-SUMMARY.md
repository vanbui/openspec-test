# Plan 06.6-07 Summary

**Comparative browser contract for record links, responsive list layouts, shared states, Risk Register scrolling, anchors, accessibility, and console output, plus guarded fixture coverage for the three list routes that lacked it. A deliberate one-surface regression fails the suite.**

## Accomplishments

- Added the attested `resolveE2eUiState` and `E2eUiStateBoundary` presentation path to My Questionnaires, My Risk Assessments, and Assessment Request Review, only after their authorised list-service result. Authoritative service failures still render outside the fixture boundary.
- Extended the route authorization matrix to prove that service resolution precedes fixture selection, and that a 403 does not reveal a fixture boundary, for all three new routes plus the existing review and administration routes.
- Added `design-contract.spec.ts`. It compares `a.record-link` styles across eleven list surfaces and dashboard record links, each against the first surface, before checking the reference against `--text-link`, at 1440px and 375px. It also asserts the desktop table and mobile card-list split with list semantics, shared state heading typography and recovery controls across every surface, the Risk Register's sticky identifier while its labelled region scrolls at 1024px, the absence of disabled or placeholder anchors, no 375px page overflow, axe cleanliness, and no console errors.

## Review Fixes

Applied during review before commit:

- **Sign-in race.** The spec's sign-in asserted `toHaveURL(/\/app$/)`, which the sign-in URL itself (`/sign-in?returnTo=/app`) satisfies before the session exists; navigating away then cancelled the sign-in. Sign-in now waits for the banner to show the signed-in role.
- **Actors per surface.** My lists are owner-scoped for every actor, so a single identity cannot populate every surface. Each surface now declares the seeded identity that owns records there: the Requestor for questionnaires, the Security Analyst elsewhere.
- **Scroll assertions.** The sticky-column check now also asserts that the labelled region overflows and actually scrolled, so it cannot pass trivially when nothing scrolls or when an inner container scrolls instead.
