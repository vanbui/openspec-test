## Narrative Findings (AI reviewer)

## Blockers

### BL-01: Questionnaire integration test always fails after changing its provider environment

**File:** `apps/strapi/tests/questionnaire-generation.integration.test.ts:7-8,40`

**Issue:** The module sets `process.env.CSRM_AI_PROVIDER` to `"openai-compatible"` before creating the harness, then the first test asserts that exact variable equals `"deterministic"`. Nothing between those statements changes the environment. The test therefore fails deterministically before it can validate authorization or provenance. If that assertion were removed without reverting the provider setup, the test would instead try the unreachable `127.0.0.1:1/v1` endpoint and later fail the completed-job assertion. This breaks the required hermetic test suite.

**Fix:** Keep this integration suite deterministic: remove the two provider/base-URL assignments (and their restoration bookkeeping if no longer needed), retain the deterministic provenance assertions, and allow the harness to use its default provider. Test the compatible provider solely through the existing fake-server unit tests. Alternatively, configure a fake compatible endpoint for this integration suite and update every expectation to the compatible provider, but do not assert a value different from the environment set by the test.
