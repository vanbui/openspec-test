<objective>
## Phase Goal

**As a** CSRM operator, **I want to** have the questionnaire and assessment-draft generators backed by a real AI provider instead of deterministic stand-ins, **so that** analysts receive genuinely contextualised output while human review and release stay mandatory.

Plans 01 and 02 wrote provenance into the generation transactions. This plan proves those fields actually land in a real Strapi instance, proves an analyst edit does not erase them, proves no client can forge them, proves the failure taxonomy survives the whole path to the analyst's job-status response, and files the contract-gap record the project's conventions require before a data-model addition.

Purpose: turn "we added two schema attributes" into "an auditor can distinguish a self-hosted model from a hosted one on a real record, and nobody but the server can write that fact."
Output: one new contract-gap document, one harness helper, assertions in both existing integration suites.
</objective>

- What `providerVersion` is: the exact model identifier configured for the operation, which is self-documenting and needs no separate version bookkeeping.
- That both fields are **persistence-only for this phase**: no API projection exposes them, `docs/references/specification.json` is unchanged, no route or capability-catalogue entry changes, and no `apps/web` code is touched.
- What remains deferred to Phase 8 and is explicitly **not** claimed by this addition: durable job records, restart recovery of an in-flight attempt, input snapshots, proposal sources, field-level human-change tracking, prompt history, and any job audit history. Interface and API projections must continue not to imply stronger persistence, recovery or attribution than this record describes.
- That no migration file accompanies the change: `apps/strapi/database/migrations/` is an empty placeholder and Strapi's own schema sync handles additive optional attributes, which is the unbroken precedent across Phases 06.1 and 06.2.
