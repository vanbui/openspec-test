<objective>
## Phase Goal

**As a** CSRM operator, **I want to** have the questionnaire and assessment-draft generators backed by a real AI provider instead of deterministic stand-ins, **so that** analysts receive genuinely contextualised output while human review and release stay mandatory.

This plan closes the two operational guarantees the tracer left open: a misconfigured real provider must fail Strapi's boot loudly rather than surprise an analyst mid-workflow (D-05), and an automated run must never reach a live endpoint regardless of what a developer's local `.env` says (D-04). It also writes the operator documentation those guarantees depend on.

Purpose: make "deterministic providers still selectable for tests and offline runs" an enforced guarantee rather than an accident of what happens to be unset, and make a configuration hole a startup error rather than a runtime one.
Output: one new validation module, one lifecycle edit, one harness edit, one new unit test, one integration assertion, and two documentation edits.
</objective>

  <action>
Create `apps/strapi/src/csrm/ai-config-validation.ts`, a small single-purpose module in the same spirit as `src/csrm/config.ts`. Export `class CsrmAiConfigurationError extends Error` (setting `this.name`) and `function assertCsrmAiConfiguration(strapi: { config: { get: (key: string) => unknown } }): void`.

The function reads `strapi.config.get('ai')`. When the resolved `provider` value is anything other than the exact string `openai-compatible`, it returns immediately — deterministic mode has no configuration to validate and boot must stay unchanged. Otherwise it presence-checks four values and throws `CsrmAiConfigurationError` on the first that is absent, not a string, or blank after trimming. The message must name the missing environment variable so the operator can act on it without reading source:

- `assessmentDraft.baseURL` — report `CSRM_AI_ASSESSMENT_BASE_URL`
- `assessmentDraft.model` — report `CSRM_AI_ASSESSMENT_MODEL`
- `questionnaireGeneration.baseURL` — report `CSRM_AI_QUESTIONNAIRE_BASE_URL`
- `questionnaireGeneration.model` — report `CSRM_AI_QUESTIONNAIRE_MODEL`

Validate both triples even though a given deployment may only exercise one: D-03 makes them independent, and a half-configured process is exactly the state that surprises an analyst later. Never validate `apiKey`: a blank key is a supported configuration for keyless self-hosted backends (D-02). Never issue any network request, DNS lookup or socket connection — a self-hosted box can legitimately be unreachable while still warming up at startup, and the `PROVIDER_*` taxonomy already covers a genuinely unreachable endpoint at call time (D-05).

In `apps/strapi/src/index.ts`, import the function and call `assertCsrmAiConfiguration(strapi)` as the first statement inside the existing `register({ strapi })` body, leaving the commented Keycloak line and the whole `bootstrap()` body untouched. `register()` runs before `bootstrap()`'s DB-dependent seeding and before the HTTP server accepts requests, which is exactly where a configuration hole should stop the process. Let the thrown error propagate — do not catch, log-and-continue, or degrade to the deterministic provider.

Create `apps/strapi/tests/ai-provider-boot.unit.test.ts` with `node:test` cases covering every row of this task's `<behavior>` block, driving `assertCsrmAiConfiguration` directly with a fake `strapi` whose `config.get('ai')` returns a hand-built object. For the no-network case, point a triple's `baseURL` at `http://127.0.0.1:1/v1` and assert the call resolves synchronously without throwing, proving validation is presence-only.
