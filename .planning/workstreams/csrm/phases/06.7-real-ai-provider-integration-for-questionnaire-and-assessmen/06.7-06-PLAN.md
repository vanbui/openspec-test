<objective>
## Phase Goal

**As a** CSRM operator, **I want to** have the questionnaire and assessment-draft generators backed by a real AI provider instead of deterministic stand-ins, **so that** analysts receive genuinely contextualised output while human review and release stay mandatory.

This plan closes the phase's remaining guarantees: that a Requestor cannot steer the model into doing something the operator would not want (D-08), that context is never silently trimmed to fit (D-10), that the job registry's idempotency and concurrency behaviour is exactly what the phase-04 contract already documents and nothing new was added (D-11), and that no provider output can release an assessment (ROADMAP criterion 4).

It also carries the phase's only human verification: a live run against the operator's own configured endpoint, harvested at end of phase.

Purpose: prove the properties that make this integration safe to point at a real model, rather than only that it works.
Output: one new unit test file plus the end-of-phase live verification instructions.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Requestor-authored free text → prompt sent to the AI endpoint | The classic injection surface: `businessPurpose` and `thirdPartyDetails` for questionnaire generation, submitted answers for assessment-draft generation. |
| AI endpoint response → assessment and questionnaire aggregates | The model's output is untrusted input that must not be able to carry workflow, release or identity facts. |
| Analyst action → assessment release | Unchanged, and this plan pins that the provider boundary cannot reach it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06.7-01 | Tampering | Prompt assembly in both adapters | high | mitigate | Asserted: request-derived text appears only as labelled data in the user message; the system message frames it as untrusted; the request carries no `tools`, `functions` or `tool_choice`; the closed parser rejects out-of-vocabulary and extra-key output. |
| T-06.7-06 | Elevation of Privilege | Provider output reaching the assessment aggregate | high | mitigate | `parseAssessmentDraftProposal` asserted to reject each of `assessmentStatus`, `approvedBy`, `approvalDate`, `assessmentDate`, `reviewedBy` and `generatedBy`, so no proposal shape can move an assessment toward release; release remains the explicit analyst transaction, covered by the existing suite. |
| T-06.7-18 | Tampering | Silent context trimming producing a confidently-wrong assessment | medium | mitigate | Positive assertion that every supplied answer, Risk Type and control number appears verbatim in the outgoing request; a sampling, summarising or clipping regression turns the suite red. |

Pinned by test. |
