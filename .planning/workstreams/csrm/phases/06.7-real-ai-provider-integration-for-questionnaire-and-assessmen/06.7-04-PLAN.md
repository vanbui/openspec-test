<objective>
## Phase Goal

**As a** CSRM operator, **I want to** have the questionnaire and assessment-draft generators backed by a real AI provider instead of deterministic stand-ins, **so that** analysts receive genuinely contextualised output while human review and release stay mandatory.

Real provider calls introduce failure modes the deterministic providers never had. This plan completes the D-09 taxonomy the tracer opened: all four internal codes reachable, for both operations, with the analyst-facing message staying generic in every case so a log can distinguish transient-and-retryable from never-succeeds-without-operator-action while the UI leaks nothing.

Purpose: make a provider failure diagnosable by an operator reading logs and safe for an analyst reading the screen, at the same time.
Output: completed error mapping in the shared client, an extended local endpoint double, one new unit test file.
</objective>

Verified SDK error classes and the mapping they drive (source: `github.com/openai/openai-node` README "Error handling"):

| SDK error / condition | internal `failure.code` |
|---|---|
| `OpenAI.AuthenticationError` (HTTP 401) | `PROVIDER_AUTH_ERROR` |
| `OpenAI.PermissionDeniedError` (HTTP 403) | `PROVIDER_AUTH_ERROR` |
| `OpenAI.RateLimitError` (HTTP 429) | `PROVIDER_RATE_LIMITED` |
| `OpenAI.APIConnectionTimeoutError` (exceeded the configured `timeout`) | `PROVIDER_TIMEOUT` |
| Any other `OpenAI.APIError` (400/404/409/422/5xx), `OpenAI.APIConnectionError`, blank message content, non-JSON body, or JSON the closed parser rejects | `PROVIDER_OUTPUT_INVALID` |

Both registries accept a typed failure only when it satisfies their own guard, otherwise they collapse it:

```typescript
// assessment-draft-registry.ts (and the structurally identical questionnaire-generation-registry.ts)
function safeFailure(error: unknown): { code: string; message: string } {
  if (error instanceof AssessmentDraftJobFailure
    && /^[A-Z][A-Z0-9_]{0,63}$/.test(error.code)
    && nonBlank(error.safeMessage, 255)) {
    return { code: error.code, message: error.safeMessage };
  }
  return { code: "DRAFT_GENERATION_FAILED", message: "Assessment draft generation failed safely." };
}
```

Job projections expose the failure as `failureCode` and `failureMessage`:
```typescript
// assessment-workflow.ts projectAssessmentDraftJob / questionnaire-generation-workflow.ts projectQuestionnaireGenerationJob
...(job.failure ? { failureCode: job.failure.code, failureMessage: job.failure.message } : {}),
```
