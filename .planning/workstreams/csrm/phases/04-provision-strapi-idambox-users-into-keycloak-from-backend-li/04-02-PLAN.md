# Plan 04-02: Backend Keycloak Provisioning Integration

<objective>
Implement Strapi-side create/update provisioning for custom `IdamBox User` records using the dedicated Keycloak Admin API client and the `externalSubject`/password handling contract.
</objective>

<requirements>
- IDP-05: Strapi can provision custom IdamBox user records into Keycloak through the Keycloak API.
- IDP-06: Keycloak provisioning is idempotent and configured through environment values rather than hard-coded secrets.
</requirements>

<threat_model>
## Threat Model

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-04-03 | Strapi persists product passwords after sending them to Keycloak. | high | Always clear `IdamBox User.password` after successful create/update provisioning. |
| T-04-04 | Provisioning silently fails and leaves Strapi/Keycloak identity drift. | high | Throw an error when provisioning is enabled and Keycloak API/config fails, causing the Strapi operation to fail. |
| T-04-05 | Provisioning creates duplicate Keycloak users. | medium | Lookup by `externalSubject` when present and by unique email when absent before create. |
| T-04-06 | Recursive password-clearing update retriggers provisioning indefinitely. | medium | Add an explicit recursion guard or internal persistence helper for `externalSubject`/password cleanup. |
</threat_model>

<must_haves>
<truths>
- D-01: Provisioning runs on custom Strapi `IdamBox User` create and update events.
- D-02: Provisioning runs only when `IDAMBOX_KEYCLOAK_PROVISIONING=true`.
- D-03: Provisioning requires `KEYCLOAK_BASE_URL`, `KEYCLOAK_REALM`, `KEYCLOAK_ADMIN_CLIENT_ID`, and `KEYCLOAK_ADMIN_CLIENT_SECRET`; missing config must not silently fall back to committed defaults.
- D-04: A Keycloak provisioning failure must fail the Strapi create/update operation when provisioning is enabled.
- D-05: Strapi-created users are created in the `idambox` realm.
- D-11: Email is the idempotency lookup key when `externalSubject` is missing.
- D-12: Keycloak user ID is stored in `IdamBox User.externalSubject`.
- D-13: Updates use `externalSubject` when present and retain email lookup when `externalSubject` is missing.
- D-14: Provisioning must not create duplicate Keycloak users for the same email address.
- D-15: When creating a Keycloak user, a non-empty `IdamBox User.password` value is used as the Keycloak account password.
- D-16: When creating without a non-empty Strapi password, create the Keycloak user without committed credentials and set required action `UPDATE_PASSWORD`.
- D-17: When updating a Keycloak user, set the Keycloak password only when `IdamBox User.password` is non-empty.
- D-18: `IdamBox User.password` must be cleared after successful provisioning.
- D-19: `IdamBox User.password` is transient and must not become a persisted product credential store.
</truths>
</must_haves>

<decision_coverage>
- **D-01:** Provisioning must run on custom Strapi `IdamBox User` create and update events.
- **D-02:** Provisioning must be explicitly gated by `IDAMBOX_KEYCLOAK_PROVISIONING=true`.
- **D-03:** Provisioning must also require complete Keycloak environment configuration. Missing required config should prevent provisioning from running successfully rather than silently using committed defaults.
- **D-04:** A failed Keycloak provisioning operation must fail the Strapi create/update operation so Strapi and Keycloak do not silently drift.
- **D-05:** Strapi-created users must be created in the existing Keycloak `idambox` realm.
- **D-11:** Provisioning should find or create Keycloak users by the unique IdamBox user email address.
- **D-12:** After successful Keycloak create or lookup, Strapi must store the Keycloak user ID in the `IdamBox User.externalSubject` field.
- **D-13:** Future updates should use `externalSubject` when present, while retaining email lookup as the idempotency path when `externalSubject` is missing.
- **D-14:** Provisioning must not create duplicate Keycloak users for the same email address.
- **D-15:** When creating a Keycloak user, if the Strapi `IdamBox User.password` field is set to a non-empty value, use it to set the Keycloak account password.
- **D-16:** When creating a Keycloak user and the Strapi password field is missing or empty, create the Keycloak account without committed passwords and set an appropriate Keycloak required action such as password setup/reset.
- **D-17:** When updating a Keycloak user, set the Keycloak password only if the Strapi `IdamBox User.password` field is set to a non-empty value.
- **D-18:** After a successful Keycloak user create or update, always clear the Strapi `IdamBox User.password` field.
- **D-19:** The Strapi password field must remain a transient write-only provisioning input, not a persisted product credential store.
</decision_coverage>
