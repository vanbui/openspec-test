## Recorded planning decisions

- **Filters (`report-query.ts`).** `risk-exposure` and `assessment-throughput` accept `assessmentType` (`Project` | `BAU` | `Other` | `none`), `division`, `businessUnit` (1–200, trimmed and case-folded, exact), joined through the request; other reports refuse them (400). Every figure link the server builds carries the active filters.
- **Sections.** `risk-exposure.residualRatingByAssessmentType: { rows: [{ assessmentType: "Project" | "BAU" | "Other" | null, critical, high, moderate, low, notRated, total }], total }` over released open risks (11's exposure scope). `assessment-throughput.releasedByAssessmentType: { rows: [{ assessmentType, releasedInPeriod, medianDaysToRelease | null }] }`.
- **Dashboard.** `exposureByAssessmentType: [{ assessmentType, critical, high, all }]` with the four rows in the order Project, BAU, Other, Not set (null), over released open risks.
- **Accepted.** Every "accepted" count in these modules uses 20-10's marker (excluding `not-confirmed`).
- **Export.** `report-tables.ts` adds a table per new section with headers `Assessment type`, `Critical`, `High`, `Moderate`, `Low`, `Not rated`, `Total` and `Assessment type`, `Released in period`, `Median days to release`.
- **Contract.** The report response schemas gain the two sections, the report operation the three filter parameters, the dashboard summary schema `exposureByAssessmentType`; `report-schema.ts` and `analyst-dashboard-schema.ts` follow.
