## Recorded planning decisions

- **Install.** `pnpm --dir apps/backend add @strapi/provider-email-nodemailer@5.51.0 --save-exact`; the lockfile changes only by that package and its `nodemailer` 9.0.1. CSRM code never imports `nodemailer` directly.
- **Plugin config.** `config/plugins.ts` adds `email: { config: emailPluginConfig(readEmailConfig(process.env, { appRoot: process.cwd() })) }`, importing from `../src/csrm/email/email-config` (the `config/middlewares.ts` import precedent).
- **Capture provider.** `createCaptureProvider(dir)` returns `{ csrmCapture: true, send(options) }` writing `{ schemaVersion: 1, capturedAt, to, from, subject, text, html }` to `{dir}/{ISO time}-{random id}.json` with `flag: "wx"`, creating the directory once. In `bootstrap()`, before the start-up run and only when the mode is `capture`, assign `strapi.plugin("email").provider = createCaptureProvider(config.captureDir)` (after the plugin's own bootstrap, so the assignment sticks).
- **Sender (`email-sender.ts`).** `emailSender(strapi)` returns one instance per Strapi with `flush(deliveryIds)`, `flushPending(now)` and `drain()`. Per delivery: CAS `UPDATE csrm_reminder_deliveries SET email_attempts = email_attempts + 1, email_last_attempt_at = :now WHERE id = :id AND email_status IN ('pending','failed') AND email_attempts < :max AND (email_last_attempt_at IS NULL OR email_last_attempt_at < :leaseStart)` (bound `Date`s; the policy's 3 attempts and 15-minute lease); one affected row → this process sends. Then: config unavailable → `skipped`/`not-configured`; recipient email missing → `skipped`/`no-address`; recipient no longer reads the subject (20-13's readability) → `skipped`/`not-readable`; the reminder no longer applies (the subject's current candidates no longer include this key: treatment complete, date moved, risk closed, round closed, review confirmed) → `skipped`/`superseded`; else build `buildReminderEmail` from the notification's facts and the subject's number, with `reminderLink(webOrigin, destination)`, and `strapi.plugin("email").service("email").send({ to, subject, text, html: "" })`. Success → `sent` and `email_sent_at`; error → `failed` with `email_error_code` matching `EMAIL_ERROR_CODE_PATTERN = /^[A-Z0-9_]{1,64}$/` (nodemailer's `code`, else `SEND_FAILED`). No address, subject or message is ever logged. In-flight sends are tracked; `drain()` awaits them.
- **Run flush.** Each subject's transaction in `reminder-run.ts` registers `onCommit(() => { void emailSender(strapi).flush(claimedIds).catch(logSendFailure); })`; each run ends with `flushPending(now)` for retries; the per-act evaluation registers its own `onCommit`.
- **Bootstrap.** `register()` calls `readEmailConfig` so an invalid value fails boot; `bootstrap()` swaps the capture provider before the start-up run; the application's `destroy()` awaits `emailSender(strapi).drain()`.
- **Settings.** `apps/backend/.env.example` gains research §R4 item 8's commented block verbatim in substance (development capture default, the schedule, and the commented production block with no secret).
- **Harness.** Before `load()`: `CSRM_EMAIL_PROVIDER=capture`, `CSRM_EMAIL_CAPTURE_DIR=.tmp/authorization-http/mail-{pid}` (removed on close), `CSRM_EMAIL_FROM`, `CSRM_WEB_PUBLIC_ORIGIN=http://127.0.0.1:3000`, and `NODE_ENV` and `CSRM_ENVIRONMENT` set to `development` unless 14-04 already does; each in the restored list. Helpers `emailSenderDrain()` and `captureDirectory()`.
- **Playwright.** The Strapi `webServer.env` gains `CSRM_EMAIL_CAPTURE_DIR: join(e2eRuntimeRoot, 'mail')`; `process.env.CSRM_E2E_MAIL_CAPTURE_DIR ??= join(e2eRuntimeRoot, 'mail')`. `e2e/helpers/mail-capture.ts`: `readCapturedMail()` parses every JSON file in the directory; `waitForCapturedMail(predicate, { timeout })` uses `expect.poll`.
