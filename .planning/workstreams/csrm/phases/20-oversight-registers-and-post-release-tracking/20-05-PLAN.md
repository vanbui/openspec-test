## Phase Goal

**As a** risk manager, **I want to** registers by assessment type that stay current after release, and as a risk or treatment owner I want to track each treatment to completion on evidence, **so that** oversight reflects what is actually being done.

This plan's slice: the two foundations every post-release act stands on. The released record stays as released while its risks change, and one repository says who may read a risk and which parts they hold.

Purpose: SC2's "the released assessment is unchanged" and SC6's "the refusal a missing record gets" both rest on these two modules; every act from 20-06 on calls them.
Output: two modules, the overlay in four readers, two integration proofs, a unit test and a harness fixture helper.

Edits Strapi source? Yes (dev servers stopped). Changes the specification? No. Runs Playwright? No.

## Recorded planning decisions

- **Fields.** `RELEASE_TRACKED_RISK_FIELDS = ["treatmentProgress", "treatmentStatus", "treatmentPlan", "treatmentOwner", "treatmentResolveDate", "treatmentCompletedAt", "treatmentCompletedBy", "treatmentEvidence", "residualLikelihood", "highestResidualConsequence", "residualRating", "residualRatingOverrideReason", "residualRatingRationale", "controlEffectiveness", "closureDate", "closedBy", "closureReason", "isExempted", "exemptionReviewDate", "decisionReviewDate", "decisionReviewOutcome"] as const`; `RELEASE_TRACKED_CONTROL_FIELDS = ["controlStatus", "implementedDate", "effectivenessRating", "evidence", "reviewDate"] as const`. Relations are stored `{ documentId, label }` (16's relation form).
- **Wrapper.** `withReleasedRiskMutation({ strapi, riskDocumentId, actor: { documentId; part } | null, source: "post-release" | "scheduled-run", now: Date, mutate })`: `strapi.db.transaction(async ({ trx, onCommit }) => …)`; resolve the risk's request; `withRequestLock` (13-03) first, then `forUpdate` on the risk row (bound to `trx`); load the risk with its control implementations; `ensureReleaseBaseline(strapi, { risk, actor, source, trx })`; then `mutate({ risk, trx, onCommit, today: utcToday(now) })`. A missing risk throws a not-found error the controllers map to 404. The wrapper does not check release or tracking: the acts call `decideRiskAct` first; the wrapper refuses only an unreleased risk with a typed `RISK_NOT_RELEASED` error as a last guard.
- **Baseline.** `ensureReleaseBaseline` reads whether a `release-baseline` row exists for the risk (safe under the risk lock), and if not writes one through `recordRiskHistory` with `buildReleaseBaselineChanges` (20-03), kind `release-baseline`, the actor and source passed in (null actor only for `scheduled-run`), the assessment and risk relations.
- **Overlay.** `loadReleaseBaselines(strapi, assessmentDocumentId)` makes one `strapi.db.query(HISTORY_UID).findMany({ where: { kind: "release-baseline", assessment: { documentId } }, select: ["changes"], populate: { risk: { select: ["documentId"] } } })` and returns `Map<riskDocumentId, baseline>`; a malformed row is logged once and skipped (the live value is then shown, which is right when nothing wrote after release). `overlayReleaseBaseline(risk, baseline)` replaces only the fields the projection already carries, and each control implementation's delivery fields by `documentId`. No released projection adds any Phase 20 column (research §R9).
- **Readers.** `released-assessment-read.ts`: the loaded released assessment's risks are overlaid before any projection (the participant view, Phase 19's export and the A4 report all read it); `assessment-scope.ts`: the analyst released detail's risks are overlaid before `projectAnalystRiskDetail`; `released-assessment-export.ts`: overlaid where it loads risks for a released assessment, if not already through the read. Phase 18's table and its export build rows from the overlaid projection, so they need no change; the integration test proves it.
- **People.** `viewerFromState(state)` → `{ documentId, isHumanAnalyst, isServiceIdentity }` from the resolved IdamBox User's roles in `ctx.state` (never the auth mode). `loadRiskPeople(strapi, riskDocumentId, { trx? })` → null for a missing risk, else `{ riskDocumentId, assessmentDocumentId, requestDocumentId, released, closed, withdrawn, treatmentAction, requestorDocumentId, assignedAnalystDocumentId, people: RiskPeopleFacts }` in one bounded read with the request's requestor and assignee and 17.1's executive approver. `assignedAnalystOf({ assignedAnalyst, approvedBy, eligible })` (D-25). `canReadRisk(viewer, loaded, isParticipant)`: a part on a released risk, a participant through 17's "readable now" check, or a human analyst. `applyRiskPersonPredicate(query, viewerDocumentId)` adds `EXISTS` over the risk owner, executive approver and treatment owner link tables and the control implementations' control owner links, restricted to released parents (11-14's `applyReleasedParent`); link-table names come from `strapi.db.metadata`, never hand-written.
- **Harness helper.** `seedReleasedTrackedAssessment(options)` builds on 17.1's released-assessment fixture (its executed name): Jane's Project request released and closed by Bob, one Treat risk (treatment owner, resolve date and risk owner as options), one Accept risk with a completing decision row and review date, a planned control implementation with a control owner, and optionally the executive approver identity; it returns every documentId.
