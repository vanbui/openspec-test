## Recorded planning decisions

- **Bodies.** Close: `{ reason, base: { closureDate: null } }`; reopen: `{ reason, base: { closureDate } }`; residual review: `{ residualLikelihood, highestResidualConsequence, residualRating?, residualRatingOverrideReason?, residualRatingRationale, controlEffectiveness?, base: { residualLikelihood, highestResidualConsequence, residualRating } }`; control delivery: `{ controlStatus?, implementedDate?, effectivenessRating?, evidence?, reviewDate?, base: { controlStatus, implementedDate, effectivenessRating, evidence, reviewDate } }`; decision review: `{ outcome: "confirmed" | "not-confirmed", rationale, base: { reviewDate } }`. Reasons 1–500; rationales 1–2,000; scale values exactly 18's labels (`SCALE_VALUE_INVALID`), a differing rating without reason `RATING_OVERRIDE_REASON_REQUIRED`.
- **Close and reopen.** Close writes `closureDate = utcToday(now)`, `closedBy`, `closureReason`, one `risk-closed` row, and nothing on the treatment; on a closed risk → 409 `RISK_CLOSED`. Reopen clears the three facts, writes `risk-reopened`, and re-derives the status (a reopened Treat risk past its date reads Overdue again); on an open risk → 409 `RISK_NOT_CLOSED`. Withdrawal stays pre-release (Phase 16).
- **Residual review.** Writes the residual fields and rationale through 18's derivation, then, if `isExempted` and the new rating is below Critical, clears `isExempted` and `exemptionReviewDate`; one `residual-reviewed` row with every changed field (the rating included when unchanged, so the review is recorded) and the rationale in `reason`. A rise to Critical adds no exception.
- **Control delivery.** The implementation must belong to the risk (else 404); allowed moves `Planned` → `Implemented` | `Retired`, `Existing` → `Retired` (else 409 `CONTROL_DELIVERY_NOT_ALLOWED`); field validation from the control-implementation workflow; `control-implementation-updated` with source `post-release`.
- **Decision review.** `reviewDecision`: `decideRiskAct` with act `review-decision`, where readers who are not an allowed reviewer get 403 `DECISION_NOT_PERMITTED`, except a risk owner or approver of a risk whose required holder is missing or ineligible, who gets 409 `REVIEW_AUTHORITY_MISSING`; then 400 body; then 409 `REVIEW_NOT_APPLICABLE` (no standing Accept or exception, or closed → `RISK_CLOSED`), `REVIEW_NOT_DUE` (before `decisionReviewOpensOn`), `TREATMENT_CHANGED` for a stale base. Confirm writes `decisionReviewOutcome: "confirmed"`, `decisionReviewDate = nextDecisionReviewDate(today, rating)` and, for an exception, `exemptionReviewDate = utcDateToInstant(that date)`; not confirm writes `not-confirmed`. One `decision-reviewed` row with the outcome, the old and new dates and the rationale. The `decision-review-not-confirmed` notification is added by 20-13.
- **SQL mirror (`decision-review.ts`).** `DECISION_REVIEW_DATE_SQL(metadata)` returns research §R7's `COALESCE(r.decision_review_date, (correlated latest completing act's review_date))` with link names from `strapi.db.metadata`; `applyDecisionReviewStatePredicate(query, state, { today, leadDays, strapi })` for `due-soon`, `due`, `overdue`, `not-confirmed`, `reviewer-missing` and `later`, with the v1 exception branch bound to instants (`exemption_review_date < :instant(D + 1)`), never a datetime cast.
- **Routes** (in `routes/risk-tracking.ts`): `POST /v1/risks/:riskId/close` → `close`; `POST /v1/risks/:riskId/reopen` → `reopenRisk`; `POST /v1/risks/:riskId/residual_reviews` → `recordResidualReview`; `PUT /v1/risks/:riskId/control_implementations/:controlImplementationId/delivery` → `recordControlDelivery`; `POST /v1/risks/:riskId/decision_reviews` → `reviewDecision`.
- **Catalogue.** Create `function.risk_register.post_release_api` (`Post-Release Risk Review API`, description `Lets a human Security Analyst review, close, reopen and record control delivery on a released risk. This API-only Function intentionally has no menuPath.`, `roleIds: ["role.security_analyst"]`); move `function.risk_register.risk_details.api.05` to `function.risk_register.post_release_api.api.01` with `functionId` updated, name and URL unchanged and the description 20-01 records; remove it from `risk_details.functionApiIds`; add `.api.02` `Reopen Risk`, `.api.03` `Record Residual Review`, `.api.04` `Record Control Delivery`; create `function.risk_register.decision_review_api` (`role.requestor`, `role.security_analyst`) with `.api.01` `Review Decision`. The four post-release literals join `HUMAN_ANALYST_ONLY_OPERATIONS` and its matrix mirror; all five join `SERVICE_IDENTITY_REFUSED_OPERATIONS`. The inventory's reserved entry for `POST:/api/v1/risks/{riskId}/close` is removed by regeneration.
- **Contract.** Spec tag `risk-tracking`; operationIds `risk-tracking/close-risk`, `/reopen-risk`, `/record-residual-review`, `/record-control-delivery`, `/review-decision`; components `RiskClosureRequest`, `RiskReopeningRequest`, `ResidualReviewRequest`, `ControlDeliveryRequest`, `DecisionReviewRequest`, `RiskReviewStateResponse` (`{ data: { riskId, closure: { closedOn, closedBy, reason } | null, residual: { likelihood, consequence, rating, overrideReason, rationale, controlEffectiveness }, exception: { isExempted, exemptionReviewDate }, decisionReview: { date, state, outcome } | null, tracking: TreatmentTracking } }`).
