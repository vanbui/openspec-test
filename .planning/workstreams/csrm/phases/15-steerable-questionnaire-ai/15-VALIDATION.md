**Known infrastructure facts.**
1. **Shared `dist`.** The orchestrator's dev Strapi (1337) and Next (3000) may run during execution. Everything that compiles Strapi shares `apps/backend/dist`: the Strapi suite, a single Strapi file, `served-operations:write` and Playwright. All of these wait until the servers are stopped.
2. **No live AI.** Every suite pins `CSRM_AI_PROVIDER=deterministic` and `CSRM_AI_DATA_CLASSIFICATION_CEILING=''` (Phase 12 D-31). Both deterministic providers of this phase emit model-facing wire JSON, so the adapter's drop rules run in every suite.
3. **Held jobs.** Concurrency proofs (a Requestor answer landing between a held job and a confirmation; completion racing an edit) use `withHeldQuestionnaireProposalProvider` (15-06), which holds the deterministic proposal provider until released.
4. **Jobs are process-local** (R-08-36). No E2E relies on a job outliving a restart; interrupted runs are Phase 12's reconciliation.
5. **Fixtures (the 06.9 lesson).** The new journey creates its own UAT-A-like request, marks its own note through Phase 13's UI, and adds its own "Is MFA enforced …" question for the rewrite.
6. **Windows vitest** can fail with `EPERM: rename`. Rerun that file alone before treating it as a real failure.
7. **Existing tests that change deliberately:** three tests of `questionnaire-generation.integration.test.ts` (D-09, W-6; 15-08-02): the regenerated-event test's second half and the change-count test replace before editing, or assert the refusal, and the CR-101 test where a replacement waits for a question add now expects the replacement to fail with `QUESTIONNAIRE_HAS_ANALYST_CHANGES` and the log to hold only the add, while the full-log and unreadable-log cases stay `HISTORY_UNAVAILABLE` unchanged; Phase 12's family J sentence is reworded (UI-D29; 15-10-03); Phase 10's Replace dialog variants (U3; 15-13-02) and families C and D in `questionnaire-workflow.test.tsx` (U4; 15-13-03); `questionnaire-generation-workflow.spec.ts` (Replace narrowed, instruction field; E2, 15-13-04). `questionnaire-workflow.unit.test.ts` does not change (it never calls `saveAnswers` or `submitQuestionnaire`; W-7): the Requestor's re-check is proven mounted (15-07-03).
8. **Widths** (W-10, E-1). The mobile project runs only the files in its closed `testMatch`, and of those only tests tagged `@journey`. `questionnaire-workflow.spec.ts`, `questionnaire-governance-workflow.spec.ts` and `questionnaire-generation-workflow.spec.ts` are desktop-only (1440; they resize to 375 only inside their own pass); `ai-context-provenance.spec.ts`, `request-attachments.spec.ts`, `request-pick-up.spec.ts` and `quick-find.spec.ts` run in both projects; Phase 15's 375 proof is `questionnaire-ai-proposals.spec.ts`, which 15-14-01 adds to the mobile `testMatch` and proves with `playwright test --list --project=mobile`.

## Sampling Rate

- **After every task commit:**
  - run the touched web test files by path;
  - run `typecheck` when types change, and `api:check` after any spec change;
  - run the touched Strapi files by path, dev servers stopped.
- **After every plan wave:**
  - run the full web suite, `typecheck` and `api:check`;
  - run the full Strapi suite after every plan that edits Strapi (15-02 to 15-09; each of those plans' closing task already runs it), and the served-operations test after 15-10;
  - run each UI plan's targeted Playwright specs once at its end, at the widths each runs (fact 8): 15-10: the desktop `performance.spec.ts`; 15-11: `questionnaire-governance-workflow.spec.ts` and `performance.spec.ts` (desktop); 15-12: `questionnaire-governance-workflow.spec.ts`, `questionnaire-workflow.spec.ts`, `ai-context-provenance.spec.ts`, then the desktop `performance.spec.ts`; 15-13: `questionnaire-generation-workflow.spec.ts`, `questionnaire-workflow.spec.ts`, `request-attachments.spec.ts`, `request-pick-up.spec.ts`, `ai-context-provenance.spec.ts`, `quick-find.spec.ts`, then the desktop `performance.spec.ts`; their closing tasks already run them, and each records the route budgets (fact 9).
- **Before `/gsd-verify-work`:** the full suite must be green. That is the phase gate above (plan 15-14, task 15-14-03), recorded with counts, duration, the flaky count and the clean `git status --short`.
- **Max feedback latency:** 90 seconds for the task-level quick runs. The tasks that close a Strapi plan run the full Strapi suite (about 22 min), and the UI plans' closing tasks run the production-build Playwright specs, so those exceed it by design.
