## Phase Goal

**As a** Security Analyst, **I want to** tell the AI what to add, change or remove in a questionnaire and to have it propose follow-up questions without touching answered ones, **so that** the question list keeps up with new information while I stay in control.

This plan's slice: whatever the AI returns, CSRM keeps only proposals it can stand behind, records everything it left out, and never lets a proposal touch an answered question.

<objective>
Build the two model-facing wire schemas, the one adapter with every drop rule, the deterministic providers that exercise each rule, the hosted OpenAI-compatible providers with their system instructions, and one shared Not sure rule (D-11, D-13, D-15, D-17). Prove the adapter with model-facing wire fixtures through `tests/helpers/fake-openai-compatible-server.ts` (the 06.7 lesson).

Purpose: QUES-11 criterion 1 (an instruction returns a proposal of additions, edits and deletions), QUES-12 criterion 2 (no proposal changes or removes an answered question) and success criteria 1 and 2 in their deterministic form.
Output: four new provider and adapter modules, one shared rule, three wire fixtures and the provider tests. No workflow calls them yet (15-06 does).

Edits Strapi source? Yes. Changes the specification? No. Runs Playwright? No.
</objective>

## Recorded planning decisions

- **Questionnaire proposals wire v1** (`schemaName: "questionnaire_proposals"`): 15-RESEARCH §B exactly: root `schemaVersion` (`integer`, `enum: [1]`) and `items`; each item requires `kind` (`add`, `change`, `remove`), `target` (`Q1…Qn` or null), `questionText`, `helpText`, `answerType` (`Text`, `Long text`, `Single select`, `Multi select`, `Date`, or null), `choices` (string array), `required` (boolean or null), `sectionTitle`, `visibleWhen` (`anyOf` of `{ question, operator, value }` and null), `rationale`, `sources` (string array). The `Q` enums are built per run from `allowed.refs`. 16 object properties, depth 3.
- **Question rewrite wire v1** (`schemaName: "question_rewrite"`): `schemaVersion` (`enum: [1]`), `questionText`, `helpText` (string or null), `choiceLabels` (string array), `rationale`.
- **Adapter steps** (`toQuestionnaireProposal(raw, adapterContext)`): structure (a structural failure throws `QuestionnaireGenerationJobFailure("PROVIDER_OUTPUT_INVALID", …)`); then per wire item, in order, the first failing rule records one adjustment and drops the item: kind rules (`invalid-item`; unused fields recorded once as `ignored-field`), target resolution (`unknown-target`, `removed-target`, `answered-target`), `duplicate-target`, bounds (`invalid-item`: text 1 to 1,000, help at most 2,000, rationale at most 1,000, section title at most 255, label at most 255, 2 to 20 choices on a select before Not sure, none otherwise), select labels unique case-insensitively, then `withCanonicalNotSure` (one canonical Not sure, where the model put its equivalent, else last), sources filtered to `allowed.sourceRefs` (unknown ones counted once per run as `sources-dropped`, at most 10 kept), additions near-duplicate against active questions, open items, rejected items, removed questions and earlier kept additions (`near-duplicate`, `isNearDuplicate`), a change identical to its target (`no-change`), apply to a copy with `createBatchAllocation` and `placeAddition` and check `validateDefinition`-equivalent parsing (`definition-invalid`) and `preservesAnswers` and `keepsControllerValues` (`answers-affected`, `definition-invalid`), then caps (`over-limit`, aggregated into one adjustment with a count). Choice and visibility values arrive as labels and map to the target's or controller's values case-insensitively; a Boolean controller maps `Yes` and `No` to true and false. Kept items get keys `i-1…` and their bases (`changeBase`, `addBase`). The result passes `parseQuestionnaireProposal(value, allowed)` or the job fails with `PROVIDER_OUTPUT_INVALID`.
- **Rewrite adapter** (`toQuestionRewriteProposal(raw, adapterContext)`): structure; bounds; `choiceLabels.length` must equal the target's choice count (empty for free text and Boolean) else the item is dropped as `rewrite-out-of-scope`; labels map positionally onto the unchanged values; no difference after normalisation → `outcome: "no-change"`, `items: []`; otherwise exactly one `change` whose `proposed` copies the answer type, values, required flag, section, order and visibility from the target. Preservation and definition validity run as for a change.
- **Adapter context** (`QuestionnaireAdapterContext`): `allowed` (15-04), the context-time rows (`PreservationRow[]` with fingerprint inputs), `generatedDate`, and the active, open, rejected and removed texts for the scorer; the workflow (15-06) builds it from the same records as the context.
- **Caps** (`QUESTIONNAIRE_PROPOSAL_CAPS`): `items: 30`, `additions: 15`, `sources: 10`, `adjustments: 60`.
- **Deterministic rules** (wire JSON; `deterministic-questionnaire-proposals` version `1`, `deterministic-question-rewrite` version `1`): 15-RESEARCH §J W1 (a marked note containing `offshore` and no active question mentioning it: the three additions in section `Offshore support`, each citing that note, required, with help text: `In which country or countries is the offshore support team based?` (Text), `Will the offshore support team have administrator access to your systems?` (Single select Yes, No), `How is the offshore team's administrator access approved and logged?` (Long text)); W2 (analyst instruction only: `tax file number` or `tfn` → `Will the service collect or store tax file numbers?` in `Personal information` citing `instruction`; `drop`, `remove` or `delete` → one removal of the unanswered active question with the highest token overlap with the rest of the instruction; `plain language` → one change on the first unanswered question R1 would change); W3 (no marked note: one conditional addition `What access will they have to your systems or data, and how is it controlled?` (Long text) on the first answered Single select offering `Yes`, visible when it equals Yes, citing that question); always, when an answered question exists, one change rewording it (dropped as `answered-target`) and one addition repeating the first active question's text with different punctuation (dropped as `near-duplicate`). R1's glossary: `MFA` or `multi-factor authentication` → `a second sign-in step (multi-factor authentication)`; `privileged` → `administrator`; `federated identities` → `accounts that sign in through another organisation`; `break-glass accounts` → `emergency administrator accounts`; `segregation of duties` → `splitting tasks so no one person can do everything`; the help text explains the first matched term in one sentence; no match → the target unchanged.
- **Hosted providers.** `openaiCompatibleQuestionnaireProposalProvider` and `openaiCompatibleQuestionRewriteProvider` use `requestJsonCompletion` with the `questionnaireGeneration` settings (no new setting, D-16), name and version as 12-05's hosted generation provider sets them, and the system message `UNTRUSTED_DATA_INSTRUCTION` followed by the Phase 15 rules (15-RESEARCH §B "System instructions"); the user message is `composeUserPrompt` of the context, which carries the slot.
- **Provider interface** (`questionnaire-proposal-provider.ts`): `QuestionnaireProposalProvider { name; version; propose(input: QuestionnaireProposalProviderInput): Promise<unknown> }` and `QuestionRewriteProvider { name; version; rewrite(input): Promise<unknown> }`, where the input carries the built prompt, the allowed sets, the marked note texts (for W1), the instruction and its source; `activeQuestionnaireProposalProviders()` selects by `CSRM_AI_PROVIDER_MODE`. The deterministic objects keep mutable `propose` and `rewrite` members so the harness can hold them (15-06).
- **Not sure** (N-1; the shipped rule is authoritative, IN-110 and WR-02). `NOT_SURE_CHOICE`, `isNotSureEquivalent` and `withCanonicalNotSure` move unchanged from `openai-compatible-questionnaire-generation-provider.ts` into `apps/backend/src/csrm/ai/not-sure-choice.ts`, with the module-private nine-entry `NOT_SURE_EQUIVALENTS` set and `comparableChoice` (case, apostrophes, hyphens, underscores, spacing and a closing stop ignored). `withCanonicalNotSure(choices)` keeps one canonical `{ value: "not-sure", label: "Not sure" }` where the model put its first equivalent, drops any second, and appends it last when the model offered none. The generation provider imports them from the shared module and keeps no copy; 12-05's generation tests (`ai-provider-questionnaire.unit.test.ts`) run unchanged. D-13's "Not sure ensured last" reads as this rule: exactly once; a model's equivalent canonicalised where the model put it; added last when absent.
